Slide 4–8

The Church-Turing Thesis claims that every feasible method of computation is either equivalent to or weaker than a Turing machine. (“This is not a theorem – it is a falsifiable scientific hypothesis. And it has been thoroughly tested!” - Ryan Williams)

Very Important Terminology: accepts / rejects / loops / does not accept / does not reject / halts (as in the last lecture).

Recognizers and Recognizability: A TM \( M \) is called a recognizer for a language \( L \) over \( \Sigma \) if \( \forall w \in \Sigma^*.\ (w \in L \leftrightarrow M \text{ accepts } w) \). A language is recognizable when there is a recognizer for it.

Which of these statements are true for all choices of TM \( M \), string \( w \), and language \( L \)?

  1. If \( M \) recognizes \( L \) and \( M \) rejects \( w \), then \( w \notin L \).
  2. If \( M \) recognizes \( L \) and \( w \notin L \), then \( M \) rejects \( w \).
  3. If \( M \) loops on \( w \) and \( w \in L \), then \( M \) does not recognize \( L \).
  4. If \( M \) loops on \( w \) and \( w \in L \), then \( L \) is not recognizable.

复习上一讲的术语和识别器定义 (见 CS103 21). 判断题, (1)(3) 对, (2)(4) 错:

  1. 对. M 拒绝 w, 就是没接受, 由识别器定义 w ∉ L.
  2. 错. 识别器对 L 外的串也可能死循环, 不一定拒绝.
  3. 对. 识别器必须接受 L 中的每个串, 在 w ∈ L 上死循环就不是 L 的识别器.
  4. 错. M 不是识别器, 不代表别的图灵机也不是; L 仍可能可识别.
Slide 9–12

Deciders and Decidability

  • A TM \( M \) is called a decider for a language \( L \) over \( \Sigma \) if the following statements are true:

    \( \forall w \in \Sigma^*.\ M \text{ halts on } w. \)
    \( \forall w \in \Sigma^*.\ (w \in L \leftrightarrow M \text{ accepts } w) \)

  • A language is decidable when there is a decider for it.

Which of these statements are true for all choices of TM \( M \), string \( w \), and language \( L \)?

  1. If \( M \) decides \( L \) and \( M \) rejects \( w \), then \( w \notin L \).
  2. If \( M \) decides \( L \) and \( w \notin L \), then \( M \) rejects \( w \).
  3. If \( M \) loops on \( w \) and \( w \in L \), then \( M \) does not decide \( L \).
  4. If \( M \) loops on \( w \) and \( w \in L \), then \( L \) is not decidable.

R and RE Languages

  • The class R consists of all decidable languages.
  • The class RE consists of all recognizable languages.
  • By definition, we know \( \mathbf{R} \subseteq \mathbf{RE} \).
  • Key Question: Does \( \mathbf{R} = \mathbf{RE} \)?

同一组判断换成判定器, (1)(2)(3) 对, (4) 错:

  1. 对, 理由同上.
  2. 对. 判定器总停机, 不接受就是拒绝.
  3. 对. 判定器不会死循环 (其实只要 M 在任何串上死循环, 它就不是判定器).
  4. 错. 一个 M 失败, 别的图灵机可能能判定 L.

R 是可判定语言类, RE 是可识别语言类, R ⊆ RE. 核心问题: R = RE 吗?

Strings, Languages, and Encodings

Slide 15–18

What problems can we solve with a computer? — What is a “computer?” — What does “solve” mean? — What is a “problem?”

Decision Problems

  • A decision problem is a problem with a yes-or-no answer.
  • For example:
    • “Given integers \( x \), \( y \), and \( z \), is \( x + y = z \)?” is a decision problem.
    • “Given integers \( x \) and \( y \), what is \( x + y \)?” is not a decision problem.
  • DFAs, NFAs, and TMs solve decision problems: they get an input and produce a yes/no output.

总问题拆成三问: 什么是计算机 (图灵机), 什么是「解决」(判定、识别), 还剩什么是「问题」. 本课研究 decision problem 判定问题: 答案只有是或否. 「x + y 是否等于 z」是判定问题; 「x + y 等于多少」不是, 它要输出一个数. 自动机和图灵机都只输出接受或拒绝, 所以研究的正是判定问题.

Strings and Objects

  • Think about how my computer encodes the image on the right. Internally, it's just a series of zeros and ones sitting on my hard drive.
  • A different sequence of 0s and 1s gives rise to the image on the right.
  • Every image can be encoded as a sequence of 0s and 1s, though not all sequences of 0s and 1s correspond to images.

图片在硬盘上就是一串 0 和 1. 不同的 0/1 串对应不同的图片; 每张图片都能编码成 0/1 串, 但不是每个 0/1 串都是一张合法的图片 (例如格式头不对). 这说明「对象」和「字符串」之间可以来回转换, 只是需要约定好编码格式.

Slide 32–35

Object Encodings

  • If Obj is some mathematical object that is discrete and finite, then we'll use the notation ⟨Obj⟩ to refer to some way of encoding that object as a string.
    • Think of ⟨Obj⟩ like a file on disk – it encodes some high-level object as a series of characters.
  • Key idea: If you want to have a TM compute something about Obj, you can provide the string ⟨Obj⟩ as input to that Turing machine.
  • A few remarks about encodings:
    • We don't care how we encode the object, just that we can.
    • The particular choice of alphabet isn't important. Given any alphabet, we can always find a way of encoding things.
  • For the purposes of what we're going to be doing, we aren't going to worry about exactly how objects are encoded.
  • For example, we can say ⟨137⟩ to mean “some encoding of 137” without worrying about how it's encoded.
    • Analogy: do you need to know how numbers are represented in Python to be a Python programmer? That's more of a CS107 question.
  • We'll assume, whenever we're dealing with encodings, that some Smart, Attractive, Witty person has figured out an encoding system for us and that we're using that encoding system.

每张图片都能编码成 0/1 串, 反过来不是每个 0/1 串都是合法的图片. 一般地, 任何离散、有限的数学对象 Obj 都可以编码成字符串, 记作 ⟨Obj⟩, 就像存在磁盘上的文件. 要让图灵机计算关于 Obj 的事情, 就把 ⟨Obj⟩ 作为输入.

本课不关心编码的具体方式, 只关心「能编码」. 字母表也不重要: 二进制、十进制、任何字母表之间都能互相转换. 写 ⟨137⟩ 就表示「137 的某种编码」, 就像写 Python 程序不需要知道整数在内存里怎样存储 (那是 CS107 计算机系统的内容). 课件开玩笑说, 假设有一位「聪明、迷人、风趣」的人替我们定好了编码方案.

Object encodings let us define languages like these:

{ ⟨n⟩ | n ∈ ℕ and n is even }
{ ⟨n⟩ | n ∈ ℕ and the Hailstone sequence terminates for n }
{ ⟨G⟩ | G is a graph and G is bipartite }

We can focus more on what property of an object we're checking for rather than how the object is represented as a string.

有了编码, 语言就能直接写成「具有某性质的对象」: 偶数、冰雹序列会终止的数、二部图. 我们关注的是性质, 而不是表示方式.

编码的一个具体例子: 图 G = (V, E), V = {1, 2, 3}, E = {{1, 2}, {2, 3}}, 可以写成字符串「3;1-2,2-3」: 分号前是节点个数, 后面列出所有边. 一个判断二部图的图灵机读到这个串, 就能还原出图再做判断. 多个对象的编码 ⟨G, s, t⟩ 可以写成「3;1-2,2-3|1|3」, 用竖线分隔三个部分. 换成别的约定也行, 只要能无歧义地还原.

Encoding Groups of Objects

  • Given a group of objects \( Obj_1, Obj_2, \dots, Obj_n \), we can create a single string encoding all these objects.
    • Intuition 1: Think of it like a .zip file, but without the compression.
    • Intuition 2: Think of it like a tuple or struct.
  • We'll denote the encoding of all of these objects as a single string by ⟨Obj₁, …, Objₙ⟩.

We can now talk about languages like these:

{ ⟨R, w⟩ | R is a regex and R matches w }
{ ⟨G, s, t⟩ | G is a graph, s and t are nodes in G, and there's a path from s to t }

Our languages are starting to look a lot more like problems in the traditional sense than sets of strings.

(图: 多个参数 (possibly multiple distinct values) 合成一个大比特串送进图灵机.)

多个参数怎么办 (如 isVertexCover(G, C)、matchesRegex(w, R))? 把多个对象一起编码成一个串 ⟨Obj₁, …, Objₙ⟩, 像不压缩的 zip 包, 或像元组、结构体. 于是可以定义「正则表达式 R 匹配串 w」「图 G 中从 s 到 t 有路径」这样的语言. 语言越来越像传统意义上的「问题」, 而不只是字符串的集合.

涌现性质
Emergent Properties

Slide 48–51

Emergent Properties

  • An emergent property of a system is a property that arises out of smaller pieces that doesn't seem to exist in any of the individual pieces.
  • Examples:
    • Individual neurons work by firing in response to particular combinations of inputs. Somehow, this leads to consciousness, love, and ennui.
    • Individual atoms obey the laws of quantum mechanics and just interact with other atoms. Somehow, it's possible to combine them together to make iPhones and pumpkin pie.
  • If this definition seems fuzzy, it's because it is. 😃
  • Computational devices (TMs and other equivalent devices) have two surprising emergent properties:
    • Universality: There is a single computing device capable of performing any computation.
    • Self-Reference: Computing devices can ask questions about their own behavior.
  • These properties are, in a sense, inherent to all computing devices. Computing can't exist without them.
  • These properties are interesting in their own rights – and are the theoretical basis for much of modern computing.
  • They also are an “Achilles' heel” of computational devices, and we'll use them to find concrete examples of problems computers can't solve.

emergent property 涌现性质: 由简单部件组合出、但在任何单个部件中都看不到的性质. 例: 单个神经元只是对输入放电, 合起来却产生意识和情感; 单个原子只服从量子力学, 合起来却能做出 iPhone 和南瓜派. 课件承认这个定义很模糊.

图灵机 (及等价设备) 有两个涌现性质: universality 通用性, 有一台机器能完成任何计算; self-reference 自指, 计算设备可以询问关于自身行为的问题. 它们是所有足够强的计算设备固有的, 是现代计算的理论基础, 同时也是计算的「阿喀琉斯之踵」: 下一讲正是用它们找到计算机解决不了的具体问题.

通用图灵机
Universal Machines

Slide 53–58

An Observation

  • Think about how you interact with your physical computer.
    • You have a single, physical computer.
    • That computer then runs multiple programs.
  • Contrast that with how we've worked with TMs.
    • We have a TM for \( \{ a^n b^n \mid n \in \mathbb{N} \} \). That TM will always perform that calculation and never do anything else.
    • We have a TM for the hailstone sequence. That TM can't compose poetry, write music, etc.
  • How do we reconcile this difference?

Can we make a “reprogrammable Turing machine”?

A TM Simulator

  • It is possible to program a TM simulator on an unbounded-memory computer.
    • You've seen this in class, and you'll use one on PS8.
  • We could imagine it as a method bool simulateTM(TM M, string w) with the following behavior:
    • If \( M \) accepts \( w \), then simulateTM(M, w) returns true.
    • If \( M \) rejects \( w \), then simulateTM(M, w) returns false.
    • If \( M \) loops on \( w \), then simulateTM(M, w) loops infinitely.

一个对比: 我们只有一台电脑, 却能运行许多程序; 而之前的每台图灵机只做一件事 (识别 \( a^n b^n \) 的那台永远只做这个). 能不能造一台「可重新编程」的图灵机?

普通计算机可以写一个图灵机模拟器 simulateTM(M, w): M 接受 w 就返回 true, 拒绝就返回 false, 死循环就跟着死循环. 注意第三条: 模拟器只是忠实地一步步执行, 无法提前知道 M 会不会停.

Slide 59–64
  • Anything that can be done with an unbounded-memory computer can be done with a TM.
  • So there must be some TM that has the behavior of simulateTM.
  • What would that TM do?

The Universal Turing Machine

  • Theorem (Turing, 1936): There is a Turing machine \( U_{TM} \) called the universal Turing machine that, when run on an input of the form ⟨M, w⟩, where M is a Turing machine and w is a string, simulates M running on w and does whatever M does on w (accepts, rejects, or loops).
  • The observable behavior of \( U_{TM} \) is the following:
    • If M accepts w, then \( U_{TM} \) accepts ⟨M, w⟩.
    • If M rejects w, then \( U_{TM} \) rejects ⟨M, w⟩.
    • If M loops on w, then \( U_{TM} \) loops on ⟨M, w⟩.

\( U_{TM} \) does to ⟨M, w⟩ what M does to w.

由 Church-Turing 论题, 普通计算机能做的图灵机都能做, 所以存在一台图灵机具有 simulateTM 的行为. 这就是 universal Turing machine 通用图灵机 \( U_{TM} \) (图灵 1936 年证明): 输入一台图灵机的编码 M 和一个串 w, 它模拟 M 在 w 上的运行, M 接受它就接受, M 拒绝它就拒绝, M 死循环它也死循环. 一句话: \( U_{TM} \) 对 ⟨M, w⟩ 做的事, 就是 M 对 w 做的事.

Slide 65–72
  • Intuition: Modern computers – laptops, phones, network routers, etc. – are universal Turing machines.
    • Each computer is a single piece of hardware.
    • With rare exceptions, we don't make specific changes to the hardware after we purchase the computer.
    • We load programs into those computers, and those computers then execute the commands in those programs.
  • Turing came up with this idea in 1936 – before any programmable computers had been built!
  • Building out \( U_{TM} \) is nontrivial, but the conceptual idea behind it isn't too bad.
  • Essentially:
    • \( U_{TM} \) splits its tape into two regions: one spot holding the source code of the TM to simulate, and one holding the tape contents for that TM.
    • \( U_{TM} \) somehow marks where in the simulated TM's tape the simulated TM's tape head is, perhaps by having a special symbol indicating “tape head here.”
    • \( U_{TM} \) repeatedly consults the source code of the simulated TM to determine what action to take, then simulates that action.
    • If the simulated TM accepts or rejects, then \( U_{TM} \) also accepts or rejects.

直觉: 现代计算机 (笔记本、手机、路由器) 都是通用图灵机: 同一套硬件, 买来后基本不改, 通过加载不同的程序来做不同的事. 图灵在 1936 年就提出了这个想法, 那时还没有任何可编程的计算机.

\( U_{TM} \) 的构造思路: 纸带分两区, 一区存被模拟机器的「源代码」, 一区存被模拟机器的纸带内容; 用一个特殊符号标出被模拟的读写头位置; 反复查源代码决定下一步动作并模拟; 被模拟的机器接受或拒绝时, 它也接受或拒绝.

Slide 73–76

Amazing Thought: \( U_{TM} \) is the most powerful computational device that can be built.

  • Assuming the Church-Turing thesis, any computation that can be performed by any computing system can be performed by a TM.
  • The universal TM can “run” any TM, so it can perform any computation any TM can perform.
  • So \( U_{TM} \) can do any computation that could ever be done by any possible feasible computing system. (Wow!)
  • And yet – it's just a simulator! All it does is simulate one step of a TM after another.

惊人之处: \( U_{TM} \) 是能造出的最强计算设备. 由 Church-Turing 论题, 任何计算都能由某台图灵机完成; \( U_{TM} \) 能运行任何图灵机, 所以它能完成任何可行计算. 而它本身只是一个模拟器, 一步一步地照着别的机器的指令走.

Slide 77–89

\( U_{TM} \) as a Recognizer

  • \( U_{TM} \), when run on a string ⟨M, w⟩, where M is a TM and w is a string, will accept / reject / loop exactly when M does on w.
  • \( U_{TM} \) recognizes some language. Which language is that?

Let \( A_{TM} \) be the language recognized by the universal TM \( U_{TM} \). This means that

\( \forall x \in \Sigma^*.\ (U_{TM} \text{ accepts } x \leftrightarrow x \in A_{TM}) \)
\( \forall M.\ \forall w \in \Sigma^*.\ (U_{TM} \text{ accepts } \langle M, w\rangle \leftrightarrow \langle M, w\rangle \in A_{TM}) \)
\( \forall M.\ \forall w \in \Sigma^*.\ (M \text{ accepts } w \leftrightarrow \langle M, w\rangle \in A_{TM}) \)

So we have

\( A_{TM} = \{ \langle M, w\rangle \mid M \text{ is a TM and } M \text{ accepts } w \} \)

The Language \( A_{TM} \)

Here's a complicated expression. Can you simplify it? ⟨\( U_{TM} \), ⟨N, x⟩⟩ ∈ \( A_{TM} \).

Given the definition of \( A_{TM} \) and \( U_{TM} \), the following statements are all equivalent to one another.

  • M accepts w.
  • \( U_{TM} \) accepts ⟨M, w⟩.
  • ⟨M, w⟩ ∈ \( A_{TM} \).

任何图灵机都识别某个语言 (它接受的串的集合), \( U_{TM} \) 也不例外. 它识别的语言记作 \( A_{TM} \) (A 代表 accept):

\[ A_{TM} = \{ \langle M, w\rangle \mid M \text{ 是图灵机且 } M \text{ 接受 } w \} \]

推导: \( U_{TM} \) 接受 ⟨M, w⟩ 当且仅当 M 接受 w, 代入识别器的定义即得. 三句话等价: M 接受 w; \( U_{TM} \) 接受 ⟨M, w⟩; ⟨M, w⟩ ∈ \( A_{TM} \).

化简练习: ⟨\( U_{TM} \), ⟨N, x⟩⟩ ∈ \( A_{TM} \) ⟺ \( U_{TM} \) 接受 ⟨N, x⟩ ⟺ N 接受 x. 由于 \( U_{TM} \) 是 \( A_{TM} \) 的识别器, \( A_{TM} \in \mathbf{RE} \), 图中的星号表示这一点. 它是否在 R 中是下一讲的问题.

例子: 若 M 是上一讲识别 \( a^n b^n \) 的图灵机, 则 ⟨M, aabb⟩ ∈ \( A_{TM} \), ⟨M, aab⟩ ∉ \( A_{TM} \). 若 M 是冰雹序列的图灵机, ⟨M, \( a^n \)⟩ 是否在 \( A_{TM} \) 中就取决于序列对 n 是否终止. 可见 \( A_{TM} \) 把「任何图灵机在任何输入上是否接受」打包成了一个问题, 它的难度至少不低于其中任何一个具体问题.

Slide 92–95

Reason 1: It has practical consequences.

Why Does This Matter?

  • The existence of a universal Turing machine has both theoretical and practical significance.
  • For a practical example, let's review this diagram from before. Previously we replaced the computer with a TM. (This gave us the universal TM.) What happens if we replace the TM with a computer program?

(图: 程序代码 code 和输入 w 送进 simulateProgram, 结果 true / false / (loop).)

  • We now have a computer program that runs other computer programs!
  • An interpreter is a program that simulates other programs. Python programs are usually executed by interpreters. Your web browser interprets JavaScript code when it visits websites.
  • A virtual machine is a program that simulates an entire operating system. Virtual machines are used in computer security, cloud computing, and even by individual end users.
  • It's not a coincidence that this is possible – Turing's 1936 paper says that any general-purpose computing system must be able to do this!

实际意义: 把图中的图灵机换成普通程序, 就得到「运行别的程序的程序」. interpreter 解释器就是这样: Python 解释器执行 Python 程序, 浏览器解释 JavaScript. virtual machine 虚拟机更进一步, 模拟整个操作系统, 用于安全隔离、云计算等. 图灵 1936 年的论文表明, 任何通用计算系统都必然能做到这一点.

在 Python 里, 内置函数 exec 就是一个「通用机」: 把一段程序代码作为字符串交给它, 它就执行这段代码. 例如 exec("print(1 + 2)") 打印 3. 程序和数据在这里没有本质区别: 同一个字符串既可以被当作数据处理 (求长度、拼接), 也可以被当作程序运行. 这种「程序即数据」的思想正是冯·诺依曼体系结构 (存储程序计算机) 的核心, 而图灵在 1936 年就从理论上提出了它.

Slide 96–98

Reason 2: It's philosophically interesting.

Can Computers Think?

  • On May 15, 1951, Turing delivered a radio lecture on the BBC on the topic of whether computers can think.
  • He had the following to say about whether a computer can be thought of as an electric brain...
“In fact I think [computers] could be used in such a manner that they could be appropriately described as brains. I should also say that ‘If any machine can be appropriately described as a brain, then any digital computer can be so described.’ This last statement needs some explanation. It may appear rather startling, but with some reservations it appears to be an inescapable fact. It can be shown to follow from a characteristic property of digital computers, which I will call their universality. A digital computer is a universal machine in the sense that it can be made to replace any machine of a certain very wide class. It will not replace a bulldozer or a steam-engine or a telescope, but it will replace any rival design of calculating machine, that is to say any machine into which one can feed data and which will later print out results.”

引文前半 (1951 年 5 月 15 日 BBC 广播「计算机能思考吗」): 图灵认为计算机可以被恰当地称为「大脑」, 并且断言: 只要有任何机器能被称为大脑, 任何数字计算机也都能. 这听上去惊人, 但他说这是数字计算机的一个特征性质推出来的必然结论, 他把这个性质叫作 universality 通用性: 数字计算机能代替非常广泛的一类机器. 它代替不了推土机、蒸汽机、望远镜这类物理设备, 但能代替任何「计算机器」, 即输入数据、之后输出结果的机器.

Slide 98
“In order to arrange for our computer to imitate a given machine it is only necessary to programme the computer to calculate what the machine in question would do under given circumstances, and in particular what answers it would print out. The computer can then be made to print out the same answers. If now some machine can be described as a brain we have only to programme our digital computer to imitate it and it will also be a brain.”

引文后半给出论证: 要让计算机模仿某台机器, 只需编程让它计算那台机器在给定情况下会做什么、会输出什么答案, 然后输出同样的答案. 所以如果某台机器可以称为大脑, 编程让数字计算机模仿它, 计算机也就是大脑了. 这正是通用图灵机的思想: 模拟就等于拥有同样的计算能力. 这次广播的观点后来发展成图灵测试 (1950 年论文《计算机器与智能》中已提出模仿游戏).

自指的软件
Self-Referential Software

Slide 100–101

Quines

  • A Quine is a program that, when run, prints its own source code.
  • Quines aren't allowed to just read the file containing their source code and print it out; that's cheating (and technically incorrect if someone changes that file!)
  • How would you write such a program?

Writing a Quine

Quine 奎因程序: 运行后打印出自己源代码的程序. 不许读取自己的源文件 (那是作弊, 而且文件被改了就不对了). 课上现场演示了如何写一个 (幻灯片只有标题).

一个两行的 Python quine (已运行验证, 输出与源代码逐字相同):

s = 's = %r\nprint(s %% s)'
print(s % s)

原理: 字符串 s 是程序的「模板」, 里面留了一个位置 %r 放 s 自己的表示形式; print(s % s) 把 s 代入自己的模板. 程序分成「数据」(s) 和「处理数据的代码」(print), 代码把数据用了两次: 一次当模板, 一次当填进去的内容. 这正是自指的标准构造, 也是下面定理的核心想法.

Slide 102–104

Self-Referential Programs

  • The fact that we can write Quines is not a coincidence.
  • Theorem: It is possible to construct TMs that perform arbitrary computations on their own source code.
  • In other words, any computing system that's equal to a Turing machine possesses some mechanism for self-reference!
  • Want to see how deep the rabbit hole goes? Take CS154!
  • Claim: Going forward, assume that any function has the ability to get access to its own source code.
  • This means we can write programs like the ones shown here:
bool narcissist(string input) {
    string me = /* source code of narcissist */;
    return input == me;
}

bool acceptLongerStrings(string input) {
    string me = /* source code of acceptLongerStrings */;
    return input.length() > me.length();
}

Quine 能写出来不是巧合. 定理 (Kleene 递归定理的一种形式): 可以构造图灵机, 让它对自己的源代码做任意计算. 也就是说, 和图灵机等价的任何计算系统都有自指能力. 细节见 CS154.

以后可以假设任何函数都能拿到自己的源代码 (变量 me). 例子: narcissist 只接受「自己的源代码」这一个串; acceptLongerStrings 接受比自己源代码长的串.

思考: narcissist 的语言恰好只有一个串, 就是它自己的源代码. 「拿到自己的源代码」看似是一种作弊的超能力, 但 quine 的例子说明它可以用普通指令实现, 不需要读文件. 下一讲会构造一个程序, 让它拿到自己的源代码后, 去问「我自己会不会接受这个输入」, 然后故意反着做, 由此推出矛盾. 这和康托尔对角线论证 (CS103 08) 是同一个套路.
