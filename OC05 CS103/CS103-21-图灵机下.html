Turing Machines

  • A Turing machine is a program that controls a tape head as it moves around an infinite tape.
  • There are six commands: Move direction; Write symbol; Goto label; Return boolean; If symbol command; If Not symbol command
  • Despite their limited vocabulary, TMs are surprisingly powerful.

这一讲回答两个问题: 图灵机到底有多强 (Church-Turing 论题); 「解决一个问题」究竟是什么意思 (可识别与可判定). 重点是接受、拒绝、死循环三种结果的区分, 以及 R 和 RE 两个语言类的定义. 图灵机的六条指令见 CS103 20.

Slide 5

A Sample Turing Machine

  • Inputs over the alphabet \( \Sigma = \{a, b\} \).
  • What strings does this TM accept?
  • Can you write a regex that matches precisely the strings this TM accepts?
Start:
  If Not 'a' Return False
Loop:
  Move Right
  If Not Blank Goto Loop
  Move Left
  If Not 'b' Return False
  Return True

逐段读: 第一个字符不是 a 就拒绝 (包括空串); Loop 一直右移到空白, 再左移一格回到最后一个字符; 最后一个字符不是 b 就拒绝, 否则接受. 所以它接受「以 a 开头、以 b 结尾」的串, 正则表达式是 a(a ∪ b)*b, 即 aΣ*b. 单独一个 a 会被拒绝: 它的最后一个字符是 a 而不是 b.

Church-Turing 论题
Just how powerful are Turing machines?

Slide 8–12

Main Questions for Today: Just how powerful are Turing machines? What problems can you solve with a computer?

Real and “Ideal” Computers

  • A real computer has memory limitations: you have a finite amount of RAM, a finite amount of disk space, etc.
  • However, as computers get more and more powerful, the amount of memory available keeps increasing.
  • An idealized computer is like a regular computer, but with unlimited RAM and disk space. It functions just like a regular computer, but never runs out of memory.

Theorem: Turing machines are equal in power to idealized computers. That is, any computation that can be done on a TM can be done on an idealized computer and vice-versa.

Key Idea: Two models of computation are equally powerful if they can simulate each other.

真实计算机内存有限, 但内存在不断变大. idealized computer 理想化计算机: 和普通计算机一样工作, 只是内存无限、永不耗尽. 定理: 图灵机和理想化计算机能力相同, 一方能做的计算另一方也能做.

比较两个计算模型的方法: 如果它们能互相模拟, 就一样强. 下面分两个方向说明.

Slide 13–14

Simulating a TM

  • The individual commands in a TM are simple and perform only basic operations: Move Write Goto Return If
  • The memory for a TM can be thought of as a string with some number keeping track of the current index.
  • To simulate a TM, we need to
    • see which line of the program we're on,
    • determine what command it is, and
    • simulate that single command.
  • Claim: An idealized computer can simulate a TM.
    • The “core” logic for the TM simulator is under fifty lines of code, including comments.

Because a computer can simulate each individual TM instruction, an idealized computer can do anything a TM can do.

Key Idea: Even the most complicated TM is made out of individual instructions, and if we can simulate those instructions, we can simulate an arbitrarily complicated TM.

方向一: 计算机能模拟图灵机. 纸带可以存成一个字符串 (或字典) 加一个表示读写头位置的下标; 模拟时只需记住当前执行到第几行, 判断是哪条指令, 执行它. 核心逻辑不到五十行代码. 本笔记前一讲就用一个 Python 小程序模拟了课件里的几个图灵机.

要点: 再复杂的图灵机也是由一条条简单指令组成的, 能模拟每条指令, 就能模拟整个机器.

Slide 15–16

Simulating a Computer

  • Programming languages provide a set of simple constructs.
    • Think things like variables, arrays, loops, functions, classes, etc.
  • You, the programmer, then combine these basic constructs together to assemble larger programs.
  • Key Idea: A TM is powerful enough to simulate each of these individual pieces. It's therefore powerful enough to simulate anything a real computer can do.

A Leap of Faith

  • Claim: A TM is powerful enough to simulate any computer program that gets an input, processes that input, then returns some result.
  • The resulting TM might be colossal, or really slow, or both, but it would still faithfully simulate the computer.
  • We're going to take this as an article of faith in CS103.
    • If you curious for more details, come talk to me after class.

方向二: 图灵机能模拟计算机. 编程语言由变量、数组、循环、函数、类等基本构件组成, 图灵机能模拟每一种构件, 也就能模拟任何「读入输入、处理、返回结果」的程序. 模拟出的图灵机可能极其庞大、极其缓慢, 但结果一样. CS103 不给出完整证明, 把它当作接受的前提.

原文笔误: “If you curious for more details” 漏了动词, 应为 “If you're curious”.

Slide 17–19

Can a TM Work With…

  • “cat pictures?” — Sure! A picture is just a 2D array of colors, and a color can be represented as a series of numbers.
  • “cat videos?” — If you think about it, a video is just a series of pictures!
  • “music?” — Sure! Music is encoded as a compressed waveform. That's just a list of numbers.
  • “ChatGPT?” — Sure! That's just applying a bunch of matrices and nonlinear functions to some input.

图灵机只能处理纸带上的符号, 能处理图片、视频、音乐、ChatGPT 吗? 都可以, 因为它们最终都编码成数字: 图片是颜色的二维数组, 视频是一串图片, 音乐是压缩后的波形数值, 大语言模型是一堆矩阵运算和非线性函数. 只要能编码成字符串, 图灵机就能处理.

Slide 20–24

The Church-Turing Thesis claims that every feasible method of computation is either equivalent to or weaker than a Turing machine.

“This is not a theorem – it is a falsifiable scientific hypothesis. And it has been thoroughly tested!” — Ryan Williams

(图: Regular Languages ⊂ CFLs ⊂ Problems Solvable by Any Feasible Computing Machine ⊂ All Languages; 由论题, 「任何可行计算机器能解决的问题」就是「图灵机能解决的问题」.)

TMs and Computation

  • Because Turing machines have the same computational powers as regular computers, we can (essentially) reason about Turing machines by reasoning about actual computer programs.
  • Going forward, we're going to switch back and forth between TMs and computer programs based on whatever is most appropriate.
  • In fact, our eventual proofs about the existence of impossible problems will involve a good amount of pseudocode. Stay tuned for details!

Church-Turing thesis 丘奇-图灵论题: 任何可行的计算方法, 能力都等于或弱于图灵机. 它不是定理, 因为「可行的计算方法」不是一个数学定义, 无法证明; 它是一个可以被证伪的科学假说, 至今经受住了所有检验 (λ 演算、递归函数、现代计算机、量子计算机在「能算什么」上都不超过图灵机).

后果: 图灵机能解决的问题就是任何计算机能解决的问题. 以后可以在图灵机和普通程序 (伪代码) 之间自由切换, 后面证明「不可能解决的问题」时会大量使用伪代码.

The Hailstone Sequence

  • Consider the following procedure, starting with some \( n \in \mathbb{N} \), where \( n \gt 0 \):
    • If \( n = 1 \), you are done.
    • If \( n \) is even, set \( n = n / 2 \).
    • Otherwise, set \( n = 3n + 1 \).
    • Repeat.
  • Question: Given a natural number \( n \gt 0 \), does this process terminate?

(动画: 17 → 52 → 26 → … → 16 → 8 → 4 → 2 → 1.)

Does the Hailstone Sequence terminate for… n = 5? Yes, after 5 steps. n = 20? Yes, after 7 steps. n = 7? Yes, after 16 steps. n = 27? Yes, after 111 steps.

「什么样的计算机」已经回答了 (图灵机), 现在问「解决」是什么意思. 例子: hailstone sequence 冰雹序列. 从正整数 n 出发, 偶数就除以 2, 奇数就乘 3 加 1, 直到变成 1. 问题: 这个过程对给定的 n 会不会终止?

试几个: 5 → 16 → 8 → 4 → 2 → 1, 5 步; 20 要 7 步; 7 要 16 步; 27 要 111 步, 途中最高升到 9232. 步数用 Python 核对过.

Slide 34–37

The Hailstone Turing Machine

  • Let \( \Sigma = \{a\} \) and consider the language

    \( L = \{ a^n \mid n \gt 0 \text{ and the hailstone sequence terminates for } n \} \).

  • We can build a TM for \( L \) as follows:
    • If the input is \( \varepsilon \), reject.
    • While the string is not a:
      • If the input has even length, halve the length of the string.
      • If the input has odd length, triple the length of the string and append a a.
    • Accept.

Does this Turing machine accept all nonempty strings?

The Collatz Conjecture

  • It is unknown whether this process will terminate for all natural numbers.
    • In other words, no one knows whether this TM always terminates!
  • The conjecture (unproven claim) that the hailstone sequence always terminates is called the Collatz Conjecture.
  • This problem has eluded a solution for a long time. The influential mathematician Paul Erdős is reported to have said “mathematics may not be ready for such problems.”

把问题写成语言: 用 n 个 a 表示数 n, L 是冰雹序列会终止的那些 \( a^n \). 图灵机直接模拟序列: 串长偶数就减半, 奇数就变成三倍再加一个 a, 变成单个 a 时接受.

这个图灵机接受所有非空串吗? 没人知道. 「冰雹序列对所有正整数都终止」就是著名的 Collatz conjecture 考拉兹猜想, 至今未被证明或推翻. 埃尔德什曾说「数学也许还没准备好处理这类问题」.

关键: 如果某个 n 的序列永不终止, 这个图灵机在 \( a^n \) 上就会永远运行下去, 既不接受也不拒绝.

Slide 38–40

An Important Observation

  • Unlike finite automata, which automatically halt after all the input is read, TMs keep running until they explicitly return true or return false.
  • As a result, it's possible for a TM to run forever without accepting or rejecting.
  • This leads to several important questions:
    • How do we formally define what it means to build a TM for a language?
    • What implications does this have about problem-solving?

Very Important Terminology

  • Let \( M \) be a Turing machine.
  • \( M \) accepts a string \( w \) if it returns true on \( w \).
  • \( M \) rejects a string \( w \) if it returns false on \( w \).
  • \( M \) loops infinitely (or just loops) on a string \( w \) if when run on \( w \) it neither returns true nor returns false.
  • \( M \) does not accept \( w \) if it either rejects \( w \) or loops on \( w \).
  • \( M \) does not reject w \( w \) if it either accepts \( w \) or loops on \( w \).
  • \( M \) halts on \( w \) if it accepts \( w \) or rejects \( w \).

(图: Accept、Reject、Loop 三块; Accept 和 Reject 合起来是 halts, Reject 和 Loop 合起来是 does not accept, Accept 和 Loop 合起来是 does not reject.)

和有限自动机不同, 有限自动机读完输入自动停机; 图灵机要执行到 Return 才停, 所以可能永远运行. 术语 (非常重要):

  • accepts 接受: 返回 true.
  • rejects 拒绝: 返回 false.
  • loops 死循环: 永远不返回.
  • halts 停机: 接受或拒绝.
  • does not accept 不接受: 拒绝或死循环.
  • does not reject 不拒绝: 接受或死循环.

易错: 「不接受」不等于「拒绝」. 三种结果互斥, 「不接受」包括了另外两种.

原文笔误: “M does not reject w w if …” 中 w 重复了一次.

Slide 41–42

Recognizers and Recognizability

  • A TM \( M \) is called a recognizer for a language \( L \) over \( \Sigma \) if the following statement is true:

    \( \forall w \in \Sigma^*.\ (w \in L \leftrightarrow M \text{ accepts } w) \)

  • A language \( L \) is called recognizable if there is a recognizer for it.
  • If you are absolutely certain that \( w \in L \), then running a recognizer for \( L \) on \( w \) will (eventually) confirm this.
    • Eventually, \( M \) will accept \( w \).
  • If you don't know whether \( w \in L \), running \( M \) on \( w \) may never tell you anything.
    • \( M \) might loop on \( w \) – but you can't differentiate between “it'll accept if you wait longer” and “it will never come back with an answer.”
  • Does this feel like “solving a problem” to you?

The hailstone TM \( M \) we saw earlier is a recognizer for the language \( L = \{ a^n \mid n \gt 0 \text{ and the hailstone sequence terminates for } n \} \).

  • If the sequence does terminate starting at \( n \), then \( M \) accepts \( a^n \).
  • If the sequence doesn't terminate, then \( M \) loops forever on \( a^n \) and never gives an answer.

If you somehow knew the hailstone sequence terminated for \( n \), this machine would (eventually) confirm this. If you didn't know, this machine might not help.

recognizer 识别器: 图灵机 M 恰好接受 L 中的串, 即 w ∈ L 当且仅当 M 接受 w. 对 L 之外的串, M 可以拒绝也可以死循环. 有识别器的语言叫 recognizable 可识别的.

识别器的局限: 如果 w ∈ L, 等足够久它一定会接受, 用来确认已知的事实没问题. 但如果你不知道 w 是否在 L 中, 它一直不返回时, 你分不清是「再等等就会接受」还是「永远不会返回」. 冰雹图灵机就是 L 的识别器: 序列终止时接受, 不终止时死循环.

Slide 43–46

Earlier this quarter you explored sums of five cubes. Now, let's talk about sums of three cubes.

Are there integers \( x \), \( y \), and \( z \) where…

  • \( x^3 + y^3 + z^3 = 10 \)? Yes! \( x = 2, y = 1, z = 1 \).
  • \( x^3 + y^3 + z^3 = 11 \)? Yes! \( x = 3, y = -2, z = -2 \).
  • \( x^3 + y^3 + z^3 = 12 \)? Yes! \( x = 7, y = 10, z = -11 \).
  • \( x^3 + y^3 + z^3 = 13 \)? Nope!

Surprising fact: until 2019, no one knew whether there were integers \( x \), \( y \), and \( z \) where \( x^3 + y^3 + z^3 = 33 \).

A heavily optimized computer search found this answer:

\( x = 8{,}866{,}128{,}975{,}287{,}528 \)
\( y = -8{,}778{,}405{,}442{,}862{,}239 \)
\( z = -2{,}736{,}111{,}468{,}807{,}040 \)

As of early 2025, no one knows whether there are integers \( x \), \( y \), and \( z \) where \( x^3 + y^3 + z^3 = 114 \).

另一个例子: 整数立方和. 10、11、12 都能写成三个整数的立方和, 13 不能: 整数的立方除以 9 的余数只能是 0、1、8, 三个相加除以 9 余数不可能是 4 或 5, 而 13 除以 9 余 4.

33 是否可以? 直到 2019 年才由大规模计算机搜索找到答案 (课件给出的三个数, 用 Python 验证立方和确实是 33). 114 至今 (课件说 2025 年初) 未知: 既没找到解, 也没证明无解.

验证「立方模 9 只有 0、1、8」: 整数 x 模 9 的余数是 0 到 8 之一, 逐个算 \( x^3 \bmod 9 \): 0, 1, 8, 0, 1, 8, 0, 1, 8. 三个这样的数相加, 可能的余数是 0+0+0 = 0, 0+0+1 = 1, …, 8+8+8 = 24 ≡ 6, 枚举可知所有组合恰好覆盖 0、1、2、3、6、7、8, 唯独没有 4 和 5. 所以模 9 余 4 或 5 的数 (如 13、22、31) 都不是三个立方之和. 33 模 9 余 6, 114 模 9 余 6, 都不能用这个方法排除, 只能靠搜索.

Slide 47–48

Consider the language \( L = \{ a^n \mid \exists x \in \mathbb{Z}.\ \exists y \in \mathbb{Z}.\ \exists z \in \mathbb{Z}.\ x^3 + y^3 + z^3 = n \} \)

Here's pseudocode for a recognizer to see whether such a triple exists:

for max = 0, 1, 2, …
  for x from -max to +max:
    for y from -max to +max:
      for z from -max to +max:
        if x³ + y³ + z³ = n: return true

If you somehow knew there was a triple \( x \), \( y \), and \( z \) where \( x^3 + y^3 + z^3 = n \), running this program will (eventually) convince you of this.

If you weren't sure whether a triple exists, this recognizer might not be useful to you.

The class RE consists of all recognizable languages. Formally speaking:

\( \mathbf{RE} = \{ L \mid L \text{ is a language and there's a recognizer for } L \} \)

  • You can think of RE as “all problems with yes/no answers where “yes” answers can be confirmed by a computer.”
    • Given a recognizable language \( L \) and a string \( w \in L \), running a recognizer for \( L \) on \( w \) will eventually confirm \( w \in L \).
    • The recognizer will never have a “false positive” of saying that a string is in \( L \) when it isn't.
  • This is a “weak” notion of solving a problem.
  • Is there a “stronger” one?

立方和问题的识别器: 搜索范围 max 从 0 开始逐步扩大, 在范围内枚举所有 (x, y, z). 有解时迟早会搜到并接受; 无解时永远搜下去. 注意外层要逐步扩大范围, 不能先把 x 从 −∞ 枚举到 +∞, 否则会卡在某个 x 上永远出不来.

所有可识别语言组成的类叫 RE (来自 recursively enumerable 递归可枚举). 直觉: 「是」的答案能被计算机确认的判定问题. 识别器不会误报 (不会接受不在 L 中的串), 但对「否」的情形可能永不回答. 这是「解决问题」的弱意义.

对比两种「失败」: 识别器对 L 之外的串可以拒绝, 也可以死循环, 定义只要求它不接受. 所以同一个语言可以有很多识别器, 有的对某些串拒绝, 有的死循环, 只要接受的集合恰好是 L 就都算. 例如立方和识别器也可以加一条规则: 若 n 模 9 余 4 或 5 就直接拒绝; 这让它在部分「否」实例上停机, 但对 114 这样的 n 仍然只能无限搜索.

Slide 49–50

Deciders and Decidability

  • Some, but not all, TMs have the following property: the TM halts on all inputs.
  • If you are given a TM \( M \) that always halts, then for the TM \( M \), the statement “\( M \) does not accept \( w \)” means “\( M \) rejects \( w \).”

(图: 只有 Accept 和 Reject 两块, 合起来是 halts (always).)

  • A TM \( M \) is called a decider for a language \( L \) over \( \Sigma \) if the following statements are true:

    \( \forall w \in \Sigma^*.\ M \text{ halts on } w. \)
    \( \forall w \in \Sigma^*.\ (w \in L \leftrightarrow M \text{ accepts } w) \)

  • A language \( L \) is called decidable if there is a decider for it.
  • A decider \( M \) for a language \( L \) accepts all strings in \( L \) and rejects all strings not in \( L \).
  • A decider \( M \) for a language \( L \) is a recognizer for \( L \) that halts on all inputs.
  • Intuitively, if you don't know whether \( w \in L \), running \( M \) on \( w \) will “create new knowledge” by telling you the answer.
  • This is a “strong” notion of “solving a problem.”

有些图灵机对所有输入都停机. 这时「不接受」就等于「拒绝」. decider 判定器: 对所有输入都停机, 并且恰好接受 L 中的串. 等价说法: 判定器是一个永远停机的识别器; 它接受 L 中的串, 拒绝其他串. 有判定器的语言叫 decidable 可判定的.

判定器能「创造新知识」: 不知道 w 是否在 L 中时, 运行它, 一定会得到答案. 这是「解决问题」的强意义.

Slide 51–52

The hailstone TM \( M \) we saw earlier is a recognizer for the language \( L = \{ a^n \mid n \gt 0 \text{ and the hailstone sequence terminates for } n \} \).

  • If the hailstone sequence terminates for \( n \), then \( M \) accepts \( a^n \). If it doesn't, then \( M \) does not accept \( a^n \).
  • We don't know if \( M \) is a decider for this language.
    • If the hailstone sequence always terminates, then \( M \) always halts and is a decider for \( L \).
    • If the hailstone sequence doesn't always terminate, then \( M \) will loop on some inputs and isn't a decider for \( L \).

While no one knows whether there are integers \( x \), \( y \), and \( z \) where \( x^3 + y^3 + z^3 = 114 \), it is very easy to figure out whether there are integers \( x \), \( y \), and \( z \) where \( x^2 + y^2 + z^2 = 114 \).

Take a minute to discuss – why is this?

冰雹图灵机是不是判定器? 取决于考拉兹猜想: 若序列总会终止, 它总停机, 就是判定器; 若有不终止的 n, 它在那里死循环, 就不是. 目前没人知道.

讨论题: 为什么平方和容易? 因为平方非负, \( x^2 \le 114 \) 意味着 |x| ≤ 10, 只需检查有限多种组合 (例如 1 + 49 + 64 = 114). 立方可以是负数, 正负可以互相抵消, 解的大小没有上界, 所以只能无限搜索.

Slide 53

Consider the language \( L = \{ a^n \mid \exists x \in \mathbb{Z}.\ \exists y \in \mathbb{Z}.\ \exists z \in \mathbb{Z}.\ x^2 + y^2 + z^2 = n \} \).

Here's pseudocode for a decider to see whether such a triple exists:

for x from 0 to n:
  for y from 0 to n:
    for z from 0 to n:
      if x² + y² + z² = n: return true
return false

After trying all possible options, this program will either find a triple that works or report that none exists.

The class R consists of all decidable languages. Formally speaking:

\( \mathbf{R} = \{ L \mid L \text{ is a language and there's a decider for } L \} \)

  • You can think of R as “all problems with yes/no answers that can be fully solved by computers.”
    • Given a decidable language, run a decider for \( L \) and see what happens.
    • Think of this as “knowledge creation” – if you don't know whether a string is in \( L \), running the decider will, given enough time, tell you.
  • The class R contains all the regular languages, all the context-free languages, most of CS161, etc.
  • This is a “strong” notion of solving a problem.

平方和的判定器: 只需枚举 0 到 n 的 x、y、z (负数的平方和正数一样, 不必枚举), 有限步后要么找到要么返回 false. 所以这个语言可判定.

所有可判定语言组成的类叫 R (来自 recursive 递归). 直觉: 能被计算机完全解决的判定问题. R 包括所有正则语言、所有上下文无关语言, 以及算法课 (CS161) 里的大多数问题.

R and RE Languages

  • Every decider for \( L \) is also a recognizer for \( L \).
  • This means that \( \mathbf{R} \subseteq \mathbf{RE} \).
  • Hugely important theoretical question: \( \mathbf{R} \overset{?}{=} \mathbf{RE} \)
  • That is, if you can just confirm “yes” answers to a problem, can you necessarily solve that problem?

每个判定器都是识别器, 所以 R ⊆ RE. 重大的理论问题: R = RE 吗? 即: 能确认「是」的答案, 是否就一定能完全解决问题? 两种图景: R 和 RE 重合, 或 R 严格小于 RE. 后面几讲会证明答案是后者: 存在可识别但不可判定的语言 (例如停机问题). 也存在 RE 之外的语言, 连识别器都没有.

一个有用的事实 (后面的课会用到类似的想法): 如果 L 和它的补 \( \overline{L} \) 都可识别, 那么 L 可判定. 做法是把两个识别器交替运行, 各走一步: 任何串 w 要么在 L 中 (L 的识别器迟早接受), 要么在 \( \overline{L} \) 中 (另一个迟早接受), 所以交替运行一定会停下来并给出正确答案. 不能先把一个跑完再跑另一个, 因为第一个可能永远不停.
