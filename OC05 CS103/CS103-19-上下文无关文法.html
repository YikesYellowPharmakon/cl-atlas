Recap from Last Time

  • If \( L \) is a language and \( S \) is a distinguishing set for \( L \) that contains infinitely many strings, then \( L \) is not regular
  • Distinguishing set: A set of strings, each of which represent information that requires a distinct state to represent it
    • e.g., “we've seen 2 a's, we've seen 3 a's, ...”
  • Infinitely many strings in a distinguishing set implies there is no finite number of states that can represent all the required information.

复习 Myhill-Nerode: 区分集里的每个串代表一条必须用单独状态记住的信息 (如「见过 2 个 a」「见过 3 个 a」); 区分集无限, 有限个状态就不够用, 语言不正则. 见 CS103 18. 这一讲介绍一种更强的语言描述工具: 上下文无关文法. 重点是文法的定义、推导, 以及设计文法的几条经验.

Context-Free Grammars

Slide 49–54

A context-free grammar (or CFG) is a recursive set of rules that define a language.

  • More on the details of these rules in a bit.
  • Warning: CFGs are not finite automata – be prepared for something completely different!

Arithmetic Expressions

Here's how we might express the recursive rules from earlier as a CFG.

Expr → int
Expr → Expr Op Expr
Expr → (Expr)
Op   → +
Op   → -
Op   → ×
Op   → /

This is called a production rule. It says “if you see Expr, you can replace it with Expr Op Expr.”

This one says “if you see Op, you can replace it with -.”

These red symbols are called nonterminals. They're placeholders that get expanded later on.

The symbols in blue monospace are terminals. They're the final characters used in the string and never get replaced.

context-free grammar 上下文无关文法 (CFG) 是一组递归的规则, 用来定义一个语言. 它和有限自动机完全不同: 自动机是「读入并判断」, 文法是「从一个符号出发生成串」.

每一条形如 A → … 的规则叫 production rule 产生式, 意思是「看到 A 就可以把它换成右边的内容」. 符号分两类:

  • nonterminal 非终结符 (课件里红色, 如 Expr、Op): 占位符, 之后还要被替换;
  • terminal 终结符 (蓝色等宽, 如 int、+、括号): 最终串里的字符, 不再被替换.

「上下文无关」指: 替换 A 时不看它周围是什么, 只要出现 A 就能用 A 的规则. 这个名称来自语言学, 见本讲最后.

两个替换过程. 第一个: 从 Expr 出发, 用 Expr → Expr Op Expr, 再把右边的 Expr 换成 int, 左边的 Expr 换成 int, 最后 Op 换成 /, 得到 int / int. 第二个得到 int × (int + int).

注意替换顺序很自由: 第一个例子先换了右边的 Expr; 第二个例子在中途先换了 Op. 只要最后没有非终结符就行. 每一步用 ⇒ 表示「一步替换」.

Slide 56–57

Context-Free Grammars

  • Formally, a context-free grammar is a collection of four items:
    • a set of nonterminal symbols (sometimes called variables),
    • a set of terminal symbols (the alphabet of the CFG),
    • a set of production rules saying how each nonterminal can be replaced by a string of terminals and nonterminals, and
    • a start symbol (which must be a nonterminal) that begins the derivation. By convention, the start symbol is the one on the left-hand side of the first production.

Some CFG Notation

  • In today's slides, capital letters in Bold Red Uppercase represent nonterminals.
    • e.g. A, B, C, D
  • Lowercase letters in blue monospace represent terminals.
    • e.g. t, u, v, w
  • Lowercase Greek letters in gray italics represent arbitrary strings of terminals and nonterminals.
    • e.g. \( \alpha, \gamma, \omega \)
  • You don't need to use these conventions on your own; just make sure whatever you do is readable.

正式定义: CFG 由四部分组成: 非终结符集合 (也叫变元); 终结符集合 (文法的字母表); 产生式集合 (每条把一个非终结符换成一串终结符和非终结符); 起始符号 (一个非终结符, 约定为第一条产生式的左边).

记号约定: 大写字母表示非终结符, 小写字母表示终结符, 小写希腊字母 \( \alpha, \gamma, \omega \) 表示任意的符号串 (可混合两类). 作业里不必照搬颜色, 清楚即可.

Slide 58–60

A Notational Shorthand

Expr → int | Expr Op Expr | (Expr)
Op   → + | - | × | /

Derivations

  • A sequence of zero or more steps where nonterminals are replaced by the right-hand side of a production is called a derivation.
  • If string \( \alpha \) derives string \( \omega \), we write \( \alpha \Rightarrow^* \omega \).
  • In the example on the left, we see that Expr ⇒* int × (int + int).

简写: 同一个非终结符的多条产生式用竖线 | 合并写在一行, 读作「或」.

derivation 推导: 零步或多步替换组成的序列. 若 \( \alpha \) 经过推导能得到 \( \omega \), 写作 \( \alpha \Rightarrow^* \omega \) (星号表示「零步或多步」, 和克林星号的含义一致). 例如上面的第二个推导说明 Expr ⇒* int × (int + int).

Slide 61–62

The Language of a Grammar

  • If \( G \) is a CFG with alphabet \( \Sigma \) and start symbol \( S \), then the language of \( G \) is the set

    \( \mathscr{L}(G) = \{ \omega \in \Sigma^* \mid S \Rightarrow^* \omega \} \)

  • That is, \( \mathscr{L}(G) \) is the set of strings of terminals derivable from the start symbol.

Consider the following CFG \( G \) over \( \Sigma = \{ a, b, c, d \} \):

Q → Qa | dH
H → bHb | c

Which of the following strings are in \( \mathscr{L}(G) \)?

dca   dc   cad   bcb   dHaa

文法 G 的语言 \( \mathscr{L}(G) \): 从起始符号出发能推导出的、只含终结符的串.

练习: 先看 G 生成什么. Q → Qa 在右边不断加 a, 最后用 Q → dH; H 生成 \( b^n c b^n \). 所以语言是 \( d\, b^n c\, b^n\, a^m \) (n、m ≥ 0). 逐个判断:

  • dca: 是 (n = 0, m = 1).
  • dc: 是 (n = 0, m = 0).
  • cad: 否, 必须以 d 开头.
  • bcb: 否, 缺开头的 d.
  • dHaa: 否, 它含非终结符 H, 是推导中间的一步, 不是语言里的串.

Context-Free Languages

  • A language \( L \) is called a context-free language (or CFL) if there is a CFG \( G \) such that \( L = \mathscr{L}(G) \).
  • Questions:
    • How are context-free and regular languages related?
    • How do we design context-free grammars for context-free languages?

存在 CFG 生成的语言叫 context-free language 上下文无关语言 (CFL). 它和正则语言 (REG) 是什么关系? 有五种可能: 不相交, 部分重叠, 相等, REG 是 CFL 的子集, CFL 是 REG 的子集. 下面一步步排除.

CFGs and Regular Expressions

Slide 66

CFGs and Regular Expressions

  • CFGs consist purely of production rules of the form \( A \to \omega \). They do not have the regular expression operators * or ∪.
    • You can use the symbols * and ∪ if you'd like in a CFG, but they just stand for themselves.
  • Consider this CFG G: 
    S → a*b
  • Here, \( \mathscr{L}(G) = \{\text{a*b}\} \) and has cardinality one. That is, \( \mathscr{L}(G) \ne \{ a^n b \mid n \in \mathbb{N} \} \).

易错: CFG 里只有产生式, 没有正则表达式的 * 和 ∪. 如果写 S → a*b, 星号只是一个普通的终结符, 这个文法只生成一个三字符的串「a*b」, 而不是 \( a^n b \). 要表达重复, 必须用递归的产生式.

Slide 67–82

Theorem: Every regular language is context-free.

Proof idea: Show how to convert an arbitrary regular expression into a context-free grammar.

a ( b ∪ ε ) c

S → aXc
X → b | ε

It's totally fine for a production to replace a nonterminal with the empty string.

( a ∪ b )²c*

S → XY
X → ZZ
Z → a | b
Y → cY | ε

定理: 每个正则语言都是上下文无关的. 证明思路: 把正则表达式逐部分翻译成文法. 两个例子:

  • a(b ∪ ε)c: 用一个新非终结符 X 表示括号里的部分, X → b | ε. 产生式右边可以是空串.
  • (a ∪ b)²c*: S 分成两段 X、Y. X → ZZ 表示两个 (a ∪ b), Z → a | b; Y → cY | ε 递归地生成任意多个 c, 这就是星号的翻译方法.

一般地: 并用 |, 连接就是并排写, 星号用 Y → RY | ε 的递归. 所以 REG ⊆ CFL, 五种可能只剩两种: 相等, 或 REG 是真子集.

Slide 97–107

Why the Extra Power?

  • Why do CFGs have more power than regular expressions?
  • Intuition: Derivations of strings have unbounded “memory.”
S → aSb | ε

(动画: 推导 aaaabbbb 的过程, 每一步中间的 S 两侧已经写下的 a 和 b 一样多.)

为什么 CFG 比正则表达式强? 直觉: 推导过程有不受限的「记忆」. 推导到中间时, 串的形如 \( a^k S b^k \), 尚未展开的 S 两边已经「记住」了 k 个 a 和 k 个 b, k 可以任意大. 正则表达式和 DFA 只能从左到右读, 读到 b 时已经无法回头核对 a 的个数; 文法却能同时向两边生长.

Designing CFGs

Slide 109–110

Designing CFGs

  • Like designing DFAs, NFAs, and regular expressions, designing CFGs is a craft.
  • When thinking about CFGs:
    • Think recursively: Build up bigger structures from smaller ones.
    • Have a construction plan: Know in what order you will build up the string.
    • Store information in nonterminals: Have each nonterminal correspond to some useful piece of information.
  • Check our online “Guide to CFGs” for more information about CFG design.
    • We'll hit the highlights in the rest of this lecture.
  • Let \( \Sigma = \{a, b\} \) and let \( L = \{ w \in \Sigma^* \mid w \text{ is a palindrome} \} \)
  • We can design a CFG for \( L \) by thinking inductively:
    • Base case: \( \varepsilon \), a, and b are palindromes.
    • If \( \omega \) is a palindrome, then a\( \omega \)a and b\( \omega \)b are palindromes.
    • No other strings are palindromes.
S → ε | a | b | aSa | bSb

设计 CFG 的三条经验: 递归地想, 用小结构拼出大结构; 有一个构造计划, 知道串按什么顺序生成; 让每个非终结符记住一条有用的信息. 课程的 Guide to CFGs 有更多说明 (见指南合集).

例: 回文. 用归纳的方式描述回文: 空串、a、b 是回文 (基础情形); 若 \( \omega \) 是回文, 两边各加同一个字母仍是回文 (递归情形); 别的都不是. 直接翻译成产生式 S → ε | a | b | aSa | bSb. 上一讲证明了回文语言不正则, 这里它却是上下文无关的.

Slide 111–116
  • Let \( \Sigma = \{ \{, \} \} \) and let \( L = \{ w \in \Sigma^* \mid w \text{ is a string of balanced braces} \} \)
  • Some sample strings in \( L \):

    {{{}}}   {{}}{}   {{}{}}{{}{}}   {{{{{}}}{{}}}}   {}{}

  • Let's think about this recursively.
    • Base case: the empty string is a string of balanced braces.
    • Recursive step: Look at the closing brace that matches the first open brace. Removing the first brace and the matching brace forms two new strings of balanced braces.
S → {S}S | ε

例: 平衡的花括号串 (每个 { 都有对应的 }, 嵌套正确). 递归结构: 空串平衡; 非空时, 找到和第一个 { 配对的 }, 这一对把串分成两部分: 它们中间的部分和它后面的部分, 二者各自也平衡. 所以 S → {S}S | ε.

为什么这样切分是唯一的: 「和第一个左括号配对的右括号」只有一个, 所以每个平衡串都恰好按一种方式分解, 文法不会漏掉或多出串.

Slide 117–122
  • Let \( \Sigma = \{a, b\} \) and let \( L = \{ w \in \Sigma^* \mid w \text{ has the same number of a's and b's} \} \)

Which of these CFGs have language \( L \)?

S → aSb | bSa | ε
S → abS | baS | ε
S → abSba | baSab | ε
S → SbaS | SabS | ε

答案: 四个都不对. 四个文法生成的串 a、b 个数确实都相等 (每条产生式加入的 a 和 b 一样多), 但都漏掉了某些串:

  • S → aSb | bSa | ε: 首尾字母必须不同, 生成不了 abba.
  • S → abS | baS | ε: 只能把 ab、ba 两两拼接, 生成不了 aabb.
  • S → abSba | baSab | ε: 长度只能是 4 的倍数, 生成不了 ab.
  • S → SbaS | SabS | ε: 每次插入的 ab 或 ba 两侧都是平衡串, 生成不了 aabb (它无法写成「平衡串 + ab/ba + 平衡串」).

这些结论用 Python 对长度不超过 10 的所有串逐一核对过. 一个正确的文法是 S → aSbS | bSaS | ε: 若串以 a 开头, 找到第一个使前缀 a、b 个数相等的位置, 那里一定是 b, 前后两段各自平衡; 以 b 开头同理. 这和上面花括号文法的思路相同.

Slide 123–124

Designing CFGs: A Caveat

  • When designing a CFG for a language, make sure that it
    • generates all the strings in the language and
    • never generates a string outside the language.
  • The first of these can be tricky – make sure to test your grammars!

CFG Caveats II

  • Is the following grammar a CFG for the language \( \{ a^n b^n \mid n \in \mathbb{N} \} \)? 
    S → aSb
  • What strings in {a, b}* can you derive?
    • Answer: None!
  • What is the language of the grammar?
    • Answer: \( \varnothing \)
  • When designing CFGs, make sure your recursion actually terminates!

设计文法要检查两个方向: 生成了语言里的所有串, 而且只生成语言里的串. 前者尤其容易出错 (上面的四个文法都只犯了这一种错), 一定要拿具体的串测试.

另一个陷阱: S → aSb 没有终止规则, S 永远消不掉, 推不出任何只含终结符的串, 语言是空集. 递归一定要有出口, 就像归纳法必须有基础情形.

Slide 125–127

Designing CFGs

  • When designing CFGs, remember that each nonterminal can be expanded out independently of the others.
  • Let \( \Sigma = \{a, ≟\} \) and let \( L = \{ a^n≟a^n \mid n \in \mathbb{N} \} \).
  • Is the following a CFG for \( L \)? 
    S → X≟X
X → aX | ε
    S ⇒ X≟X ⇒ aX≟X ⇒ a≟X ⇒ a≟aX ⇒ a≟a

Finding a Build Order

  • To build a CFG for \( L \), we need to be more clever with how we construct the string.
    • If we build the strings of a's independently of one another, then we can't enforce that they have the same length.
    • Idea: Build both strings of a's at the same time.
  • Here's one possible grammar based on that idea: 
    S → ≟ | aSa
    S ⇒ aSa ⇒ aaSaa ⇒ aaaSaaa ⇒ aaa≟aaa

Summary of CFG Design Tips

  • Look for recursive structures where they exist: they can help guide you toward a solution.
  • Keep the build order in mind – often, you'll build two totally different parts of the string concurrently.
    • Usually, those parts are built in opposite directions: one's built left-to-right, the other right-to-left.
  • Use different nonterminals to represent different structures.

每个非终结符的展开相互独立. 语言 \( a^n≟a^n \) 如果写成 S → X≟X, 两个 X 各自展开, 无法保证个数相同, 课件的推导得到 a≟a 是对的, 但同样的步骤让右边的 X 多展开一次 (a≟aX ⇒ a≟aaX ⇒ a≟aa), 就生成了不在 L 中的 a≟aa.

正确思路是找好「构造顺序」: 两边的 a 同时生成, S → aSa 每次两边各加一个, 最后 S → ≟. 两部分通常方向相反: 左边从左往右长, 右边从右往左长, 和 \( a^n b^n \)、回文的文法一样.

小结: 找递归结构; 注意构造顺序, 需要相互约束的部分要同时生成; 不同结构用不同的非终结符表示.

Grammars in Compilers

  • One of the key steps in a compiler is figuring out what a program “means.”
  • This is usually done by defining a grammar showing the high-level structure of a programming language.
  • There are certain classes of grammars (LL(1) grammars, LR(1) grammars, LALR(1) grammars, etc.) for which it's easy to figure out how a particular string was derived.
  • Tools like yacc or bison automatically generate parsers from these grammars.
  • Curious to learn more? Take CS143!

编程语言的语法就是用 CFG 定义的: 代码块是一条语句或花括号里的一串语句; 语句可以是表达式加分号、if、while、do-while 等; 表达式由标识符、常量和运算组成. 注意 if 的产生式里又出现 BLOCK, 这种互相递归允许任意深的嵌套.

编译器的关键一步是从源代码还原出它是怎样被推导出来的 (语法分析, parsing), 由此得到程序的结构和含义. LL(1)、LR(1)、LALR(1) 等特殊类型的文法便于高效分析; yacc、bison 能根据文法自动生成语法分析器. 详见 CS143 编译原理.

Natural Language Processing

  • By building context-free grammars for actual languages and applying statistical inference, it's possible for a computer to recover the likely meaning of a sentence.
  • In fact, CFGs were first called phrase-structure grammars and were introduced by Noam Chomsky in his seminal work Syntactic Structures.
    • They were then adapted for use in the context of programming languages, where they were called Backus-Naur forms.
  • The Stanford Parser project is one place to look for an example of this.
  • Want to learn more? Take CS124 or CS224N!

自然语言处理: 给真实语言写 CFG, 再结合统计推断, 计算机就能推测一句话最可能的句法结构和含义 (例如斯坦福句法分析器). CFG 最早就是语言学家乔姆斯基在《句法结构》(Syntactic Structures, 1957) 中提出的 phrase-structure grammar 短语结构文法; 后来被用于编程语言, 写法叫 Backus-Naur form (BNF, 巴科斯-诺尔范式). 相关课程: CS124、CS224N.
