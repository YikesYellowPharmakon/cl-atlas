The Halting Problem

  • The most famous undecidable problem is the halting problem, which asks:

    Given a TM \( M \) and a string \( w \), will \( M \) halt* when run on \( w \)?

  • As a formal language, this problem would be expressed as

    \( \mathrm{HALT} = \{ \langle M, w\rangle \mid M \text{ is a TM that halts on } w \} \)

  • How hard is this problem to solve?

* i.e., accept or reject (“halting” execution, as opposed to infinite loop)

上一讲证明了 R ≠ RE. 这一讲先看最著名的不可判定问题 halting problem 停机问题: 给定图灵机 M 和串 w, M 在 w 上会不会停机 (接受或拒绝, 而不是死循环)? 写成语言 HALT. 然后介绍 RE 的另一种刻画: 验证器. 重点是验证器的定义, 以及「有验证器 ⟺ 可识别」的双向构造.

Slide 5–6

HALT ∈ RE

  • Claim: HALT ∈ RE.
  • Idea: We can just run TM M on w, and see if it halts. (It might not, but that's ok, we just need a recognizer TM to show HALT ∈ RE.)
bool checkHalt(TM M, string w) {
    // This might infinite loop, and if it does, we will
    // not reach the "if" code below this
    bool result = M(w);
    // whether result is true or false, at least M did halt,
    // so we return true
    if (result || !result) {
        return true;
    }
}

HALT and \( A_{TM} \): Comparing recognizer TMs for HALT and \( A_{TM} \)

bool checkHalt(TM M, string w) {
    // This might infinite loop
    bool result = M(w);
    // Accept both true and false
    if (result || !result) {
        return true;
    }
}
bool checkATM(TM M, string w) {
    // This might infinite loop
    bool result = M(w);
    // Accept only true
    if (result) {
        return true;
    } else {
        return false;
    }
}

HALT 可识别: 直接运行 M(w). 若 M 停机 (无论结果是 true 还是 false), 就返回 true; 若 M 死循环, 识别器也跟着死循环, 这对识别器是允许的 (此时 ⟨M, w⟩ ∉ HALT, 识别器只需不接受).

和 \( A_{TM} \) 的识别器对比: 二者都先运行 M(w), 区别只在最后: HALT 对 true 和 false 都接受, \( A_{TM} \) 只接受 true. 代码里 result || !result 永远为真, 只是为了强调「只要能走到这里就接受」.

Slide 7–8

HALT ∉ R

  • Claim: HALT ∉ R.
  • If HALT is decidable, there would exist some decider function bool willHalt(TM M, string w) that reports whether the program M will halt when run on the given input w.
  • Then, we could do a trickster setup like we did for \( A_{TM} \).
  • (skipping the formal proof for the sake of time, but it follows the same template as \( A_{TM} \), but using this version of trickster)
bool trickster(string input) {
    string me = mySource();
    if (willHalt(me, input)) {
        while (true) {
            // loop infinitely
        }
    } else {
        return true;
    }
}

HALT 不可判定. 若有判定器 willHalt, 构造新的 trickster: 问 willHalt「我在这个输入上会停机吗」, 若说会停就故意死循环, 若说不会停就立刻返回. 于是 trickster 停机 ⟺ willHalt 说它不停 ⟺ (由 willHalt 的正确性) trickster 不停机, 矛盾. 和 \( A_{TM} \) 的证明完全同一个模板, 只是把「取反返回值」换成「死循环与否取反」.

所以 HALT ∈ RE − R, 和 \( A_{TM} \) 一样处在 R 与 RE 之间的那一圈.

The Class RE

  • Languages \( L \) that are in RE, but not R, are those where:
    • We can build a TM \( M \), where \( \mathscr{L}(M) = L \)
    • That TM \( M \) has the risk of getting stuck in an infinite loop for at least one input string that is not in \( L \)
  • Next: Just like the class Regular was defined in multiple ways (DFAs, NFAs, RegExes), today we'll learn another way to define this class

在 RE 但不在 R 中的语言: 能造出识别它的图灵机, 但任何这样的图灵机都至少在某个 L 外的串上死循环. 正则语言有 DFA、NFA、正则表达式三种等价描述; RE 也有另一种描述, 就是下面的验证器.

Slide 10–14

(代码框: /* imagine 5000 lines of TM code */)

Does this code HALT on input “abbababababbbb”?

Reflection: Hard for humans! We know that TMs are also not able to answer this in the general case without the possibility of looping (HALT in RE, not R).

Idea: What if I gave you a hint? What if I told you that this code HALTs on this input after exactly 20 steps of execution.

If your only job was deciding if my hint is truthful, could you write a decider TM to do that? It should accept if the hint is true, and reject otherwise. If so, describe what your decider TM does.

Here's the catch: You don't know if my hint is truthful.

Decider TM: Run the code on the input for exactly 20 steps of execution. If on the 20th step we observe it HALT, accept. Otherwise reject (hint was not truthful).

给一段 5000 行的图灵机代码, 问它在某输入上会不会停机. 人难以回答, 图灵机也无法在一般情况下保证不陷入死循环 (HALT 不在 R 中).

换一个任务: 如果有人给你一个提示, 「它会在恰好第 20 步停机」, 你只需判断提示真不真. 这很容易, 而且一定能停: 模拟恰好 20 步, 第 20 步看到它停机就接受, 否则拒绝. 难点在于你不知道提示是否可信, 所以必须检查.

Slide 15–18

Example: Someone gives us the number of steps hint “20.” We run the TM on the input “abbababababbbb” and observe the TM accepts the input on step 20. This ⟨M, w⟩ is in the language HALT.

… and observe the TM rejects the input on step 20. Is this ⟨M, w⟩ in the language HALT? — This ⟨M, w⟩ is in the language HALT.

… and observe the TM has neither accepted nor rejected the input after 20 steps (M would keep running if we let it, but we stop after 20 steps). Is this ⟨M, w⟩ in the language HALT?

  • In each of the preceding cases, we were given some TM M and some input string w, and some evidence/hint supporting the claim that M halts on w.
  • Given a truthful evidence/hint, we can write a decider TM to see that the answer is indeed “yes,” M halts on w.
  • Given false evidence, we aren't immediately sure whether M halts on w.
    • Maybe there's no evidence saying that the answer is “yes,” because the answer is no, M doesn't halt on w!
    • Or maybe there is some evidence, but just not the evidence we were given.
  • Let's formalize this idea.

三种情况:

  • 第 20 步接受: M 在 w 上停机, ⟨M, w⟩ ∈ HALT.
  • 第 20 步拒绝: 也是停机, 同样 ⟨M, w⟩ ∈ HALT.
  • 20 步后既没接受也没拒绝: 不能下结论. 也许 M 永不停机; 也许它会在第 21 步、第 10 000 步停机, 只是提示给错了.

总结: 真的提示能让我们确认「是」; 假的提示什么也说明不了. 下面把这个想法形式化.

Slide 19–23

Verifiers

  • A verifier for a language \( L \) is a TM \( V \) with the following properties:
    • \( V \) halts on all inputs.
    • For any string \( w \in \Sigma^* \), the following is true:

      \( w \in L \leftrightarrow \exists c \in \Sigma^*.\ V \text{ accepts } \langle w, c\rangle \)

  • A string \( c \) where \( V \) accepts ⟨w, c⟩ is called a certificate for \( w \).
    • This is the “evidence.”
  • Intuitively, what does this mean?

Deciders and Verifiers

“Solve the problem”: input string (w) → Decider M for L → yes! / no! — If M accepts, then w ∈ L. If M rejects, then w ∉ L. M halts on all inputs. w ∈ L ↔ M accepts w

“Check the answer”: input string (w) + certificate (c) → Verifier V for L → yes! — If V accepts ⟨w, c⟩, then w ∈ L. If V rejects ⟨w, c⟩, we don't know whether w ∈ L. V halts on all inputs. w ∈ L ↔ ∃c ∈ Σ*. V accepts ⟨w, c⟩. “certificate” is the official term for a “hint” — Helpful certificate / Unhelpful certificate.

verifier 验证器 V: 一个总停机的图灵机, 输入是串 w 和一个附加串 c, 满足: w ∈ L 当且仅当存在某个 c 使 V 接受 ⟨w, c⟩. 使 V 接受的 c 叫 w 的 certificate 证书 (即「提示」「证据」).

和判定器对比: 判定器「解决问题」, 只拿到 w, 必须自己给出对或错; 验证器「检查答案」, 拿到 w 和一个证书. V 接受, 就确定 w ∈ L; V 拒绝, 不能下结论 (证书可能只是没给对).

Slide 24–27

Verifiers

  • Some notes about \( V \):
    • If \( V \) accepts ⟨w, c⟩, then we're guaranteed \( w \in L \).
    • If \( V \) does not accept ⟨w, c⟩, then either
      • \( w \in L \), but you gave the wrong \( c \), or
      • \( w \notin L \), so no possible \( c \) will work.
  • More notes about \( V \):
    • Notice that \( c \) is existentially quantified.
    • Notice \( V \) is required to halt always (like a decider).
    • Notice that \( \mathscr{L}(V) \ne L \). (Good question to hold on to for a second: what is \( \mathscr{L}(V) \)?)
    • The job of \( V \) is just to check certificates, not to decide membership in \( L \).
  • A note about \( c \):
    • Figuring out what would make a good certificate (should it be a number of steps to take, an equation-solving variable assignment, a set of graph nodes, an array of numbers to fill in a whole Sudoku board?) is custom work to do for each different language \( L \).

几点说明:

  • V 不接受时, 要么 w ∈ L 但证书给错了, 要么 w ∉ L, 任何证书都不行.
  • c 是存在量化的: 只要有一个好证书就够, 不要求每个证书都好.
  • V 必须总停机, 这一点像判定器.
  • \( \mathscr{L}(V) \ne L \). V 接受的是对 ⟨w, c⟩, 所以 \( \mathscr{L}(V) = \{ \langle w, c\rangle \mid c \text{ 是 } w \text{ 的证书} \} \), 是一个由对组成的语言, 不是 L 本身.
  • V 的任务只是检查证书, 不是判断 w 是否属于 L.

好的证书长什么样, 要针对每个语言设计: 可能是步数、方程的一组解、图中的一组节点、填满的数独盘面.

例子: 语言「有解的数独题」. 证书是一个填满的盘面. 验证器检查两件事: 盘面和题目给出的数字一致; 每行、每列、每宫都恰好是 1 到 9. 检查只需扫描固定的 81 格, 一定停机. 有解的题目存在证书 (它的解); 无解的题目不论给什么盘面都过不了检查. 再如立方和语言, 证书就是三元组 (x, y, z), 验证器只要算一次 \( x^3 + y^3 + z^3 \) 是否等于 n. 「找」证书可能极难, 「查」证书却很容易, 这就是验证器视角的价值.

Some Verifiers

  • Let \( L \) be the following language:

    \( L = \{ \langle n\rangle \mid n \in \mathbb{N} \text{ and the hailstone sequence terminates for } n \} \)

bool checkHailstone(int n, int c) {
    for (int i = 0; i < c; i++) {
        if (n % 2 == 0) n /= 2;
        else n = 3*n + 1;
        if (n == 1) return true;
    }
    return n == 1;
}

Does this always halt?

For one given ⟨n⟩ ∈ L (say 11), how many different values of c will work to cause the verifier to accept?

How many of these statements are true of \( \mathscr{L}(V) \)?

  • \( \mathscr{L}(V) = L \)
  • \( \mathscr{L}(V) \subseteq L \)
  • \( L \subseteq \mathscr{L}(V) \)

冰雹序列语言的验证器: 证书 c 是步数, 最多模拟 c 步, 途中到达 1 就接受.

  • 总会停机吗? 会. 循环最多执行 c 次, 每次常数时间.
  • 对 n = 11, 有多少个 c 能让它接受? 无穷多个. 11 的冰雹序列在第 14 步到达 1 (Python 核对), 因为循环中途到 1 就返回 true, 所以任何 c ≥ 14 都行.
  • 关于 \( \mathscr{L}(V) \) 的三句话都不对: V 接受的是数对 ⟨n, c⟩, L 里是单个的 ⟨n⟩, 两个集合的元素类型不同, 谁也不包含谁.

Verifier for \( A_{TM} \)?

  • Consider \( A_{TM} \): \( A_{TM} = \{ \langle M, w\rangle \mid M \text{ is a TM and } M \text{ accepts } w \} \).
  • This is our standard example of an undecidable language. There's no way, in general, to tell whether a TM M will accept a string w.
  • Although this language is undecidable, it's an RE language, and it's possible to build a verifier for it!
  • What would make a good certificate for a verifier for \( A_{TM} \)?

A Verifier for \( A_{TM} \)

bool checkWillAccept(TM M, string w, int c) {
    set up a simulation of M running on w;
    for (int i = 0; i < c; i++) {
        simulate the next step of M running on w;
    }
    return whether M is in an accepting state;
}
  • Do you see why M accepts w iff there is some c such that checkWillAccept(M, w, c) returns true?
  • Do you see why checkWillAccept always halts?

就像正则语言里 NFA 和正则表达式能互相转换, 这一节要证明验证器和识别器能互相转换.

先看 \( A_{TM} \) 的验证器. 好的证书是「M 接受 w 所用的步数」. checkWillAccept 模拟 M 在 w 上运行 c 步, 看此时是否已接受.

  • 为什么总停机: 只模拟有限的 c 步.
  • 为什么正确: 若 M 接受 w, 一定是在某个有限步数 c 时接受的, 用这个 c 就能让验证器接受; 若 M 不接受 w (拒绝或死循环), 无论模拟多少步都看不到接受, 任何 c 都不行.
Slide 37–41

Equivalence of Verifiers and Recognizers: Recognizer → Verifier: Enforce a step count; Verifier → Recognizer: Try all certificates.

What languages are verifiable?

Let \( V \) be a verifier for a language \( L \). Consider the following function given in pseudocode:

bool mysteryFunction(string w) {
    int i = 0;
    while (true) {
        for (each string c of length i) {
            if (V accepts ⟨w, c⟩) return true;
        }
        i++;
    }
}

What set of strings does mysteryFunction return true on?

Theorem: If \( L \) is a language, then there is a verifier for \( L \) if and only if \( L \in \mathbf{RE} \).

两个方向的思路: 识别器 → 验证器, 用「限制步数」(把步数当证书); 验证器 → 识别器, 用「穷举所有证书」.

mysteryFunction 按长度从短到长穷举所有可能的证书 c, 每个都交给 V 检查, 找到能让 V 接受的就返回 true. 它返回 true 的串恰好是 L 中的串: w ∈ L 时存在证书, 它有某个有限长度, 穷举迟早会试到; w ∉ L 时没有证书, 函数永远找下去. 所以 mysteryFunction 是 L 的识别器.

按长度逐层穷举是关键: 每一层的串只有有限个, 所以任何具体的证书都会在有限时间内被试到. 由于 V 总停机, 检查单个证书不会卡住.

定理: L 有验证器 ⟺ L ∈ RE. 这给出了 RE 的第二种刻画.

Slide 42–70

Verifiers and RE

  • Theorem: If there is a verifier \( V \) for a language \( L \), then \( L \in \mathbf{RE} \).
  • Proof goal: Given a verifier \( V \) for a language \( L \), find a way to construct a recognizer \( M \) for \( L \).

We will try all possible certificates (values of c): \( \varepsilon \), a, b, aa, ab, ba, bb, aaa, aab, aba, abb, baa, …

  • Proof sketch: Consider the following program:
bool isInL(string w) {
    int i = 0;
    while (true) {
        for (each string c of length i) {
            if (V accepts ⟨w, c⟩) return true;
        }
        i++;
    }
}
  • Theorem: If \( L \in \mathbf{RE} \), then there is a verifier for \( L \).
  • Proof goal: Beginning with a recognizer \( M \) for the language \( L \), show how to construct a verifier \( V \) for \( L \).
  • The challenges:
    • A recognizer \( M \) is not required to halt on all inputs. A verifier \( V \) must always halt.
    • A recognizer \( M \) takes in one single input. A verifier \( V \) takes in two inputs.
    • We'll need to find a way of reconciling these differences.

第一个方向 (验证器 ⟹ RE) 就是上面的 mysteryFunction, 这里命名为 isInL, 证书按 \( \varepsilon \), a, b, aa, ab, … 的顺序枚举.

第二个方向 (RE ⟹ 验证器) 的困难: 识别器可能不停机, 验证器必须总停机; 识别器只有一个输入, 验证器有两个. 需要用第二个输入来弥补停机问题.

Recall: If \( M \) is a recognizer for a language \( L \), then \( M \) accepts \( w \) iff \( w \in L \).

Key insight: If \( M \) accepts a string \( w \), it always does so in a finite number of steps.

Idea: Adapt the verifier for \( A_{TM} \) into a more general construction that turns any recognizer into a verifier by running it for a fixed number of steps.

Verifiers and RE

  • Theorem: If \( L \in \mathbf{RE} \), then there is a verifier for \( L \).
  • Proof sketch: Consider the following program:
bool checkIsInL(string w, int c) {
    set up a simulation of M running on w;
    for (int i = 0; i < c; i++) {
        simulate the next step of M running on W;
    }
    return whether M is in an accepting state;
}

Notice that checkIsInL always halts, since each step takes only finite time to complete. Next, notice that if there is a \( c \) where checkIsInL(w, c) returns true, then \( M \) accepted \( w \) after running for \( c \) steps, so \( w \in L \). Conversely, if \( w \in L \), then \( M \) accepts \( w \) after some number of steps (call that number \( c \)). Then checkIsInL(w, c) will run \( M \) on \( w \) for \( c \) steps, watch \( M \) accept \( w \), then return true. \( \blacksquare \)

关键观察: 识别器若接受 w, 一定是在有限步内接受的. 所以把步数当证书, 套用 \( A_{TM} \) 验证器的构造: checkIsInL(w, c) 模拟识别器 M 在 w 上运行 c 步, 看是否已接受.

  • 总停机: 只模拟 c 步.
  • 若存在 c 使它返回 true, 说明 M 在 c 步内接受了 w, 所以 w ∈ L.
  • 若 w ∈ L, M 在某个 c 步时接受, 这个 c 就是证书.

两个方向合起来, 定理得证.

原文笔误: 代码里 “simulate the next step of M running on W” 的 W 应为小写 w, 和参数名一致.

Slide 73–74

RE and Proofs

  • Verifiers and recognizers give two different perspectives on the “proof” intuition for RE.
  • Verifiers are explicitly built to check proofs that strings are in the language.
    • If you know that some string \( w \) belongs to the language and you have the proof of it, you can convince someone else that \( w \in L \).
  • You can think of a recognizer as a device that “searches” for a proof that \( w \in L \).
    • If it finds it, great!
    • If not, it might loop forever.
  • If the RE languages represent languages where membership can be proven, what does a non-RE language look like?
  • Intuitively, a language is not in RE if there is no general way to prove that a given string \( w \in L \) actually belongs to \( L \).
  • In other words, even if you knew that a string was in the language, you may never be able to convince anyone of it!

RE 的直观含义: 「属于 L」这件事可以被证明. 验证器就是检查证明的机器: 你知道 w ∈ L 并有证明, 就能说服别人. 识别器是「搜索证明」的机器: 找到了就接受, 找不到可能永远找下去.

那么不在 RE 中的语言是什么样? 没有一般的方法能证明 w 属于它: 即使你知道 w 在里面, 也可能永远无法说服别人. 下一讲会找到这样的语言.
