What problems can we solve with a computer?

(图: 层层包含的区域: Regular Languages ⊂ CFLs ⊂ Languages recognizable by any feasible computing machine ⊂ All Languages; 第二张是「按比例画的同一张图」, 前几类在所有语言中只占极小的一点.)

The Problem

  • Finite automata accept precisely the regular languages.
  • We may need unbounded memory to recognize context-free languages.
    • e.g. \( \{ a^n b^n \mid n \in \mathbb{N} \} \) requires unbounded counting.
  • How do we model a computing device that has unbounded memory?

回到总问题: 计算机能解决什么问题? 目前已知正则语言 ⊂ 上下文无关语言, 之外还有「任何可行的计算机器能识别的语言」, 再外面是所有语言. 按比例画, 能被计算机识别的语言只占所有语言的极小一部分 (第 00 讲的计数论证).

有限自动机恰好识别正则语言; 识别上下文无关语言 (如 \( a^n b^n \)) 可能需要无限的内存来计数. 这一讲的问题: 怎样给拥有无限内存的计算设备建模. 重点是图灵机的六条指令和三个编程例子.

一点历史
A Brief History Lesson

Slide 7

Turing Machines

  • In March 1936, Alan Turing (aged 23!) published a paper detailing the a-machine (for automatic machine), an automaton for computing on real numbers.
  • They're now more popularly referred to as Turing machines in his honor.
  • He also later made contributions to computational biology, artificial intelligence, cryptography, etc. Seriously, Google this guy.

(照片: 艾伦·图灵.)

1936 年, 23 岁的艾伦·图灵发表论文, 提出 a-machine (automatic machine, 自动机器), 用来计算实数, 后人称为 Turing machine 图灵机. 图灵后来还在计算生物学 (形态发生)、人工智能 (图灵测试)、密码学 (二战中破译 Enigma) 等领域做出了重要贡献.

Key Idea: Even if you need huge amounts of scratch space to perform a calculation, at each point in the calculation you only need access to a small amount of that scratch space.

图灵的出发点是人用纸笔计算的过程. 以竖式加法为例 (e 和 π 的前若干位相加): 一列一列地从右往左算, 每一步只需要看当前这一列的两个数字和进位, 写下一位结果.

关键想法: 即使整个计算需要大量草稿空间, 每一时刻只需要接触其中很小的一部分. 所以可以给机器一条无限长的「草稿纸」, 但每次只让它看一格.

核算竖式: 27182818284590 + 31415926535897 = 58598744820487, 和课件最后一行一致 (用 Python 验证过).

Slide 25–30

Turing Machines

  • To provide his machines extra memory, Turing gave his machines access to an infinite tape subdivided into a number of tape cells.
  • A Turing machine can only see one tape cell at a time, the one pointed at by the tape head.
  • The Turing machine can
    • read the cell under the tape head,
    • (possibly) change which symbol was written under the tape head, and
    • move its tape head to the left or to the right.

图灵机的额外内存是一条两端无限长的 tape 纸带, 分成一个个 cell 格子. 机器每次只能看到 tape head 读写头指着的那一格. 它能做三件事: 读这一格; (可以) 改写这一格的符号; 把读写头左移或右移一格. 动画里纸带上的内容从 aqikd… 被逐格改写.

Slide 31–33
  • Over the years, there have been many simplifications and edits to Turing's original automata.
    • In practice, electronic computers are written in terms of individual instructions rather than states and transitions.
    • Turing's original paper deals with computing individual real numbers; we typically want to compute functions of inputs.
  • What we're going to present as “Turing machines” in this class differ significantly from Turing's original description, while retaining the core essential ideas.
  • (Our model is closer to Emil Post's Formulation 1 and Hao Wang's Basic Machine B, for those of you who are curious.)

CS103 讲的「图灵机」和图灵原始的定义差别很大: 原始版用状态和转移描述, 而且计算的是单个实数; 课程版用一条条指令写程序 (更像真实计算机), 计算的是对输入的判断. 核心思想 (有限的控制 + 无限纸带 + 一次看一格) 不变. 课程模型更接近 Emil Post 的 Formulation 1 和王浩 (Hao Wang) 的 Basic Machine B.

教科书 (如 Sipser) 里的标准定义是状态转移形式的, 两种形式能力相同.

图灵机程序
Turing Machines as Programs

Slide 34–40
  • A TM is a series of instructions that control a tape head as it moves across an infinite tape.
  • The tape begins with the input string written somewhere, surrounded by infinitely many blank cells.
    • Rule: The input string cannot contain blank cells.
  • The tape head begins above the first character of the input. (If the input is \( \varepsilon \), the tape head points somewhere on a blank tape.)
Start:
  If Blank Return True
  If 'b' Return False
  Write 'x'
  Move Right
  If Not 'b' Return False
  Write 'x'
  Move Right
  Goto Start

(纸带: … a b a b a b …, 读写头在第一个 a 上.)

  • We begin at the Start label.
  • Labels indicate different sections of code. The name Start is special and means “begin here.”
  • Labels have no effect when executed. We just move to the next line.

课程版图灵机是一串指令, 控制读写头在纸带上移动. 初始时输入串写在纸带某处, 两边是无穷多个空白格 (Blank); 输入串本身不能含空白. 读写头从输入的第一个字符开始 (输入是空串时就停在一片空白上).

程序从标签 Start 开始. 标签 (以冒号结尾的名字) 只标记一段代码的位置, 执行到它时什么也不做, 直接执行下一行.

Slide 41–60
  • A statement of the form If symbol command checks if the character under the tape head is symbol.
    • If so, it executes command.
    • If not, nothing happens.
  • The statement Write symbol writes symbol to the cell under the tape head.
    • The symbol can either be Blank or a character in quotes.
  • The command Move direction moves the tape head one step in the indicated direction (either Left or Right).
  • A statement of the form If Not symbol command sees if the cell under the tape head holds symbol.
    • If so, nothing happens.
    • If not, it executes command.
  • The command Goto label jumps to the indicated label.
    • This program just has a Start label, but most interesting programs have other labels beyond this.
  • A TM stops when executing the Return result command.
    • Here, result can be either True or False.
    • (If we “fall off” the bottom of the program, the TM acts as though it executes the Return False command.)

各条指令的含义:

  • If 符号 命令: 当前格是该符号就执行命令, 否则什么也不做.
  • If Not 符号 命令: 反过来, 当前格不是该符号才执行.
  • Write 符号: 把当前格改写成该符号 (可以写 Blank 擦掉).
  • Move Left/Right: 读写头移动一格.
  • Goto 标签: 跳到标签处继续执行.
  • Return True/False: 停机并给出结果. 执行到程序末尾还没返回, 等同于 Return False.
Slide 61–97

(动画: 在 ababab 上运行上面的程序, 纸带依次变为 xbabab, xxabab, …, xxxxxx, 最后读写头遇到空白.)

This TM initially started up with the string ababab on its tape, so this means that TM returns true on the input ababab, not xxxxxx.

An intuition for this: we gave this program an input. It therefore returned true with respect to that input, not whatever internal data it generated in making its decision.

To summarize, we only have six commands:

  • Move direction
  • Write symbol
  • Goto label
  • Return result
  • If symbol command
  • If Not symbol command

Despite their simplicitly, TMs are surprisingly powerful. The rest of this lecture explores why.

运行例子: 程序每轮检查当前格是 a (不是 b、不是空白), 改成 x, 右移; 再检查是 b, 改成 x, 右移; 回到 Start. 读到空白时返回 True. 在 ababab 上把六个字符都改成 x, 最后返回 True. 这个程序接受的语言是 \( (ab)^* \) (用 Python 模拟器对长度 ≤ 8 的所有 a、b 串核对过).

注意: 结论是「它接受输入 ababab」, 而不是接受纸带上最后剩下的 xxxxxx. 纸带上的改写只是计算过程中的草稿.

总共只有六条指令: Move、Write、Goto、Return、If、If Not. 指令这么少, 图灵机却出乎意料地强大.

原文笔误: “Despite their simplicitly” 应为 simplicity.

Your Turn!

Does this TM accept or reject bbaacc? More generally, what does this TM do?

Start:
  If 'a' Goto Mirth
  If Blank Return False
  Move Right
  Goto Start

Mirth:
  If 'b' Return True
  If Blank Return False
  Move Right
  Goto Mirth

(纸带: … b b a a c c …)

在 bbaacc 上: Start 段跳过两个 b, 遇到 a 就跳到 Mirth; Mirth 段向右找 b, 依次经过 a、c、c, 遇到空白返回 False. 所以拒绝.

一般地: Start 段找第一个 a, 找不到就拒绝; Mirth 段在那之后找 b, 找到就接受. 所以它接受「某个 a 之后出现了 b」的串, 用正则表达式写是 Σ*aΣ*bΣ* (用模拟器在 {a, b, c} 上长度 ≤ 6 的串核对过).

编写图灵机: aⁿbⁿ
Programming Turing Machines

Slide 101–104

Our First Challenge

  • The language \( \{ a^n b^n \mid n \in \mathbb{N} \} \) is a canonical example of a nonregular language. It's not possible to check if a string is in this language given only finite memory.
  • Turing machines, however, are powerful enough to do this. Let's see how.

A Recursive Approach

  • We can process our string using a recursive approach:
    • The string \( \varepsilon \) is in L.
    • The string awb is in L if and only if w is in L.
    • Any string starting with b is not in L.
    • Any string ending with a is not in L.
  • All that's left to do now is write a TM that implements this.

A Sketch of our TM

(动画: aaaabbbb → aaabbbb → aaabbb → aabbb → aabb → … → 空, 每次擦掉开头的 a 和末尾的 b.)

\( a^n b^n \) 不正则, 但图灵机能识别它. 思路是递归:

  • 空串属于 L;
  • awb 属于 L 当且仅当中间的 w 属于 L;
  • 以 b 开头或以 a 结尾的 (非空) 串不属于 L.

图灵机的做法: 反复擦掉第一个 a 和最后一个 b, 直到纸带变空 (接受), 或者开头不是 a、结尾不是 b (拒绝).

Slide 105–276 
Start:
  If Blank Return True
  If 'b' Return False
  Write Blank

ZipRight:
  Move Right
  If Not Blank Goto ZipRight
  Move Left
  If Not 'b' Return False
  Write Blank

ZipLeft:
  Move Left
  If Not Blank Goto ZipLeft
  Move Right
  Goto Start

(动画: 在 aaabbb 上运行, 纸带依次变为 aabbb, aabb, abb, ab, b, 空, 最后 If Blank Return True.)

程序分三段:

  1. Start: 当前格是空白, 说明串已经擦空, 接受; 是 b 就拒绝 (以 b 开头); 否则是 a, 把它擦成空白.
  2. ZipRight: 一路向右直到碰到空白, 再左移一格, 就到了串的最后一个字符. 不是 b 就拒绝; 是 b 就擦掉.
  3. ZipLeft: 一路向左直到碰到空白, 再右移一格, 回到串的第一个字符, 回 Start 重复.

这里用空白当「边界标记」: 因为擦掉的是两端的字符, 剩下的串始终连续, 左右两边紧挨着就是空白. 用模拟器核对: 对长度 ≤ 8 的所有 a、b 串, 程序恰好接受 \( a^n b^n \).

第二个挑战: a 和 b 一样多
Our Next Challenge

Slide 280–307

Our Next Challenge

  • Let's try a more involved language:

    \( \{ w \in \{a, b\}^* \mid w \text{ has an equal number of a's and b's} \} \)

  • This language is not regular (do you see why?)
  • It is context-free, but it's a bit tricky to write a CFG for it.
  • Let's see how to design a TM for it.

A Caveat

(动画: 尝试把配对的 a 和 b 都擦成空白, 例如 aaaabbabba → aaabbabba → …, 中间出现空白格.)

How do we know that this blank isn't one of the infinitely many blanks after our input string?

新语言: a 和 b 个数相等. 它不正则 (区分集 \( \{a^n\} \): \( a^m \) 和 \( a^n \) 用后缀 \( b^m \) 区分), 是上下文无关的, 但文法不好写 (上一讲的投票题). 图灵机怎么做?

自然的想法: 每次找一个 a 和一个 b, 把它们擦掉. 问题是擦掉的位置在串中间, 留下空白格. 之后机器扫描时遇到空白, 分不清它是中间被擦出来的洞, 还是输入末尾之后的无穷空白.

Slide 308–324

One Solution

(动画: aaaabbabba → axaabbabba → axaaxbabba → axxaxbabba → axxaxxabba, 被配对的字符改写成 x 而不是空白.)

解决办法: 不擦成空白, 而是改写成一个新符号 x, 表示「已经配对用掉了」. x 不是空白, 所以串的边界始终清楚, 扫描时跳过 x 即可. 纸带的字母表可以比输入字母表大, 这是图灵机常用的技巧.

Slide 325–645 
Start:
  If 'a' Goto FoundA
  If 'b' Goto FoundB
  If Blank Return True
  Move Right
  Goto Start

FoundA:
  Write 'x'
LoopA:
  Move Right
  If 'a' Goto LoopA
  If 'x' Goto LoopA
  If Blank Return False
  Write 'x'
  Goto GoHome

GoHome:
  Move Left
  If Not Blank Goto GoHome
  Move Right
  Goto Start

FoundB:
  Write 'x'
LoopB:
  Move Right
  If 'b' Goto LoopB
  If 'x' Goto LoopB
  If Blank Return False
  Write 'x'
  Goto GoHome

(动画: 在多个输入上逐步运行这个程序, 有的以 If Blank Return True 接受, 有的以 If Blank Return False 拒绝.)

程序结构:

  1. Start: 从左往右跳过 x, 找第一个还没用掉的字符. 是 a 去 FoundA, 是 b 去 FoundB; 走到空白说明全部配对完, 接受.
  2. FoundA: 把这个 a 改成 x, 然后 LoopA 向右跳过 a 和 x, 找一个 b. 碰到空白说明 a 多出来了, 拒绝; 找到 b (唯一剩下的可能) 就改成 x, 回家.
  3. FoundB: 对称地找一个 a 配对.
  4. GoHome: 向左走到空白再右移一格, 回到串的开头. 因为开头的字符变成了 x 而不是空白, 这一步能正确找到起点.

每一轮配掉一对 a、b; 个数相等时最终全部变成 x, 接受. 用模拟器对长度 ≤ 8 的所有 a、b 串核对过, 结果与「a、b 个数相等」完全一致.

Slide 646–655

Another Idea

  • We just built a TM for the language \( \{ w \in \{a, b\}^* \mid w \text{ has the same number of a's and b's} \} \).
  • An observation: this would be a lot easier to test for if all the a's came before all the b's.
  • In fact, that would turn this into checking if the string has the form \( a^n b^n \), which we already know how to do!
  • Idea: Could we sort the characters of our input string?

The Idea

(动画: 纸带上的 aababb 被重新排列成 aaabbb.)

另一种思路: 如果所有 a 都排在 b 前面, 问题就变成检查 \( a^n b^n \), 这个已经会了. 所以可以先把输入排序 (aababb → aaabbb), 再交给 \( a^n b^n \) 的程序. 这体现了编程的组合思想: 用已有的图灵机作为「子程序」拼出新的图灵机.

排序本身可以这样做: 反复寻找相邻的「ba」并交换成「ab」, 直到找不到为止, 类似冒泡排序.

Slide 656–657

Summary for Today

  • Turing machines are abstract computers that issue commands to an infinite tape subdivided into cells.
  • Each step of the TM can move the tape head, change what's on the tape, or jump to a different part of the program.
  • TMs can be composed together to build larger TMs out of smaller ones.
