# 复习层同步更新方案

笔记有新增、修改、换版，或加入新课程时，让图谱、术语、跨课关联跟着更新，并且不出 bug。写成 lmu-course-notes skill 每次都能照做的步骤。

- 复习层只读笔记，**任何时候都不改笔记**。
- 正式主页 `Computerlinguistik/笔记总目录.html` 由 `python3 复习层/build.py` 生成。`sync_repo.py`（包括 `--local-only`）会自动调用它。
- 构建是确定的：同样的输入，每次输出逐字相同。
- 质量闸门（cover.py）不通过就不生成主页，现有主页保持不变。

---

## A. 每次笔记任务收尾都做（4 条命令）

新写笔记、改笔记、换版、新课，做完笔记本身的常规检查之后、同步到仓库之前：

```
python3 复习层/tests/notes_hash.py snapshot    # 1. 记下此刻笔记的哈希 (笔记的改动到此为止)
python3 复习层/build.py                         # 2. 构建, 读输出
python3 复习层/tests/check_data.py              # 3. 数据体检, 必须 0 个问题
python3 复习层/tests/notes_hash.py check        # 4. 复习层的工作没碰笔记, 必须 0 个变化
```

第 2 步的输出决定要不要跟进：

| 输出 | 意思 | 去哪一节 |
| --- | --- | --- |
| `新讲次未进图谱 <课> [...]` | 这门课有新的一讲，概念还没进图谱和术语 | B |
| `需更新 <课> {...}` | 已进图谱的笔记改过了（文件或锚点变了） | D |
| `闸门未通过 ...` | 考点、小节或加粗词没有覆盖，详情在 `cand/<课>.cover.txt` | B 或 D |
| `<课> 校验失败` | 内容文件写错了（锚点不存在、ID 撞名、字段错） | 按报错改 `content/<课>.txt` |
| 只有最后一行 `courses …` | 没有要跟进的 | 结束 |

收尾前，屏幕没锁时再跑一次 `zsh 复习层/tests/quick.sh`（构建、体检、浏览器冒烟、笔记链接能打开）。然后按用户的规则同步到仓库。

## B. 已有课程新增一讲或练习单

1. 只读新笔记，以及构建时自动刷新的候选 `复习层/cand/<课>.txt`（小节、加粗词、锚点）。
2. 改 `复习层/content/<课>.txt`，格式见文件头和 `docs/抓取规范.md`：
   - `N` 行：新概念。放进已有分支；确实是新主题才加 `B` 行。分支总数保持在 4–11 个。
   - `E` 行：连到已有概念，`>` 先修、`~` 对照，写明理由，不能形成先修环。
   - `T` 行：术语。冠词以 Duden 为准，名称不机翻，不收非知识和「易错」类条目。
   - `M` 行：自动对不上的「术语 → 概念」手写对应。
3. 改 `复习层/content/<课>.deep.txt`：德语定义、讲解、子概念。
4. **跨课：** 在 `复习层/content/_bridges.txt` 里查其他课有没有同一个或相通的概念，有就补 `X` 行，写明关系。
5. **ID 规则：**
   - 新 ID 不和本课任何分支、概念、子概念重名。构建会自动给撞名的分支改名，但写的时候就要避免。
   - 已有 ID 永远不改、不复用。改了会让旧链接和跨课连线断掉。
6. 重新跑 A 的 4 条命令，直到闸门通过、体检 0 个问题。

## C. 新课程

1. 先判断这门课做不做图谱和术语。语言课、写作课、OC 公开课目前不做，名单在 `复习层/pipeline/candidates_rules.py` 的 `NOGRAPH`。不做的课只在笔记栏出现。
2. 按 skill 已有流程登记新课：课程表、课程配色、`sync_repo.py` 的 `COURSE_INFO` 和 `GROUPS`。
3. `python3 复习层/pipeline/candidates.py <课>` 生成候选。
4. 从零写 `content/<课>.txt` 和 `content/<课>.deep.txt`，按 `docs/抓取规范.md`。考点要全覆盖，不抓非知识。
5. 补 `_bridges.txt` 里和其他课的关联。
6. 跑 A；再在浏览器里看一遍这门课的图谱：外圈每个分支都有弧线和名字，文字不重叠，学习路线顺序合理。

## D. 已有课程的内容改了（改笔记、学期换版）

接在 skill「材料换版」一节第 3 步（只改受影响的部分）之后。

1. 笔记改完后，构建会对改过的笔记报 `需更新`。依据是 `content/<课>.lock.json`，里面记着上次核对时每篇笔记的哈希。
2. 只处理受影响的部分：
   - **锚点没了**（小节删掉或改名）：构建会报错。小节改名就改概念的锚点；内容整个删掉，就删这个概念，并同时删掉它的 `E` 连线、`M` 对应和 `_bridges.txt` 里的跨课连线。
   - **定义或课件原句改了**：更新概念的一句话、`deep.txt` 的讲解。课件原句（`Q` 行）重新核对，必须逐字出现在新版笔记的原文卡片里。
   - **新增的页有新知识点**：按 B 补。
   - 没变的内容一字不动；概念 ID 不变，旧学期复习过的概念保持同一个 ID。
3. 全部核对完，确认无误后才运行 `python3 复习层/build.py --relock`，把新的笔记哈希记为「已核对」。**没核对完不能 relock**，否则改动会被当成已处理而漏掉。
4. 在 `content/<课>.txt` 头部注释记一行换版说明，例如 `# 换版 2027-04: 依据 SoSe 2027 课件; 改 3 讲, 新增概念 x, 删除 y`。
5. 跑 A。

## E. 写进 skill 时的位置建议

- 替换 skill 里过时的「复习层（试点）」一节：改成现在的三栏复习层说明，并引用本方案。
- 「工作流程」最后一步前加一句：「收尾时跑复习层同步检查（复习层/docs/同步更新方案.md 的 A 节）」。
- 「材料换版」第 3 步后加一句：「笔记改完后按复习层同步更新方案的 D 节更新图谱和术语」。
- 「同步到 GitHub 仓库」一节注明：本地主页现由复习层生成，`--local-only` 会调用 `复习层/build.py`。
