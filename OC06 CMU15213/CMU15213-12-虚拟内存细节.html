Review: Memory Accesses without VM — CPU sends physical address to cache · Cache sends data to CPU

Review: Memory Accesses with VM

没有虚拟内存时, CPU 直接用物理地址访问缓存. 有虚拟内存时多了一层: CPU 把虚拟地址交给 MMU, MMU 查页表; 页在内存中就把物理地址送到缓存; 不在就触发缺页, 由操作系统接管: 能恢复 (如从磁盘把页读进来) 就恢复并让 MMU 重新执行这次访问, 不能恢复 (非法地址) 就终止这个出错的进程.

Review: the problem (with k-level page tables) — Page table base register (PTBR) · VIRTUAL ADDRESS: VPN 1 · VPN 2 · ... · VPN k · VPO → Level 1 page table → Level 2 page table → … → Level k page table → PPN · PPO — Cache miss! Cache miss! Cache miss! Cache miss! Cache miss!

单级页表太大: 48 位地址空间、4 KB 页、每项 8 字节, 需要 2⁴⁸ / 4096 × 8 = 2³⁹ 字节 = 512 GB. 多级页表解决了空间问题, 却带来时间问题: k 级页表每次翻译要依次读 k 个页表项, 再读数据本身, 最坏情况下这 k + 1 次都缓存不命中. 这正是 TLB 要解决的.

Page Faults

Slide 12–14

What happens on a page fault? — What is a page fault? · Why can they happen? How does the OS know?

OS tracks VM “areas” — Each area has permissions / purpose / etc (Areas: Stack (at 00007FFFFFFFFFFF), Shared Libraries, Heap, Data, Text (at 400000), down to 000000)

Types of Faults

  1. This is a legal address · Hard / Major faults – “normal” page faults · Soft / minor faults – the OS took the page away, but has not reused
  2. The address is legal, but … The type of access is wrong, so “protection exception”
  3. The address is not legal · Segmentation fault or bus error

缺页时操作系统怎么知道该做什么? 它为每个进程记录若干区域 (area, Linux 叫 VMA): 栈、共享库、堆、数据、代码各是一个区域, 每个区域有自己的权限和用途. 缺页处理程序根据出错地址和访问类型分三种情况:

  1. 地址合法 (落在某个区域内, 访问类型也允许): 正常的缺页. 硬缺页 (主缺页) 需要从磁盘读入; 软缺页 (次缺页) 是页还在物理内存里 (操作系统收回了映射但还没挪作他用), 只需重新建立映射.
  2. 地址合法但访问类型不对 (如写只读页): 保护异常.
  3. 地址不在任何区域中: 段错误 (或总线错误). 程序崩溃时看到的 Segmentation fault 就是这种.

Before fetching the Page Table Entry (PTE) from a one-level page table in a simple system, the Memory Management Unit (MMU) performs the following sub-steps: 1. Virtual Address Splitting: The MMU splits the virtual address into two parts: Virtual Page Number (VPN): The leftmost bits of the address represent the VPN. 小测 1: 一级页表时, MMU 取 PTE 之前要做什么? 课件展示的是一个聊天机器人的回答, 内容正确: 把虚拟地址拆成 VPN (高位) 和 VPO (低位); 用 VPN 作为数组下标. 更精确地说, MMU 要算出 PTE 的物理地址: PTEA = PTBR + VPN × PTE 大小, 然后读取它.

小测 2: 为什么页表的地址必须是物理地址? 课件展示的聊天机器人回答说了一堆「为了高效、为了权限检查」, 并没有答到点子上. 真正的原因是: 如果页表的地址是虚拟地址, 那么要读页表就得先翻译这个地址, 而翻译又需要读页表, 陷入无穷递归. 所以 PTBR (x86 的 CR3) 存的是物理地址, 各级页表项里指向下一级页表的也都是物理地址.

完整走一遍虚拟地址 0x369 的读取 (每一步都用 Python 核对过):

  1. 拆虚拟地址: 0x369 = 00 0011 0110 1001, VPN = 高 8 位 = 0x0D, VPO = 低 6 位 = 0x29.
  2. 查 TLB: TLBI = 1, TLBT = 0x03, 命中, PPN = 0x2D (与页表中 VPN 0x0D → PPN 0x2D 一致; 若 TLB 不命中, 就去查页表).
  3. 拼物理地址: PA = PPN 与 PPO (= VPO) 拼接 = 10 1101 | 10 1001 = 0xB69.
  4. 查缓存 (直接映射, 16 行, 每行 4 字节): CO = 低 2 位 = 1, CI = 接下来 4 位 = 0xA, CT = 高 6 位 = 0x2D.
  5. 第 0xA 行标记 2D、有效, 命中, 取第 1 个字节 B1 = 0x15.

这类「给定 TLB、页表、缓存的内容, 求某个地址的读取结果」是考试常见题型.

Slide 24

End-to-end Core i7 Address Translation

端到端过程: 虚拟地址 48 位 (页 4 KB, 偏移 12 位, VPN 36 位). VPN 的低 4 位选 L1 TLB 的组 (16 组, 每组 4 项, 共 64 项), 高 32 位作标记. TLB 命中就直接得到 40 位 PPN; 不命中则从 CR3 开始, 用 VPN1–VPN4 (各 9 位) 逐级查 4 级页表. 物理地址 52 位 = PPN 40 位 + 偏移 12 位, 再拆成缓存标记 CT 40 位、组索引 CI 6 位、块偏移 CO 6 位 (64 组 × 8 行 × 64 字节 = 32 KB) 查 L1, 不命中依次去 L2、L3、主存.

Core i7 Level 1-3 Page Table Entries — 63: XD · 62–52: Unused · 51–12: Page table physical base address · 11–9: Unused · 8: G · 7: PS · 6: · 5: A · 4: CD · 3: WT · 2: U/S · 1: R/W · 0: P=1 — (P=0: Available for OS (page table location on disk))

Each entry references a 4K child page table. Significant fields: · P: Child page table present in physical memory (1) or not (0). · R/W: Read-only or read-write access access permission for all reachable pages. · U/S: user or supervisor (kernel) mode access permission for all reachable pages. · WT: Write-through or write-back cache policy for the child page table. · A: Reference bit (set by MMU on reads and writes, cleared by software). · PS: Page size either 4 KB or 4 MB (defined for Level 1 PTEs only). · Page table physical base address: 40 most significant bits of physical page table address (forces page tables to be 4KB aligned) · XD: Disable or enable instruction fetches from all pages reachable from this PTE.

前三级页表项 (每项 8 字节) 指向一个 4 KB 的下一级页表. 主要字段: P 存在位 (为 0 时其余位留给操作系统, 如记录在磁盘上的位置); R/W 读写权限、U/S 用户/内核权限, 作用于经由此项可达的所有页; WT 缓存策略; A 访问位 (MMU 在读写时置 1, 由软件清零, 供页面替换算法判断最近是否用过); PS 页大小; 40 位物理基址 (页表必须 4 KB 对齐, 低 12 位为 0 不用存); XD 禁止执行位 (就是上一讲说的 NX).

幻灯片小错: "PS: Page size either 4 KB or 4 MB (defined for Level 1 PTEs only)" 沿用了教材的说法, 与 x86-64 实际不符: 4 MB 页是 32 位 x86 的概念; x86-64 中 PS 位在第 2 级 (PDPT) 项中表示 1 GB 大页, 在第 3 级 (页目录) 项中表示 2 MB 大页, 第 1 级 (PML4) 项中没有 PS. 另外 "access access permission" 重复了一个词.

第 4 级页表项直接指向 4 KB 的物理页, 比前三级多了 D 脏位 (MMU 在写时置 1, 换出时据此决定是否写回磁盘) 和 G 全局位 (切换进程时不从 TLB 中清除, 用于内核页).

Cute Trick for Speeding Up L1 Access — CT (40) · CI (6) · CO (6) — Physical address (PA): PPN · PPO — Virtual address (VA): VPN (36) · VPO (12) — Address Translation · No Change · Tag Check · L1 Cache

  • Observation
    • Bits that determine CI identical in virtual and physical address
    • Can index into cache while address translation taking place
    • Generally we hit in TLB, so PPN bits (CT bits) available quickly
    • “Virtually indexed, physically tagged”
    • Cache carefully sized to make this possible

加速 L1 访问的技巧: L1 的组索引 CI 和块偏移 CO 共 12 位, 恰好落在页内偏移里, 而页内偏移在翻译前后不变. 于是 CPU 可以在查 TLB 的同时用虚拟地址的低位选出 L1 的组, 等 TLB 给出 PPN (即缓存标记 CT) 时直接比较标记. 这叫虚拟索引、物理标记. 代价是缓存要「精心设计大小」: 组数 × 块大小不能超过页大小, 32 KB 的 L1 只能靠 8 路相联来做大 (64 组 × 64 字节 = 4 KB, 再乘 8 路).

Memory-Mapped Files — Paging = every page of a program's physical RAM is backed by some page of disk* · Normally, those pages belong to swap space · But what if some pages were backed by … files? · * This is how it used to work 20 years ago. Nowadays, not always true.

(Figure: Process virtual memory → Physical memory → Swap space / File on disk; then two processes, Process 1 and Process 2, mapping the same file pages)

内存映射文件: 换页机制里, 进程用的每个物理页背后都有一个磁盘页作后备, 通常在交换空间 (swap) 里. 如果让一部分页的后备直接是某个文件, 那么读这些虚拟地址就等于读文件, 缺页时由操作系统从文件按需读入, 无需显式的 read 调用. 多个进程映射同一个文件, 就共享同一份物理页. 可执行文件的代码和共享库就是这样加载的. (注: 二十年前每个物理页都有磁盘后备, 现在的系统不一定如此, 例如可以不配置交换空间.)

Slide 34–36

Copy-on-write sharing — fork creates a new process by copying the entire address space of the parent process · That sounds slow · It is slow · Clever trick: · Just duplicate the page tables · Mark everything read only · Copy only on write faults

写时复制: fork 要给子进程一份父进程整个地址空间的副本, 真的复制会很慢. 技巧: 只复制页表, 父子进程的页表指向同样的物理页, 并把这些页都标成只读; 谁对某页写入, 就触发保护异常, 内核此时才复制这一页、改成可写. 没被写的页 (如代码) 永远共享. 由于 fork 后子进程常常马上调用 execve 换成新程序, 大部分页根本不用复制.

Slide 38–41

Conceptual Quiz: 3 — Why are one-level page tables impractical and how do multi-level page tables fix this problem? — A single-level page table covering the entire address space of a typical system would be much too large. For instance, with 4kB pages, a 48-bit address space, and a 8-byte PTE, a single-level page table would occupy 512 gigabytes, which is more RAM than most computers have.

Conceptual Quiz: 4 — Why is memory access slower with a multi-level page table than with a single-level page table? — A k-level page table requires k memory loads in order to determine the physical address. There is no spatial locality to these loads.

Conceptual Quiz: 5 — What is the Translation Lookaside Buffer (TLB), what problem does it solve, and when is it used? — The TLB is a small cache dedicated to storing mappings from virtual to physical addresses. It avoids the cost of lookups in a multi-level page table. The MMU consults the TLB for each address as its first action; if there is a TLB hit, it does not need to fetch anything from the page table.

Conceptual Quiz: 6 — How does virtual memory interact with the memory cache(s)? — The cache's function is to speed up access to whatever data is most frequently used. The MMU sits “in between” the CPU and the cache; the cache works only with physical addresses. This means data from multiple processes may coexist in the cache (or compete for cache space).

其余四道小测 (讲师给出的答案):

  1. 单级页表太大 (48 位地址、4 KB 页、8 字节 PTE 时 512 GB). 题目还问了多级页表如何解决, 答案只讲了问题: 多级页表只为实际用到的地址区域建立下级页表, 未用的大片区域在上级只占一个 null 项.
  2. k 级页表要 k 次内存读取才能得到物理地址, 而且这些读取分散在不同的页表页里, 没有空间局部性.
  3. TLB 是专门缓存虚拟到物理映射的小缓存, MMU 对每个地址首先查 TLB, 命中就完全不用读页表.
  4. MMU 位于 CPU 和缓存之间, 缓存只使用物理地址; 因此不同进程的数据可以同时在缓存里, 也会相互争夺缓存空间.
