显式空闲链表
Explicit free lists

Slide 9–10

Explicit Free Lists

  • Maintain list(s) of free blocks, not all blocks · Luckily we track only free blocks, so we can use payload area · The “next” free block could be anywhere · So we need to store forward/back pointers, not just sizes · Still need boundary tags for coalescing · To find adjacent blocks according to memory order

Logically: A → B → C · Physically: blocks can be in any order

显式空闲链表: 只把空闲块串成链表, 而不是所有块. 空闲块的载荷区反正没人用, 正好存放两个指针: 指向下一个和上一个空闲块 (双向链表). 下一个空闲块可能在堆中任何位置, 所以必须存指针, 不能只靠大小推算. 仍然需要边界标记, 因为合并时要找内存中相邻的块, 那与链表顺序无关.

逻辑上链表是 A → B → C, 物理上三个块在内存中的顺序可以是任意的 (图中是 A、C、B).

Freeing With Explicit Free Lists — Insertion policy: Where in the free list do you put a newly freed block? · Unordered · LIFO (last-in-first-out) policy · Insert freed block at the beginning of the free list · FIFO (first-in-first-out) policy · Insert freed block at the end of the free list · Pro: simple and constant time · Con: studies suggest fragmentation is worse than address ordered · Address-ordered policy · Insert freed blocks so that free list blocks are always in address order: addr(prev) < addr(curr) < addr(next) · Con: requires search · Pro: studies suggest fragmentation is lower than LIFO/FIFO

分配: 在空闲链表中找到合适的块, 分配出去; 若分割, 剩下的部分留在链表中原来的位置 (只需调整指针).

释放时把块插到链表的哪里 (插入策略)? 无序: LIFO 插到表头, 或 FIFO 插到表尾, 简单, 常数时间, 但研究表明碎片比按地址排序多. 按地址排序: 保持链表中块的地址递增, 插入时要搜索, 但碎片更少 (按地址排序的首次适配接近最佳适配).

Slide 13–16

Freeing With a LIFO Policy (Case 1) — Allocated / Allocated · Insert the freed block at the root of the list

(Case 2) — Allocated / Free · Splice out adjacent successor block, coalesce both memory blocks, and insert the new block at the root of the list

(Case 3) — Free / Allocated · Splice out adjacent predecessor block, coalesce both memory blocks, and insert the new block at the root of the list

(Case 4) — Free / Free · Splice out adjacent predecessor and successor blocks, coalesce all 3 blocks, and insert the new block at the root of the list

LIFO 策略下释放的四种情况 (按内存中前后邻居是否空闲): ① 都已分配: 直接把本块插到表头; ② 后一块空闲: 把后一块从链表中摘出, 与本块合并, 合并后的块插到表头; ③ 前一块空闲: 摘出前一块, 合并, 插到表头; ④ 都空闲: 摘出前后两块, 三块合并, 插到表头. 「摘出」是双向链表的常数时间操作 (改前驱的 next 和后继的 prev), 所以释放仍是常数时间.

Slide 17

Explicit List Summary — Comparison to implicit list: · Allocate is linear time in number of free blocks instead of all blocks · Much faster when most of the memory is full · Slightly more complicated allocate and free · Need to splice blocks in and out of the list · Some extra space for the links (2 extra words needed for each block) · Does this increase internal fragmentation?

与隐式链表相比: 分配时间与空闲块数成线性, 而不是所有块, 内存快满时 (空闲块少) 快得多; 分配和释放稍复杂, 要维护链表; 每块要能放下两个指针. 回答课件的问题: 指针只在空闲块里占空间, 已分配块不受影响, 但最小块大小变大了 (块头 + 两个指针 + 块尾 = 32 字节), 很小的请求也要占至少这么大的块, 所以内部碎片会增加一些.

分离空闲链表
Segregated free lists

Slide 19

Segregated List (Seglist) Allocators — Have several free lists, one for each size class of blocks

  • Which blocks go in which size classes is a design decision · Can have major impact on both utilization and throughput · Common choices include: · One class for each small size (16, 32, 48, 64, …) · At some point switch to powers of two: [2i+1,2i+1]
  • The list for the largest blocks must have no upper limit · (well, 2⁶⁴)

分离空闲链表: 维护多条空闲链表, 每条存一个大小类的块. 大小类怎么划分是设计决策, 对利用率和吞吐量影响很大. 常见做法: 小尺寸每个大小一类 (16、32、48、64……); 到一定大小后按 2 的幂分档, 第 i 类存 2ⁱ + 1 到 2ⁱ⁺¹ 字节的块. 最大的一类必须没有上限 (实际上限是 2⁶⁴).

Slide 20–21

Seglist Allocator — Given an array of free lists, each one for some size class · To allocate a block of size n: · Search appropriate free list for block of size m ≥ n (i.e., first fit) · If an appropriate block is found: · Split block and place fragment on appropriate list · If no block is found, try next larger class · Repeat until block is found · If no block is found: · Request additional heap memory from OS (using sbrk()) · Allocate block of n bytes from this new memory · Place remainder as a single free block in appropriate size class.

Seglist Allocator (cont.) — To free a block: · Coalesce and place on appropriate list · Advantages of seglist allocators vs. non-seglist allocators (both with first-fit) · Higher throughput · log time for power-of-two size classes vs. linear time · Better memory utilization · First-fit search of segregated free list approximates a best-fit search of entire heap. · Extreme case: Giving each block its own size class is equivalent to best-fit.

分配大小 n: 先在 n 所属的大小类链表中首次适配找 m ≥ n 的块; 找到就分割, 剩下的碎片放到它所属的链表; 找不到就去更大的类找; 都没有就用 sbrk 向操作系统要更多堆内存, 从中分配 n 字节, 剩余部分作为一个空闲块放进相应的类. 释放: 合并后放进合并结果所属的链表.

优点: 吞吐量高, 按 2 的幂分类时只需检查对数个类, 而不是线性扫描; 利用率好, 在分离链表上做首次适配, 近似于在整个堆上做最佳适配 (同类块大小相近). 极端情况下每个大小一类, 就等于最佳适配. glibc 的 malloc 和 malloclab 推荐的实现都属于这一类.

Memory-Related Perils and Pitfalls — Dereferencing bad pointers · Reading uninitialized memory · Overwriting memory · Referencing nonexistent variables · Freeing blocks multiple times · Referencing freed blocks · Failing to free blocks

Dereferencing Bad Pointers — The classic scanf bug

int val;
...
scanf("%d", val);

/* inside scanf: */
case 'd': {
    int *valp = va_arg(ap, int *);
    *valp = (int)strtol(valbuf, &endp, 10);
    ...
}

Crash here … if you're lucky

Reading Uninitialized Memory — Assuming that heap data is initialized to zero

/* return y = Ax */
int *matvec(int **A, int *x) {
    int *y = malloc(N*sizeof(int));
    int i, j;

    for (i=0; i<N; i++)
        for (j=0; j<N; j++)
            y[i] += A[i][j]*x[j];
    return y;
}

Can avoid by using calloc

七类内存错误: 解引用坏指针、读未初始化的内存、覆盖内存、引用不存在的变量、多次释放、引用已释放的块、忘记释放.

  • 坏指针: scanf 要的是变量的地址, 写成 scanf("%d", val) 时, scanf 把 val 的值 (一个随意的整数) 当作地址往里写. 若这个值恰好不是合法地址就立刻崩溃, 这已经是「幸运」的结果; 若恰好是合法地址, 就悄悄改坏了别处的数据. 应写 &val.
  • 读未初始化内存: malloc 返回的内存内容是不确定的 (可能是以前用过的残留), 不一定是 0. matvec 中 y[i] += … 假设 y 初值为 0, 是错的. 改用 calloc (分配并清零), 或在循环前先写 y[i] = 0.

Overwriting Memory — Allocating the (possibly) wrong sized object

int **p;

p = malloc(N*sizeof(int));

for (i=0; i<N; i++) {
    p[i] = malloc(M*sizeof(int));
}

Can you spot the bug? · Off-by-one errors

p = malloc(N*sizeof(int *));

for (i=0; i<=N; i++) {
    p[i] = malloc(M*sizeof(int));
}

char *p;
p = malloc(strlen(s));
strcpy(p,s);

Not checking the max string size

char s[8];
int i;

gets(s); /* reads “123456789” from stdin */

Basis for classic buffer overflow attacks

Misunderstanding pointer arithmetic

int *search(int *p, int val) {

    while (p && *p != val)
        p += sizeof(int);

    return p;
}

覆盖内存的几种形式:

  • 分配的大小不对: p 是 int **, 数组元素是指针 (8 字节), 却按 sizeof(int) (4 字节) 分配, 循环写 p[i] 会越界. 应为 N*sizeof(int *).
  • 差一错误: i <= N 多写了一个元素 p[N]; malloc(strlen(s)) 少分配了结尾的 '\0' 的 1 字节, strcpy 会多写一个字节. 应为 strlen(s) + 1.
  • 不检查字符串长度: gets 读入 "123456789" 共 9 个字符加 '\0', 超出 s[8], 这就是缓冲区溢出攻击的基础 (见 CMU15213 06).
  • 误解指针运算: 对 int * 加 1 就已经前进 4 字节, 写 p += sizeof(int) 实际每次跳过 4 个 int. 应为 p++. (此外 while 条件 p && … 也不能防止越过数组末尾.)

Referencing a pointer instead of the object it points to

int *BinheapDelete(int **binheap, int *size) {
    int *packet;
    packet = binheap[0];
    binheap[0] = binheap[*size - 1];
    *size--;
    Heapify(binheap, *size, 0);
    return(packet);
}

What gets decremented? · (See next slide) · Same effect as · size--; · Rewrite as · (*size)--;

Referencing Nonexistent Variables — Forgetting that local variables disappear when a function returns

int *foo () {
    int val;

    return &val;
}

引用指针而非它指向的对象: *size-- 中后缀 -- 的优先级高于 *, 所以先把指针 size 减一 (指向别处), 再解引用但结果没用; 实际效果等于 size--, 堆的大小根本没减. 应写 (*size)--. 拿不准优先级时就加括号.

引用不存在的变量: 返回局部变量的地址. foo 返回后它的栈帧被释放, val 的空间会被之后的函数调用覆盖, 通过返回的指针读写就是未定义行为. gcc 对这种写法会警告 (-Wreturn-local-addr).

Freeing Blocks Multiple Times — Nasty!

x = malloc(N*sizeof(int));
    <manipulate x>
free(x);

y = malloc(M*sizeof(int));
    <manipulate y>
free(x);

Referencing Freed Blocks — Evil!

x = malloc(N*sizeof(int));
    <manipulate x>
free(x);
    ...
y = malloc(M*sizeof(int));
for (i=0; i<M; i++)
    y[i] = x[i]++;

Failing to Free Blocks (Memory Leaks) — Slow, long-term killer!

foo() {
    int *x = malloc(N*sizeof(int));
    ...
    return;
}

Freeing only part of a data structure

struct list {
    int val;
    struct list *next;
};

foo() {
    struct list *head = malloc(sizeof(struct list));
    head->val = 0;
    head->next = NULL;
    <create and manipulate the rest of the list>
    ...
    free(head);
    return;
}
  • 重复释放 (double free): x 已释放, 之后又 free(x). 此时 x 指向的块可能已被分配给 y (很可能就是同一块), 再次释放会破坏分配器的数据结构, 后果在很久以后才以奇怪的方式出现. 「恶心!」
  • 引用已释放的块 (use after free): 释放 x 后又读写 x[i], 而那块内存可能已经分给 y, 读到的是 y 的数据, 写入又改坏了 y. 「邪恶!」这也是常见的安全漏洞来源.
  • 内存泄漏: foo 分配后返回, 再也没有指针指向那块内存, 无法释放. 每次调用漏一块, 长期运行的程序 (服务器) 会慢慢耗尽内存, 是「慢性杀手».
  • 只释放了数据结构的一部分: 链表只 free(head), 其余节点全部泄漏. 应逐个释放所有节点.

课件中这几段代码依赖片段 (<manipulate x> 等), 外层的函数和花括号是在笔记中补出的.

Dealing With Memory Bugs — Debugger: gdb · Good for finding bad pointer dereferences · Hard to detect the other memory bugs · Data structure consistency checker · Runs silently, prints message only on error · Use as a probe to zero in on error · Binary translator: valgrind · Powerful debugging and analysis technique · Rewrites text section of executable object file · Checks each individual reference at runtime · Bad pointers, overwrites, refs outside of allocated block · glibc malloc contains checking code · setenv MALLOC_CHECK_ 3

对付内存错误的工具: gdb 适合找坏指针解引用 (程序在出错处崩溃, 看调用栈即可), 但很难发现其他几类; 数据结构一致性检查器 (malloclab 要求写的 heap checker), 平时静默运行, 发现不一致才打印, 可以插在不同位置逐步缩小出错范围; Valgrind 在运行时改写程序代码、检查每一次内存访问, 能发现坏指针、越界写、访问已分配块之外的内存、内存泄漏等; glibc 的 malloc 自带检查, 设置环境变量 MALLOC_CHECK_=3 即可启用 (课件写的是 csh 的 setenv 语法, bash 中写 export MALLOC_CHECK_=3). 另一个常用工具是编译器的 AddressSanitizer (gcc -fsanitize=address).
