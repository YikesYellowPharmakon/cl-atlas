Slide 8–9

Processes — Definition: A process is an instance of a running program. · One of the most profound ideas in computer science · Not the same as “program” or “processor” · Process provides each program with two key abstractions: · Private address space · Each program seems to have exclusive use of main memory. · Provided by kernel mechanism called virtual memory · Logical control flow · Each program seems to have exclusive use of the CPU · Provided by kernel mechanism called context switching

Control Flow — Processors do only one thing: · From startup to shutdown, each CPU core simply reads and executes a sequence of machine instructions, one at a time * · This sequence is the CPU's control flow (or flow of control) · (Physical control flow: <startup> inst1 inst2 inst3 … instn <shutdown>) · * many modern CPUs execute several instructions at once and/or out of program order, but this is invisible to the programmer

进程是运行中的程序的实例. 它给每个程序两个关键的抽象: ① 私有地址空间, 程序好像独占了内存, 由虚拟内存实现; ② 逻辑控制流, 程序好像独占了 CPU, 由上下文切换实现.

处理器只做一件事: 从开机到关机, 每个核按顺序读取并执行一条条机器指令, 这个序列就是控制流. (现代 CPU 实际上同时执行多条指令、乱序执行, 但对程序员不可见.)

Slide 10–15

Context Switching — Processes are managed by a shared chunk of memory-resident OS code called the kernel · Important: the kernel is not a separate process, but rather runs as part of some existing process. · Control flow passes from one process to another via a context switch

Context Switching (Uniprocessor) — Single processor executes multiple processes concurrently · Process executions interleaved (multitasking) · Address spaces managed by virtual memory system (like last week) · Register values for nonexecuting processes saved in memory · Save current registers in memory · Schedule next process for execution · Load saved registers and switch address space (context switch)

Context Switching (Multicore) — Multicore processors · Multiple CPUs on single chip · Share main memory (and some caches) · Each can execute a separate process · Scheduling of processors onto cores done by kernel

进程由内核管理: 内核是常驻内存的一段操作系统代码, 它不是一个单独的进程, 而是作为某个现有进程的一部分运行 (进程陷入内核态时执行内核代码). 控制流通过上下文切换从一个进程转到另一个.

单处理器: 多个进程的执行交错进行 (多任务); 各自的地址空间由虚拟内存管理; 没在运行的进程, 其寄存器值保存在内存中. 切换的步骤: 把当前寄存器存入内存; 调度选出下一个进程; 恢复它的寄存器并切换地址空间. 多核处理器: 多个核共享主存 (和部分缓存), 每个核可以运行一个进程, 由内核决定哪个进程在哪个核上运行.

Slide 16–18

User View of Concurrent Processes — Two processes run concurrently (are concurrent) if their execution overlaps in time · Otherwise, they are sequential · Appears as if concurrent processes run in parallel with each other · This means they can interfere with each other (more on that in a couple weeks) · (A and B concurrent · A and C concurrent · B and C sequential)

Traditional (Uniprocessor) Reality — Only one process runs at a time · A and B execution is interleaved, not truly concurrent · Similarly for A and C · Still possible for A and B / A and C to interfere with each other

How does the kernel take control? — The CPU executes instructions in sequence · We don't write “now run kernel code” in our programs… · Or do we?? · (Physical control flow: inst1 inst2 syscall → <kernel entry> insta instb instc … <kernel exit> → inst3 … instn)

两个进程的执行在时间上有重叠, 就说它们并发, 否则是顺序的. 例: A 与 B 并发, A 与 C 并发, B 与 C 顺序 (B 结束后 C 才开始). 并发的进程看起来像在并行运行, 因此可能相互干扰 (后面几讲讲). 在单处理器上, 同一时刻只有一个进程真正运行, 并发只是交错执行, 但仍可能相互干扰.

内核怎样获得控制权? 程序里不会写「现在运行内核代码」…… 其实会: syscall 指令就是程序主动进入内核. 另外还有中断等方式 (下一讲).

System Calls

Slide 20

System Calls — Whenever a program wants to cause an effect outside its own process, it must ask the kernel for help · Examples: · Read/write files · Get current time · Allocate RAM (sbrk) · Create new processes

// fopen.c
FILE *fopen(const char *fname,
            const char *mode) {
    int flags = mode2flags(mode);
    if (!flags) return NULL;
    int fd = open(fname, flags,
                  DEFPERMS);
    if (fd == -1) return NULL;
    return fdopen(fd, mode);
}
// open.S
.global open
open:
    mov  $SYS_open, %eax
    syscall
    cmp  $SYS_error_thresh, %rax
    ja   __syscall_error
    ret

系统调用: 程序想产生任何超出自身进程的效果 (读写文件、取当前时间、扩大堆、创建进程), 都必须请求内核. 例: C 库的 fopen 调用 open, open 是一小段汇编: 把系统调用号放进 %eax, 执行 syscall 指令陷入内核, 内核完成后返回; 返回值若在出错范围内就跳到错误处理 (设置 errno).

Slide 22–24

System Call Error Handling — Almost all system-level operations can fail · Only exception is the handful of functions that return void · You must explicitly check for failure · On error, most system-level functions return −1 and set global variable errno to indicate cause. · Example:

pid_t pid = fork();
if (pid == -1) {
    fprintf(stderr, "fork error: %s\n", strerror(errno));
    exit(1);
}

Error-reporting functions — Can simplify somewhat using an error-reporting function:

void unix_error(char *msg) /* Unix-style error */
{
    fprintf(stderr, "%s: %s\n", msg, strerror(errno));
    exit(1);
}

pid_t pid = fork();
if (pid == -1)
    unix_error("fork error");

Note: csapp.c exits with 0. · Not always appropriate to exit when something goes wrong.

Error-handling Wrappers — We simplify the code we present to you even further by using Stevens¹-style error-handling wrappers:

pid_t Fork(void)
{
    pid_t pid = fork();
    if (pid == -1)
        unix_error("Fork error");
    return pid;
}

pid = Fork(); // Only returns if successful

NOT what you generally want to do in a real application · ¹e.g., in “UNIX Network Programming: The sockets networking API“ W. Richard Stevens

几乎所有系统级操作都可能失败 (除了少数返回 void 的), 必须显式检查. 惯例: 出错时返回 −1, 并设置全局变量 errno 说明原因, strerror(errno) 把它变成可读的文字.

为了简化, 写一个报错函数 unix_error (打印信息后退出); 再进一步, 仿照 Stevens 的书写包装函数: 首字母大写的 Fork 内部调用 fork 并检查错误, 出错直接退出, 所以调用者拿到的一定是成功的结果. 课件和教材的代码都用这种写法 (定义在 csapp.c 中), 但真实应用里通常不该一出错就退出, 而要视情况处理. (课件附注: csapp.c 中的版本退出码是 0. 这里补出的 exit(1) 和 if 判断是课件版式中省略的部分.)

进程控制
Process Control

Slide 26–28

Obtaining Process IDs — pid_t getpid(void) · Returns PID of current process · pid_t getppid(void) · Returns PID of parent process

Process States — At any time, each process is either: · Running · Process is either executing instructions, or it could be executing instructions if there were enough CPU cores. · Blocked / Sleeping · Process cannot execute any more instructions until some external event happens (usually I/O). · Stopped · Process has been prevented from executing by user action (control-Z). · Terminated / Zombie · Process is finished. Parent process has not yet been notified.

Terminating Processes — Process becomes terminated for one of three reasons: · Receiving a signal whose default action is to terminate (next lecture) · Returning from the main routine · Calling the exit function · void exit(int status) · Terminates with an exit status of status · Convention: normal return status is 0, nonzero on error · Another way to explicitly set the exit status is to return an integer value from the main routine · exit is called once but never returns.

getpid 返回自己的 PID, getppid 返回父进程的 PID.

进程的四种状态: 运行 (正在执行, 或核够多的话可以执行); 阻塞/睡眠 (要等外部事件, 通常是 I/O, 才能继续); 停止 (被用户暂停, 如按 Ctrl-Z); 终止/僵尸 (已结束, 但父进程还没收到通知).

进程终止的三种原因: 收到默认动作为终止的信号 (下一讲); 从 main 返回; 调用 exit. exit(status) 以 status 为退出状态终止, 惯例是 0 表示正常, 非 0 表示出错; 从 main 返回一个整数也设置退出状态. exit 调用一次, 永不返回.

Slide 29–30

Creating Processes — Parent process creates a new running child process by calling fork · int fork(void) · Returns 0 to the child process, child's PID to parent process · Child is almost identical to parent: · Child get an identical (but separate) copy of the parent's virtual address space. · Child gets identical copies of the parent's open file descriptors · Child has a different PID than the parent · fork is interesting (and often confusing) because it is called once but returns twice

Conceptual View of fork — (parent Memory (Stack, Heap, Data, Code), Saved registers → child copy) · Make complete copy of execution state · Designate one as parent and one as child · Resume execution of parent or child · (Optimization: Use copy-on-write to avoid copying RAM)

fork: 父进程调用 fork 创建一个新的子进程. 它调用一次, 返回两次: 在子进程中返回 0, 在父进程中返回子进程的 PID. 子进程几乎和父进程一样: 得到父进程虚拟地址空间的一份相同但独立的副本 (之后各改各的), 得到父进程所有打开的文件描述符的副本, 只有 PID 不同.

概念上, fork 把整个执行状态 (内存和寄存器) 复制一份, 一个作父一个作子, 然后两者各自继续. 实际用上一讲的写时复制, 不真的复制内存. 课件写的返回类型 int fork(void) 是简化写法, 实际原型是 pid_t fork(void).

Slide 31–32

fork Example

int main(int argc, char** argv)
{
    pid_t pid;
    int x = 1;

    pid = Fork();
    if (pid == 0) {  /* Child */
        printf("child : x=%d\n", ++x);
        return 0;
    }

    /* Parent */
    printf("parent: x=%d\n", --x);
    return 0;
}
linux> ./fork        linux> ./fork        linux> ./fork        linux> ./fork
parent: x=0          child : x=2          parent: x=0          parent: x=0
child : x=2          parent: x=0          child : x=2          child : x=2
  • Call once, return twice
  • Concurrent execution · Can't predict execution order of parent and child
  • Duplicate but separate address space · x has a value of 1 when fork returns in parent and child · Subsequent changes to x are independent
  • Shared open files · stdout is the same in both parent and child

例子要点: ① 调用一次返回两次, 用返回值区分父子. ② 父子并发执行, 谁先打印无法预测, 多次运行可能得到不同顺序. ③ 地址空间是副本: fork 返回时两边的 x 都是 1, 之后子进程 ++x 得 2、父进程 --x 得 0, 互不影响. ④ 打开的文件共享: 两者的输出都出现在同一个终端 (stdout).

Slide 33–35

Modeling fork with Process Graphs — A process graph is a useful tool for capturing the partial ordering of statements in a concurrent program: · Each vertex is the execution of a statement · a -> b means a happens before b · Edges can be labeled with current value of variables · printf vertices can be labeled with output · Each graph begins with a vertex with no inedges · Any topological sort of the graph corresponds to a feasible total ordering. · Total ordering of vertices where all edges point from left to right

Interpreting Process Graphs — Original graph · Relabled graph: a (main) → b (fork) → c (printf) → d (exit), and b → e (printf) → f (exit) · Feasible total ordering: a b e c f d · Feasible or Infeasible? a b f c e d · Infeasible: not a topological sort

进程图描述并发程序中语句的偏序: 每个顶点是一条语句的执行, 边 a → b 表示 a 一定在 b 之前发生; 边上可以标变量的值, printf 顶点标输出. 图的任何一个拓扑排序 (排成一列, 使所有边都从左指向右) 都是一种可能的实际执行顺序.

例: 重新标号后父进程路径是 a → b → c → d, 子进程是 b → e → f. a b e c f d 是拓扑排序, 可行; a b f c e d 中 f 排在 e 前面, 违反了 e → f, 不可行.

Slide 36

fork Example: Two consecutive forks

void fork2()
{
    printf("L0\n");
    fork();
    printf("L1\n");
    fork();
    printf("Bye\n");
}

两次连续 fork: 打印 L0 后 fork 成 2 个进程, 各打印 L1, 再各 fork 一次成 4 个进程, 各打印 Bye. 共输出 1 个 L0、2 个 L1、4 个 Bye. 可行与否看拓扑排序: 「L0 Bye L1 …」不可行, 因为任何 Bye 之前都必须有一个 L1 (同一条路径上 L1 在 Bye 之前), 而这里第一个 Bye 出现在任何 L1 之前.

Slide 37–38

fork Example: Nested forks in parent

void fork4()
{
    printf("L0\n");
    if (fork() != 0) {
        printf("L1\n");
        if (fork() != 0) {
            printf("L2\n");
        }
    }
    printf("Bye\n");
}

fork Example: Nested forks in children

void fork5()
{
    printf("L0\n");
    if (fork() == 0) {
        printf("L1\n");
        if (fork() == 0) {
            printf("L2\n");
        }
    }
    printf("Bye\n");
}

fork4 (嵌套在父进程中): fork 返回非 0 的是父进程, 只有父进程继续打印 L1、再 fork、再打印 L2. 父进程路径: L0 → L1 → L2 → Bye; 两个子进程分别在两次 fork 后直接打印 Bye. 所以最后一个 Bye (父进程的) 必须在 L2 之后, 而 L2 之后至少还有这一个 Bye. 序列 L0 Bye L1 Bye Bye L2 以 L2 结尾, 父进程的 Bye 无处安放, 不可行; L0 L1 Bye Bye L2 Bye 可行.

fork5 (嵌套在子进程中): 返回 0 的子进程继续. 路径: 父 L0 → Bye; 子 L1 → (fork) → Bye; 孙 L2 → Bye. L2 之后必须还有一个 Bye (孙进程的). L0 Bye L1 Bye Bye L2 以 L2 结尾, 不可行; L0 Bye L1 L2 Bye Bye 可行.

Slide 39–41

Reaping Child Processes — Idea · When process terminates, it still consumes system resources · Examples: Exit status, various OS tables · Called a “zombie” · Living corpse, half alive and half dead · Reaping · Performed by parent on terminated child (using wait or waitpid) · Parent is given exit status information · Kernel then deletes zombie child process · What if parent doesn't reap? · If any parent terminates without reaping a child, then the orphaned child should be reaped by init process (pid == 1) · Unless it was init that terminated! Then need to reboot… · So, only need explicit reaping in long-running processes · e.g., shells and servers

void fork7() {
    if (fork() == 0) {
        /* Child */
        printf("Terminating Child, PID = %d\n", getpid());
        exit(0);
    } else {
        printf("Running Parent, PID = %d\n", getpid());
        while (1)
            ; /* Infinite loop */
    }
}

ps shows child process as “defunct” (i.e., a zombie) · Killing parent allows child to be reaped by init

回收子进程: 进程终止后仍占用一些系统资源 (退出状态、内核中的各种表项), 这时它叫僵尸进程, 「半死不活». 父进程用 wait 或 waitpid 回收它: 父进程拿到退出状态, 内核删除僵尸. 父进程没回收就自己终止的话, 孤儿子进程由 init 进程 (PID 1) 接管并回收. 所以只有长时间运行的进程 (shell、服务器) 才必须显式回收.

fork7: 子进程立即退出, 父进程死循环不回收, ps 显示子进程为 <defunct> (僵尸). 杀死父进程后, 子进程被 init 回收, 从列表中消失.

Slide 42–44

wait: Synchronizing with Children — Parent reaps a child with one of these system calls: · pid_t wait(int *status) · Suspends current process until one of its children terminates · Returns PID of child, records exit status in status · pid_t waitpid(pid_t pid, int *status, int options) · More flexible version of wait: · Can wait for a specific child or group of children · Can be told to return immediately if there are no children to reap

void fork9() {
    int child_status;

    if (fork() == 0) {
        printf("HC: hello from child\n");
        exit(0);
    } else {
        printf("HP: hello from parent\n");
        wait(&child_status);
        printf("CT: child has terminated\n");
    }
    printf("Bye\n");
}

Feasible output(s): HC HP CT Bye · HP HC CT Bye — Infeasible output: HP CT Bye HC

wait: Status codes — Return value of wait is the pid of the child process that terminated · If status != NULL, then the integer it points to will be set to a value that indicates the exit status · More information than the value passed to exit · Must be decoded, using macros defined in sys/wait.h · WIFEXITED, WEXITSTATUS, WIFSIGNALED, WTERMSIG, WIFSTOPPED, WSTOPSIG, WIFCONTINUED · See textbook for details

wait 挂起当前进程, 直到它的某个子进程终止, 返回该子进程的 PID 并把退出状态写进 *status. waitpid 更灵活: 可以等指定的子进程或一组子进程, 也可以设置成没有可回收的子进程时立即返回.

fork9: wait 在父进程中建立了一个先后关系: 子进程的 HC 一定在父进程的 CT 之前. 所以 HC 和 HP 谁先都可以, 但 CT 和 Bye 一定在 HC 之后; HP CT Bye HC 不可行.

status 里的信息比 exit 的参数多 (还包括是否被信号终止、是否被停止等), 要用 sys/wait.h 中的宏解码: WIFEXITED 判断是否正常退出, WEXITSTATUS 取出退出码, WIFSIGNALED/WTERMSIG 判断是否被信号终止及是哪个信号, 等等.

Slide 45–46

Another wait Example — If multiple children completed, will take in arbitrary order · Can use macros WIFEXITED and WEXITSTATUS to get information about exit status

void fork10() {
    pid_t pid[N];
    int i, child_status;

    for (i = 0; i < N; i++)
        if ((pid[i] = fork()) == 0) {
            exit(100+i); /* Child */
        }
    for (i = 0; i < N; i++) { /* Parent */
        pid_t wpid = wait(&child_status);
        if (WIFEXITED(child_status))
            printf("Child %d terminated with exit status %d\n",
                   wpid, WEXITSTATUS(child_status));
        else
            printf("Child %d terminate abnormally\n", wpid);
    }
}

waitpid: Waiting for a Specific Process — pid_t waitpid(pid_t pid, int *status, int options) · Suspends current process until specific process terminates · Various options (see textbook)

void fork11() {
    pid_t pid[N];
    int i;
    int child_status;

    for (i = 0; i < N; i++)
        if ((pid[i] = fork()) == 0)
            exit(100+i); /* Child */
    for (i = N-1; i >= 0; i--) {
        pid_t wpid = waitpid(pid[i], &child_status, 0);
        if (WIFEXITED(child_status))
            printf("Child %d terminated with exit status %d\n",
                   wpid, WEXITSTATUS(child_status));
        else
            printf("Child %d terminate abnormally\n", wpid);
    }
}

fork10: 创建 N 个子进程, 第 i 个以退出码 100 + i 退出; 父进程 wait N 次. 多个子进程都已结束时, wait 回收的顺序是任意的, 所以输出顺序不确定. fork11 改用 waitpid 按 PID 倒序逐个等待, 输出顺序就确定了 (最后创建的先报告). 课件第 46 页只给出了与 fork10 不同的几行, 这里按教材补全.

execve: Loading and Running Programs — int execve(char *filename, char *argv[], char *envp[]) · Loads and runs in the current process: · Executable file filename · Can be object file or script file beginning with #!interpreter (e.g., #!/bin/bash) · …with argument list argv · By convention argv[0]==filename · …and environment variable list envp · “name=value” strings (e.g., USER=droh) · getenv, putenv, printenv · Overwrites code, data, and stack · Retains PID, open files and signal context · Called once and never returns · …except if there is an error

if ((pid = Fork()) == 0) { /* Child runs program */
    if (execve(myargv[0], myargv, environ) < 0) {
        printf("%s: %s\n", myargv[0], strerror(errno));
        exit(1);
    }
}

execve 在当前进程中加载并运行一个新程序: filename 是可执行文件 (也可以是以 #! 开头的脚本, 由指定的解释器运行); argv 是参数列表, 惯例 argv[0] 是程序名; envp 是环境变量列表, 每项是 "名字=值" 的字符串. 它用新程序覆盖当前的代码、数据和栈, 但保留 PID、打开的文件和信号设置. 调用一次, 成功则永不返回 (原来的代码已不存在); 只有出错时才返回.

fork 和 execve 配合: 先 fork 出子进程, 子进程再 execve 新程序, 这就是 Unix 运行程序的标准方式. 例: 子进程运行 /bin/ls -lt /usr/include, 参数数组以 NULL 结尾, 环境变量直接传全局变量 environ (继承当前环境).

Simple Shell eval Function

void eval(char *cmdline)
{
    char *argv[MAXARGS]; /* Argument list execve() */
    char buf[MAXLINE];   /* Holds modified command line */
    int bg;              /* Should the job run in bg or fg? */
    pid_t pid;           /* Process id */

    strcpy(buf, cmdline);
    bg = parseline(buf, argv);
    if (argv[0] == NULL)
        return;   /* Ignore empty lines */

    if (!builtin_command(argv)) {
        if ((pid = Fork()) == 0) {   /* Child runs user job */
            if (execve(argv[0], argv, environ) < 0) {
                printf("%s: Command not found.\n", argv[0]);
                exit(0);   /* 课件此处被注释框遮住, 按教材补出 */
            }
        }

        /* Parent waits for foreground job to terminate */
        if (!bg) {
            int status;
            if (waitpid(pid, &status, 0) < 0)
                unix_error("waitfg: waitpid error");
        }
        else
            printf("%d %s", pid, cmdline);
    }
    return;
}

parseline will parse ‘buf’ into ‘argv’ and return whether or not input line ended in ‘&’

shell 的主循环: 打印提示符, 读一行 (遇到文件结束就退出), 交给 eval 求值, 如此反复, 「读—求值」循环.

eval 的步骤: parseline 把命令行拆成参数数组 argv, 并返回末尾是否有 & (是否后台运行); 空行直接忽略; 若是内置命令 (这里只有 quit) 就在 shell 自身中处理; 否则 fork 出子进程, 子进程 execve 运行 argv[0] 指定的程序 (失败时打印「找不到命令」并退出); 父进程若是前台作业就 waitpid 等它结束 (同时回收), 若是后台作业就打印 PID 和命令行后立即返回, 继续接受下一条命令.

Slide 65–67

Problem with Simple Shell Example — Shell designed to run indefinitely · Should not accumulate unneeded resources · Memory · Child processes · File descriptors · Our example shell correctly waits for and reaps foreground jobs · But what about background jobs? · Will become zombies when they terminate · Will never be reaped because shell (typically) will not terminate · Could run the entire computer out of memory · More likely, run out of PIDs

Summary — Processes · At any given time, system has multiple active processes · Only one can execute at a time on any single core · Each process appears to have total control of processor + private memory space

Summary (cont.) — Spawning processes · Call fork · One call, two returns · Process completion · Call exit · One call, no return · Reaping and waiting for processes · Call wait or waitpid · Loading and running programs · Call execve (or variant) · One call, (normally) no return

问题: shell 要一直运行, 不能积累无用的资源 (内存、子进程、文件描述符). 这个简单 shell 正确地回收了前台作业, 但后台作业结束后成为僵尸, 而 shell 一般不会退出, 它们永远得不到回收, 最终可能耗尽内存, 更可能先耗尽 PID. 解决办法要用到下一讲的信号 (子进程结束时内核给父进程发 SIGCHLD).

总结: 系统中同时有多个活动进程, 每个核同一时刻只执行一个, 每个进程都以为自己独占处理器和私有内存. 四个关键调用: fork 调用一次返回两次; exit 调用一次不返回; wait/waitpid 回收子进程; execve 调用一次 (正常情况下) 不返回.
