#include <stdio.h>

int main(void) {
    FILE *fp = fopen("output.txt", "w");
    if (!fp) {
        perror("output.txt");
        return 1;
    }
    fputs("baby shark (do doo dooo)\n", fp);
    if (fclose(fp)) {
        perror("output.txt");
        return 1;
    }
    return 0;
}
FILE *fopen(const char *fname,
            const char *mode) {
    int fd = open(fname,
                  __mode2flags(mode),
                  DEFFILEPERMS);
    if (fd == -1) {
        return NULL;
    }
    return fdopen(fd, mode);
}

int fputs(const char *s, FILE *fp) {
    size_t n = strlen(s);
    while (n > 0) {
        ssize_t written =
            write(fp->fd, s, n);
        if (written < 0) return EOF;
        n -= written;
        s += written;
    }
    return 0;
}

int fclose(FILE *fp) {
    int rv = close(fp->fd);
    __ffree(fp);
    return rv;
}
.globl close
close:
    mov  $3, %eax
    syscall
    cmp  $-4096, %rax
    jae  __syscall_error
    ret

系统级 I/O 位于标准 I/O 之下. 左边是普通的 C 程序, 用 stdio 的 fopen、fputs、fclose 写文件; 它们各自是对系统调用的包装 (这里是简化示意): fopen 调用 open 得到文件描述符, 再用 fdopen 包成 FILE 结构; fputs 循环调用 write, 直到写完 (write 可能只写了一部分); fclose 调用 close 并释放 FILE. 最底层的 close 是一小段汇编: 系统调用号 3 放进 %eax, 执行 syscall.

幻灯片小错: 标题页日期 "18th Lecture, November 6, 2025" 是秋季学期的, 与 2026 年春季不符.

前后不一致: 这里的出错判断写成 cmp $-4096, %rax; jae, 即把 −4096 到 −1 都当作错误; 上一讲 __open 的反汇编是 cmp $0xfffffffffffff001, %rax, 即 −4095. Linux 的错误码范围是 −4095 到 −1, glibc 用的是 −4095. 差一个数在实际中不会出问题 (errno 没有 4096), 但两讲写法不一致.

Why do we have two sets?

You can write your own set of high-level convenient functions if you want! · (Standard I/O:) Less control · More convenience · Not safe in signal handlers · Not safe with network connections · (Unix I/O:) Maximum control · Minimum convenience · Can be used from signal handlers · Can be used for network connections

为什么有两套 (其实是三套) I/O? 中间是内核提供的 Unix I/O: open、read、write、lseek、close、stat. 左边的标准 I/O (C 库) 和右边本课提供的 RIO 包都建立在它之上. 标准 I/O 方便但控制少, 不能在信号处理程序里用, 也不适合网络连接; Unix I/O 控制最多但最不方便, 可以在信号处理程序里用, 也适合网络. 你也可以在 Unix I/O 上写自己的高层函数.

Unix I/O Overview — A file is a sequence of bytes: · B0 , B1 , .... , Bk , .... , Bm-1 · Cool fact: All I/O devices are represented as files: · /dev/sda2 (disk partition) · /dev/tty2 (terminal) · /dev/null (discard all writes / read empty file) · Cool fact: Kernel data structures are exposed as files · cat /proc/$$/status · ls -l /proc/$$/fd/ · ls –RC /sys/devices | less

Kernel offers a set of basic operations for all files · Opening and closing files · open() and close() · Reading and writing a file · read() and write() · Look up information about a file (size, type, last modification time, …) · stat(), lstat(), fstat() · Changing the current file position (seek) · indicates next offset into file to read or write · lseek() · (B0 B1 • • • Bk-1 Bk Bk+1 • • • — Current file position = k (in between bytes k-1 and k))

Unix 中一个文件就是一个字节序列. 有两个巧妙之处: 所有 I/O 设备都表示为文件 (磁盘分区 /dev/sda2、终端 /dev/tty2、丢弃一切写入的 /dev/null); 内核的数据结构也以文件形式暴露 (/proc/$$/status 是当前 shell 进程的状态, $$ 是 shell 的 PID; /proc/$$/fd/ 列出它打开的描述符; /sys/devices 是设备树). 于是同一组操作能用于一切.

内核为所有文件提供的基本操作: 打开和关闭 (open、close), 读和写 (read、write), 查询文件信息 (stat、lstat、fstat), 改变当前文件位置 (lseek). 文件位置 k 指向下一次读写的偏移, 位于第 k−1 和第 k 个字节之间.

Slide 8–9

File Types — Each file has a type indicating its role in the system · Regular file: Stores arbitrary data · Directory: Index for a related group of files · Socket: For communicating with a process on another machine · Other file types beyond our scope · Named pipes (FIFOs) · Symbolic links · Character and block devices

Regular Files — A regular file contains arbitrary data · Applications often distinguish between text and binary files · Text files contain human-readable text · Binary files are everything else (object files, JPEG images, …) · Kernel doesn't care! It's all just bytes! · Text file is sequence of text lines · Text line is sequence of characters terminated (not separated!) by end of line indicator · Characters are defined by a text encoding (ASCII, UTF-8, EUC-JP, …) · End of line (EOL) indicators: · All “Unix”: Single byte 0x0A · line feed (LF) · DOS, Windows: Two bytes 0x0D 0x0A · Carriage return (CR) followed by line feed (LF) · Also used by many Internet protocols · C library translates to '\n'

文件类型: 普通文件 (任意数据)、目录 (一组相关文件的索引)、套接字 (与另一台机器上的进程通信). 本课不讲的还有命名管道、符号链接、字符设备和块设备.

普通文件: 应用程序区分文本文件 (人能读的文本) 和二进制文件 (其他一切, 如目标文件、JPEG), 但内核不在乎, 全都只是字节. 文本文件是一串文本行, 每行以行尾符结束 (不是分隔! 所以最后一行后面也应有行尾符). 行尾符: Unix 用一个字节 0x0A (换行 LF); DOS/Windows 和很多互联网协议 (如 HTTP) 用两个字节 0x0D 0x0A (回车 CR + 换行 LF). C 库在 Windows 上会把它转换成 '\n'.

Directories — Directory consists of an array of entries (also called links) · Each entry maps a filename to a file · Each directory contains at least two entries · . Directory Hierarchy — All files are organized as a hierarchy anchored by root directory named / (slash) · (/ → bin/ (bash), dev/ (tty1), etc/ (group, passwd), home/ (droh/ (hello.c), bryant/), usr/ (include/ (stdio.h, sys/ (unistd.h)), bin/ (vim))) · Kernel maintains current working directory (cwd) for each process · Modified using the cd command

目录是一组条目 (也叫链接), 每个条目把一个文件名映射到一个文件. 每个目录至少有两个条目: . 指自己, .. 指父目录. 所有文件组成以根目录 / 为根的层次结构; 内核为每个进程维护一个当前工作目录, 用 cd 改变. 绝对路径以 / 开头, 从根开始; 相对路径从当前工作目录开始. 例: 当前目录是 /home/bryant 时, ../droh/hello.c 就是 /home/droh/hello.c.

Slide 13–14

Opening Files — Opening a file informs the kernel that you are getting ready to access that file

int fd;   /* file descriptor */

if ((fd = open("/etc/hosts", O_RDONLY)) < 0) {
    perror("open");
    exit(1);
}

Returns a small identifying integer file descriptor · fd == -1 indicates that an error occurred · Each process begins life with three open files · 0: standard input (stdin) · 1: standard output (stdout) · 2: standard error (stderr) · These could be files, pipes, your terminal, or even a network connection!

Lots of ways to call open — Open an existing file: open(path, flags) · flags must include exactly one of: · O_RDONLY Only want to read from file · O_WRONLY Only want to write to file · O_RDWR Want to do both · Flags may also include (use | to combine) · O_APPEND All writes go to the very end · O_TRUNC Delete existing contents if any · O_CLOEXEC Close this file if execve() is called · Open or create a file: open(path, flags, mode) · flags must include O_CREAT Create the file if it doesn't exist · and exactly one of: · O_WRONLY Only want to write to file · O_RDWR Want to write and read · and maybe also some of: · O_EXCL Fail if file does exist · O_APPEND · O_TRUNC · O_CLOEXEC · (and many more… consult the open() manpage)

打开文件是告诉内核「我要访问这个文件了». open 返回一个小整数, 叫文件描述符, 之后的操作都用它指代这个文件; 返回 −1 表示出错. 每个进程一开始就有三个打开的文件: 0 标准输入、1 标准输出、2 标准错误; 它们可以是文件、管道、终端, 甚至网络连接.

open 的两种用法. 打开已有文件: flags 必须恰好包含 O_RDONLY、O_WRONLY、O_RDWR 之一, 可以用 | 组合 O_APPEND (所有写入都追加到末尾)、O_TRUNC (清空原内容)、O_CLOEXEC (execve 时自动关闭). 打开或创建: flags 必须含 O_CREAT, 再加 O_WRONLY 或 O_RDWR 之一 (只读地创建文件没有意义), 可选 O_EXCL (文件已存在就失败, 常用来防止两个进程同时创建同一个文件) 等, 并要给第三个参数 mode.

Slide 15–16

The third argument to open — Yes, open takes either two or three arguments · Bet you thought you couldn't do that in C · Look through /usr/include/fcntl.h and try to figure out how it's done · Third argument must be present when O_CREAT appears in second argument; ignored otherwise · Third argument (mode) gives default access permissions for newly created files · Modified by umask setting (see man umask) · Use DEFFILEMODE (from sys/stat.h) unless you have a specific reason to want something else · More explanation: · https://linuxfoundation.org/blog/classic-sysadmin-understanding-linux-file-permissions/ · https://linuxcommand.org/lc3_lts0090.php · https://devconnected.com/linux-file-permissions-complete-guide/

Closing Files — Closing a file informs the kernel that you are finished accessing that file

if (close(fd) < 0) {
    fprintf(stderr, "%s: write error: %s",
            filename, strerror(errno));
    exit(1);
}

Take care not to close any file more than once · Same as not calling free() twice on the same pointer · Closing a file can fail! · Well, not exactly fail—the file is still closed · The OS is taking this opportunity to report a delayed error from a previous write operation · You might silently lose data if you don't check!

open 可以有两个或三个参数: 它在 fcntl.h 中声明为可变参数函数 int open(const char *path, int flags, ...), 和 printf 一样. 第三个参数只在有 O_CREAT 时才需要, 给出新文件的访问权限, 实际权限还要被进程的 umask 屏蔽掉一部分 (mode & ~umask). 没有特殊理由就用 DEFFILEMODE (0666, 即所有人可读写, 再经 umask 022 变成 0644).

关闭文件: 不要关闭两次, 和不要 free 两次一个道理 (描述符号可能已经被别的 open 重用了). close 也可能「失败»: 文件其实已经关了, 但操作系统借这个机会报告之前某次 write 延迟发生的错误 (例如网络文件系统写入失败、磁盘满), 不检查就可能悄悄丢数据. 所以示例的出错信息写的是 "write error".

Slide 17–18

Reading Files — Reading a file copies bytes from the current file position to memory, and then updates file position

char buf[512];
int fd;       /* file descriptor */
int nbytes;   /* number of bytes read */

/* Open file fd ...  */
/* Then read up to 512 bytes from file fd */
if ((nbytes = read(fd, buf, sizeof(buf))) < 0) {
    perror("read");
    exit(1);
}

Returns number of bytes read from file fd into buf · Return type ssize_t is signed integer · nbytes < 0 indicates that an error occurred · Short counts (nbytes < sizeof(buf)) are possible and are not errors!

Writing Files — Writing a file copies bytes from memory to the current file position, and then updates current file position

char buf[512];
int fd;       /* file descriptor */
int nbytes;   /* number of bytes written */

/* Open the file fd ... */
/* Then write up to 512 bytes from buf to file fd */
if ((nbytes = write(fd, buf, sizeof(buf)) < 0) {
    perror("write");
    exit(1);
}

Returns number of bytes written from buf to file fd · As with reads, short counts are possible and are not errors!

read 从当前文件位置把字节复制到内存, 然后推进文件位置; write 反过来, 从内存复制到文件的当前位置. 返回实际传送的字节数, 类型 ssize_t 是有符号的 (size_t 无符号), 这样才能用 −1 表示出错. 实际传送的字节数可能少于请求的数, 叫不足值 (short count), 这不是错误, 程序必须处理.

幻灯片错误 (括号位置): 第 18 页 if ((nbytes = write(fd, buf, sizeof(buf)) < 0) 少了一个右括号的位置: < 的优先级高于 =, 实际执行的是 nbytes = (write(…) < 0), nbytes 得到的是比较结果 0 或 1, 而不是写入的字节数 (出错判断碰巧仍然正确). 应与第 17 页一致写成 if ((nbytes = write(fd, buf, sizeof(buf))) < 0). 这个笔误在教材的配套幻灯片中沿用多年.

Simple Unix I/O example — Copying stdin to stdout, one byte at a time

#include <unistd.h>

int main(void) {
    char c;
    while(read(STDIN_FILENO, &c, 1) != 0)

}

Always check return codes from system calls!

#include <stdio.h>
#include <unistd.h>

int main(void) {
    char c;

        ssize_t nread = read(STDIN_FILENO, &c, 1);
        if (nread == 0) {
            return 0;
        } else if (nread < 0) {
            perror("stdin");

“Stevens wrappers” make things shorter… but they don't let you recover from errors

例: 逐字节把标准输入复制到标准输出. 第一版没有检查错误: 若 read 出错返回 −1, != 0 成立, 会把未初始化的 c 写出去并无限循环. 第二版完整检查: read 返回 0 是文件结束, 正常退出; 返回负数是出错; write 写不满 1 个字节也算出错. 第三版用 Stevens 风格的包装函数 Read、Write (出错时打印信息并退出), 代码短, 但不能从错误中恢复.

Slide 22

On Short Counts — Short counts can occur in these situations: · Encountering (end-of-file) EOF on reads · Reading text lines from a terminal · Reading and writing network sockets, pipes, etc. · Short counts never occur in these situations: · Reading from disk files (except for EOF) · Writing to disk files · Best practice is to always allow for short counts.

不足值出现的情形: 读到文件末尾; 从终端读一行文本 (read 只返回当前这一行); 读写网络套接字、管道 (数据分批到达, 内核缓冲区有限). 不会出现的情形: 读磁盘文件 (除了到达文件末尾)、写磁盘文件. 最佳实践是总是考虑不足值, 这样同一段代码换成网络连接也不会出错. 本课的 RIO 包 (见附录幻灯片) 就是为此写的.

Slide 24–25

Standard I/O Functions — The C standard library (libc.so) contains a collection of higher-level standard I/O functions · Documented in Appendix B of K&R · Examples of standard I/O functions: · Opening and closing files (fopen and fclose) · Reading and writing bytes (fread and fwrite) · Reading and writing text lines (fgets and fputs) · Formatted reading and writing (fscanf and fprintf)

Standard I/O Streams — Standard I/O models open files as streams · Abstraction for a file descriptor and a buffer in memory · C programs begin life with three open streams (defined in stdio.h) · stdin (standard input) · stdout (standard output) · stderr (standard error)

#include <stdio.h>
extern FILE *stdin;  /* standard input  (descriptor 0) */
extern FILE *stdout; /* standard output (descriptor 1) */
extern FILE *stderr; /* standard error  (descriptor 2) */

int main() {
    fprintf(stdout, "Hello, world\n");
}

C 标准库 (libc.so) 提供一组较高层的标准 I/O 函数 (K&R 附录 B): 打开关闭 fopen/fclose, 按字节读写 fread/fwrite, 按行读写 fgets/fputs, 格式化读写 fscanf/fprintf.

标准 I/O 把打开的文件看作流: 一个文件描述符加上内存里的一块缓冲区, 类型是 FILE *. C 程序启动时已有三个流 stdin、stdout、stderr, 分别对应描述符 0、1、2.

Slide 26–28

Buffered I/O: Motivation — Applications often read/write one character at a time · getc, putc, ungetc · gets, fgets · Read line of text one character at a time, stopping at newline · Implementing as Unix I/O calls is expensive · read and write require Unix kernel calls · > 10,000 clock cycles · Solution: Buffered read · Use Unix read to grab block of bytes · User input functions take one byte at a time from buffer · Refill buffer when empty · (Buffer: already read | unread)

Buffering in Standard I/O — Standard I/O functions use buffered I/O

printf("h");
printf("e");
printf("l");
printf("l");
printf("o");
printf("\n");      /* buf: h e l l o \n */
fflush(stdout);    /* → write(1, buf, 6); */

Buffer flushed to output fd on “\n”, call to fflush or exit, or return from main.

Standard I/O Buffering in Action — You can see this buffering in action for yourself, using the always fascinating Linux strace program:

#include <stdio.h>

int main()
{
    printf("h");
    printf("e");
    printf("l");
    printf("l");
    printf("o");
    printf("\n");
    fflush(stdout);
    exit(0);
}
linux> strace ./hello
execve("./hello", ["hello"], [/* ... */]).
...
write(1, "hello\n", 6)               = 6
...
exit_group(0)                        = ?

缓冲的动机: 程序常常一次读写一个字符 (getc、putc、fgets 逐字符读一行), 若每次都直接 read/write 就要陷入内核, 代价很高. 解决办法: 用 read 一次读一大块到缓冲区, 用户函数每次从缓冲区取一个字节, 取空了再填. 写也一样: 6 次 printf 只是把字符放进缓冲区, 遇到 "\n" (终端输出时)、调用 fflush 或 exit、从 main 返回时, 才一次性 write 出去. 用 strace (跟踪系统调用) 可以看到, 只有一次 write(1, "hello\n", 6).

细节: stdout 连接终端时是行缓冲 (遇换行就刷新); 重定向到文件时是全缓冲 (缓冲区满才刷新); stderr 不缓冲. 所以 fork 前没有刷新的输出可能被父子进程各输出一次.

数字过时: "> 10,000 clock cycles" 是教材沿用的旧数据. 现代 x86-64 Linux 上一次简单系统调用 (syscall 进出内核) 的开销大约是一百到几百个周期, 加上内核漏洞缓解措施后通常在一千个周期左右, 远不到一万. 结论不变: 系统调用仍比普通函数调用贵得多, 值得缓冲.

何时用哪种 I/O
Which I/O when

Slide 31–32

Pros and Cons of Unix I/O — Pros · Unix I/O is the most general form of I/O · All other I/O packages are implemented using Unix I/O functions · Unix I/O provides functions for accessing file metadata · Unix I/O functions are async-signal-safe and can be used safely in signal handlers · Cons · Dealing with short counts is tricky and error prone · Efficient reading of text lines requires some form of buffering, also tricky and error prone

Pros and Cons of Standard I/O — Pros: · Buffering increases efficiency by decreasing the number of read and write system calls · Short counts are handled automatically · Cons: · Provides no function for accessing file metadata · Standard I/O functions are not async-signal-safe, and not appropriate for signal handlers · Standard I/O is not appropriate for input and output on network sockets · There are poorly documented restrictions on streams that interact badly with restrictions on sockets (CS:APP3e, Sec 10.11)

Unix I/O 的优点: 最通用, 其他 I/O 包都建立在它之上; 能访问文件元数据; 异步信号安全, 可以在信号处理程序中用. 缺点: 处理不足值麻烦易错; 高效地按行读需要自己做缓冲, 也麻烦易错.

标准 I/O 的优点: 有缓冲, 减少系统调用次数; 自动处理不足值. 缺点: 不能访问元数据; 不是异步信号安全的; 不适合网络套接字 (流的限制和套接字的限制互相冲突: 同一个流上输入后接输出, 中间必须插入 fflush 或 fseek 等, 而套接字不能 fseek, 见教材 10.11).

Slide 33–34

Choosing I/O Functions — General rule: use the highest-level I/O functions you can · Many C programmers are able to do all of their work using the standard I/O functions · But, be sure to understand the functions you use! · When to use standard I/O · When working with “ordinary” files · When to use raw Unix I/O · Inside signal handlers, because Unix I/O is async-signal-safe · When you are reading and writing network sockets · Libraries dedicated to buffered network I/O make this easier · CS:APP rio_* functions; libevent, libuv, … · In rare cases when you need absolute highest performance

Aside: Working with Binary Files — Functions you should never use on binary files · Text-oriented I/O: such as fgets, scanf, rio_readlineb · Interpret EOL characters. · Use functions like rio_readn or rio_readnb instead · String functions · strlen, strcpy, strcat · Interprets byte value 0 (end of string) as special

选择原则: 尽量用最高层的 I/O 函数, 但要理解它们. 普通文件用标准 I/O; 信号处理程序里、读写网络套接字 (可借助专门的缓冲网络 I/O 库, 如本课的 rio_*、libevent、libuv)、极少数追求极致性能时, 用 Unix I/O.

处理二进制文件时绝不要用: 面向文本的函数 (fgets、scanf、rio_readlineb), 它们会把 0x0A 字节当作行尾; 字符串函数 (strlen、strcpy、strcat), 它们把字节 0 当作字符串结束. 二进制数据里这两个字节随时可能出现.

Slide 37–38

How the Unix Kernel Represents Open Files — Two descriptors referencing two distinct open files. Descriptor 1 (stdout) points to terminal, and descriptor 4 points to open disk file

File pos is maintained per open file

File Sharing — Two distinct descriptors sharing the same disk file through two distinct open file table entries · E.g., Calling open twice with the same filename argument

Different logical but same physical file

内核用三张表表示打开的文件. ① 描述符表: 每个进程一张, 以描述符为下标, 每项指向打开文件表中的一项. ② 打开文件表: 所有进程共享, 每项代表一次「打开», 记录当前文件位置和引用计数 refcnt (有多少个描述符指向它); refcnt 降到 0 时内核才删除这一项. ③ v-node 表: 所有进程共享, 每项代表一个文件本身, 含 stat 中的信息 (访问权限、大小、类型).

对同一个文件名调用两次 open, 得到两个描述符、两个打开文件表项 (各有自己的文件位置), 指向同一个 v-node: 逻辑上是两个文件, 物理上是一个. 两边各读各的, 互不影响位置.

Slide 39–40

How Processes Share Files: fork — A child process inherits its parent's open files · Note: situation unchanged by exec functions (use fcntl to change) · Before fork call: (as on slide 37) · After fork: · Child's table same as parent's, and +1 to each refcnt

File is shared between processes

子进程继承父进程打开的文件: fork 复制描述符表, 子进程的每个描述符指向与父进程相同的打开文件表项, 每项 refcnt 加 1. 因为共享同一个表项, 父子进程共享文件位置: 一方读了, 另一方的位置也跟着前进. execve 不改变这一点 (除非描述符设置了 close-on-exec, 可用 fcntl 或 O_CLOEXEC 设置). 这也解释了为什么父子进程能同时向同一个终端输出.

Slide 41–43

I/O Redirection — Question: How does a shell implement I/O redirection? · linux> ls > foo.txt · Answer: By calling the dup2(oldfd, newfd) function · Copies (per-process) descriptor table entry oldfd to entry newfd

I/O Redirection Example — Step #1: open file to which stdout should be redirected · Happens in child executing shell code, before exec · (descriptor 1 → File A; descriptor 4 → File B)

Step #2: call dup2(4,1) · cause fd=1 (stdout) to refer to disk file pointed at by fd=4

Two descriptors point to the same file

shell 怎样实现 ls > foo.txt? 用 dup2(oldfd, newfd): 把描述符表项 oldfd 复制到 newfd (若 newfd 原来已打开, 先把它关闭). 步骤: shell fork 出子进程; 子进程 open foo.txt 得到 fd 4; dup2(4, 1) 让标准输出也指向 foo.txt (原来的终端项 refcnt 减为 0, 被删除; 新项 refcnt 为 2); 然后 execve ls. ls 照常往 fd 1 写, 内容就进了文件, ls 完全不知道自己被重定向了. 注意参数顺序: dup2(4,1) 是「让 1 变成 4」.

Slide 44–45

Warm-Up: I/O and Redirection Example

#include "csapp.h"
int main(int argc, char *argv[])
{
    int fd1, fd2, fd3;
    char c1, c2, c3;
    char *fname = argv[1];
    fd1 = open(fname, O_RDONLY, 0);
    fd2 = open(fname, O_RDONLY, 0);
    fd3 = open(fname, O_RDONLY, 0);
    dup2(fd2, fd3);
    read(fd1, &c1, 1);
    read(fd2, &c2, 1);
    read(fd3, &c3, 1);
    printf("c1 = %c, c2 = %c, c3 = %c\n", c1, c2, c3);
    return 0;
}

What would this program print for file containing “abcde”? · c1 = a, c2 = a, c3 = b

三次 open 得到三个独立的打开文件表项. dup2(fd2, fd3) 让 fd3 指向 fd2 的表项, 两者共享文件位置. fd1 自己的位置从 0 开始, 读到 a; fd2 从 0 开始读到 a, 位置变成 1; fd3 和 fd2 共享位置, 从 1 读到 b. 输出 c1 = a, c2 = a, c3 = b.

Slide 46–47

Master Class: Process Control and I/O

#include "csapp.h"
int main(int argc, char *argv[])
{
    int fd1;
    int s = getpid() & 0x1;
    char c1, c2;
    char *fname = argv[1];
    fd1 = open(fname, O_RDONLY, 0);
    read(fd1, &c1, 1);
    if (fork()) { /* Parent */
        sleep(s);
        read(fd1, &c2, 1);
        printf("Parent: c1 = %c, c2 = %c\n", c1, c2);
    } else { /* Child */
        sleep(1-s);
        read(fd1, &c2, 1);
        printf("Child: c1 = %c, c2 = %c\n", c1, c2);
    }
    return 0;
}

What would this program print for file containing “abcde”? · Child: c1 = a, c2 = b · Parent: c1 = a, c2 = c — or — Parent: c1 = a, c2 = b · Child: c1 = a, c2 = c

fork 前父进程读了一个字节 a, 位置为 1; fork 后父子共享同一个打开文件表项, 也就共享位置. s 由父进程 PID 的奇偶决定: s = 0 时父进程不睡, 先读到 b, 子进程睡 1 秒后读到 c; s = 1 时反过来. 两者的 c1 都是 fork 前读到的 a (c1 在复制的地址空间里). 所以两种可能的输出: 先睡醒的一方 (先读的) 得 b, 另一方得 c. 若是父子各自 open 同一文件, 就不会共享位置.

The RIO Package (213/CS:APP Package) — RIO is a set of wrappers that provide efficient and robust I/O in apps, such as network programs that are subject to short counts · RIO provides two different kinds of functions · Unbuffered input and output of binary data · rio_readn and rio_writen · Buffered input of text lines and binary data · rio_readlineb and rio_readnb · Buffered RIO routines are thread-safe and can be interleaved arbitrarily on the same descriptor · Download from http://csapp.cs.cmu.edu/3e/code.html · src/csapp.c and include/csapp.h

Unbuffered RIO Input and Output — Same interface as Unix read and write · Especially useful for transferring data on network sockets

#include "csapp.h"

ssize_t rio_readn(int fd, void *usrbuf, size_t n);
ssize_t rio_writen(int fd, void *usrbuf, size_t n);

/* Return: num. bytes transferred if OK, 0 on EOF (rio_readn only), -1 on error */

rio_readn returns short count only if it encounters EOF · Only use it when you know how many bytes to read · rio_writen never returns a short count · Calls to rio_readn and rio_writen can be interleaved arbitrarily on the same descriptor

附录幻灯片: RIO (Robust I/O) 是本课提供的一组包装函数, 为容易出现不足值的程序 (如网络程序) 提供高效、稳健的 I/O. 两类: 无缓冲的二进制输入输出 rio_readn、rio_writen; 带缓冲的文本行和二进制输入 rio_readlineb、rio_readnb. 带缓冲的函数是线程安全的, 可以在同一个描述符上任意交替调用. 源码在 csapp.c / csapp.h.

rio_readn 与 read 接口相同, 但内部循环调用 read, 直到读满 n 字节, 只有遇到文件末尾才返回不足值, 所以只在知道要读多少字节时用. rio_writen 循环直到写完, 从不返回不足值. 两者可以在同一描述符上任意交替调用.

Buffered RIO Input Functions — Efficiently read text lines and binary data from a file partially cached in an internal memory buffer

rio_readlineb reads a text line of up to maxlen bytes from file fd and stores the line in usrbuf · Especially useful for reading text lines from network sockets · Stopping conditions · maxlen bytes read · EOF encountered · Newline (‘\n’) encountered

rio_readnb reads up to n bytes from file fd · Stopping conditions · maxlen bytes read · EOF encountered · Calls to rio_readlineb and rio_readnb can be interleaved arbitrarily on the same descriptor · Warning: Don't interleave with calls to rio_readn

带缓冲的 RIO: 先用 rio_readinitb 把描述符和一个 rio_t 缓冲区关联起来. rio_readlineb 读一行文本 (最多 maxlen − 1 个字节, 末尾补 '\0'), 遇到读满、文件末尾或换行就停, 特别适合从网络套接字读文本行 (如 HTTP 请求头). rio_readnb 最多读 n 字节. 这两个带缓冲的函数可以交替调用, 但不要与无缓冲的 rio_readn 交替: 缓冲区里已经预读的数据, rio_readn 看不到, 会错位.
