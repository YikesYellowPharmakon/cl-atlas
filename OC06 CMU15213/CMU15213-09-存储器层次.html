Slide 11–17

Modern Connection between CPU and Memory — A bus is a collection of parallel wires that carry address, data, and control signals. · Buses are typically shared by multiple devices. (CPU chip: Register file, ALU, Memory Controller — Memory bus — Main memory)

Memory Read Transaction (Load operation: movq A, %rax) — (1) CPU places address A on the memory bus. (2) Main memory reads A from the memory bus, retrieves word x, and places it on the bus. (3) CPU reads word x from the bus and copies it into register %rax.

Memory Write Transaction (Store operation: movq %rax, A) — (1) CPU places address A on bus. Main memory reads it and waits for the corresponding data word to arrive. (2) CPU places data word y on the bus. (3) Main memory reads data word y from the bus and stores it at address A.

bus 总线: 一组并行导线, 传送地址、数据和控制信号, 通常由多个设备共享. CPU 芯片上的内存控制器通过内存总线连到主存.

读事务 (load) 三步: CPU 把地址 A 放上总线; 主存读到 A, 取出字 x 放上总线; CPU 从总线读回 x 存进 %rax. 写事务 (store) 三步: CPU 放地址 A, 主存等待数据; CPU 放数据 y; 主存把 y 存到 A. 每次访问都要经过这样的往返, 这就是访问主存要几十纳秒的原因之一.

Random-Access Memory (RAM) — Key features · RAM is traditionally packaged as a chip. · or embedded as part of processor chip · Basic storage unit is normally a cell (one bit per cell). · Multiple RAM chips form a memory. · RAM comes in two varieties: SRAM (Static RAM) · DRAM (Dynamic RAM)

EDC: Error detection and correction · Trends · SRAM scales with semiconductor technology · Reaching its limits · DRAM scaling limited by need for minimum capacitance · Aspect ratio limits how deep can make capacitor · Also reaching its limits

RAM: 基本单元是存储一位的单元 (cell), 多个芯片组成内存. 两种:

  • SRAM 静态 RAM: 每位 6 (或 8) 个晶体管, 只要通电就一直保持状态, 快 (约为 DRAM 的 10 倍), 贵 (约 100 倍), 用作缓存.
  • DRAM 动态 RAM: 每位 1 个晶体管 + 1 个电容 (电容竖直放置以节省面积). 电容会漏电, 必须周期性刷新; 更容易受干扰, 需要检错纠错 (EDC). 用作主存和帧缓冲.

趋势: SRAM 随半导体工艺缩小, 但已接近极限; DRAM 的电容需要最小电容量, 缩小受限于电容能做多深, 也接近极限.

为什么 DRAM 要刷新: 电容存储的电荷会通过漏电慢慢流失, 几十毫秒后就无法区分 0 和 1. 内存控制器因此每隔约 64 ms 把所有行依次读出再写回 (读一行本身就会把它写回, 所以只要轮流「读」每一行即可). 刷新期间该存储体不能响应访问, 这也是 DRAM 比 SRAM 慢的原因之一. SRAM 用 6 个晶体管组成双稳态电路, 只要通电就能保持, 不需要刷新, 但面积大、成本高.

局部性
Locality of reference

Slide 24–26

Locality to the Rescue! The key to bridging this CPU-Memory gap is an important property of computer programs known as locality.

Locality — Principle of Locality: Many Programs tend to use data and instructions with addresses near or equal to those they have used recently. · Temporal locality: Recently referenced items are likely to be referenced again in the near future · Spatial locality: Items with nearby addresses tend to be referenced close together in time

long sum = 0;
for (int i = 0; i < n; i++)
    sum += a[i];
return sum;
Spatial or Temporal Locality?
Data references: Reference array elements in succession (stride-1 reference pattern).spatial
Data references: Reference variable sum each iteration.temporal
Instruction references: Reference instructions in sequence.spatial
Instruction references: Cycle through loop repeatedly.temporal

弥合差距的关键是程序的局部性: 程序倾向于访问与最近访问过的地址相同或相近的数据和指令. 两种: 时间局部性, 最近访问过的很可能很快再访问; 空间局部性, 地址相近的往往在相近的时间被访问.

求和循环: 依次访问 a 的元素 (步长为 1) 是空间局部性; 每次都访问 sum 是时间局部性; 指令顺序执行是空间局部性; 反复执行循环体是时间局部性.

Slide 27–29

Qualitative Estimates of Locality — Claim: Being able to look at code and get a qualitative sense of its locality is a key skill for a professional programmer. · Question: Does this function have good locality with respect to array a?

int sum_array_rows(int a[M][N])
{
    int i, j, sum = 0;
    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            sum += a[i][j];
    return sum;
}

Hint: array layout is row-major order — a[0][0] • • • a[0][N-1] a[1][0] • • • a[1][N-1] • • • a[M-1][0] • • • a[M-1][N-1] — Answer: yes

int sum_array_cols(int a[M][N])
{
    int i, j, sum = 0;
    for (j = 0; j < N; j++)
        for (i = 0; i < M; i++)
            sum += a[i][j];
    return sum;
}

Answer: no · Stride N reference pattern · Note: If M is very small then good locality. Why?

Question: Can you permute the loops so that the function scans the 3-d array a with a stride-1 reference pattern (and thus has good spatial locality)?

int sum_array_3d(int a[M][N][N])
{
    int i, j, k, sum = 0;
    for (i = 0; i < N; i++)
        for (j = 0; j < N; j++)
            for (k = 0; k < M; k++)
                sum += a[k][i][j];
    return sum;
}

Answer: make j the inner loop

能看代码估计局部性是专业程序员的基本功. C 的多维数组按行优先存储, 同一行的元素相邻.

  • sum_array_rows 按行扫描, 步长为 1, 局部性好.
  • sum_array_cols 按列扫描, 相邻两次访问相隔 N 个元素 (步长 N), 局部性差. 若 M 很小, 一列只有几个元素, 这几行可能同时都在缓存里, 第二列访问时它们所在的块还没被换出, 局部性又变好了.
  • 三维数组 a[k][i][j] 中最右边的下标 j 变化时地址相邻, 所以 j 应在最内层; 最左边的 k 应在最外层, 循环顺序改为 k、i、j.

定量估计: 设 int 为 4 字节, 缓存块 64 字节 (一块装 16 个 int), 数组远大于缓存, 缓存初始为空.

  • sum_array_rows: 每读到一个新块的第一个元素不命中一次, 之后 15 个都命中, 不命中率约 1/16 ≈ 6%.
  • sum_array_cols: 若 M 行的块装不下缓存, 每次访问都落在不同的块上, 等回到同一块的下一个元素时它早已被换出, 不命中率接近 100%.

两者执行的加法次数完全相同, 运行时间却可能差十几倍, 这就是第 1 讲 copyij 与 copyji 相差约 19 倍的原因. 下一讲会用缓存的具体结构把这种估计做准确.

存储器层次
The memory hierarchy

Slide 31–33

Memory Hierarchies — Some fundamental and enduring properties of hardware and software: · Fast storage technologies cost more per byte, have less capacity, and require more power (heat!). · The gap between CPU and main memory speed is widening. · Well-written programs tend to exhibit good locality. · These properties complement each other well for many types of programs. · They suggest an approach for organizing memory and storage systems known as a memory hierarchy.

Memory size affects latency & energy — Small Memory vs Big Memory · Signals have further to travel · Fan out to more locations

三个长期成立的事实: 快的存储技术每字节更贵、容量更小、功耗更大; CPU 和主存的速度差距在扩大; 写得好的程序有好的局部性. 三者正好互补, 由此产生存储器层次的组织方式. 存储器越大, 信号要走得越远、要扇出到更多位置, 所以越慢越耗能, 这是物理上无法避免的.

典型层次: 寄存器 → L1、L2、L3 缓存 (SRAM) → 主存 (DRAM) → 本地磁盘 → 远程存储. 每一层保存着从下一层取来的数据: 寄存器存从 L1 取来的字, L1 存从 L2 取来的缓存行, 主存存从磁盘取来的块, 本地磁盘存从远程服务器取来的文件.

对层次的量级有个直观印象很有用 (以一台 3 GHz 左右的桌面处理器为例, 数值是常见的典型值): 寄存器约十几个、访问不到 1 个周期; L1 每核约 32–48 KB、约 4 个周期; L2 每核约 256 KB–1 MB、约 10–14 个周期; L3 全芯片共享几 MB 到几十 MB、约 40 个周期; DRAM 几 GB 到几十 GB、约 200 个周期 (60–100 ns); SSD 一次随机读约几十到一百微秒; 机械硬盘约 10 ms. 相邻两层之间, 容量通常大一到两个数量级, 延迟也慢几倍到几个数量级. 可以在 Linux 上用 lscpu 或 getconf -a | grep CACHE 查看自己机器的缓存大小.

Slide 34–36

Caches — Cache: A smaller, faster storage device that acts as a staging area for a subset of the data in a larger, slower device. · Fundamental idea of a memory hierarchy: For each k, the faster, smaller device at level k serves as a cache for the larger, slower device at level k+1. · Why do memory hierarchies work? · Because of locality: programs tend to access the data at level k more often than they access the data at level k+1. · Thus, the storage at level k+1 can be slower, and thus larger and cheaper per bit. · Big Idea (Ideal): The memory hierarchy creates a large pool of storage that costs as much as the cheap storage near the bottom, but that serves data to programs at the rate of the fast storage near the top.

Hierarchy provides the illusion of large & fast memory (Small Memory · Big Memory (rarely accessed))

Cache vs Memory — Caches are invisible (transparent) to software · Managed by hardware in response to loads & stores · Performance & energy improve without software changes · Caveat: Recent CPUs have some instructions to manage cache (e.g., prefetch, invalidate, partition…) · Memory is visible to software · I.e., addressable directly by instructions (memory address, registers) · Some optimization opportunities, but only w/ software changes

cache 缓存: 较小较快的存储, 作为较大较慢存储中部分数据的「中转站». 层次的核心思想: 第 k 层是第 k + 1 层的缓存. 之所以有效, 是因为局部性使程序访问第 k 层远多于第 k + 1 层, 所以第 k + 1 层可以慢一些, 从而更大更便宜. 理想效果: 一个容量像底层一样大、价格像底层一样便宜、速度却接近顶层的存储池.

缓存对软件是透明的: 由硬件根据 load/store 自动管理, 不改程序也能受益 (较新的 CPU 也提供预取、失效等管理指令). 内存则对软件可见, 指令直接用地址访问它.

Slide 37–39

General Cache Concepts — Smaller, faster, more expensive memory caches a subset of the blocks (Cache: 8 9 14 3) · Data is copied in block-sized transfer units · Larger, slower, cheaper memory viewed as partitioned into “blocks” (Memory: 0 … 15)

Hit — Request: 14 · Data in block b is needed · Block b is in cache: Hit!

Miss — Request: 12 · Block b is not in cache: Miss! · Block b is fetched from memory · Block b is stored in cache · Placement policy: determines where b goes · Replacement policy: determines which block gets evicted (victim)

缓存的一般概念: 下层存储被划分成大小固定的块, 数据以块为单位在两层之间复制; 缓存保存其中一部分块. 请求块 14, 它在缓存里: 命中. 请求块 12, 不在: 不命中, 从下层取来块 12 放进缓存. 放到哪里由放置策略决定; 缓存满时换出哪个块 (牺牲块) 由替换策略决定 (如 LRU, 换出最久未使用的).

Slide 40–41

General Caching Concepts: 3 Types of Cache Misses

  • Cold (compulsory) miss · Cold misses occur because this is the first reference to the block. · Misses with an infinitely large cache with no placement restrictions.
  • Capacity miss · Occurs when the set of active cache blocks (working set) is larger than the cache. · Additional misses from finite-sized cache (and still no placement restrictions).
  • Conflict miss · Most caches limit blocks at level k+1 to a small subset (sometimes a singleton) of the block positions at level k. · E.g. Block i at level k+1 must be placed in block (i mod 4) at level k. · Conflict misses occur when the level k cache is large enough, but multiple data objects all map to the same level k block. · E.g. Referencing blocks 0, 8, 0, 8, 0, 8, ... would miss every time. · Additional misses due to actual placement policy.

三种不命中 (3C):

  • 冷不命中 (强制不命中): 第一次访问某块, 缓存里不可能有. 即使缓存无限大、放置不受限也会发生.
  • 容量不命中: 当前活跃的块 (工作集) 比缓存大, 装不下. 是缓存有限大小带来的额外不命中.
  • 冲突不命中: 缓存总容量够, 但放置规则限制了块能放的位置 (例如块 i 只能放在第 i mod 4 个位置), 多个块挤同一个位置. 交替访问块 0 和 8 (都映射到位置 0) 会每次都不命中, 即使缓存其余位置都空着.

分辨三种不命中的思路: 想象一个无限大、可以随意放置的缓存, 这时仍发生的不命中是冷不命中; 换成同样大小但可随意放置的缓存, 多出来的是容量不命中; 再换成实际的放置规则, 多出来的就是冲突不命中. 对策也不同: 冷不命中靠预取或增大块来减少; 容量不命中要缩小工作集 (如分块计算) 或换更大的缓存; 冲突不命中可以靠增加相联度 (一组多行) 或调整数据布局 (如数组之间加填充) 来消除. 第 10 讲的矩阵乘法和分块就是这些思路的应用.

Working Set, Locality, and Caches — Working Set: The set of data a program is currently “working on” · Definition of “currently” depends on context, e.g., in this loop · Includes accesses to data and instructions · Principle of Locality: Programs tend to use data and instructions with addresses near or equal to those they have used recently · Nearby addresses: Spatial Locality · Equal addresses: Temporal locality · Caches take advantage of temporal locality by storing recently used data, and spatial locality by copying data in block-sized transfer units · Locality reduces working set sizes · Caches are most effective when the working set fits in the cache

How Many Cold Cache Misses?

long sum = 0;
for (int i = 0; i < 16; i++)
    sum += a[i];
return sum;

References array elements in succession (spatial locality) · References sum and i each iteration (temporal locality; put in registers) · Answer depends on: Are any elements already in the cache? · How many elements fit in one cache block? · Is the start of the array aligned with the start of a cache block? · Example: If cache starts empty, 8 elements fit evenly in a cache block, and the array is aligned with the start of a cache block then 2 cold misses.

working set 工作集: 程序「当前」正在使用的数据和指令 (「当前」视语境而定, 如这个循环期间). 缓存利用时间局部性 (保留最近用过的数据) 和空间局部性 (以块为单位搬运). 工作集能放进缓存时缓存最有效.

求和 16 个 long 有几次冷不命中? 取决于: 缓存初始是否已有这些元素; 一个块装几个元素; 数组起点是否与块边界对齐. 例: 缓存初始为空、64 字节的块装 8 个 long、数组对齐, 则 16 个元素占 2 个块, 只有 2 次冷不命中, 其余 14 次都命中. 若不对齐, 16 个元素跨 3 个块, 就是 3 次.

两种持久存储: 磁盘, 把数据存在磁性介质上, 靠机械运动访问; 闪存, 把数据存为持久的电荷, 现代闪存是 3D 结构, 一百多层单元, 每单元存 3–4 位.

Slide 51–52

Nonvolatile Memories — DRAM and SRAM are volatile memories · Lose information if powered off. · Nonvolatile memories retain value even if powered off · Read-only memory (ROM): programmed during production · Electrically eraseable PROM (EEPROM): electronic erase capability · Flash memory: EEPROMs, with partial (block-level) erase capability · Wears out after about 100,000 erasings · 3D XPoint (Intel Optane) & emerging NVMs · New materials · Uses for Nonvolatile Memories · Firmware programs stored in a ROM (BIOS, controllers for disks, network cards, graphics accelerators, security subsystems,…) · Solid state disks (replacing rotating disks) · Disk caches

Solid State Disks (SSDs) — Requests to read and write logical disk blocks (I/O bus) → Flash translation layer · DRAM Buffer · Flash memory: Block 0 … Block B-1, each Page 0 … Page P-1 · Pages: 512KB to 4KB, Blocks: 32 to 128 pages · Data read/written in units of pages. · Page can be written only after its block has been erased. · A block wears out after about 10,000 repeated writes.

易失性存储 (SRAM、DRAM) 断电即丢失数据; 非易失性存储断电后保留: ROM (出厂时写入)、EEPROM (可电擦除)、闪存 (EEPROM 的一种, 按块擦除, 擦写次数有限)、Intel Optane 等新型存储. 用途: 固件 (BIOS、各种控制器的程序)、固态盘、磁盘缓存.

SSD: 主机按逻辑块读写, 由闪存翻译层 (FTL) 映射到物理的闪存. 闪存由块组成, 每块 32–128 页; 读写以页为单位; 但一页只有在它所在的整块被擦除后才能写, 而且块的擦写次数有限.

幻灯片错误: "Pages: 512KB to 4KB" 应为 512 B 到 4 KB (教材原文是 512 bytes to 4 KB; 页比块小, 不可能是 512 KB 到 4 KB). 前后不一致: Slide 51 说闪存擦写约 100,000 次后损坏, Slide 52 却说一个块约 10,000 次. 教材第 3 版写的是约 100,000 次; 实际数值随闪存类型不同 (每单元存的位数越多, 寿命越短, 现代 TLC/QLC 只有几千次). 另外 "eraseable" 应为 erasable.

SSD 性能: 顺序读写约 2 GB/s, 单线程随机读只有 62 MB/s, 差 30 多倍. 顺序访问快于随机访问是整个存储器层次的共同规律. 同时发出很多请求 (深队列) 能把随机读提高到约 950 MB/s, 说明随机读慢主要是延迟问题, 并发能掩盖延迟.

随机写的难点: 擦除一个块要约 1 ms (SSD 预先准备好一批已擦除的块); 改一页需要把同块的其他页复制到新块 (由写缓存合并写入来缓解).

与机械硬盘相比, SSD 没有活动部件, 更快、更省电、更耐摔; 缺点是会磨损 (FTL 用磨损均衡把写入分散到各块, 厂商保证总写入量约为容量的 600 倍) 和每字节更贵 (差距在迅速缩小). 机械硬盘仍用于大容量存储 (视频、海量数据集) 和廉价存储.

为什么各层都是顺序访问快: 机械硬盘顺序读不用重新寻道, 只等磁盘转过来; DRAM 读同一行内的连续数据只需一次行激活 (行缓冲命中); 缓存一次取回整块, 后面的元素都命中; 硬件预取器还能识别出顺序或固定步长的访问模式, 提前把后续的块取来. 所以「让访问连续」是适用于整个存储器层次的优化原则.

幻灯片小错: "Samsung 940 EVO Plus" 应为 970 EVO Plus (与上一页的测试型号一致; 三星没有 940 这个型号).

CPU 主频在 2003 年前后达到约 3 GHz 后不再提高, 甚至略降: 设计者撞上了功耗墙 (主频越高功耗越大, 芯片散热跟不上). 此后性能提升转向多核, 「有效周期」按核数折算, 仍从 166 ns 降到 0.08 ns, 提高约 2000 倍, 远快于 DRAM 的 10 倍.

功耗墙的原因: 动态功耗约与 电容 × 电压² × 频率 成正比. 2005 年以前, 晶体管缩小时电压也能随之降低 (Dennard 缩放), 主频提高而功耗密度不变; 此后电压降不下去了 (漏电流增大), 继续提高主频会让芯片过热. 于是厂商改为在同一芯片上放更多核心. 代价是程序必须并行化才能用上这些核心, 这是课程最后几讲 (并发与并行) 的背景.

Slide 61–64

Conventional DRAM Organization — d x w DRAM: d⋅w total bits organized as d supercells of size w bits (16 x 8 DRAM chip: 4 rows × 4 cols of 8-bit supercells; 2 bits addr, 8 bits data; Internal row buffer)

Reading DRAM Supercell (2,1) — Step 1(a): Row access strobe (RAS) selects row 2. · Step 1(b): Row 2 copied from DRAM array to row buffer. · Step 2(a): Column access strobe (CAS) selects column 1. · Step 2(b): Supercell (2,1) copied from buffer to data lines, and eventually back to the CPU. · Step 3: All data written back to row to provide refresh

Memory Modules — 64 MB memory module consisting of eight 8Mx8 DRAMs · addr (row = i, col = j) → supercell (i,j) of each DRAM · DRAM 0 supplies bits 0-7, …, DRAM 7 supplies bits 56-63 of the 64-bit word at main memory address A

DRAM 芯片内部: d × w 的 DRAM 有 d 个超单元, 每个 w 位, 排成二维阵列. 16 × 8 的芯片是 4 × 4 个 8 位超单元. 读超单元 (2, 1): 先发行地址 (RAS) 2, 整行复制到芯片内的行缓冲; 再发列地址 (CAS) 1, 从行缓冲取出该超单元送出; 最后整行写回 (顺便刷新). 行列分两次发送, 可以减少地址引脚 (这里只需 2 根).

内存模块: 8 个 8M × 8 的 DRAM 组成 64 MB 模块. 读一个 64 位字时, 每个芯片同时提供同一位置 (i, j) 的 8 位, 拼成 64 位.

Slide 65–68

Disk Access Time — Average time to access some target sector approximated by: Taccess = Tavg seek + Tavg rotation + Tavg transfer · Seek time (Tavg seek) · Time to position heads over cylinder containing target sector. · Typical Tavg seek is 3—9 ms · Rotational latency (Tavg rotation) · Time waiting for first bit of target sector to pass under r/w head. · Tavg rotation = 1/2 x 1/RPMs x 60 sec/1 min · Typical rotational rate = 7,200 RPMs · Transfer time (Tavg transfer) · Time to read the bits in the target sector. · Tavg transfer = 1/RPM x 1/(avg # sectors/track) x 60 secs/1 min

Disk Access Time Example — Given: Rotational rate = 7,200 RPM · Average seek time = 9 ms · Avg # sectors/track = 400 · Derived: Tavg rotation = 1/2 x (60 secs/7200 RPM) x 1000 ms/sec = 4 ms · Tavg transfer = 60/7200 x 1/400 x 1000 ms/sec = 0.02 ms · Taccess = 9 ms + 4 ms + 0.02 ms · Important points: Access time dominated by seek time and rotational latency. · First bit in a sector is the most expensive, the rest are free. · SRAM access time is about 4 ns/doubleword, DRAM about 60 ns · Disk is about 40,000 times slower than SRAM, · 2,500 times slower than DRAM.

磁盘访问时间 = 平均寻道 + 平均旋转延迟 + 平均传输. 旋转延迟平均是转半圈的时间; 传输时间是转过一个扇区的时间.

例题 (7200 转/分, 平均寻道 9 ms, 每道 400 扇区): 转一圈 60/7200 s = 8.33 ms, 平均旋转延迟约 4.17 ms (课件取 4 ms); 传输 8.33 ms / 400 ≈ 0.02 ms; 总计约 13 ms. 寻道和旋转占了几乎全部, 一旦开始读, 扇区里后面的位几乎「免费」. 「慢 40,000 倍」的算法 (教材 6.1.2 节): 从内存读一个扇区大小 (512 字节 = 64 个 8 字节字) 的块, SRAM 约 64 × 4 = 256 ns, DRAM 约 64 × 60 ≈ 4000 ns; 磁盘约 10 ms, 分别是它们的约 40,000 倍和 2,500 倍.

Slide 69–70

Disk Capacity — Capacity: maximum number of bits that can be stored. · Vendors express capacity in units of gigabytes (GB) or terabytes (TB), where 1 GB = 10⁹ Bytes and 1 TB = 10¹² Bytes · Capacity is determined by these technology factors: · Recording density (bits/in): number of bits that can be squeezed into a 1 inch segment of a track. · Track density (tracks/in): number of tracks that can be squeezed into a 1 inch radial segment. · Areal density (bits/in²): product of recording and track density.

Disk Operation (Single-Platter View) — The disk surface spins at a fixed rotational rate · The read/write head is attached to the end of the arm and flies over the disk surface on a thin cushion of air. · By moving radially, the arm can position the read/write head over any track. (Multi-Platter View) Read/write heads move in unison from cylinder to cylinder

磁盘容量: 厂商用十进制单位, 1 GB = 10⁹ 字节 (而内存的 GB 通常指 2³⁰ 字节). 容量由记录密度 (每英寸磁道上的位数)、磁道密度 (每英寸径向的磁道数) 及二者之积面密度决定. 磁头悬浮在一层薄薄的空气垫上, 臂径向移动选磁道; 多盘片时所有磁头一起移动, 同一半径上的各面磁道组成柱面.

Slide 71–74

I/O Bus — CPU chip (Register file, ALU, Bus interface) — System bus — I/O bridge — Memory bus — Main memory · I/O bus: USB controller, Graphics adapter, Disk controller · Expansion slots for other devices such as network adapters.

Reading a Disk Sector — (1) CPU initiates a disk read by writing a command, logical block number, and destination memory address to a port (address) associated with disk controller. (2) Disk controller reads the sector and performs a direct memory access (DMA) transfer into main memory. (3) When the DMA transfer completes, the disk controller notifies the CPU with an interrupt (i.e., asserts a special “interrupt” pin on the CPU).

I/O 总线: CPU 通过系统总线和 I/O 桥连到内存总线和 I/O 总线, USB、显卡、磁盘控制器等挂在 I/O 总线上. 读磁盘扇区: CPU 往磁盘控制器的端口地址写入命令、逻辑块号和目标内存地址后就去做别的事; 控制器读出扇区, 用 DMA (直接存储器访问) 不经 CPU 直接写入内存; 完成后通过中断通知 CPU. 这样 CPU 不必在漫长的磁盘访问期间空等 (中断在异常控制流一讲详述).
