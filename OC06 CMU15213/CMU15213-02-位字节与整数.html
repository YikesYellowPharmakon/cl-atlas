Analog Computers

  • Before digital computers there were analog computers.
  • Consider a couple of simple analog computers:
    • A simple circuit can allow one to adjust voltages using variable resistors and measure the output using a volt meter:
    • A simple network of adjustable parallel resistors can allow one to find the average of the inputs.

Needing Less Accuracy+Precision is Easier

  • We don't try to measure exactly
    • We just ask, is it high enough to be “On”, or
    • Is it low enough to be “Off”.
  • We have two states, so we have a binary, or 2-ary, system.
    • We represent these states as 0 and 1
  • Now we can easily interpret, communicate, and duplicate signals well enough to know what they mean.

(图: 电压随时间波动的信号, 1.1V / 0.9V 附近读作 1, 0.2V / 0.0V 附近读作 0, 读出 0 1 0.)

数字计算机之前有模拟计算机: 用可变电阻调电压、用电压表读结果, 或用并联电阻网络求输入的平均值. 模拟量要精确测量, 很难.

数字系统降低了要求: 不测精确值, 只问电压「够高算开」还是「够低算关」. 两个状态就是二进制, 记作 0 和 1. 这样信号即使有噪声 (0.9 V 和 1.1 V 都读作 1) 也能可靠地解释、传输和复制.

Slide 7–8

Binary Representation

  • Binary representation -> binary, base-2, numbering system
    • 0 represents 0
    • 1 represents 1
    • Each “place” represents a power of two, exactly as each place in our usual “base 10”, 10-ary numbering system represents a power of ten
  • Encoding/interpreting sets of bits can represent…
    • Operations to be executed by the processor
    • numbers
    • enumerable things, such as text characters
    • more!
  • If can assign it to a discrete number, we can represent it in binary

Binary Representation: Simple Numbers

  • Example: we can count in binary, a base-2 numbering system
    • 000, 001, 010, 011, 100, 101, 110, 111, …
    • 000 = 0*2² + 0*2¹ + 0*2⁰ = 0 (in decimal)
    • 001 = 0*2² + 0*2¹ + 1*2⁰ = 1 (in decimal)
    • 010 = 0*2² + 1*2¹ + 0*2⁰ = 2 (in decimal)
    • 011 = 0*2² + 1*2¹ + 1*2⁰ = 3 (in decimal)
  • For reference, consider some base-10 examples:
    • 357 = 3*10² + 5*10¹ + 7*10⁰

二进制是以 2 为底的进位制: 每一位代表 2 的一个幂, 就像十进制每一位代表 10 的一个幂 (357 = 3·10² + 5·10¹ + 7·10⁰, 而 011 = 0·2² + 1·2¹ + 1·2⁰ = 3). 一组位可以编码处理器要执行的指令、数、字符等可枚举的东西. 只要能给一样东西编上离散的号码, 就能用二进制表示它.

Hexadecimal and Octal

  • Writing numbers in binary takes too many digits
  • Want a way to represent numbers more densely such that fewer digits are required
    • But also so it is easy to get at the bits that we want
  • Any power-of-two base provides this property
    • Octal (base 8) and hexadecimal (base 16) are closest to our familiar base-10.
    • Each has been used by “computer people” over time
    • Hexadecimal is often preferred because it is denser.

  • The C Language prefixes hexadecimal numbers with “0x” so they aren't confused with decimal numbers
  • Write FA1D37B₁₆ in C as 0xFA1D37B or 0xfa1d37b

二进制写起来位数太多. 以 2 的幂为底的进位制 (八进制、十六进制) 既紧凑, 又能直接看出每一位: 十六进制的一位正好对应 4 个二进制位, 所以比八进制 (一位对应 3 位) 更紧凑, 更常用. 十六进制用 0–9 和 A–F (10–15) 作数字, C 语言用前缀 0x 表示, 大小写都可以.

    • Algebraic representation of logic
    • Encode “True” as 1 and “False” as 0

Boolean algebra 布尔代数: 19 世纪 Boole 提出的逻辑代数, 真记作 1、假记作 0. 四种运算: 与 & (两者都为 1 才为 1)、或 | (至少一个为 1)、非 ~ (取反)、异或 ^ (恰有一个为 1, 即两者不同).

作用在位向量上时逐位运算, 例子里每一列独立计算. 布尔代数的所有性质 (交换律、结合律、分配律、德摩根律等) 都对逐位运算成立.

Slide 14

Example: Representing & Manipulating Sets

  • Representation
    • Width w bit vector represents subsets of {0, …, w–1}
    • aj​=1 if j ∈ A
      • 01101001 = { 0, 3, 5, 6 } (bit positions 76543210)
      • 01010101 = { 0, 2, 4, 6 }
  • Operations
    • & Intersection: 01000001 = { 0, 6 }
    • | Union: 01111101 = { 0, 2, 3, 4, 5, 6 }
    • ^ Symmetric difference: 00111100 = { 2, 3, 4, 5 }
    • ~ Complement: 10101010 = { 1, 3, 5, 7 }

位向量可以表示集合: 宽度为 w 的位向量表示 {0, …, w − 1} 的一个子集, 第 j 位为 1 表示 j 在集合中 (位从右往左编号, 最右是第 0 位). 于是 & 是交集, | 是并集, ^ 是对称差, ~ 是补集 (例子里 ~ 作用于第二个集合 {0, 2, 4, 6}). 这正是 CS103 第 0 讲集合运算的位级实现, 程序里常用一个整数当作小集合 (标志位).

Slide 15–17

Bit-Level Operations in C

  • Operations &, |, ~, ^ Available in C
    • Apply to any “integral” data type
      • long, int, short, char, unsigned
    • View arguments as bit vectors
    • Arguments applied bit-wise
  • Examples (Char data type)
    • ~0x41 → 0xBE (~01000001₂ → 10111110₂)
    • ~0x00 → 0xFF (~00000000₂ → 11111111₂)
    • 0x69 & 0x55 → 0x41 (01101001₂ & 01010101₂ → 01000001₂)
    • 0x69 | 0x55 → 0x7D (01101001₂ | 01010101₂ → 01111101₂)

C 的 &、|、~、^ 适用于所有整型 (long、int、short、char、unsigned), 把参数当作位向量逐位运算. 做题方法: 先把十六进制展开成二进制, 逐位算, 再合回十六进制. 例如 0x69 = 0110 1001, 0x55 = 0101 0101, 按位与得 0100 0001 = 0x41.

Slide 18

Contrast: Logic Operations in C

  • Contrast to Bit-Level Operators
    • Logic Operations: &&, ||, !
      • View 0 as “False”
      • Anything nonzero as “True”
      • Always return 0 or 1
      • Early termination
  • Examples (char data type)
    • !0x41 → 0x00
    • !0x00 → 0x01
    • !!0x41 → 0x01
    • 0x69 && 0x55 → 0x01
    • 0x69 || 0x55 → 0x01
    • p && *p (avoids null pointer access)

Watch out for && vs. & (and || vs. |)… Super common C programming pitfall!

逻辑运算 &&、||、! 与位运算不同: 把 0 当假、任何非 0 当真, 结果只有 0 或 1, 而且短路求值 (左边已能决定结果时不再算右边). 所以 !0x41 = 0, !!0x41 = 1 (常用来把非零值规范化为 1); 0x69 && 0x55 = 1, 而 0x69 & 0x55 = 0x41. p && *p 利用短路: p 是空指针时不会去解引用.

易错: 把 && 写成 & (或 || 写成 |) 是极常见的 C 错误. 例如 0x01 & 0x02 = 0 (假), 而 0x01 && 0x02 = 1 (真).

Shift Operations

  • Left Shift: x << y
    • Shift bit-vector x left y positions
      • Throw away extra bits on left
    • Fill with 0's on right
  • Right Shift: x >> y
    • Shift bit-vector x right y positions
      • Throw away extra bits on right
    • Logical shift
      • Fill with 0's on left
    • Arithmetic shift
      • Replicate most significant bit on left
  • Undefined Behavior
    • Shift amount < 0 or ≥ word size

左移 x << y: 整体左移 y 位, 左边移出的位丢掉, 右边补 0. 右移 x >> y 有两种: logical shift 逻辑右移左边补 0; arithmetic shift 算术右移左边复制最高位 (符号位). 表中第一个数最高位是 0, 两种右移结果相同; 第二个数最高位是 1, 算术右移在左边补 1. C 标准中无符号数的右移是逻辑右移; 有符号数几乎所有机器都用算术右移. 移位量为负或不小于字长 (如 32 位 int 移 32 位) 是未定义行为.

Slide 23–24

Overflow

  • Let's consider a simple 3 digit number line: 000 001 010 011 100 101 110 111
  • What happens if we add 1 to 7?
    • In other words, what happens if we add 1 to 111?
  • 111 + 001 = 1 000
    • But, we only get 3 bits – so we lose the leading 1.
    • This is called overflow
  • The result is 000

Modulus Arithmetic

  • 111 + 001 = 1 000 = 000 · 111 + 010 = 1 001 = 001 · 111 + 011 = 1 010 = 010 · 111 + 100 = 1 011 = 011 · … · 111 + 110 = 1 101 = 101 · 111 + 111 = 1 110 = 110
  • So, arithmetic “wraps around” when it gets “too positive”

overflow 溢出: 3 位能表示 0–7, 7 + 1 = 1000 需要 4 位, 只保留低 3 位, 最高位的 1 丢掉, 结果是 000. 一般地, 结果超出范围时会「绕回来」, 即运算在模 2ʷ (这里模 8) 下进行: 7 + k 得到 k − 1.

Slide 25–26

Unsigned and Non-Negative Integers

  • We'll use the term “ints” to mean the finite set of integer numbers that we can represent on a number line enumerated by some fixed number of bits, i.e. bit width.
  • We normally represent unsigned and non-negative int using simple binary as we have already discussed
    • An “unsigned” int is any int on a number line, e.g. of a data type, that doesn't contain any negative numbers
    • A non-negative number is a number greater than or equal to (>=) 0 on a number line, e.g. of a data type, that does contain negative numbers

How to represent negative Numbers?

  • We could use the leading bit as a sign bit: 0 means non-negative · 1 means negative
    • 000 001 010 011 100 101 110 111 → 0 1 2 3 -0 -1 -2 -3
  • Benefits: represents negative and non-negative numbers · 0 represents 0
  • Drawbacks
    • There is a -0, which is the same as 0, except that it is different
    • How to add such numbers 1 + -1 should equal 0
    • But, by simple math, 001 + 101 = 110, which is -2?

术语: 「int」指固定位宽能表示的有限个整数. unsigned 无符号: 所在数轴上没有负数; 非负数: 所在数轴上有负数, 但这个数 ≥ 0. 两者都用普通二进制表示.

负数怎么表示? 最直接的办法是符号-数值表示: 最高位当符号位. 缺点: 有两个零 (000 和 100, 即 −0); 加法不能直接用普通的二进制加法, 1 + (−1) 按位相加得 001 + 101 = 110, 读作 −2, 错了.

Slide 27–28

A Trick!

  • Let's start with three ideas: 1 should be represented as 1 · -1 + 1 = 0 · We want addition to work in the familiar way, with simple rules.
  • Consider a 3 bit number: 001 + “-1” = 0 · 001 + 111 = 0 · Remember 001 + 111 = 1 000, and the leading one is lost to overflow.
  • “-1” = 111 · Yep!

Negative Numbers

  • Well, if 111 is -1, what is -2? · -1 - 1 · 111 – 001 = 110
  • Does that really work? · If it does -2 + 2 = 0 · 110 + 010 = 1 000 = 000
  • -2 + 5 should be 3, right? · 110 + 101 = 1 011 = 011

技巧: 要求 1 仍表示为 001, 且 (−1) + 1 = 0 用普通加法成立. 001 + 111 = 1000, 溢出丢掉最高位得 000, 所以 −1 就该是 111. 再往下: −2 = −1 − 1 = 111 − 001 = 110, 检验 110 + 010 = 1000 → 000 ✓. 这样定义的负数, 加法直接用普通二进制加法再丢掉进位即可, 这就是补码的思想.

幻灯片小错: "-2 + 5 should be 3" 这个例子在 3 位补码里不严谨: 3 位补码只能表示 −4 到 3, 5 不在范围内, 101 在补码下读作 −3. 计算 110 + 101 = 011 得到 3 是对的, 但应理解为模 8 的运算 (5 ≡ −3 mod 8), 而不是 "−2 + 5" 这两个补码数相加.

Slide 29–31

Finding –x the easy way

  • Given a non-negative number in binary, e.g. 5, represented with a fixed bit width, e.g. 4: 0101
  • Find its negative by flipping each bit and adding 1
    • 0101 This is 5
    • 1010 This is the “ones complement of 5”, e.g. 5 with bits flipped
    • 1011 This is the “twos complement of 5”, e.g. 5 with the bits flipped and 1 added
    • 0101 + 1011 = 1 0000 = 0000
    • -x = ~x+1
  • Because of the fixed width, the “two's complement” of a number can be used as its negative.

Why Does This Work?

  • … if they are added, all bits are necessarily set: 0101 + 1010 = 1111
  • Adding 1 to the sum of a number and its complement necessarily results in a 0 due to overflow: (0101 + 1010) + 1 = 1111 + 1 = 1 0000 = 0000
  • And if x + y = 0, y must equal –x
  • Another way of looking at it: if x + (Complement(x) + 1) = 0 · x + Complement(x) = -1 · x = -1 - Complement(x) · -x = 1 + Complement(x)

求 −x 的快捷办法: 按位取反再加 1, 即 −x=∼x+1. 例: 5 = 0101, 取反得 1010 (ones' complement 反码), 再加 1 得 1011 (two's complement 补码), 0101 + 1011 = 10000, 丢掉进位得 0000.

为什么成立: x 和 ~x 每一位恰好互补, 相加必然是全 1 (1111), 而全 1 再加 1 溢出成 0. 所以 x + (~x + 1) = 0, 即 ~x + 1 = −x. 另一种看法: 全 1 就是 −1, 所以 x + ~x = −1, 移项得 −x = ~x + 1.

Signed vs. Unsigned in C

  • Constants
    • By default are considered to be signed integers
    • Unsigned if have “U” as suffix: 0U, 4294967259U
  • Casting
    • Explicit casting between signed & unsigned same as U2T and T2U
int tx, ty;
unsigned ux, uy;
tx = (int) ux;
uy = (unsigned) ty;
  • Implicit casting also occurs via assignments and procedure calls
tx = ux;          int fun(unsigned u);
uy = ty;          uy = fun(tx);

C 中整数常量默认是有符号的, 加后缀 U 才是无符号. 显式强制转换 (int)、(unsigned) 就是 U2T、T2U, 位模式不变. 隐式转换也会发生: 赋值给另一种类型的变量、把参数传给形参类型不同的函数时都会自动转换, 不会有任何提示.

规则: 同一个表达式里混有有符号和无符号时, 有符号数会被隐式转成无符号数, 比较运算也一样. 逐行理解:

  • −1 < 0 (有符号比较), 但 −1 > 0U: −1 转成无符号是 4294967295.
  • TMin 写成 −2147483647−1 而不是 −2147483648, 因为后者是对常量 2147483648 取负, 而 2147483648 超出 int 范围, 类型会变成更大的类型.
  • 2147483647U < −2147483647−1: 右边转成无符号是 2147483648.
  • (unsigned)−1 > −2: 两边都按无符号, 4294967295 > 4294967294.
  • (int) 2147483648U 是 TMin, 所以 2147483647 比它大.

易错: for (unsigned i = n - 1; i >= 0; i--) 永远不会停, 因为无符号数总是 ≥ 0; if (len - 1 < x) 中若 len 是 unsigned 且为 0, len − 1 是 UMax.

Sign Extension

  • Task: Given w-bit signed integer x · Convert it to w+k-bit integer with same value
  • Rule: Make k copies of sign bit: X′=xw−1​,…,xw−1​,xw−1​,xw−2​,…,x0​ (k copies of MSB, then the original w bits)

把较短的整数扩展成较长的整数, 值要保持不变. 无符号数: 高位补 0 (1 还是 1). 有符号数: sign extension 符号扩展, 把符号位复制 k 次放在高位. 例: int8 的 −1 是 0xff, 扩展成 int16 必须是 0xffff (仍是 −1), 而不是 0x00ff (那是 255).

为什么符号扩展保值: 在最高位前再加一位 1, 新最高位权值 −2ʷ, 原最高位权值从 −2ʷ⁻¹ 变成 +2ʷ⁻¹, 合计 −2ʷ + 2ʷ⁻¹ = −2ʷ⁻¹, 与原来相同. 归纳地加 k 位都成立.

Truncation

  • Task: Given k+w-bit signed or unsigned integer X · Convert it to w-bit integer X' with same value for “small enough” X
  • Rule: Drop top k bits: X′=xw−1​,xw−2​,…,x0​

truncation 截断: 把长整数转成短整数时直接丢掉高 k 位. 只有当原值「足够小」(在短类型的范围内) 时值才不变. 例: uint16 的 1000 转成 uint8, 1000 = 0x03E8, 只留低 8 位 0xE8 = 232, 即 1000 mod 256.

幻灯片小错: 课件的小测写 "bu = 0x8000 (0b100..) = negative max", 但前面声明的 bu 是 uint16_t, 0x8000 是 32768, 不是负数. 只有把它当作 int16_t 时, 0x8000 才是最小负数 −32768. 截断到 8 位后两种情况都得到 0x00.

Slide 52

Summary: Expanding, Truncating: Basic Rules

  • Expanding (e.g., short int to int)
    • Unsigned: zeros added
    • Signed: sign extension
    • Both yield expected result
  • Truncating (e.g., unsigned to unsigned short)
    • Unsigned/signed: bits are truncated
    • Result reinterpreted
    • Unsigned: mod operation
    • Signed: similar to mod
    • For small (in magnitude) numbers yields expected behavior

小结: 扩展时无符号补 0、有符号做符号扩展, 值都不变. 截断时都是直接丢高位再重新解释: 无符号就是取模 2ʷ; 有符号类似取模 (取模后再按补码解释). 只有绝对值较小的数截断后保持不变.

补码加法和无符号加法在位级上完全相同: 同样逐位相加、丢掉进位, 只是对结果的解释不同. 所以先转成 unsigned 相加再转回 int, 和直接用 int 相加结果一样. 同一个例子按补码读: 0xE9 = −23, 0xD5 = −43, 和 0xBE = −66, 正确. 这就是硬件只需要一个加法器的原因.

Visualizing “True Sum” Integer Addition — 4-bit integers u, v · Compute true sum Add₄(u, v) · Values increase linearly with u and v · Forms planar surface

Visualizing Unsigned Addition — Wraps Around · If true sum ≥ 2ʷ · At most once

Visualizing 2's Complement Addition — Values: 4-bit two's comp. · Range from -8 to +7 · Wraps Around: If sum ≥ 2ʷ⁻¹ · Becomes negative · At most once · If sum < –2ʷ⁻¹ · Becomes positive · At most once

读图: 真实和 u + v 是一个平面. 无符号加法把 ≥ 2ʷ 的部分减去 2ʷ, 平面被切成两块, 溢出最多发生一次 (两个 w 位数之和小于 2ʷ⁺¹). 补码加法有两种溢出: 两个正数相加超过 2ʷ⁻¹ − 1 时变成负数 (正溢出), 两个负数相加小于 −2ʷ⁻¹ 时变成正数 (负溢出), 也都最多一次. 一正一负相加永远不会溢出.

检测补码溢出的方法: 两个正数相加得负数, 或两个负数相加得非负数.

用 C 写溢出检测 (CS:APP 练习 2.30 的思路): 对 int 的 x 和 y, 先算 s = x + y (按补码绕回), 然后

int tadd_ok(int x, int y) {
    int s = x + y;
    int pos_over = x >= 0 && y >= 0 && s < 0;
    int neg_over = x < 0 && y < 0 && s >= 0;
    return !pos_over && !neg_over;
}

严格说, 有符号溢出在 C 标准里是未定义行为, 编译器可能据此做出意外的优化; 实际代码里更稳妥的是先比较再加 (如 y > 0 时检查 x > INT_MAX − y), 或使用编译器内建的 __builtin_add_overflow. 无符号加法溢出是有定义的: s = x + y 小于 x 就说明溢出了.

Slide 59

Multiplication

  • Goal: Computing Product of w-bit numbers x, y
    • Either signed or unsigned
  • Result: Same as computing ideal, exact result x*y and keeping w lower bits.
  • Ideal, exact results can be bigger than w bits
    • Worst case is up to 2w bits
      • Unsigned, because all bits are magnitude
      • Signed, but only for Tmin*Tmin, because anything added to Tmin reduces its magnitude and Tmax is less than Tmin.
  • So, maintaining exact results…
    • would need to keep expanding word size with each product computed
    • Impossible in hardware (at least without limits), as all resources are finite
    • In practice, is done in software, if needed
      • e.g., by “arbitrary precision” arithmetic packages

乘法: 无论有符号还是无符号, 结果都等于精确乘积的低 w 位. 精确乘积最多需要 2w 位: 无符号的最大积 (2ʷ − 1)² 接近 2²ʷ; 有符号只有 TMin × TMin = 2²ʷ⁻² 需要满 2w 位 (其他乘积的绝对值都更小, 因为 |TMax| < |TMin|). 要保留精确结果, 字长就得随每次乘法不断增加, 硬件做不到, 需要时由软件的任意精度算术库 (如 Python 的 int、GMP) 完成.

Power-of-2 Multiply with Shift

    • Both signed and unsigned

Operands: w bits u · * 2ᵏ (0•••010•••00) · True Product: w+k bits u · 2ᵏ · Discard k bits: w bits UMultw​(u,2k), TMultw​(u,2k)

乘以 2 的幂可以用左移: u << k = u · 2ᵏ (截断到 w 位), 有符号和无符号都成立. 乘以其他常数可以拆成几次移位加减: u · 24 = u · 32 − u · 8 = (u << 5) − (u << 3). 大多数机器上移位和加法比乘法快, 编译器会自动做这种替换.

除以 2ᵏ 可以用右移 (有符号数用算术右移). 但右移是向下取整: −5 >> 1 = −3 (−2.5 向下取整), 而 C 的整数除法要求向零取整, −5 / 2 应为 −2. 对负数先加一个偏置 2ᵏ − 1 再右移, 就变成向零取整: (−5 + 1) >> 1 = −4 >> 1 = −2; 能整除时加偏置不影响结果 (−4 + 1 = −3, −3 >> 1 = −2). 正数不加偏置. 编译器对 x / 8 这类代码会生成「判断符号、加偏置、右移」的指令序列.

再看一个 k = 3 的例子: −17 / 8 应为 −2 (−2.125 向零取整). 直接算术右移: −17 >> 3 = −3 (向下取整). 加偏置 2³ − 1 = 7: (−17 + 7) >> 3 = −10 >> 3 = −2, 正确. 能整除时, 如 −16 / 8: (−16 + 7) >> 3 = −9 >> 3 = −2, 偏置不足以跨过下一个 8 的倍数, 结果不变.

幻灯片排版问题: Slide 63 第二个例子写作 "-4 + 1 % 2", 意思应是「−4 加偏置 1 再除以 2」, 写法容易误读 (按 C 的优先级 1 % 2 先算).

Byte Ordering

  • So, how are the bytes within a multi-byte word ordered in memory?
  • Conventions
    • Big Endian: Sun (Oracle SPARC), PPC Mac, Internet
      • Least significant byte has highest address
    • Little Endian: x86, ARM processors running Android, iOS, and Linux
      • Least significant byte has lowest address
  • Becomes a concern when data is communicated
    • Over a network, via files, etc.
  • Important notes
    • Bits are not reversed, as the low order bit is the reference point.
    • Doesn't affect chars, or strings (arrays of chars), as chars are only one byte

Byte Ordering Example — Variable x has 4-byte value of 0x01234567 · Address given by &x is 0x100

0x1000x1010x1020x103
Big Endian01234567
Little Endian67452301

多字节的数在内存里按什么顺序存? big endian 大端: 最高有效字节放在最低地址 (像书写顺序); little endian 小端: 最低有效字节放在最低地址. x86 和常见的 ARM 系统是小端, 网络协议规定大端 (所以叫「网络字节序」). 例: 0x01234567 存在 0x100 开始的 4 个字节, 大端依次是 01 23 45 67, 小端是 67 45 23 01.

注意: 颠倒的是字节, 不是位; 字符串是字节数组, 不受影响. 字节序只在跨机器交换数据 (网络、文件) 时才需要关心.
