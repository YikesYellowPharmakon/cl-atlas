上次小测的两道题. 第一题: 利用 ~x + 1 = −x, 把 (~x) + 15 拆成 (~x + 1) + 14 = −x + 14, 所以 x += −x + 14 得 x = 14, 与 x 原来是多少无关. 第二题: D(Rb, Ri, S) 的地址是 D + Rb + Ri·S = 22 + 5000 + 16·2 = 5054 (题中都是十进制), mov 把 %rax 的 67 写到这个地址.

Slide 17

Sometimes an instruction may only change portions of the register destination.

63 · 31 · 15 · 7 · 0 — %rax %eax %ax %al — Lower order portions of integer registers can be accessed as byte, word (2-byte), double word (4-byte), and quad word (8-byte).

movabsq $0x0011223344556677, %rax    %rax = 0011223344556677
movb    $-1, %al                     %rax = 00112233445566FF
movw    $-1, %ax                     %rax = 001122334455FFFF
movl    $-1, %eax                    %rax = 00000000FFFFFFFF
movq    $-1, %rax                    %rax = FFFFFFFFFFFFFFFF

Convention: Any instruction that generates a 32-bit value for a register also sets upper 32 bits to 0.

写寄存器的一部分时, 其余部分怎么办? 例子从 %rax = 0x0011223344556677 开始 (movabsq 用来装入 64 位立即数): 写 1 字节 %al 或 2 字节 %ax 时只改动这几个字节, 高位保持不变; 写 4 字节 %eax 时, 高 32 位被清零; 写 8 字节则整个替换. 规则: 任何产生 32 位结果的指令都会把目标寄存器的高 32 位清零. 这是 x86-64 的设计, 目的是避免对旧值的依赖, 方便流水线.

Slide 19–22

There are several “addressing modes” that allow the CPU to interact with memory through addresses contained in registers. General form: D(%rsi, %rdi, S) = Memory[%rsi + %rdi*S + D] · Special Cases: (%rsi) Memory[%rsi] · (%rsi, %rdi) Memory[%rsi + %rdi] · D(%rsi, %rdi) Memory[%rsi + %rdi + D] · (%rsi, %rdi, S) Memory[%rsi + %rdi*S]

Load effective addressing instruction (lea) does math and does not access memory.

AssemblyC equivalent
mov 6(%rbx,%rdi,8), %axax = *(rbx + rdi*8 + 6)
add 6(%rbx,%rdi,8), %axax += *(rbx + rdi*8 + 6)
xor %ax, 6(%rbx,%rdi,8)*(rbx + rdi*8 + 6) ^= ax
lea 6(%rbx,%rdi,8), %raxrax = rbx + rdi*8 + 6

Why use lea? Compiler authors often use it for ordinary arithmetic · It can do complex calculations in one instruction · It's one of the only three-operand instructions the x86 has · It doesn't touch the condition codes (we'll come back to this)

不只 mov, 很多指令 (add、xor 等) 都可以直接用内存操作数: 读内存、运算、再写回. 而 lea 只算地址, 不访问内存. 编译器常用 lea 做普通算术, 原因有三: 一条指令能完成「加法 + 小常数乘法」; 它是 x86 少有的「三操作数」指令 (结果可以放到第三个寄存器, 不覆盖源); 它不改变条件码 (下一节会看到这很重要).

条件码
Condition codes

Slide 25–26

Every arithmetic and logical operation (except for lea) implicitly updates special single-bit registers called “condition codes”.

  • ZF Zero Flag
  • SF Sign Flag (for signed)
  • OF Overflow Flag (for signed)
  • CF Carry Flag (for unsigned)

GDB prints these as one “eflags” register: eflags 0x246 [ PF ZF IF ] — Z set, CSO clear

Example: addq Src,Dest — t = a + b

ZF1 if t == 0 (otherwise 0)000000000000…00000000000
SFt < 0 (signed)1xxxxxxxxxxx…xxxxxxxxxxx
CF(unsigned) t < (unsigned) a
OF(a < 0 == b < 0) && (t < 0 != a < 0)

除 lea 外, 每条算术和逻辑指令都会顺带更新四个单比特的条件码: ZF 零标志, SF 符号标志, OF 有符号溢出标志, CF 无符号进位标志. gdb 把它们打印成一个 eflags 寄存器, 如 [ PF ZF IF ] 表示 ZF 置位, CF、SF、OF 都是 0 (PF 奇偶、IF 中断允许是本课不用的其他标志).

以 t = a + b 为例: ZF 当 t 为 0; SF 当 t 的最高位为 1; CF 当无符号加法溢出, 这时绕回后的 t 比 a 还小; OF 当 a、b 同号而 t 与它们异号. 后两条正是上一讲判断溢出的方法.

Slide 27–29

CF set when unsigned overflow:

    1xxxxxxxxxxxx...            0xxxxxxxxxxxx...
  + 1xxxxxxxxxxxx...   Carry  - 1xxxxxxxxxxxx...   Borrow
  1 xxxxxxxxxxxxx...          1 1xxxxxxxxxxxx...

OF set when signed overflow:

    wxxxxxxxxxxxx...
  + yxxxxxxxxxxxx...
    zxxxxxxxxxxxx...          w==y && w!=z

Example: addq Src,Dest — t = a+b · ZF 1 if t == 0 (otherwise 0) · SF 1 if t < 0 (as signed) · OF 1 if two's-complement (signed overflow) · CF 1 if carry out from most significant bit (unsigned overflow)

CF: 加法时最高位产生进位, 或减法时最高位需要借位, 即无符号运算溢出. OF: 两个操作数的符号位 w、y 相同, 而结果的符号位 z 与它们不同, 即有符号运算溢出. 同一次加法同时设置所有四个码, CPU 并不知道你把数当成有符号还是无符号; 由后面的跳转指令决定看哪个码.

Slide 30–33

Before sub instruction: sub %rsi, %rax · a in %rsi · b in %rax

After sub instruction: a in %rsi, b in %rax · compute b-a and store in %rax · Condition Codes: ZF 1, SF 0, OF 0, CF 0 · %rax b-a

cmp instruction computes subtraction but does not change second operand. cmp %rsi, %rax · a in %rsi, b in %rax · computes y-x (no store!) · used to compute if ( a < b ) { … }

Why use a cmp instruction instead of a sub instruction to compare two?

sub %rsi, %rax 计算 b − a 并存回 %rax, 同时设置条件码. cmp %rsi, %rax 做同样的减法、设置同样的条件码, 但不保存结果, %rax 仍是 b. 用 cmp 而不用 sub 的原因 (课件的提问): 比较之后通常还需要原来的值, sub 会把 b 覆盖掉, 而 cmp 只留下比较结果, 不必先复制一份.

幻灯片前后不一致: Slide 32 写 "computes y-x", 但同一页用的变量名是 a (在 %rsi) 和 b (在 %rax), 应为 "computes b-a". 另外 Slide 31 的条件码画成 ZF = 1, 这只在 a = b 时成立, 对一般的 a、b 不对; 应理解为一个具体的例子.

Slide 34–35

test instruction computes & but does not change second operand.

test %rdi, %rdi · z (which equals 0) in %rdi · computes z & z (no store!) · only updates ZF and SF! · used to check if %rdi is zero

test %rsi, %rax · a in %rsi, b in %rax · computes a & b (no store!) · used to check if any of the 1-bits in %rax are also set in %rsi (and vice versa)

test 做按位与, 只设置条件码 (只有 ZF 和 SF 有意义, CF、OF 被清零), 不保存结果. test %rdi, %rdi 是判断一个值是否为零 (ZF) 或为负 (SF) 的惯用写法, 比 cmp $0, %rdi 的机器码更短; test %rsi, %rax 判断两者是否有共同的 1 位, 常用于检查标志位.

幻灯片小错: Slide 34 的条件码图里 %rdi = 0、ZF = 1, 但 SF 也画成了 1. 0 & 0 = 0, 最高位是 0, SF 应为 0.

条件分支与条件传送
Conditional branches

Slide 42–43

Programs often need to change control flow based on conditionals. Control flow in x86 is all done with “goto code”.

extern void op1(void);          decision:
extern void op2(void);              subq    $8, %rsp
                                    testl   %edi, %edi
void decision(int x) {              je      .L2
    if (x) {                        call    op1
        op1();                      jmp     .L1
    } else {                    .L2:
        op2();                      call    op2
    }                           .L1:
}                                   addq    $8, %rsp
                                    ret

同上一讲的 decision 例子, 这次是完整版: 多了 subq $8, %rsp 和 addq $8, %rsp. 它们把栈指针下移 8 字节再恢复, 是为了满足 x86-64 调用约定「调用其他函数时栈要 16 字节对齐」的要求 (进入函数时返回地址已占 8 字节, 再减 8 正好对齐). 下一讲讲栈和过程调用时会解释.

Useful to be able to know translation of code to goto style.

Jumps are implemented by updating the pointer to the next instruction (%rip)

0x112d <+4>:   cmp  %rsi,%rdi
0x1130 <+7>:   jle  0x1139 <absdiff+16>
0x1132 <+9>:   mov  %rdi,%rax
0x1135 <+12>:  sub  %rsi,%rax
0x1138 <+15>:  ret
0x1139 <+16>:  mov  %rsi,%rax
0x113c <+19>:  sub  %rdi,%rax
0x113f <+22>:  ret

Before executing line 1: %rip 0x112d · After executing line 1: %rip 0x1130 · After executing line 2: %rip 0x1139

把 if-else 改写成 goto 风格, 就是汇编的结构: 先算出「条件的否定」ntest = x <= y, 成立时跳到 else 分支; 否则顺序执行 then 分支, 再跳过 else. 汇编里 cmp %rsi, %rdi 比较 x 和 y, jle 在 x ≤ y 时跳到 0x1139 (else 分支). 跳转就是修改 %rip: 执行完 cmp 后 %rip 是下一条 0x1130; 若 jle 条件成立, %rip 直接变成 0x1139. 这里编译器把两个分支各自写了 ret, 省掉了 goto Done.

例子 (x = 3, y = 5): cmp 计算 3 − 5 = −2, SF = 1、OF = 0, jle 条件 (SF^OF)|ZF 为真, 跳到 0x1139, 算 y − x = 2.

Using Conditional Moves

  • Conditional Move Instructions
    • Instruction supports: if (Test) Dest ← Src
    • Supported in post-1995 x86 processors
    • GCC tries to use them · But, only when known to be safe
  • Why?
    • Branches are very disruptive to instruction flow through pipelines
    • Conditional moves do not require control transfer
result = Then_Expr;
eval = Else_Expr;
nt = !Test;
if (nt) result = eval;
return result;

条件表达式的两种翻译. 分支版: then 和 else 各一段代码, 只执行其中一段. conditional move 条件传送版: 两个值都先算出来, 再用 cmov 指令「条件成立才传送」选出结果, 不发生跳转.

为什么要条件传送: 现代处理器用流水线同时处理多条指令, 遇到分支必须猜下一步走哪边 (分支预测); 猜错就要清空流水线, 浪费十几个时钟周期. 条件传送没有控制转移, 不需要猜. GCC 只在安全时使用它 (见后面的反例).

Slide 50–55

Alternative to conditional branching with conditional move

absdiff:
    movq    %rdi, %rax    # x
    subq    %rsi, %rax    # result = x-y
    movq    %rsi, %rdx
    subq    %rdi, %rdx    # eval = y-x
    cmpq    %rsi, %rdi    # x:y
    cmovle  %rdx, %rax    # if <=, result = eval
    ret

After executing line 2: %rax x · line 3: %rax x-y · line 4: %rdx y · line 5: %rdx y-x · line 6 and 7: %rax result

同一个 absdiff 用条件传送实现: 先算 result = x − y (放 %rax), 再算 eval = y − x (放 %rdx), 然后 cmpq 比较 x 和 y, cmovle 在 x ≤ y 时把 %rdx 传给 %rax. 无论哪种情况都执行完全相同的 7 条指令, 没有跳转.

Slide 56

Bad Cases for Conditional Move

  • Expensive Computations: val = Test(x) ? Hard1(x) : Hard2(x); — Both values get computed · Only makes sense when computations are very simple — Bad Performance
  • Risky Computations: val = p ? *p : 0; — Both values get computed · May have undesirable effects — Unsafe
  • Computations with side effects: val = x > 0 ? x*=7 : x+=3; — Both values get computed · Must be side-effect free — Illegal

条件传送要求两边都先算, 所以三种情况不能用: 两边计算都很昂贵 (白算一份, 性能更差); 计算有风险 (p 为空时提前算 *p 会段错误); 计算有副作用 (两边都改 x, 结果就错了, 编译器不允许). GCC 只在两个分支都简单、安全、无副作用时才用 cmov.

Slide 58–60

Generic do … while goto conversion

    Body                Body

                            goto loop

Body: { Statement1; Statement2; … Statementn; }

“Do-While” Loop example: Count number of 1s in argument x

long pcount_do                 long pcount_goto
  (unsigned long x) {            (unsigned long x) {
  long result = 0;               long result = 0;
  do {                         loop:
    result += x & 0x1;           result += x & 0x1;
    x >>= 1;                     x >>= 1;
  } while (x);                   if(x) goto loop;
  return result;                 return result;
}                              }

C 有三种循环, 汇编里都要用条件跳转实现. do-while 最直接: 先执行循环体, 再判断条件, 成立就跳回开头. 例子 pcount 统计 x 的二进制中 1 的个数 (popcount): 每次取最低位加到 result, 再把 x 右移一位, 直到 x 变成 0. x 是 unsigned, 所以是逻辑右移, 高位补 0, 循环一定会结束.

Slide 61–67

“Do-While” Loop Compilation

    movl    $0, %eax      # result = 0
.L2:                      # loop:
    movq    %rdi, %rdx
    andl    $1, %edx      # t = x & 0x1
    addq    %rdx, %rax    # result += t
    shrq    %rdi          # x >>= 1
    jne     .L2           # if (x) goto loop
    rep; ret

Loop iteration #1: … After executing line 4: %rdx x & 0x1 · After executing line 5: %rax x & 0x1 · After executing line 6: %rdi x >> 1 · Loop iteration #2: After executing line 6 & 7: (goto .L2) …

%rdi stores loop control variable x · %rax stores return value result

逐行对应: movl $0, %eax 把 result 清零 (写 %eax 同时清零高 32 位); 循环体复制 x 到 %rdx, 与 1 取最低位, 加到 %rax; shrq %rdi 把 x 逻辑右移一位, 并顺带设置 ZF; jne 直接利用 shrq 设置的条件码, x 不为 0 就跳回 .L2. 没有单独的 test/cmp 指令, 这就是「算术指令隐式设置条件码」的用处.

rep; ret 是 AMD 处理器的一个历史技巧: 紧跟在跳转后的单字节 ret 会干扰 AMD 的分支预测器, 加一个无意义的 rep 前缀可以避开, 对程序逻辑没有影响.

while 循环要先判断再执行, 有两种翻译:

  • jump to middle (跳到中间, -Og 时使用): 先无条件跳到循环末尾的判断处, 判断成立再跳回循环体. 只有一份判断代码.
  • guarded do (守护的 do-while, -O1 时使用): 先判断一次, 不成立直接跳到结束; 成立就进入一个 do-while 循环. 判断代码出现两次, 但编译器常常能在编译时确定第一次判断的结果, 把它优化掉, 而且循环体内的跳转更少.
Slide 72–73

“For” Loop → Do-While Loop

For version
for (Init; Test; Update )
    Body

Do-While Version        Goto Version
if (!Test)                  if (!Test)
    goto done;                  goto done;

    Body                        Body
    Update                      Update
} while(Test);                  if (Test)
done:                               goto loop;
                            done:

Initial test can often be optimized away – why?

long pcount_for
  (unsigned long x)
{
  size_t i;
  long result = 0;
  for (i = 0; i < WSIZE; i++)
  {
    unsigned bit =
      (x >> i) & 0x1;
    result += bit;
  }
  return result;
}

Goto Version: i = 0; (Init) · if (!(i < WSIZE)) goto done; (!Test) · loop: { unsigned bit = (x >> i) & 0x1; result += bit; } (Body) · i++; (Update) · if (i < WSIZE) goto loop; (Test) · done: return result; — Initial test can be optimized away

for 循环先改写成 while: Init; while (Test) { Body; Update; }, 再按 guarded-do 翻译. pcount_for 中 Init 是 i = 0, Test 是 i < WSIZE (WSIZE 是字长, 8 × sizeof(long) = 64). 回答课件的问题: 初始判断 0 < 64 在编译时就知道为真, 所以第一次的 if (!Test) goto done 可以整个删掉.

幻灯片错误: Slide 72 的 Do-While 版本和 Goto 版本都漏写了 Init. 正确的转换应以 Init; 开头, 然后才是 if (!Test) goto done;. Slide 73 的具体例子里写了 i = 0, 是对的.

Reverse engineering loops is challenging! — Compiler may use variables in assembly code that have no C equivalent and vice-versa · Compiler may “optimize” away conditional checks · Compiler may reuse registers

If you remember nothing else from this lecture… There are three ways to set condition codes: - Arithmetic and logical operations (not lea) - Test - Cmp. There are many ways to do things different depending on condition condes: - Set bytes - Jumps - Conditional moves. You can mix and match these combinations.

x86-64 code reading tips..

  • Use an x86-64 reference while reading code (you don't need to memorize everything!)
  • You can use gdb hex to decimal conversions! (gdb) print /x 0x8 + 0x8 → 0x10
  • Put a breakpoint before the function that that you want to inspect: (gdb) break phase_1
  • Code trace with simulated inputs like what happens if x is in %rsi and y is %rdi, etc. Write things down and draw things like register state after each instruction.

从汇编还原循环不容易: 编译器会引入 C 里没有的变量 (或删掉 C 里的变量)、优化掉判断、复用寄存器. 本讲最重要的一句话: 设置条件码有三种方式 (算术逻辑指令、test、cmp), 使用条件码也有三种方式 (set 字节、条件跳转、条件传送), 可以任意组合.

读汇编的建议 (bomblab 用得上): 备一份 x86-64 参考表; 用 gdb 的 print /x 做进制换算; 在要看的函数前设断点 (break phase_1); 用假想的输入手工跟踪, 每条指令后把寄存器状态写下来. 原文 "condition condes" 和 "that that" 是笔误.

Switch Statement Example — Multiple case labels · Here: 5 & 6 · Fall through cases · Here: 2 · Missing cases · Here: 4

Jump Table Structure — Switch Form: switch(x) { case val_0: Block 0 · case val_1: Block 1 · • • • · case val_n-1: Block n–1 } · Jump Table jtab: Targ0, Targ1, Targ2, …, Targn-1 · Jump Targets: Targ0: Code Block 0 · Targ1: Code Block 1 · … · Translation (Extended C): goto *JTab[x];

switch 例子包含三种特殊情况: 多个标签共用一段代码 (case 5 和 6); 贯穿 (case 2 没有 break, 执行完继续执行 case 3); 缺失的值 (没有 case 4, 走 default).

当 case 值比较密集时, 编译器用跳转表实现: 一个数组, 第 x 项存放 case x 对应代码块的地址, 执行时直接 goto *JTab[x] (取出地址并跳过去). 不管有多少个 case, 只需一次查表, 比一串 if-else 快.

my_switch:

    .align 8
.L4:
    .quad   .L8   # x = 0
    .quad   .L3   # x = 1
    .quad   .L5   # x = 2
    .quad   .L9   # x = 3
    .quad   .L8   # x = 4
    .quad   .L7   # x = 5
    .quad   .L7   # x = 6

Table Structure — Each target requires 8 bytes · Base address at .L4

Jumping — Direct: jmp .L8 · Jump target is denoted by label .L8 · Indirect: jmp *.L4(,%rdi,8) · Start of jump table: .L4 · Must scale by factor of 8 (addresses are 8 bytes) · Fetch target from effective Address .L4 + x*8 · Only for 0 ≤ x ≤ 6

汇编: 先 cmpq $6, %rdi 再 ja (无符号的「高于」): 把 x 当无符号数与 6 比较, 一次就同时排除了 x > 6 和 x < 0 两种越界 (负数当成无符号是很大的数), 都跳到 default. 然后间接跳转 jmp *.L4(,%rdi,8): 从地址 .L4 + 8x 处取出 8 字节的目标地址并跳过去. 星号表示间接跳转.

跳转表放在只读数据段 .rodata, 8 字节对齐, 每项一个 .quad 地址. x = 0 和 4 没有对应的 case, 填 default 的地址 .L8; 5 和 6 都填 .L7.

Handling Fall-Through — case 2: w = y/z; goto merge; · case 3: w = 1; merge: w += z;

Code Blocks (x == 2, x == 3)

.L5:                      # Case 2
    movq    %rsi, %rax
    cqto
    idivq   %rcx          # y/z
    jmp     .L6           # goto merge
.L9:                      # Case 3
    movl    $1, %eax      # w = 1
.L6:                      # merge:
    addq    %rcx, %rax    # w += z
    ret

Code Blocks (x == 5, x == 6, default)

.L7:                      # Case 5,6
    movl    $1, %eax      # w = 1
    subq    %rdx, %rax    # w -= z
    ret
.L8:                      # Default:
    movl    $2, %eax      # 2
    ret

Register Use(s): %rdi Argument x · %rsi Argument y · %rdx Argument z · %rax Return value

各代码块: case 1 计算 y·z. 贯穿的处理: case 2 算出 w = y/z 后跳到公共的 merge 处; case 3 先把 w 设为 1 再落到 merge; merge 处执行 w += z. case 5、6 是 1 − z, default 返回 2.

除法细节: idivq 把 128 位的 %rdx:%rax 除以操作数, 商放 %rax、余数放 %rdx. 所以先 cqto 把 %rax 符号扩展到 %rdx:%rax, 这会覆盖 %rdx. 因此编译器在函数开头就把 z 从 %rdx 复制到了 %rcx (见下一页的反汇编第一条 mov %rdx,%rcx), case 2、3 用的是 %rcx. 课件 Slide 80 的汇编省略了这条指令, 表里也只写了 %rdx 是 z.

Slide 88–93

Which numbers are pointers?

  • They aren't labeled · You have to figure it out from context
  • %rsp and %rip always hold pointers
  • Register values that are “close” to %rsp or %rip are probably also pointers
  • If a register is being used as a pointer… mov (%rsi), %rsi · …Then its value is expected to be a pointer. · There might be a bug that makes its value incorrect.
  • Not as obvious with complicated address “modes”
    • (%rsi, %rbx) – One of these is a pointer, we don't know which.
    • (%rsi, %rbx, 2) – %rsi is a pointer, %rbx isn't (why?)
    • 0x400570(, %rbx, 2) – 0x400570 is a pointer, %rbx isn't (why?)
    • lea (anything), %rax – (anything) may or may not be a pointer

寄存器里的数没有类型标签, 是不是指针要靠上下文判断: %rsp、%rip 永远是指针; 数值和 %rsp 接近的 (0x7fff… 开头, 栈区) 或和 %rip 接近的 (0x40… 开头, 代码和全局数据区) 很可能也是指针; 被放在括号里当地址用的, 程序认为它是指针 (当然可能有 bug). 例子里 rdx、rsi 是栈上的地址 (实际上是 main 的 envp、argv), rdi = 1 是 argc.
