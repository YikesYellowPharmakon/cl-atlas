Slide 5–6

CPUs store data in Registers and Memory

  • Registers: Super-fast memory right on the CPU core itself.
    • About 16 named registers on x86
  • Many instructions operate on registers
  • Registers are fixed-width, often 32 or 64 bits
  • “int x = 5; x *= y; x++” – x is probably stored in a register while being operated on frequently.
  • Registers are accessed by their name
  • “Memory” means DRAM, typically off-chip storage, bigger and cheaper and slower. When you call “malloc”, you usually get this.
  • Memory is accessed by (byte) address

Introduction to Assembly

  • Assembly is a programming language
    • It has types
    • It has control flow shape
    • It is also an intermediate, very limited verbs, need to be explicit
  • Assembly is defined by the ISA (instruction set architecture)
    • x86, ARM, RISC-V, etc
  • Implemented by the microarchitecture - e.g., a “core i7” x86 processor

CPU 把数据放在两个地方: register 寄存器, 在 CPU 核心内部, 极快, x86 上约有 16 个有名字的通用寄存器, 宽度固定 (32 或 64 位), 按名字访问, 频繁使用的局部变量通常就放在寄存器里; memory 内存, 指 DRAM, 一般在芯片外, 更大、更便宜、更慢, malloc 分配的就是这里, 按字节地址访问.

汇编也是一门编程语言: 有类型 (操作数的大小)、有控制流, 但「动词」很少, 什么都要写明. 汇编由 ISA (指令集体系结构, 如 x86、ARM、RISC-V) 定义, 由微体系结构 (具体的处理器, 如 Core i7) 实现.

X86 registers – some history

Intel created x86 in the 16-bit microprocessor 8086. Its registers held 16 bits. So: “ax”, the “accumulator”, stored 16 bits of data. Initially the registers had a defined purpose. (They mostly don't now.) In 1985, Intel introduced the 32-bit 80386, and “e”xtended the registers to 32 bits, creating “eax”. In 2003, AMD introduced x86-64, growing registers to 64 bits and creating “rax”.

汇编的「语法」: 操作 + 操作数. 本课用 AT&T 语法 (GCC 默认), 寄存器名前加 %, 源操作数在前、目标在后: add %rbx, %rax 表示 rax += rbx. (Intel 语法的顺序相反, 读别的资料时要注意.)

「名词」是寄存器和内存. 寄存器名有固定规律: %rax、%rbx、%rcx、%rdx; %rdi、%rsi; %rbp、%rip、%rsp (有特殊含义); %r8–%r15. 名字的来历: 8086 是 16 位, ax 是累加器; 1985 年 80386 扩展到 32 位, 加前缀 e 成为 eax; 2003 年 AMD 推出 x86-64, 扩展到 64 位, 改前缀为 r 成为 rax. 当初每个寄存器有特定用途, 现在大多已是通用的.

x86-64 有 16 个 64 位整数寄存器. 每个都可以只访问低 4 字节 (%eax、%r8d), 也可以访问低 2 字节 (%ax、%r8w) 和低 1 字节 (%al、%r8b). 寄存器不属于内存, 也不在缓存里, 没有地址.

易错: 往 32 位寄存器 (如 %eax) 写入时, 硬件会把对应 64 位寄存器的高 32 位清零; 往 16 位或 8 位部分写入时, 其余位保持不变. 这是后面 movzbl %al, %eax 能把整个 %rax 清干净的原因.

「动词」只有三类: 在内存和寄存器之间搬运数据 (load 从内存读到寄存器, store 从寄存器写回内存); 对寄存器或内存中的数据做算术运算; 转移控制 (无条件跳转、过程调用和返回、条件分支、间接跳转).

mov 是最基本的指令, 把源复制到目标. 三种操作数: immediate 立即数, 以 $ 开头的常数; 寄存器; 内存, 用括号表示, (%rsi) 就是 C 的 *p, 即「以 %rsi 的值为地址的那块内存」. 括号总是表示地址计算 + 访问内存.

void swap
  (long *xp, long *yp)
{
  long t0 = *xp;      /* movq (%rdi), %rax */
  long t1 = *yp;      /* movq (%rsi), %rdx */
  *xp = t1;           /* movq %rdx, (%rdi) */
  *yp = t0;           /* movq %rax, (%rsi) */
}                     /* ret */

We have now written the “pseudo-C” for the assembly, using the types and replacing each register with a “variable name”.

读汇编的练习: 第一个参数在 %rdi、第二个在 %rsi (见后面的调用约定). %rdi 被放在括号里使用, 说明它是一个地址, 所以参数类型是指针; movq 一次搬 8 字节, 所以指向 long. 逐条翻译: 读 *xp 到 %rax, 读 *yp 到 %rdx, 再交叉写回. 这就是交换两个 long 的 swap 函数. 方法: 给每个寄存器起一个变量名, 把每条指令改写成 C 语句, 得到「伪 C」.

逐步执行 (初始: %rdi = 0x120, %rsi = 0x100, 内存 0x120 处是 123, 0x100 处是 456):

  1. movq (%rdi), %rax: 读地址 0x120, %rax = 123.
  2. movq (%rsi), %rdx: 读地址 0x100, %rdx = 456.
  3. movq %rdx, (%rdi): 把 456 写到 0x120.
  4. movq %rax, (%rsi): 把 123 写到 0x100.

寄存器 %rdi、%rsi 的值 (地址) 始终没变, 变的是它们指向的内存.

幻灯片错误: 这两页的汇编和上面的 C 代码对不上.

  • Slide 25: d[y] = a 是把一个 char 写进内存, 应为 1 字节的 store, 如 movb %al, (%rdi,%rsi); 课件写成 movq %rax, (%rdi, %rsi), 后面还多了一个 ", %rax", 既是 8 字节写入又不是合法的两操作数格式.
  • Slide 26: 同样是 d[y] = a (store), 课件却写成从内存读到 %rax 的 movq (%rdi, %rsi, 4), %rax (load), 方向反了; int 是 4 字节, 应为 movl %eax, (%rdi,%rsi,4) (a 先符号扩展成 int). 另外声明的是 int s, 下标用的却是 y.

比例因子 4 = sizeof(int) 这个要点是对的.

Slide 27–28

Generalized memory grammar

D(Rb,Ri,S) → Mem[Reg[Rb]+S*Reg[Ri]+ D]

  • D: Constant “displacement” 1, 2, or 4 bytes
  • Rb: Base register: Any of 16 integer registers
  • Ri: Index register: Any, except for %rsp
  • S: Scale: 1, 2, 4, or 8

If a value is “missing”, it is the identity element: +0 or *1

Address Computation Examples (%rdx = 0xf000, %rcx = 0x0100)

ExpressionAddress ComputationAddress
0x8(%rdx)0xf000 + 0x80xf008
(%rdx,%rcx)0xf000 + 0x1000xf100
(%rdx,%rcx,4)0xf000 + 4*0x1000xf400
0x80(,%rdx,2)2*0xf000 + 0x800x1e080

通用寻址方式 D(Rb, Ri, S), 地址 = Rb + S·Ri + D. D 是 1、2 或 4 字节的常数偏移; 基址寄存器 Rb 可以是任意整数寄存器; 变址寄存器 Ri 可以是除 %rsp 以外的任何一个; 比例因子 S 只能是 1、2、4、8 (正好对应 char、short、int、long/指针的大小). 省略的部分取单位元: 偏移省略为 0, 比例省略为 1.

例子逐个算: 0x80(,%rdx,2) 没有基址, 是 2 × 0xf000 + 0x80 = 0x1e000 + 0x80 = 0x1e080. 这种写法常用于访问全局数组 (基址是常数).

Address Computation Instruction

  • leaq Src, Dst
    • Src is address mode expression
    • Set Dst to address denoted by expression
  • Uses
    • Computing addresses without a memory reference
      • E.g., translation of p = &x[i];
    • Computing arithmetic expressions of the form x + k*y
      • k = 1, 2, 4, or 8
long m12(long x)            Converted to ASM by compiler:
{
  return x*12;              leaq (%rdi,%rdi,2), %rax   # t = x+2*x
}                           salq $2, %rax              # return t<<2

leaq (load effective address) 用寻址方式的语法计算地址, 但不访问内存, 直接把地址值放进目标寄存器. 用途: 取地址 (p = &x[i]); 更常见的是借它做 x + k·y 形式的算术 (k = 1、2、4、8), 一条指令完成加法和乘法. 例: x·12 = (x + 2x) · 4, 编译器先用 leaq 算 3x, 再左移 2 位.

易错: leaq (%rdi), %rax 是 rax = rdi; movq (%rdi), %rax 是 rax = *rdi. 括号在 lea 里不表示访问内存.

Slide 31

Registers have conventions

  • Architectural requirements:
    • %rip – program counter / instruction pointer
      • Only points to the next instruction to execute
    • %rsp – stack pointer
    • %rbp – sometimes also stack related
  • “Calling Convention” (must be agreed upon for interop!)
    • %rax – return value
    • %rdi – first argument
    • %rsi – second argument
    • %rdx – third argument
    • …

寄存器有约定用途. 体系结构规定的: %rip 是程序计数器 (指令指针), 永远指向下一条要执行的指令; %rsp 是栈指针; %rbp 有时也和栈有关. 调用约定 (编译器和库都要遵守, 才能互相调用): %rax 放返回值, 参数依次放 %rdi、%rsi、%rdx (后面还有 %rcx、%r8、%r9, 第 5 讲详述). 读汇编时先看函数用了哪些参数寄存器, 就知道有几个参数.

%rdiArgument x

综合练习: 用到 %rdi、%rsi、%rdx, 所以有 3 个参数; 全用 q 后缀, 是 long; 返回值在 %rax. 逐条对应:

  • leaq (%rdi,%rsi) → t1 = x + y; addq %rdx → t2 = t1 + z.
  • leaq (%rsi,%rsi,2) 得 3y, salq $4 再乘 16, 得 t4 = 48y. 编译器把乘 48 拆成了 lea + 移位.
  • leaq 4(%rdi,%rdx) 得 x + 4 + 48y, 把 t3 = x + 4 和 t5 = t3 + t4 合并成一条指令, t3 根本没有单独出现.
  • imulq 算 rval = t2 · t5.

寄存器会被复用: %rdx 先是参数 z, 用完后存 t4; %rax 依次存 t1、t2、rval. C 的局部变量不一定一一对应寄存器.

Condition codes and jumps

Slide 35–39

Expressing Inequality — We want to express numeric relations in assembly: Equals, not equals · Greater, less than

Control Flow — We also need assembly to make decisions based on these (in)equalities · We call the sequence of instructions executed, the control flow

extern void op1(void);
extern void op2(void);

void decision(int x) {
    if (x) {
        op1();
    } else {
        op2();
    }
}
decision:
    testl   %edi, %edi
    je      .L2
    call    op1
    jmp     .L1
.L2:
    call    op2
.L1:
    ret

It's all done with GOTO!

Conditional “Goto” — The first jump instruction is conditional · It uses processor state set by the test instruction · Processor has special registers to hold specific state · We call this specific state, “condition codes”

汇编需要表达大小关系, 并据此改变控制流 (实际执行的指令序列). 汇编里没有 if/else, 全靠 goto: testl %edi, %edi 检查 x 是否为 0, 设置处理器的状态位; je .L2 在「等于零」时跳到 else 分支; 否则顺序执行 call op1, 然后 jmp .L1 跳过 else 部分. 这些保存比较结果的特殊状态位叫 condition codes 条件码.

Slide 40–42

Expressing Inequality — x86 has two instructions to set the specific state: cmp · test — Instructions other than lea also implicitly set the state on x86

Compare Instruction — cmp a, b · Computes 𝑏 − 𝑎 (just like sub) · Sets condition codes based on result, but… · Does not change 𝒃 · Used for if (a < b) { … } whenever 𝑏 − 𝑎 isn't needed for anything else

Test Instruction — test a, b · Computes 𝑏&𝑎 (just like and) · Sets condition codes (only SF and ZF) based on result, but… · Most common use: test %rX, %rX to compare %rX to zero · Second most common use: test %rX, %rY tests if any of the 1-bits in %rY are also 1 in %rX (or vice versa)

两条专门设置条件码的指令: cmp a, b 计算 b − a (和 sub 一样), 只设置条件码, 不保存结果; test a, b 计算 b & a (和 and 一样), 也只设置条件码. 最常见的用法 test %rax, %rax 判断 %rax 是否为零或为负; test %rX, %rY 判断两者是否有共同的 1 位. 除 lea 外, 大多数算术指令也会顺带设置条件码 (lea 不设, 所以编译器喜欢用它做算术而不破坏条件码).

四个条件码: ZF 结果为零; SF 结果为负 (最高位是 1); CF 无符号运算产生进位/借位 (无符号溢出); OF 有符号运算溢出.

易错: AT&T 语法中 cmp a, b 比较的是 b 和 a, 后面的 jg 表示「b > a」时跳转.

为什么「小于」是 SF ^ OF: cmp 算 b − a. 不溢出时, 结果为负 (SF = 1) 就说明 b < a; 若发生有符号溢出 (OF = 1), 结果的符号是反的. 所以 b < a 当且仅当 SF 和 OF 不同. 例: 4 位时 b = −8, a = 1, b − a = −9 溢出成 +7, SF = 0、OF = 1, 异或为 1, 判断为小于, 正确. 无符号的「低于」看借位 CF 即可.

    • Y – source bit width
    • Z – destination bit width
  • movzbl %al, %eax
    • z – zero
    • b – source is 1 byte
    • l – destination is 4 bytes

要把比较结果作为值返回, 用 setX: 根据条件码把目标的最低字节设为 0 或 1, 其余字节不变. gt 函数: cmpq %rsi, %rdi 比较 x 和 y (计算 x − y); setg %al 在 x > y 时把 %al 设为 1; movzbl 把 %al 零扩展到 %eax, 而写 %eax 又会清零 %rax 的高 32 位, 这样整个 %rax 就是干净的 0 或 1.

带扩展的 mov 有两个大小后缀: movzXY 零扩展、movsXY 符号扩展, X 是源大小、Y 是目标大小. movzbl = 1 字节零扩展到 4 字节; movsbq = 1 字节符号扩展到 8 字节. 对应上一讲的「无符号补 0、有符号做符号扩展」.

Slide 50–51

Where does it come from?

  • Assembly is usually generated by the compiler
    • We can ask the compiler to show us the assembly
    • We can also generate assembly from machine code
  • The compiler runs a separate tool that generates machine code
    • Machine code is just bytes in memory
  • Execution gives bytes their “types”

Turning C into Object Code

  • Code in files p1.c p2.c
  • Compile with command: gcc –Og p1.c p2.c -o p
    • Use debugging-friendly optimizations (-Og)
    • Put resulting binary in file p

text C program (p1.c p2.c) → Compiler (gcc –Og -S) → text Asm program (p1.s p2.s) → Assembler (gcc –c or as) → binary Object program (p1.o p2.o) + Static libraries (.a) → Linker (gcc or ld) → binary Executable program (p)

汇编通常由编译器生成, 可以让编译器把它输出来, 也可以从机器码反汇编得到. 机器码只是内存里的字节, 字节本身没有类型, 「执行」才赋予它们类型 (被当作指令执行就是指令, 被当作数据读就是数据).

编译流程: C 源文件 → 编译器 (gcc -S) 生成文本的汇编 .s → 汇编器 (gcc -c 或 as) 生成二进制的目标文件 .o → 链接器 (gcc 或 ld) 把目标文件和静态库 .a 合成可执行文件. -Og 是「便于调试」的优化级别, 生成的汇编和 C 代码对应得比较整齐.

Slide 52–54

Compiling Into Assembly

long plus(long x, long y);

void sumstore(long x, long y,
              long *dest)
{
    long t = plus(x, y);
    *dest = t;
}
sumstore:
    pushq   %rbx
    movq    %rdx, %rbx
    call    plus
    movq    %rax, (%rbx)
    popq    %rbx
    ret

Obtain (on shark machine) with command gcc –Og –S sum.c · Produces file sum.s · Warning: Will get very different results on non-Shark machines (Andrew Linux, Mac OS-X, …) due to different versions of gcc and different compiler settings.

What it really looks like

    .globl  sumstore
    .type   sumstore, @function
sumstore:
.LFB35:
    .cfi_startproc
    pushq   %rbx
    .cfi_def_cfa_offset 16
    .cfi_offset 3, -16
    movq    %rdx, %rbx
    call    plus
    movq    %rax, (%rbx)
    popq    %rbx
    .cfi_def_cfa_offset 8
    ret
    .cfi_endproc
.LFE35:
    .size   sumstore, .-sumstore

Things that look weird and are preceded by a ‘.’ are generally directives.

sumstore 的汇编: dest 在 %rdx 中, 但调用 plus 会改动 %rdx (调用者保存寄存器), 所以先把 %rbx 原值压栈保存, 再把 dest 放进 %rbx (被调用者保存寄存器, plus 必须保证它不变); plus 的返回值在 %rax, 写到 *dest; 最后恢复 %rbx 并返回. 寄存器保存规则在第 5 讲 (过程) 详细讲.

真实的 .s 文件里还有很多以点开头的行, 它们是伪指令 (directive), 给汇编器和调试器的信息 (.globl 导出符号、.cfi_* 是栈回溯用的调用帧信息), 不对应机器指令. 不同机器、不同 gcc 版本生成的汇编会有差别.

Object Code — Code for sumstore

0x0400595:  0x53 0x48 0x89 0xd3 0xe8 0xf2 0xff 0xff 0xff 0x48 0x89 0x03 0x5b 0xc3

Total of 14 bytes · Each instruction 1, 3, or 5 bytes · Starts at address 0x0400595

  • Assembler
    • Translates .s into .o
    • Binary encoding of each instruction
    • Nearly-complete image of executable code
    • Missing linkages between code in different files
  • Linker
    • Resolves references between files
    • Combines with static run-time libraries · E.g., code for malloc, printf
    • Some libraries are dynamically linked · Linking occurs when program begins execution

Machine Instruction Example — C Code: *dest = t; Store value t where designated by dest · Assembly: movq %rax, (%rbx) · Move 8-byte value to memory · Quad words in x86-64 parlance · Operands: t: Register %rax · dest: Register %rbx · *dest: Memory M[%rbx] · Object Code: 0x40059e: 48 89 03 · 3-byte instruction · Stored at address 0x40059e

assembler 汇编器把 .s 翻译成 .o: 每条指令编码成二进制, 得到几乎完整的可执行代码, 只缺不同文件之间的引用 (比如 plus 的地址). linker 链接器解决文件之间的引用, 合并静态库 (如 malloc、printf 的代码); 动态链接的库要等程序开始运行时再链接. 第 7 讲专门讲链接.

sumstore 的机器码共 14 字节, 6 条指令长度为 1、3、5、3、1、1 字节 (x86 指令是变长的). 例: *dest = t 编译成 movq %rax, (%rbx), 机器码 48 89 03 共 3 字节, 存在地址 0x40059e.
