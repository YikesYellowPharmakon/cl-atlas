The x86-64 Stack

Some things we need to review from last time… An x86 program's view (CPU: PC, registers, condition codes; Memory: Operating system, Code, Data, Heap, Stack)

Traditional view of a stack — %rsp is the stack pointer · It points to the current “top of the stack”

Address0xff500xff580xff600xff680xff700xff780xff800xff88

本讲讲 C 的过程 (函数) 调用在 x86-64 上如何实现. 核心数据结构是栈: 内存中的一块区域, 后进先出. 寄存器 %rsp 是栈指针, 指向当前栈顶元素. 例子里栈底在 0xff88, 栈顶元素 0xfc43 在 0xff70; 每个元素 8 字节.

Slide 7–13

A traditional view of the stack shows growing the stack from the “bottom up”. Pushing onto the stack puts an element on the top of the stack. Popping elements off the stack removes the most recent thing added to the stack.

By convention in this class, we draw the x86-64 stack “upside down”! The stack grows down towards lower addresses. This is still “last-in-first-out” but we show the it growing down rather than up. Pushing elements puts them on top of the stack (but we show this upside down). Popping is different than removing the element! Let's look at the instructions and examples.

栈的生长方向: x86-64 的栈向低地址增长, 压入一个元素, %rsp 减 8. 本课画图时把高地址画在上面、低地址画在下面, 所以栈看起来是「倒挂」的, 栈顶在图的下方. 这仍然是后进先出, 只是画法. 「弹出」和「删除」不同, 见下面的 popq.

Slide 14–22

Pushing stack data with pushq — pushq Src: 1. Decrement %rsp by 8 bytes · 2. Write operand into the address given by %rsp

Example: pushq %rbp (%rsp 0xff70 → 0xff68, %rbp = 0xabcd): 0xff68 now holds 0xabcd.

Popping stack data with popq — popq Dest: 1. Read from address given by %rsp and store in operand · 2. Increment %rsp by 8 bytes

Example: popq %rdx (%rsp 0xff68 → 0xff70): %rdx = 0xabcd.

Important Note: Value is copied into Dest, it is still in memory at old %rsp

Summary: Pushing and popping stack data

pushq %rbp              popq %rdx
is equivalent to        is equivalent to
subq $8, %rsp           movq (%rsp), %rdx
movq %rbp, (%rsp)       addq $8, %rsp

pushq Src: 先把 %rsp 减 8, 再把操作数写到 %rsp 指向的地址. popq Dest: 先从 %rsp 指向的地址读出 8 字节放进 Dest, 再把 %rsp 加 8. 例: %rbp = 0xabcd, %rsp = 0xff70, pushq %rbp 后 %rsp = 0xff68, 地址 0xff68 存 0xabcd; 接着 popq %rdx, %rdx = 0xabcd, %rsp 回到 0xff70.

重要: pop 只是复制并移动 %rsp, 0xabcd 仍留在内存 0xff68 处, 只是不再属于栈 (下次 push 会覆盖它). 所以栈上「已释放」的数据可能还能被读到, 这在安全上很重要.

过程调用需要的机制
Mechanisms in procedures

Slide 23–33

Today: How does x86-64 implement C procedure calls? Mechanisms in procedures · Calling Conventions: Passing Control · Passing Data · Managing Local Data

void multstore
  (long x, long y, long *dest)
{
  long t = mult2(x, y);
  *dest = t;
}

long mult2(long a, long b)
{
  long s = a * b;
  return s;
}
  • Passing Control: Program needs to stop execution of caller (multstore) to execute callee (mult2) and then return to caller and continue execution.
  • Passing Data: Program needs to pass arguments to callee (mult2) and return values to caller (multstore).
  • Managing Local Memory: Program may need to allocate memory for local variables in callee (mult2) and then deallocate after returning to caller (multstore).

实现过程调用需要三种机制, 以 multstore 调用 mult2 为例:

  • 传递控制: caller 调用者 multstore 暂停, 转去执行 callee 被调用者 mult2, 结束后回到调用者原来的位置继续.
  • 传递数据: 把参数 x、y 传给 mult2, 再把返回值 s 传回.
  • 管理局部数据: 被调用者执行时可能需要局部变量的空间, 返回时释放.

这三者都由调用约定 (calling convention) 规定, 编译器和库都遵守它, 不同编译器编出的代码才能互相调用.

传递控制
Passing Control

Slide 35–36 
0000000000400540 <multstore>:
  400540: push %rbx               # Save %rbx
  400541: mov  %rdx,%rbx          # Save dest
  400544: call 400550 <mult2>     # mult2(x,y)
  400549: mov  %rax,(%rbx)        # Save at dest
  40054c: pop  %rbx               # Restore %rbx
  40054d: ret                     # Return

0000000000400550 <mult2>:
  400550: mov  %rdi,%rax          # a
  400553: imul %rsi,%rax          # a * b
  400557: ret                     # Return

To implement passing control, programs use call and ret instructions which use the stack to store return address.

  • call addr <label>: 1. Push return address on stack · 2. Jump to addr
  • ret: 1. Pop return address on stack · 2. Jump to return address

传递控制靠 call 和 ret, 二者用栈保存返回地址. call addr: 把下一条指令的地址 (返回地址) 压栈, 再跳到 addr. ret: 从栈顶弹出返回地址, 跳回去. 因为返回地址存在栈上而不是固定位置, 函数可以嵌套调用和递归调用, 每层的返回地址按后进先出的顺序取回.

Slide 37–45

Before call: %rsp 0x120 · %rip 0x400544

Executing call: push return address — %rsp 0x118 · memory 0x118: 0x400549

Executing call: jmp to address of function to execute — %rip 0x400550

Before ret: %rip 0x400557 · %rsp 0x118

Executing ret: pop return address — %rsp 0x120

Executing ret: jmp to return address — %rip 0x400549 (mov %rax,(%rbx) # Save at dest)

逐步跟踪: 执行 call 前 %rsp = 0x120, %rip = 0x400544 (call 指令本身). call 先把返回地址 0x400549 (call 的下一条指令) 压栈, %rsp 变成 0x118; 再把 %rip 设为 mult2 的起点 0x400550. mult2 执行到 ret 时, %rsp 仍是 0x118 (mult2 没有动栈); ret 弹出 0x400549, %rsp 回到 0x120, %rip = 0x400549, 回到 multstore 继续执行 mov %rax,(%rbx).

传递数据
Passing Data

Slide 48–51

The first 6 arguments to a procedure are stored in registers, the remaining are stored on stack. As illustrated in the activity:

Registers%rdi%rsi%rdx%rcx%r8%r9
Arg 1Arg 2Arg 3Arg 4Arg 5Arg 6

Stack: … Arg n … Arg 8, Arg 7 (Arg 7 nearest the top)

Important note: Programs only allocate stack space when it is needed.

Example of where arguments and return values are stored: multstore: # x in %rdi, y in %rsi, dest in %rdx … # t in %rax · mult2: # a in %rdi, b in %rsi … # s in %rax

Arguments are “passed” in the argument registers. Return values are “returned” in return register.

前 6 个整数或指针参数依次放在 %rdi、%rsi、%rdx、%rcx、%r8、%r9 (记忆: "Diane's silk dress costs $89"); 第 7 个及以后的参数放在栈上, 第 7 个离栈顶最近. 返回值放 %rax. 只有确实需要时才分配栈空间, 大多数函数参数少于 7 个, 完全不碰栈.

例子: multstore 的 x、y、dest 分别在 %rdi、%rsi、%rdx; 调用 mult2 时, x、y 恰好已在 mult2 的第 1、2 个参数位置, 不用移动; mult2 的结果 s 放在 %rax 返回.

管理局部数据: 栈帧
Managing Local Data

Slide 53–56

Languages that support recursion like C require some place to store state for each instantiation of the same procedure.

  • Code must be “reentrant”: Support multiple instances of a single procedure
  • Requires needing some place to store state of each instantiation including arguments, local variables, and return value
  • The stack allocated in frames where each frame contains state for a given procedure
yoo(…)          who(…)          amI(…)
{               {               {
  •               • • •           •
  who();          amI();          amI();
  •               • • •           •
}                 amI();        }
                  • • •
                }
Procedure amI() is recursive
Call Chain: yoo → who → amI → amI → amI, and who → amI

When calling a procedure, that procedure's stack frame is pushed onto the stack. The “setup” code: The program allocates space on the stack (if needed) and does call instruction. The “finish” code: The program deallocates space on the stack (if needed) and does ret instruction. (Previous Frame · Frame for proc · Frame Pointer: %rbp (Optional) · Stack Pointer: %rsp · Stack “Top”)

C 支持递归, 同一个函数可能同时有多个实例在执行 (代码必须可重入), 每个实例都需要自己的参数、局部变量和返回地址. 解决办法: 每次调用在栈上分配一个stack frame 栈帧, 存放这一次调用的状态; 返回时释放. 栈帧的分配和释放正好符合后进先出.

调用链例子: yoo 调用 who, who 两次调用 amI, amI 递归调用自己. 进入一个函数时它的栈帧压在栈顶 (设置代码: 必要时分配空间, 执行 call), 返回时弹出 (结束代码: 释放空间, 执行 ret). %rsp 指向当前帧的顶部; %rbp 可以作为帧指针指向当前帧的底部, 但这是可选的, 现代编译器默认不用.

Slide 57–67

Example (animation): Stack contents as the call chain proceeds —

yoo → yoo, who → yoo, who, amI → yoo, who, amI, amI → yoo, who, amI, amI, amI → (returns) yoo, who, amI, amI → yoo, who, amI → yoo, who → yoo, who, amI → yoo, who → yoo

(%rbp and %rsp delimit the current top frame at each step.)

动画逐步展示调用链对应的栈: 每调用一次, 栈顶加一个帧; 每返回一次, 栈顶的帧去掉. amI 递归三层时栈上同时有三个 amI 的帧, 各自保存自己的局部状态, 互不干扰. 之后 who 第二次调用 amI, 新的 amI 帧占用的是刚才释放的同一块栈空间. 任何时刻, 只有栈顶的帧是活动的 (正在执行的函数), 其余帧都在等待被调用的函数返回.

Slide 69

x86-64/Linux Stack Frame

  • Current stack frame is on the top of the stack and is the current executing procedure
  • Caller stack frame has return address pushed by call instruction and the arguments for this call

Important Note: Stack space only allocated if needed by procedure!

一个栈帧从高地址到低地址的内容: 调用者帧的末尾是本次调用的第 7 个以后的参数, 然后是 call 压入的返回地址 (算作调用者帧的一部分); 当前帧中, 可选的旧 %rbp (使用帧指针时保存), 被调用者需要保存的寄存器和局部变量, 最下面是「参数构造区」, 当前函数调用别的函数且参数超过 6 个时, 在这里放第 7 个以后的参数. 各部分都只在需要时才存在, 简单的函数 (如 mult2) 根本没有栈帧.

Slide 70–71

Example: incr

long incr(long *p, long val) {
  long x = *p;
  long y = x + val;
  *p = y;
  return x;
}
incr:
    movq    (%rdi), %rax
    addq    %rax, %rsi
    movq    %rsi, (%rdi)
    ret

Register Use: %rdi Argument p · %rsi Argument val, y · %rax x, Return value

Example: Calling incr with a local variable address

long call_incr() {
  long v1 = 15213;
  long v2 = incr(&v1, 3000);
  return v1+v2;
}
call_incr:
    subq    $16, %rsp
    movq    $15213, 8(%rsp)
    movl    $3000, %esi
    leaq    8(%rsp), %rdi
    call    incr
    addq    8(%rsp), %rax
    addq    $16, %rsp
    ret

incr 把 *p 加上 val, 返回原来的值: 读 *p 到 %rax (x, 也是返回值), 把 x 加到 %rsi 上得 y, 再写回 *p.

call_incr 需要把局部变量 v1 的地址传给 incr, 而寄存器没有地址, 所以 v1 必须放在内存里, 也就是栈上. 这是局部变量必须放栈上的典型原因之一 (其他原因: 寄存器不够用、局部数组或结构体).

Slide 72–85

Before calling incr: Storing arguments — Initial Stack Structure: … Return address ← %rsp · Resulting Stack Structure: Return address · 15213 (%rsp+8) · Unused (%rsp)

Registers: %rdi &v1 · %rsi 3000

Aside 1: movl $3000, %esi — Remember, movl -> %exx zeros out high order 32 bits. · Why use movl instead of movq? 1 byte shorter.

Aside 2: leaq 8(%rsp), %rdi — Computes %rsp+8 · Actually, used for what it is meant!

Calling incr — … After calling incr: Getting return value — %rax Return value (15213) · stack: 18213 (%rsp+8)

After calling incr: Calculating return value — addq 8(%rsp), %rax · Deallocate space — addq $16, %rsp · Updated Stack Structure: Rtn address ← %rsp · Returning — ret · Final Stack Structure: … ← %rsp

逐步看栈:

  1. subq $16, %rsp: 分配 16 字节的栈帧 (只用 8 字节, 多出的 8 字节是为了让栈保持 16 字节对齐).
  2. movq $15213, 8(%rsp): v1 放在 %rsp + 8.
  3. movl $3000, %esi: 第二个参数. 用 movl 而非 movq: 写 32 位寄存器会自动清零高 32 位, 效果相同, 而机器码短 1 字节.
  4. leaq 8(%rsp), %rdi: 第一个参数是 v1 的地址 %rsp + 8. 这里 lea 用于它的本意: 计算地址.
  5. call incr: incr 把栈上的 v1 改成 15213 + 3000 = 18213, 返回旧值 15213 (在 %rax).
  6. addq 8(%rsp), %rax: 15213 + 18213 = 33426, 即 v2 + v1 (此时 v1 已是 18213).
  7. addq $16, %rsp 释放栈帧, ret 返回.

寄存器保存约定
Register Saving Conventions

Slide 86–87

Register Saving Conventions — When procedure yoo calls who: yoo is the caller · who is the callee · Can register be used for temporary storage?

yoo:                        who:
    • • •                       • • •
    movq  $15213, %rdx          subq  $18213, %rdx
    call  who                   • • •
    addq  %rdx, %rax            ret
    • • •
    ret
  • Contents of register %rdx overwritten by who · This could be trouble ➙ something should be done! · Need some coordination
  • Conventions
    • “Caller Saved” (aka “Call-Clobbered”) · Caller saves temporary values in its frame before the call
    • “Callee Saved” (aka “Call-Preserved”) · Callee saves temporary values in its frame before using · Callee restores them before returning to caller

寄存器只有一套, 调用者和被调用者共用. yoo 把 15213 放在 %rdx, 调用 who 后还想用它, 但 who 改了 %rdx, 结果出错. 需要约定由谁负责保存:

  • caller-saved 调用者保存 (又叫 call-clobbered, 「调用会破坏」): 被调用者可以随便改; 调用者若在调用后还要用其中的值, 自己在调用前把它存到栈帧里.
  • callee-saved 被调用者保存 (又叫 call-preserved, 「调用会保持」): 被调用者若要用它, 必须先把旧值存到自己的栈帧里, 返回前恢复. 调用者可以放心把调用后要用的值放在这类寄存器里.
Slide 88–89

x86-64 Linux Register Usage #1

  • %rax · Return value · Call-clobbered (i.e., caller must save&restore if value needed after the call)
  • %rdi, ..., %r9 · Arguments · Call-clobbered
  • %r10, %r11 · Call-clobbered temporaries

x86-64 Linux Register Usage #2

  • %rbx, %r12, %r13, %r14, %r15 · Call-preserved (i.e., Callee must save & restore)
  • %rbp · Call-preserved · May be used as frame pointer · Can mix & match
  • %rsp · Special form of call-preserved · Restored to original value upon exit from procedure

x86-64 Linux 的分工 (16 个寄存器):

寄存器用途保存方式
%rax返回值调用者保存
%rdi, %rsi, %rdx, %rcx, %r8, %r9参数 1–6调用者保存
%r10, %r11临时调用者保存
%rbx, %r12–%r15临时被调用者保存
%rbp临时, 或帧指针被调用者保存
%rsp栈指针特殊: 返回时必须恢复原值

记法: 参数和返回值寄存器、%r10、%r11 共 9 个是调用者保存; %rbx、%rbp、%r12–%r15 共 6 个是被调用者保存.

Slide 102–110

Callee-Saved Example

long call_incr2(long x) {
  long v1 = 15213;
  long v2 = incr(&v1, 3000);
  return x+v2;
}
  • X comes in register %rdi.
  • We need %rdi for the call to incr.
  • Where should be put x, so we can use it after the call to incr?
call_incr2:
    pushq   %rbx
    subq    $16, %rsp
    movq    %rdi, %rbx
    movq    $15213, 8(%rsp)
    movl    $3000, %esi
    leaq    8(%rsp), %rdi
    call    incr
    addq    %rbx, %rax
    addq    $16, %rsp
    popq    %rbx
    ret

Resulting Stack Structure: … Rtn address · Saved %rbx · 15213 (%rsp+8) · Unused (%rsp) — X saved in %rbx. A callee saved register. · X Is safe in %rbx · Return result in %rax · Pre-return Stack Structure: … Rtn address ← %rsp

被调用者保存寄存器的用法: x 进来时在 %rdi, 但调用 incr 时 %rdi 要装 &v1, 而且 incr 可能改动 %rdi. 解决: 把 x 放进被调用者保存的 %rbx, incr 保证不改它. 但 call_incr2 自己也是被调用者, 也要对它的调用者保证 %rbx 不变, 所以开头先 pushq %rbx 保存旧值, 返回前 popq %rbx 恢复. 中间 incr 返回后, %rbx 里的 x 完好, addq %rbx, %rax 得 x + v2.

Slide 90

x86-64 Procedure Summary

  • Important Points
    • Stack is the right data structure for procedure call/return · If P calls Q, then Q returns before P
  • Recursion (& mutual recursion) handled by normal calling conventions
    • Can safely store values in local stack frame and in call-preserved registers
    • Put function arguments at top of stack
    • Result return in %rax
  • Pointers are addresses of values · On stack or global

小结: 栈正好适合过程调用和返回, 因为 P 调用 Q 时 Q 一定先于 P 返回. 递归和相互递归不需要特殊处理, 只要遵守调用约定: 值可以安全地存在自己的栈帧或被调用者保存的寄存器里; 多余的参数放在栈顶; 结果放 %rax. 指针就是值的地址, 可以指向栈上或全局区.

递归
Recursive Function

Slide 92–98 
/* Recursive popcount */
long pcount_r(unsigned long x) {
  if (x == 0)
    return 0;
  else
    return (x & 1)
      + pcount_r(x >> 1);
}
pcount_r:
    movl    $0, %eax
    testq   %rdi, %rdi
    je      .L6
    pushq   %rbx
    movq    %rdi, %rbx
    andl    $1, %ebx
    shrq    %rdi
    call    pcount_r
    addq    %rbx, %rax
    popq    %rbx
.L6:
    rep; ret

Terminal Case: %rdi x Argument · %rax Return value · Register Save: … Rtn address · Saved %rbx ← %rsp · Call Setup: %rdi x >> 1 Rec. argument · %rbx x & 1 Callee-saved · Call: %rax Recursive call return value · Result: %rax Return value · Completion: … ← %rsp

递归版 popcount. 汇编逐段:

  • 先设返回值 0; testq 判断 x 是否为 0, 是则直接跳到 .L6 返回 0 (终止情况, 不碰栈).
  • 否则要在递归调用后用到 x & 1, 于是用被调用者保存的 %rbx 存放它: 先 push 保存调用者的 %rbx, 再把 x & 1 放进 %rbx.
  • shrq 把 %rdi 变成 x >> 1, 作为递归调用的参数.
  • 递归返回后 %rax 是 pcount_r(x >> 1), 加上 %rbx 中的 x & 1; 恢复 %rbx 后返回.

每一层递归都把自己的 x & 1 存在 %rbx, 并把上一层的 %rbx 压在自己的栈帧里, 所以层与层之间互不干扰.

Slide 99

Observations About Recursion

  • Handled Without Special Consideration
    • Stack frames mean that each function call has private storage · Saved registers & local variables · Saved return pointer
    • Register saving conventions prevent one function call from corrupting another's data · Unless the C code explicitly does so (e.g., buffer overflow in Lecture 9)
    • Stack discipline follows call / return pattern · If P calls Q, then Q returns before P · Last-In, First-Out
  • Also works for mutual recursion · P calls Q; Q calls P

递归不需要任何特殊机制: 栈帧给每次调用提供私有存储 (保存的寄存器、局部变量、返回地址); 寄存器保存约定防止一次调用破坏另一次调用的数据, 除非 C 代码自己越界 (缓冲区溢出); 栈的后进先出正好对应调用和返回的嵌套. 相互递归 (P 调 Q, Q 调 P) 同样适用.

  • Which registers do we need to save? Ill-posed question. Need assembly. rbx, rbp, r9 (during first call to add5)
add10:                          add5:
    pushq   %rbp                    addq    %rsi, %rdi
    pushq   %rbx                    addq    %rdi, %rdx
    movq    %r9, %rbp               addq    %rdx, %rcx
    call    add5                    leaq    (%rcx,%r8), %rax
    movq    %rax, %rbx              ret
    movq    48(%rsp), %r8
    movq    40(%rsp), %rcx
    movq    32(%rsp), %rdx
    movq    24(%rsp), %rsi
    movq    %rbp, %rdi
    call    add5
    addq    %rbx, %rax
    popq    %rbx
    popq    %rbp
    ret

练习: add10 的 a0–a5 在 6 个参数寄存器, a6–a9 在栈上; add5 的 5 个参数在前 5 个寄存器. 第一次调用 add5 时 a0–a4 已经在正确位置, 不用移动. 但 a5 (在 %r9) 要留到第二次调用, 而 %r9 是调用者保存的, 所以先把它移到被调用者保存的 %rbp; 第一次的结果也要保留, 放在 %rbx. 用了这两个寄存器, add10 自己就要在开头 push、结尾 pop 它们.

栈上参数的偏移: 进入 add10 时 a6 在 8(%rsp) (0(%rsp) 是返回地址); 两次 push 后栈下移 16 字节, a6、a7、a8、a9 分别在 24、32、40、48(%rsp). 于是第二次调用的参数依次是 a5 (%rbp)、a6、a7、a8、a9. add5 用一串 add 和最后一条 lea 求和 (lea 做三操作数加法).
