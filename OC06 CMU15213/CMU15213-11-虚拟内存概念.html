为什么需要虚拟内存
This Picture is a Lie

Slide 3–5

This Picture is a Lie — This is RAM, we said… · But the computer can run more than one program at a time! · Where are all the other programs? · Let's investigate.

Processes — Definition: A process is an instance of a running program. · One of the most profound ideas in computer science · Not the same as “program” or “processor” · Unix: A parent process creates a new child process by calling fork · Child is (sort of) a copy of the parent · fork returns twice—once in each process · Different return value in each · Parent can wait for child to finish by calling waitpid · For now, think of this as “what main returns to”

Hmmm, How Does This Work?! — Process 1 · Process 2 · … · Process n — Solution: Virtual Memory (today and next lecture)

前几讲画的内存图 (代码、数据、堆、栈从 0 排到最高地址) 「是个谎言」: 计算机同时运行着很多程序, 它们不可能都从 0x400000 开始占用同一块物理内存. 那其他程序在哪里?

process 进程: 一个正在运行的程序的实例, 是计算机科学最深刻的概念之一, 与「程序」(磁盘上的文件) 和「处理器」都不同. Unix 中父进程调用 fork 创建子进程, 子进程 (大致) 是父进程的副本; fork 调用一次返回两次, 在父子进程中返回值不同; 父进程可以用 waitpid 等子进程结束 (第 16 讲详述). 多个进程各自以为独占整个地址空间, 实现这一点的就是虚拟内存 (本讲和下一讲).

Slide 6–7

A System Using Physical Addressing — CPU → Physical address (PA) → Main memory (0: … M-1:) → Data word · Used in “simple” systems like embedded microcontrollers in devices like cars, elevators, and digital picture frames

A System Using Virtual Addressing — CPU Chip: CPU → Virtual address (VA) 4100 → MMU → Physical address (PA) 4 → Main memory → Data word · Used in all modern servers, laptops, and smart phones · One of the great ideas in computer science

物理寻址: CPU 直接用物理地址访问主存, 用于汽车、电梯、数码相框里的简单嵌入式微控制器. 虚拟寻址: CPU 发出虚拟地址 (VA, 如 4100), 由芯片上的 MMU (内存管理单元) 翻译成物理地址 (PA, 如 4), 再访问主存. 所有现代服务器、笔记本、手机都用虚拟寻址.

Slide 8–9

VM as a Tool for Memory Management — Key idea: each process has its own virtual address space · It can view memory as a simple linear array · Mapping function scatters addresses through physical memory · Well-chosen mappings can improve locality

  • Simplifying memory allocation · Each virtual page can be mapped to any physical page · A virtual page can be stored in different physical pages at different times
  • Sharing code and data among processes · Map virtual pages to the same physical page (here: PP 6)

虚拟内存作为内存管理工具: 每个进程有自己的虚拟地址空间, 看起来是一个简单的线性数组; 映射函数把这些地址散布到物理内存各处. 好处: 分配简单, 任何虚拟页 (VP) 都可以放进任何物理页 (PP), 同一个虚拟页在不同时候可以在不同的物理页里; 共享方便, 把两个进程的虚拟页映射到同一个物理页 (图中的 PP 6), 就能共享库代码等数据.

Slide 10

Simplifying Linking and Loading

  • Linking · Each program has similar virtual address space · Code, data, and heap always start at the same addresses.
  • Loading · execve allocates virtual pages for .text and .data sections & creates PTEs marked as invalid · The .text and .data sections are copied, page by page, on demand by the virtual memory system

(Memory layout: Kernel virtual memory (invisible to user code) · User stack (created at runtime), %rsp · Memory-mapped region for shared libraries · Run-time heap (created by malloc), brk · Read/write segment (.data, .bss) · Read-only segment (.init, .text, .rodata), 0x400000 — Loaded from the executable file · Unused)

简化链接和加载: 每个程序的虚拟地址空间布局都一样, 代码总从 0x400000 开始, 链接器可以按固定地址生成可执行文件, 不用关心实际放在物理内存的哪里. 加载时 execve 只为 .text、.data 分配虚拟页并建立「无效」的页表项, 并不真正读文件; 第一次访问某页时才由虚拟内存系统按需一页一页读进来.

地址空间与地址翻译
Address Spaces and Translation

Slide 11–14

Address Spaces — Linear address space: Ordered set of contiguous non-negative integer addresses: {0, 1, 2, 3 … } · Virtual address space: Set of N = 2ⁿ virtual addresses {0, 1, 2, 3, …, N-1} · Physical address space: Set of M = 2ᵐ physical addresses {0, 1, 2, 3, …, M-1}

Why Virtual Memory (VM)? — Uses main memory efficiently · Use DRAM as a cache for parts of a virtual address space · Simplifies memory management · Each process gets the same uniform linear address space · Isolates address spaces · One process can't interfere with another's memory · User program cannot access privileged kernel information and code

VM Address Translation — Virtual Address Space V = {0, 1, …, N–1} · Physical Address Space P = {0, 1, …, M–1} · Address Translation · MAP: V → P ∪ {∅} · For virtual address a: · MAP(a) = a' if data at virtual address a is at physical address a' in P · MAP(a) = ∅ if data at virtual address a is not in physical memory – Either invalid or stored on disk

MAP: V -> P — Mapping function from virtual pages to physical pages · Page is the granularity of mapping set by the ISA · Function must be simple and efficient · Implemented in hardware · Significant design constraints · K-nary tree aka Page Table · Each node of the tree is 1 page in size

地址空间: 虚拟地址空间有 N = 2ⁿ 个地址, 物理地址空间有 M = 2ᵐ 个. 虚拟内存的三大作用: ① 高效使用主存, 把 DRAM 当作虚拟地址空间的缓存; ② 简化内存管理, 每个进程都有统一的线性地址空间; ③ 隔离, 进程之间互不干扰, 用户程序不能访问内核的特权数据和代码.

地址翻译就是一个映射 MAP: V → P ∪ {∅}: 虚拟地址 a 的数据在物理地址 a' 处则映射到 a'; 不在物理内存中 (无效, 或在磁盘上) 则映射到 ∅. 映射以页为单位, 页大小由 ISA 规定. 映射函数要简单高效, 由硬件实现, 实际做成一棵 k 叉树, 即页表, 树的每个节点正好一页大.

Slide 15–16

Enabling Data Structure: Page Table — A page table is an array of page table entries (PTEs) that maps virtual pages to physical pages. · Per-process kernel data structure in DRAM

Address Translation With a Page Table

page table 页表: 由页表项 (PTE) 组成的数组, 每个进程一个, 由内核维护, 存在 DRAM 中. 第 i 项描述虚拟页 i: 有效位为 1 时存物理页号 (该页在内存中); 有效位为 0 时, 要么是 null (该虚拟页未分配), 要么存磁盘地址 (已分配但目前只在磁盘上).

翻译过程: 虚拟地址的低 p 位是页内偏移 VPO (页大小 P = 2ᵖ), 高位是虚拟页号 VPN. 硬件从 PTBR 寄存器找到当前进程的页表, 以 VPN 为下标取出 PTE; 有效则把其中的物理页号 PPN 和偏移拼起来得到物理地址 (偏移不变, PPO = VPO); 无效则触发缺页.

Slide 17–18

Page Hit — Page hit: reference to VM word that is in physical memory (DRAM cache hit)

Address Translation: Page Hit — CPU Chip: CPU → VA → MMU → PTEA → Cache/Memory → PTE → MMU → PA → Cache/Memory → Data → CPU

  1. Processor sends virtual address to MMU
  2. 2-3) MMU fetches PTE from page table in memory
  3. 4) MMU sends physical address to cache/memory
  4. 5) Cache/memory sends data word to processor

页命中: 访问的虚拟页在物理内存中 (相当于 DRAM 缓存命中). 硬件步骤: CPU 把虚拟地址给 MMU; MMU 根据页表项地址 (PTEA) 从缓存或内存取回 PTE; MMU 用 PTE 拼出物理地址发给缓存/内存; 数据返回 CPU. 注意一次访存至少要两次内存访问 (先取 PTE 再取数据), 后面的 TLB 就是为了省掉第一次.

Slide 19–24

Page Fault — Page fault: reference to VM word that is not in physical memory (DRAM cache miss)

  1. Processor sends virtual address to MMU
  2. 2-3) MMU fetches PTE from page table in memory
  3. 4) Valid bit is zero, so MMU triggers page fault exception
  4. 5) Handler identifies victim (and, if dirty, pages it out to disk)
  5. 6) Handler pages in new page and updates PTE in memory
  6. 7) Handler returns to original process, restarting faulting instruction

Handling Page Fault — Page miss causes page fault (an exception) · Page fault handler selects a victim to be evicted (here VP 4) · (PTE now: 1 VP 3 PP 3) · Offending instruction is restarted: page hit! · Key point: Waiting until the miss to copy the page to DRAM is known as demand paging

Allocating Pages — Allocating a new page (VP 5) of virtual memory. (A null PTE is changed to point to VP 5 on disk.)

缺页 (page fault): 访问的虚拟页不在物理内存中 (DRAM 缓存不命中). MMU 发现 PTE 无效, 触发缺页异常, 转入内核的缺页处理程序: 选一个牺牲页 (若被改过就先写回磁盘), 把所需页从磁盘读进腾出的物理页, 更新 PTE, 然后返回并重新执行出错的那条指令, 这次就命中了. 例子中访问 VP 3, 牺牲 VP 4, VP 3 装入 PP 3.

等到不命中时才把页调入内存, 叫按需调页 (demand paging). 分配新的虚拟页 (如 malloc 扩堆时的 VP 5) 只是把 null 的 PTE 改为指向磁盘上的位置, 并不立即占用物理内存.

Slide 26

VM as a Tool for Memory Protection — Extend PTEs with permission bits · MMU checks these bits on each access

虚拟内存作为保护工具: 在 PTE 中加权限位, MMU 每次访问都检查. SUP 表示只有内核模式能访问; READ、WRITE、EXEC 分别表示可读、可写、可执行. 例: 进程 i 的 VP 0 可读可执行不可写 (代码页), VP 2 需要内核权限且不可执行. 违反权限 (如写只读页、执行不可执行页, 即上一讲防缓冲区溢出的 NX) 会触发保护异常, Linux 上表现为段错误. 两个进程的页可以映射到同一个 PP 6, 但各自的权限可以不同.

虚拟内存作为缓存
VM is also Caching

Slide 27–29

VM is also Caching — Programs allocate virtual address ranges · Implicitly via binaries / libraries · Explicitly through heap / stack · The operating system decides which virtual pages should be resident (i.e., in physical memory) · OS manages the placement / replacement policies between DRAM and disk

VM as a Tool for Caching — Conceptually, virtual memory is an array of N contiguous bytes stored on disk. · The contents of the array on disk are cached in physical memory (DRAM cache) · These cache blocks are called pages (size is P = 2ᵖ bytes) · (Virtual pages (VPs) stored on disk: Unallocated / Cached / Uncached — Physical pages (PPs) cached in DRAM)

DRAM Cache Organization — DRAM cache organization driven by the enormous miss penalty · DRAM is about 10x slower than SRAM · Disk is about 10,000x slower than DRAM · Consequences · Large page (block) size: typically 4 KB, sometimes 4 MB · Fully associative · Any VP can be placed in any PP · Requires a “large” mapping function – different from cache memories · Highly sophisticated, expensive replacement algorithms · Too complicated and open-ended to be implemented in hardware · Write-back rather than write-through

虚拟内存也是一种缓存: 概念上, 虚拟内存是存在磁盘上的 N 字节数组, 物理内存 (DRAM) 缓存其中的一部分, 缓存块叫页. 虚拟页分三种状态: 未分配; 已缓存 (在物理内存中); 未缓存 (已分配, 但只在磁盘上). 由操作系统决定哪些页常驻内存, 并管理放置与替换.

DRAM 缓存的设计由巨大的不命中代价决定 (磁盘比 DRAM 慢得多): 页很大 (通常 4 KB, 有时 4 MB 的大页), 一次搬运摊薄寻道开销; 全相联, 任何虚拟页可以放在任何物理页, 尽量减少不命中, 代价是需要页表这样的大映射; 替换算法复杂精细, 由操作系统软件而不是硬件实现; 总是写回, 不用直写 (每次写都访问磁盘太慢).

幻灯片小错: "Disk is about 10,000x slower than DRAM" 与教材 (9.3.1 节: 约 100,000 倍) 不符, 也与上一讲的说法 (按扇区大小的块比较约 2,500 倍) 不一致. 按单次访问延迟算 (约 10 ms 对约 60–100 ns), 机械硬盘比 DRAM 慢约 10 万倍; SSD 则约慢 1000 倍.

Slide 30–31

Integrating VM and Cache — CPU Chip: CPU → VA → MMU → PTEA → L1 cache (PTEA hit / PTEA miss → Memory) → PTE → MMU → PA → L1 cache (PA hit / PA miss → Memory) → Data → CPU · VA: virtual address, PA: physical address, PTE: page table entry, PTEA = PTE address

Locality to the Rescue Again! — Virtual memory seems terribly inefficient, but it works because of locality. · At any point in time, programs tend to access a set of active virtual pages called the working set · Programs with better temporal locality will have smaller working sets · If (working set size < main memory size) · Good performance for one process after compulsory misses · If ( SUM(working set sizes) > main memory size ) · Thrashing: Performance meltdown where pages are swapped (copied) in and out continuously

虚拟内存与高速缓存结合: 高速缓存 (L1 等) 用物理地址索引. MMU 取 PTE 时, PTE 本身也是内存中的数据, 可能命中 L1, 也可能要去主存取; 翻译得到物理地址后, 再用它访问 L1.

虚拟内存看起来很低效 (每次访问都要翻译, 缺页代价巨大), 能用全靠局部性. 程序在任一时刻只活跃地使用一组页, 即工作集. 工作集小于物理内存时, 除了开始的强制缺页, 性能很好; 所有进程的工作集之和超过物理内存时, 页不断被换进换出, 性能崩溃, 叫抖动 (thrashing).

用 TLB 加速翻译
Speeding up Translation with a TLB

Slide 32–33

Speeding up Translation with a TLB — Page table entries (PTEs) are cached in L1 like any other memory word · PTEs may be evicted by other data references · PTE hit still requires a small L1 delay · Solution: Translation Lookaside Buffer (TLB) · Small set-associative hardware cache in MMU · Maps virtual page numbers to physical page numbers · Contains complete page table entries for small number of pages

Accessing the TLB — MMU uses the VPN portion of the virtual address to access the TLB: T = 2ᵗ sets · VPN = TLB tag (TLBT) [bits n-1 … p+t] · TLB index (TLBI) [bits p+t-1 … p] · VPO [bits p-1 … 0] · TLBI selects the set · TLBT matches tag of line within set · (Set 0 … Set T-1, each with lines: v tag PTE)

PTE 缓存在 L1 中也有问题: 可能被其他数据挤出去, 即使命中也有 L1 的延迟. 解决: TLB (翻译后备缓冲区), MMU 内部一个小的组相联缓存, 专门缓存少量页的完整 PTE, 把虚拟页号直接映射到物理页号.

访问 TLB 和访问普通缓存的方法一样, 只是用的是 VPN 而不是整个地址: VPN 的低 t 位是 TLB 组索引 (TLBI), 高位是 TLB 标记 (TLBT). TLBI 选组, TLBT 与组内各行比较.

Slide 34–36

TLB Hit — CPU → VA → MMU → VPN → TLB → PTE → MMU → PA → Cache/Memory → Data · A TLB hit eliminates a memory access

TLB Miss — CPU → VA → MMU → VPN → TLB (miss) → PTEA → Cache/Memory → PTE → TLB → MMU → PA → Cache/Memory → Data · A TLB miss incurs an additional memory access (the PTE) · Fortunately, TLB misses are rare. Why?

Summary of Address Translation Symbols — Basic Parameters · N = 2ⁿ : Number of addresses in virtual address space · M = 2ᵐ : Number of addresses in physical address space · P = 2ᵖ : Page size (bytes) · Components of the virtual address (VA) · TLBI: TLB index · TLBT: TLB tag · VPO: Virtual page offset · VPN: Virtual page number · Components of the physical address (PA) · PPO: Physical page offset (same as VPO) · PPN: Physical page number

TLB 命中: MMU 直接从 TLB 得到 PTE, 省掉一次访存. TLB 不命中: 要额外访问一次缓存/内存取 PTE, 并放进 TLB. 回答课件的问题: TLB 不命中很少, 因为一个 TLB 项覆盖一整页 (4 KB), 程序的局部性使它在一段时间内反复访问同一批页; 几十到上千个 TLB 项就能覆盖几百 KB 到几 MB 的工作集.

符号汇总: N、M、P 分别是虚拟地址数、物理地址数、页大小; 虚拟地址 = VPN + VPO, VPN 又分成 TLBT + TLBI; 物理地址 = PPN + PPO, 且 PPO = VPO. 下一讲的地址翻译例题会用到这些符号.

多级页表
Multi-Level Page Tables

Slide 38–39

We have a problem — 32 bit addresses, 4KB pages, 4-byte PTEs · 2²⁰ Entries of 4 bytes each · Virtual memory: VP 0 … VP 1023, VP 1024 … VP 2047: 2K allocated VM pages for code and data · Gap: 6K unallocated VM pages · 1023 unallocated pages · VP 9215: 1 allocated VM page for the stack

Multi-Level Page Tables — Suppose: 4KB (2¹²) page size, 48-bit address space, 8-byte PTE · Problem: Would need a 512 GB page table! · 2⁴⁸ * 2⁻¹² * 2³ = 2³⁹ bytes · Common solution: Multi-level page table · Example: 2-level page table · Level 1 table: each PTE points to a page table (always memory resident) · Level 2 table: each PTE points to a page (paged in and out like any other data)

单级页表的问题: 32 位地址、4 KB 页时, 页表有 2²⁰ 项, 每项 4 字节, 每个进程 4 MB, 哪怕程序只用了 2K 页的代码数据和 1 页的栈, 中间大片未分配的地址也要占页表项. 48 位地址、8 字节 PTE 时更糟: 2⁴⁸ / 2¹² × 2³ = 2³⁹ 字节 = 512 GB, 根本放不下.

解决: 多级页表. 两级为例: 一级页表的每项指向一个二级页表 (一级页表常驻内存); 二级页表的每项指向一个页 (二级页表本身可以像普通数据一样换进换出). 关键在于: 一级项为 null 时, 对应的整个二级页表根本不用创建.

Slide 40–43

A Two-Level Page Table Hierarchy

Translating with a k-level Page Table — Page table base register (PTBR) · VIRTUAL ADDRESS: VPN 1 · VPN 2 · ... · VPN k · VPO → Level 1 page table → Level 2 page table → … → Level k page table → PPN · PHYSICAL ADDRESS: PPN · PPO

TLBs and k-level Page Tables — TLBs cache the complete virtual to physical mapping · Regardless of the levels of page tables, the TLB stores the VPN -> PPN

Summary — Programmer's view of virtual memory · Each process has its own private linear address space · Cannot be corrupted by other processes · System view of virtual memory · Uses memory efficiently by caching virtual memory pages · Efficient only because of locality · Simplifies memory management and programming · Simplifies protection by providing a convenient interpositioning point to check permissions

两级页表的例子 (32 位地址、4 KB 页、4 字节 PTE): 每个二级页表恰好一页, 1024 项, 覆盖 4 MB 地址. 程序用到 2K 个代码数据页 (需要 2 个二级页表)、中间 6K 个未分配页 (一级项 null, 不建二级页表)、栈 1 页 (第 9 个二级页表, 只有最后一项有效). 总共只需一级页表加 3 个二级页表, 约 16 KB, 而不是 4 MB.

k 级页表的翻译: VPN 被切成 k 段, 第 i 段作为第 i 级页表的下标, 逐级查找, 最后一级给出 PPN. x86-64 用 4 级页表 (下一讲). 不论多少级, TLB 都缓存完整的 VPN → PPN 映射, TLB 命中时不必逐级查表.

小结: 对程序员, 每个进程有私有的线性地址空间, 别的进程破坏不了; 对系统, 虚拟内存借助局部性高效地缓存页, 简化内存管理和编程, 并在每次访问时提供一个检查权限的「拦截点」.
