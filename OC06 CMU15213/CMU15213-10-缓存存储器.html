Slide 9–10

General Cache Organization (S, E, B)

Cache size = S x E x B data bytes

Cache Read — Locate set · Check if any line in set has matching tag · Yes + line valid: hit · Locate data starting at offset

Address of word: t bits (tag) · s bits (set index) · b bits (block offset) · data begins at this offset

缓存的结构用三个参数 (S, E, B) 描述: S = 2ˢ 个组 (set); 每组 E = 2ᵉ 行 (line); 每行一个有效位、一个标记 (tag) 和一个 B = 2ᵇ 字节的数据块. 容量 C = S × E × B (不计有效位和标记).

读的过程: 把地址分成三段, 从高到低是 t 位标记、s 位组索引、b 位块偏移. ① 用组索引找到组; ② 检查组内是否有某一行有效且标记相同, 有则命中; ③ 用块偏移在块中找到数据的起点. 地址共 m 位时, t = m − s − b.

Slide 11–13

Example: Direct Mapped Cache (E = 1) — Direct mapped: One line per set · Assume: cache block size B=8 bytes

Address of int: t bits · 0…01 · 100 — find set · valid? + match: if yes (= hit) · block offset · int (4 Bytes) is here

If tag doesn't match (= miss): old line is evicted and replaced

直接映射缓存: 每组只有一行 (E = 1). 例: 块大小 8 字节, 一个 int 的地址中间几位 0…01 选中第 1 组; 若该行有效且标记相同则命中, 块偏移 100 (= 4) 指出 int 从块内第 4 字节开始. 标记不同就不命中, 唯一的那一行被换掉, 不需要替换策略.

Slide 19–20

What about writes? — Multiple copies of data exist: L1, L2, L3, Main Memory (line: v d tag 0 1 2 … B-1; valid bit, dirty bit)

  • What to do on a write-hit? · Write-through (write immediately to memory) · Write-back (defer write to memory until replacement of line) · Each cache line needs a dirty bit (set if data has been written to)
  • What to do on a write-miss? · Write-allocate (load into cache, update line in cache) · Good if more writes to the location will follow · No-write-allocate (writes straight to memory, does not load into cache)
  • Typical · Write-through + No-write-allocate · Write-back + Write-allocate

Practical Write-back Write-allocate — A write to address X is issued · If it is a hit · Update the contents of block · Set dirty bit to 1 (bit is sticky and only cleared on eviction) · If it is a miss · Fetch block from memory (per a read miss) · The perform the write operations (per a write hit) · If a line is evicted and dirty bit is set to 1 · The entire block of 2ᵇ bytes are written back to memory · Dirty bit is cleared (set to 0) · Line is replaced by new contents

写的问题在于数据有多个副本 (L1、L2、L3、主存). 写命中时: 直写 (write-through), 立即同时写下一层, 简单但流量大; 写回 (write-back), 先只改缓存, 等这行被换出时才写回, 每行需要一个脏位记录是否被改过. 写不命中时: 写分配, 先把块读进缓存再写 (后面还会写附近的位置时划算); 非写分配, 直接写到下一层, 不装入缓存. 常见组合是直写 + 非写分配, 或写回 + 写分配 (现代处理器多用后者).

写回 + 写分配的流程: 命中则改块并置脏位 (脏位一旦置 1, 只在换出时清零); 不命中则先像读不命中那样取块, 再像写命中那样写. 换出脏行时把整块 2ᵇ 字节写回, 清脏位, 再装入新内容. 原文 "The perform" 应为 "Then perform".

Slide 22–24

Cache Performance Metrics — Miss Rate · Fraction of memory references not found in cache (misses / accesses) = 1 – hit rate · Typical numbers (in percentages): 3-10% for L1 · can be quite small (e.g., < 1%) for L2, depending on size, etc. · Hit Time · Time to deliver a line in the cache to the processor · includes time to determine whether the line is in the cache · Typical numbers: 4 clock cycle for L1 · 10 clock cycles for L2 · Miss Penalty · Additional time required because of a miss · typically 50-200 cycles for main memory (Trend: increasing!)

Let's think about those numbers — Huge difference between a hit and a miss · Could be 100x, if just L1 and main memory · Would you believe 99% hits is twice as good as 97%? · Consider this simplified example: cache hit time of 1 cycle · miss penalty of 100 cycles · Average access time: 97% hits: 1 cycle + 0.03 x 100 cycles = 4 cycles · 99% hits: 1 cycle + 0.01 x 100 cycles = 2 cycles · This is why “miss rate” is used instead of “hit rate”

Writing Cache Friendly Code — Make the common case go fast · Focus on the inner loops of the core functions · Minimize the misses in the inner loops · Repeated references to variables are good (temporal locality) · Stride-1 reference patterns are good (spatial locality) · Key idea: Our qualitative notion of locality is quantified through our understanding of cache memories

三个性能指标: 不命中率 (L1 一般 3–10%, L2 可低于 1%); 命中时间 (含判断是否命中的时间, L1 约 4 周期, L2 约 10 周期); 不命中代价 (去主存要 50–200 周期, 而且在增大).

平均访问时间 = 命中时间 + 不命中率 × 不命中代价. 例: 命中 1 周期、代价 100 周期时, 97% 命中平均 4 周期, 99% 命中平均 2 周期, 命中率只差 2 个百分点, 性能差一倍. 所以通常看不命中率 (3% 对 1%), 它更能反映差别.

写缓存友好的代码: 让常见情况快, 集中优化核心函数的内层循环; 减少内层循环的不命中: 反复使用同一变量 (时间局部性), 步长为 1 地访问 (空间局部性). 理解了缓存, 「局部性」就从定性概念变成可以定量计算的东西.

Slide 31

Memory Mountain Test Function

long data[MAXELEMS];  /* Global array to traverse */

/* test - Iterate over first "elems" elements of
 *        array "data" with stride of "stride",
 *        using 4x4 loop unrolling.
 */
int test(int elems, int stride) {
    long i, sx2=stride*2, sx3=stride*3, sx4=stride*4;
    long acc0 = 0, acc1 = 0, acc2 = 0, acc3 = 0;
    long length = elems, limit = length - sx4;

    /* Combine 4 elements at a time */
    for (i = 0; i < limit; i += sx4) {
        acc0 = acc0 + data[i];
        acc1 = acc1 + data[i+stride];
        acc2 = acc2 + data[i+sx2];
        acc3 = acc3 + data[i+sx3];
    }

    /* Finish any remaining elements */
    for (; i < length; i++) {
        acc0 = acc0 + data[i];
    }
    return ((acc0 + acc1) + (acc2 + acc3));
}

Call test() with many combinations of elems and stride. For each elems and stride: 1. Call test() once to warm up the caches. 2. Call test() again and measure the read throughput (MB/s) — mountain/mountain.c

测试函数: 以步长 stride 读数组的前 elems 个元素并求和. elems 决定工作集大小 (时间局部性: 越小越容易全部留在某层缓存里), stride 决定空间局部性 (步长 1 时一个块的 8 个 long 全用上). 循环展开成 4 路, 用 4 个累加器, 是为了消除计算上的依赖, 让测出的时间只反映存储系统 (循环展开在第 15 讲「程序优化」中讲). 对每组参数先调用一次预热缓存, 再调用一次计时.

Rearranging loops to improve spatial locality

Slide 34–37

Remember matrix multiplication — Out[i, j] = dot product(A[i, ..], B[..,j]) = sum (a[i, 0] * b[0, j], a[i, 1] * b[1, j], …)

/* ijk */
for (i=0; i<n; i++) {
  for (j=0; j<n; j++) {
    sum = 0.0;
    for (k=0; k<n; k++)
      sum += a[i][k] * b[k][j];
    c[i][j] = sum;
  }
}

Description: Multiply N x N matrices · Matrix elements are doubles (8 bytes) · O(N³) total operations · N reads per source element · N values summed per destination · but may be able to hold in register (Variable sum held in register) — matmult/mm.c

Miss Rate Analysis for Matrix Multiply — Assume: Block size = 32B (big enough for four doubles) · Matrix dimension (N) is very large · Approximate 1/N as 0.0 · Cache is not even big enough to hold multiple rows · Analysis Method: Look at access pattern of inner loop

Layout of C Arrays in Memory (review) — C arrays allocated in row-major order · Stepping through columns in one row: for (i = 0; i < N; i++) sum += a[0][i] · if block size (B) > sizeof(aij) bytes, exploit spatial locality · miss rate = sizeof(aij) / B · Stepping through rows in one column: for (i = 0; i < M; i++) sum += a[i][0]; · accesses distant elements: no spatial locality! · miss rate = 1 (i.e. 100%)

矩阵乘法 C = A × B: c[i][j] 是 A 的第 i 行与 B 的第 j 列的点积. N × N 的 double 矩阵, 共 O(N³) 次运算. 三重循环有 6 种排列顺序, 结果都一样, 但访存模式不同.

分析方法: 只看最内层循环的访问模式, 假设块 32 字节 (4 个 double)、N 很大 (1/N ≈ 0)、缓存连几行都装不下. 两个基本事实: 沿一行扫 (步长 1), 每 4 个元素一次不命中, 不命中率 = 8/32 = 0.25; 沿一列扫 (步长 N), 每次都不命中, 不命中率 1.

三类排列 (jik 与 ijk、ikj 与 kij、kji 与 jki 各自相同):

  • ijk: 内层沿 A 的行 (0.25)、B 的列 (1.0), c[i][j] 固定在寄存器里 (0). 每次迭代平均 1.25 次不命中.
  • kij: a[i][k] 固定 (0), 内层沿 B 的行 (0.25) 和 C 的行 (0.25). 平均 0.5 次.
  • jki: b[k][j] 固定 (0), 内层沿 A 的列 (1.0) 和 C 的列 (1.0). 平均 2.0 次.

判断口诀: 看内层循环变量出现在哪个下标位置; 出现在最后一个下标 (列下标) 就是按行扫, 好; 出现在第一个下标就是按列扫, 坏; 不出现就是固定.

Slide 44–45

Summary of Matrix Multiplication — ijk (& jik): 2 loads, 0 stores · avg misses/iter = 1.25 · kij (& ikj): 2 loads, 1 store · avg misses/iter = 0.5 · jki (& kji): 2 loads, 1 store · avg misses/iter = 2.0

Core i7 Matrix Multiply Performance

汇总: ijk 每次迭代 2 次读、0 次写 (c 在寄存器累加), 不命中 1.25 次; kij 2 次读、1 次写, 不命中只有 0.5 次; jki 不命中 2.0 次.

实测: 三组曲线的高低与不命中数一一对应. kij 虽然多一次写, 却最快, 且几乎不随 n 变化; jki 在矩阵变大后每次迭代要 100 个周期左右, 比 kij 慢约 40 倍. ijk 在 n 较小时还能靠缓存装下 B 的若干列, n 大于约 450 后迅速变慢. 结论: 不命中率比访存次数更决定性能.

分块改善时间局部性
Using blocking to improve temporal locality

Slide 47–49

Example: Matrix Multiplication

c = (double *) calloc(sizeof(double), n*n);

/* Multiply n x n matrices a and b */
void mmm(double *a, double *b, double *c, int n) {
    int i, j, k;
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            for (k = 0; k < n; k++)
                c[i*n + j] += a[i*n + k] * b[k*n + j];
}

Cache Miss Analysis — Assume: Matrix elements are doubles · Cache block = 8 doubles · Cache size C << n (much smaller than n) · First iteration: n/8 + n = 9n/8 misses · Afterwards in cache: (schematic) 8 wide · Second iteration: Again: n/8 + n = 9n/8 misses · Total misses: 9n/8 n² = (9/8) n³

不分块的 ijk 版本 (矩阵用一维数组存, a[i*n + k] 就是 a[i][k]). 设一个块装 8 个 double, 缓存远小于 n (一行都装不下). 计算一个 c[i][j]: 扫 A 的一行, n/8 次不命中; 扫 B 的一列, n 次不命中; 共 9n/8 次. 下一个 c[i][j+1] 要扫 B 的另一列, 上次装入的 B 的块早被换出, 只有 A 的那一行的块可能还在 (但缓存太小, 假设也没了), 又是 9n/8 次. 共 n² 个元素, 总不命中 (9/8) n³.

Slide 50

Blocked Matrix Multiplication

c = (double *) calloc(sizeof(double), n*n);

/* Multiply n x n matrices a and b */
void mmm(double *a, double *b, double *c, int n) {
    int i, j, k;
    for (i = 0; i < n; i+=B)
        for (j = 0; j < n; j+=B)
            for (k = 0; k < n; k+=B)
                /* B x B mini matrix multiplications */
                for (i1 = i; i1 < i+B; i1++)
                    for (j1 = j; j1 < j+B; j1++)
                        for (k1 = k; k1 < k+B; k1++)
                            c[i1*n+j1] += a[i1*n + k1]*b[k1*n + j1];
}

matmult/bmm.c · Notation Note: This “B” is not the cache block size · Block size B x B

分块: 把矩阵切成 B × B 的小块, 外三层循环遍历小块, 内三层对小块做普通的矩阵乘法 (c 的一小块 += a 的一小块 × b 的一小块). 只要三个小块能同时放进缓存, 小块里的每个元素装入一次后就能被反复使用 B 次. 注意这里的 B 是分块边长, 不是缓存块大小.

幻灯片小错: 代码中只声明了 int i, j, k;, 内层用到的 i1、j1、k1 没有声明, 照抄无法编译 (应为 int i, j, k, i1, j1, k1;). 另外代码假设 n 是 B 的整数倍. calloc 的两个参数顺序也写反了 (应为 calloc(n*n, sizeof(double))), 不过结果相同.

Cache Miss Analysis — Assume: Cache block = 8 doubles · Cache size C << n (much smaller than n) · Three blocks fit into cache: 3B² < C · First (block) iteration: B*B/8 misses for each block · 2n/B x B²/8 = nB/4 (omitting matrix c) · n/B blocks · Afterwards in cache (schematic) · Second (block) iteration: Same as first iteration · 2n/B x B²/8 = nB/4 · Total misses: nB/4 * (n/B)² = n³/(4B)

Blocking Summary — No blocking: (9/8) n³ misses · Blocking: (1/(4B)) n³ misses · Use largest block size B, such that B satisfies 3B² < C · Fit three blocks in cache! Two input, one output. · Reason for dramatic difference: · Matrix multiplication has inherent temporal locality: · Input data: 3n², computation 2n³ · Every array elements used O(n) times! · But program has to be written properly

Cache Summary — Cache memories can have significant performance impact · You can write your programs to exploit this! · Focus on the inner loops, where bulk of computations and memory accesses occur. · Try to maximize spatial locality by reading data objects sequentially with stride 1. · Try to maximize temporal locality by using a data object as often as possible once it's read from memory.

分块后的不命中分析 (假设 3 个 B × B 小块能同时放进缓存, 3B² < C): 计算 c 的一个小块, 要用 A 的一行小块和 B 的一列小块, 共 2n/B 个小块, 每个装入时有 B²/8 次不命中, 合计 nB/4. c 共 (n/B)² 个小块, 总不命中 n³/(4B).

对比: 不分块 (9/8) n³, 分块 n³/(4B). B 取满足 3B² < C 的最大值, 例如 C = 32 KB = 4096 个 double 时 B 约为 36, 不命中约降到原来的 1/160. 原因: 矩阵乘法本身有很强的时间局部性, 输入数据只有 3n² 个, 计算却有 2n³ 次, 每个元素被用 O(n) 次; 但程序必须写得恰当才能利用. 原文 "Blocking: (1/(4B)) n misses" 中的 n 应为 n³ (课件提取时上标可能丢失, 以计算为准).

缓存小结: 集中优化内层循环; 尽量以步长 1 顺序读取, 最大化空间局部性; 数据读进来后尽量多用几次, 最大化时间局部性.

Slide 59–62

Why Index Using Middle Bits? — Standard Method: Middle bit indexing (t bits · 0…01 · 100) · Alternative Method: High bit indexing (1…11 · t bits · 100)

Illustration of Indexing Approaches — 64-byte memory · 6-bit addresses · 16 byte, direct-mapped cache · Block size = 4. (Thus, 4 sets; why?) · 2 bits tag, 2 bits index, 2 bits offset

Middle Bit Indexing — Addresses of form TTSSBB · TT Tag bits · SS Set index bits · BB Offset bits · Makes good use of spatial locality

High Bit Indexing — Addresses of form SSTTBB · Program with high spatial locality would generate lots of conflicts

为什么组索引用地址的中间位而不是高位? 例: 64 字节内存、16 字节直接映射缓存、块大小 4, 所以有 16/4 = 4 组, 地址 6 位分成 2 位标记、2 位组索引、2 位偏移. 用中间位索引 (TTSSBB) 时, 地址连续的 4 个块依次落进 4 个不同的组, 一段连续的数据能同时留在缓存里. 用高位索引 (SSTTBB) 时, 地址连续的 4 个块组索引相同, 全挤进同一组, 空间局部性好的程序反而产生大量冲突不命中.

Matrix Multiplication (jik) — /* jik */ for (j=0; j<n; j++) { for (i=0; i<n; i++) { sum = 0.0; for (k=0; k<n; k++) sum += a[i][k] * b[k][j]; c[i][j] = sum } } · A Row-wise · B Column-wise · C Fixed · Misses per inner loop iteration: 0.25 · 1.0 · 0.0

Matrix Multiplication (ikj) — /* ikj */ for (i=0; i<n; i++) { for (k=0; k<n; k++) { r = a[i][k]; for (j=0; j<n; j++) c[i][j] += r * b[k][j]; } } · A Fixed · B Row-wise · C Row-wise · 0.0 · 0.25 · 0.25

Matrix Multiplication (kji) — /* kji */ for (k=0; k<n; k++) { for (j=0; j<n; j++) { r = b[k][j]; for (i=0; i<n; i++) c[i][j] += a[i][k] * r; } } · A Column-wise · B Fixed · C Column-wise · 1.0 · 0.0 · 1.0

另外三种循环顺序: 它们的最内层循环与对应的一种完全相同 (jik 同 ijk, ikj 同 kij, kji 同 jki), 只是外两层交换了次序, 所以内层的不命中率也相同. 这也说明分析时只需看最内层循环. jik 的代码中 c[i][j] = sum 少了分号, 是课件笔误.
