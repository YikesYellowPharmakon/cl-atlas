Activity 1: Bit-level and Logical — 1. De Morgan's Law enables one to distribute negation over AND and OR. Given the following expression, complete the following table to verify for the 4-bit inputs. · ~(x & y) == (~x) | (~y)

The next section will explore logical operations. These operations contrast with bit-level operations in that they treat the entire value as a single element. … The three logical operators are AND (&&), OR (||), and NOT (!). “!” is commonly termed “bang”. · 2. Evaluate the following expression: (0x3 && 0xC) == (0x3 & 0xC) · 3. Test whether (!!X) == X holds across different values of X. Do the same for bitwise complement: (~~X) == X.

1. 德摩根律: 4 位下, 0xF & 0x1 = 0x1, 取反得 0xE; 0x5 & 0x7 = 0x5, 取反得 0xA; 0x3 & 0xC = 0, 取反得 0xF. 右边 (~x) | (~y) 分别是 0x0 | 0xE = 0xE、0xA | 0x8 = 0xA、0xC | 0x3 = 0xF, 两边相等.

2. 逻辑运算把整个值当作一个真假值: 0x3 && 0xC 两边都非零, 结果 1; 0x3 & 0xC = 0. 所以 1 == 0 不成立, 整个表达式为 0.

3. 官方答案的表:

−1010−1

~~X == X 总成立; !!X == X 只在 X 为 0 或 1 时成立. !!X 是把任意值规范化为 0/1 的惯用写法 (datalab 中常用). ~X = −X − 1.

4. Find an algorithm for computing the expression (cond) ? t : f, which evaluates to t if cond is 1 and f if cond is 0. Assume cond will either be 1 or 0.

int conditional(int cond, int t, int f) {
    /* Compute a mask that equals 0x00000000 or
       0xFFFFFFFF depending on the value of cond */
    int mask = ________________________________;
    /* Use the mask to toggle between returning t or returning f */
    return ________________________________________;

1–2. −2 右移 1 位预期得 −2/2 = −1. 4 位下 −2 = 0b1110; 算术右移补符号位得 0b1111 = −1; 若是逻辑右移补 0, 得 0b0111 = 7. C 对有符号数右移的方式由实现定义 (实际编译器都是算术右移, C23 起规定为算术右移).

3. −8 = 0b1000 取负: 取反加一还是 0b1000, 即 −TMin = TMin (4 位下不存在 +8). 官方答案写作 "-int min is int min".

4. 官方答案中没有给出这一题的解答, 一种写法 (已用 Python 按 32 位模拟核对):

int mask = ~cond + 1;              /* cond=1 → 0xFFFFFFFF, cond=0 → 0 */
return (mask & t) | (~mask & f);

~cond + 1 就是 −cond: cond = 1 得全 1, cond = 0 得全 0. 全 1 时取 t 的所有位, 全 0 时取 f. 这正是 datalab 中 conditional 题的思路.

官方答案:

int bitCount2bit(int x) {
    int bit1 = 0b01 & x;
    int bit2 = 0b01 & (x >> 1);
    return bit1 + bit2;
}
int bitCount4bit(int x) {
    int mask = 0b0101;
    int halfSum = (mask & x) + (mask & (x >> 1));
    int mask2 = 0b0011;
    return (mask2 & halfSum) + (mask2 & (halfSum >> 2));
}
int bitCount8bit(int x) {
    int mask = 0b01010101;
    int quarterSum = (mask & x) + (mask & (x >> 1));
    int mask2 = 0b00110011;
    int halfSum = (mask2 & quarterSum) + (mask2 & (quarterSum >> 2));
    int mask3 = 0b00001111;
    return (mask3 & halfSum) + (mask3 & (halfSum >> 4));
}

分治的思路: 第一步把相邻两位相加, 每 2 位一组存放该组的 1 的个数 (0–2); 第二步把相邻两组相加, 每 4 位一组存放计数 (0–4); 第三步每 8 位一组. 每一步都是「掩码取偶数组 + 右移后掩码取奇数组 + 相加», 3 个运算符一步, 加上 return 的一步, 8 位共 12 个运算符. 32 位推广到 5 步. 8 位版本已对 0–255 全部输入用 Python 核对. 注意 0b 前缀不是标准 C (GCC 扩展, C23 才纳入标准), datalab 中要写十六进制 0x55、0x33、0x0F, 而且 datalab 只允许 0–255 的常量, 更大的掩码要用移位拼出来.

Calling Conventions: Passing Control — How can we pass control from the assembly for the current function to the assembly for the function we want to call? · How can we pass control back to the caller once we're done?

0000000000400540 <multstore>:
  400540: push   %rbx            # Save %rbx
  400541: mov    %rdx,%rbx       # Save dest
  400544: call   400550 <mult2>  # mult2(x,y)
  400549: mov    %rax,(%rbx)     # Save at dest
  40054c: pop    %rbx            # Restore %rbx
  40054d: ret                    # Return

0000000000400550 <mult2>:
  400550: mov    %rdi,%rax       # a
  400553: imul   %rsi,%rax       # a * b
  400557: ret                    # Return

Procedure Call: call label · Push return address onto the stack (so that we can pass control back to the caller!) · Jump to label · Procedure Return: ret · Pop address from stack · This is the address of the next instruction of the caller · Jump to that address

Calling Conventions: Passing Data — First 6 arguments passed in registers. · Remaining arguments put at the end of the caller's stack frame. · Return value placed in %rax by convention.

Calling Conventions: Caller/Callee-Saved — If foo() calls bar(): foo() is the caller, bar() is the callee · Both foo() and bar() want to use registers. · How can bar() use a register without overwriting something foo() was using? · Need a consistent convention for saving/overwriting registers so we don't lose data. · Caller-Saved (“Call Clobbered”) · Procedures can overwrite these registers freely · So the caller has to save them! · Callee-Saved (“Call Preserved”) · The callee will save these values on the stack before using them. · Before the callee returns, it restores these registers from the stack. · Which registers are caller/callee-saved?

调用约定预习 (第 5 讲). 控制: call 把返回地址 (下一条指令的地址, 这里是 0x400549) 压栈, 然后跳到目标; ret 从栈上弹出返回地址并跳过去. 数据: 前 6 个参数依次放在 %rdi、%rsi、%rdx、%rcx、%r8、%r9, 更多参数放在调用者栈帧的末尾; 返回值放 %rax. 例: mult2 把 %rdi (a) 复制到 %rax, 乘以 %rsi (b) 后返回.

调用者保存的寄存器可以被被调函数随意改写, 调用者若需要它们的值, 要自己在调用前保存: %rax、%rcx、%rdx、%rsi、%rdi、%r8–%r11. 被调者保存的寄存器, 被调函数要用就得先压栈、返回前恢复: %rbx、%rbp、%r12–%r15 (%rsp 特殊). 第 22 页的空表正是要填这两组. multstore 要在 call 之后还用 dest, 所以把它放进被调者保存的 %rbx, 并在开头 push %rbx、结尾 pop %rbx.

void mm_blocking(int a[4][4], int b[4][4], int c[4][4]) {
    int i, j, k;

Review: What is a TLB? — The TLB (or Translation Lookaside Buffer) is a cache that stores translations from virtual to physical addresses. · Upon a TLB hit, we do not have to perform a page walk to perform translations!

TLB is a Cache! — We can make similar analysis of TLBs as we did with caches · TLBs are usually set associative · Accesses to memory blocks –> Accesses to pages · This changes how we think about locality and misses · But the general ideas still carry over from cachelab!

Analyzing TLB Benefits — 1. Locality of Access 2. Size of Working Set

Locality of Access — Suppose a workload has good locality, what are the benefits we get from a TLB? · Good locality indicates reuse in memory in the same contiguous region in memory, or the same page · Memory accesses to the same page benefit from previously stored translations!

Size of Working Set — The working set of a program is the set of accessed, active virtual pages. · What can happen if our working set is too large? · A large working set results in thrashing, or the constant swapping of pages. · For the TLB, this means a previously stored translation for a page will likely be invalid as the page has been swapped out. · Similar to capacity miss?

malloc 要做三件事: 在堆里用一定的结构组织块和块的元数据; 据此决定新块放在哪里; 分配和释放时正确更新结构, 保持堆的不变式. 目标是同时最大化吞吐率 (每秒操作数) 和利用率 (请求的有效载荷总量的峰值 ÷ 堆的大小). 回顾第 13–14 讲:

  • 隐式链表: 靠块长度从一块跳到下一块, 找空闲块要遍历所有块 (包括已分配的), 吞吐率很差.
  • 合并: 把相邻的空闲块合成一个大块, 减少外部碎片 (总空闲空间够, 但没有一个块够大), 提高利用率.
  • 显式链表: 用 next/prev 指针只串起空闲块, 吞吐率大幅提高. 代价: 指针放在空闲块的有效载荷区, 最小块变大 (头 + 两个指针 + 脚), 很小的请求也要占这么大一块, 内部碎片增加.
  • 分离链表: 按大小类别维护多条空闲链表, 直接到合适的类别中找, 更快; 若在类别内做近似最佳适配, 利用率也会提高.

Recall: Signal Handlers — Parent process sends SIGINT to child process. What is the behavior of the child? · No handler specified: default action. · Can catch the signal with a signal handler.

void sigchld_handler(int sig)
{
    int olderrno = errno;                  // Save and restore errno
    sigset_t mask_all, prev_all;
    pid_t pid;

    sigfillset(&mask_all);
    while ((pid = waitpid(-1, NULL, 0)) > 0) { /* Reap */
        sigprocmask(SIG_BLOCK, &mask_all, &prev_all);  // Temporarily block signals to protect shared data
        deletejob(pid); /* Delete from job list */
        sigprocmask(SIG_SETMASK, &prev_all, NULL);
    }
    if (pid != 0 && errno != ECHILD)
        sio_eprintf("waitpid error");     // Call only async-signal-safe functions
    errno = olderrno;
}

高效等待信号用 sigsuspend: 原子地换上 mask、睡眠到有信号被处理、恢复原掩码, 不会在「检查条件」和「开始睡眠」之间漏掉信号 (第 17 讲). 阻塞信号的推荐写法: SIG_BLOCK 时保存旧掩码, 结束时用 SIG_SETMASK 恢复, 而不是 SIG_UNBLOCK: 如果调用前这个信号本来就被阻塞, SIG_UNBLOCK 会错误地把它放开; 恢复旧掩码的写法可以任意嵌套.

What is a makefile? — Automates the process of creating files (using a compiler) · Running make bomb will update bomb · Only if any of the source files have changed; avoids unnecessary work · Remembers complicated compiler commands for you · Can also store recipes for automating development tasks

Makefiles are lists of rules — Normal rules create files · Phony rules don't directly create files · Each rule has a target. · Rules may have prerequisites · If any of the prerequisites doesn't exist, it must be created first · If any of the prerequisites is newer than the target, the target is “out of date” and must be re-created · Rules may have commands.

.PHONY: clean

Special variables $@ and $< give the name of the .o and .c files respectively · This rule is implicit — built into Make · The .PHONY annotation can be anywhere in the makefile

The make command — Running make … will attempt to create the first target listed in the Makefile. · make <target_name> · By convention, the first target is a phony target named all · Phony rules serve as entry points into the Makefile · make all creates everything, make clean deletes all generated files, make check runs tests

Makefile 是一组规则: 目标、先决条件 (依赖)、命令. 目标文件不存在, 或任何一个先决条件比它新, 就执行命令重建; 否则什么也不做, 避免重复工作. 普通规则生成以目标命名的文件; 伪目标 (.PHONY, 如 all、clean) 不对应文件, 只是一组命令的入口. 只有先决条件没有命令的规则 (bomb.o: bomb.c …), 命令来自模式规则 %.o: %.c, 其中 $@ 是目标、$< 是第一个先决条件; 这条规则 make 已经内置. 命令行必须以 Tab 开头. make 不带参数时构建第一个目标, 惯例是 all.

What does a linker do? — Symbol resolution · Programs define and reference symbols (global variables and functions) · Linker associates each symbol reference with exactly 1 symbol definition · Relocation · Merges separate code and data sections into single sections · Relocates symbols from relative locations in .o files to final memory locations · Updates all references to symbols to reflect new positions

Linker symbols — Global symbols · non-static C functions and non-static global variables · External symbols · Global symbols that are referenced by module m but defined by some other module · Local symbols · C functions and global variables defined with the static attribute · Local linker symbols are not local program variables

Static vs Dynamic Linking — Static Linking: Executable files and running memory images contain only the library code they actually use · Dynamic linking: Executable files contain no library code · During execution, single copy of library code can be shared across all executing processes

Types of object files — Relocatable object file (.o file) · Executable object file (a.out file) · Shared object file (.so file)

How Linker resolves duplicate symbol definitions — Program symbols are either strong or weak · Strong: procedures and initialized globals · Weak: uninitialized globals · Or one's declared with specifier extern · 1. Multiple strong symbols are not allowed · 2. Given a strong symbol and multiple weak symbols, choose the strong symbol · 3. If there are multiple weak symbols, pick an arbitrary one

LD_LIBRARY_PATH — If you are using dynamic libraries, you need to tell the compiler where to look for the library! · It is easiest to use dynamic libraries with makefiles, just include this line: LD_LIBRARY_PATH = “~/my/path”

附录是第 7 讲链接内容的摘要: 链接器做符号解析 (每个引用对应唯一的定义) 和重定位 (合并各节、确定最终地址、修正所有引用). 符号分全局、外部、局部 (static) 三类. 静态链接把用到的库代码复制进可执行文件; 动态链接运行时共享一份库代码. 目标文件三种: 可重定位 .o、可执行、共享 .so. 重复定义按强弱规则处理.

幻灯片错误: ① 弱符号「或用 extern 声明的符号» 不对: extern 声明只是引用, 不是定义, 根本不参与强弱规则; 弱符号只是未初始化的全局变量 (而且 GCC 10 起默认 -fno-common, 未初始化的全局变量也按强符号处理, 重复定义会报错). ② LD_LIBRARY_PATH 一页: 它是运行时动态链接器查找 .so 的环境变量, 不是告诉编译器去哪里找库 (那是 -L 选项); 在 Makefile 中写 LD_LIBRARY_PATH = "~/my/path" 只定义了一个 make 变量, 既不会导出到环境, 引号和 ~ 也不会按 shell 的方式处理.
