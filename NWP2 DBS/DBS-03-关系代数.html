查询语言
Anfragesprachen

Folie 1–2

Kapitel 3 · Relationale Algebra

  • Anfragesprache (QL) ermöglicht es Benutzern, Daten aus einer Datenbank abzurufen und zu manipulieren
  • Relationales Modell unterstützt einfache, aber leistungsfähige Anfragesprachen
    • Starke formale Grundlage basierend auf Logik
    • Ermöglicht Optimierung von Anfragen

Anfragesprache = Programmiersprache

  • Bieten einfachen Zugriff auf große Datenmengen
  • Nicht für komplexe Anwendungen oder Berechnungen gedacht
  • Anfragesprachen müssen nicht Turing-vollständig sein

Kategorien von Anfragesprachen

  • Deklarativ: Fokus auf „was abgerufen werden soll“
  • Prozedural: Fokus auf „wie auf die Daten zugegriffen wird“

Anfragesprache 查询语言 (Query Language, QL) 让用户从数据库里取数据、改数据. 关系模型支持的查询语言简单而强大: 它们建立在逻辑之上, 有严格的形式基础, 所以系统可以自动优化查询 (把一个查询换成结果相同、算得更快的写法).

查询语言不是编程语言: 它擅长方便地访问大量数据, 不是用来写复杂应用或做复杂计算的, 也不需要图灵完备. 能力受限反而是好事: 每个查询都保证会结束, 系统也更容易分析和优化它.

两类查询语言: deklarativ 声明式只说要「什么」结果 (SQL 基本就是这样); prozedural 过程式说清楚「怎样」一步步得到结果. 下面的关系代数属于后者.

Folie 3
  • Zwei mathematische Anfragesprachen bilden die Grundlage moderner Anfragesprachen (z. B. SQL) und deren Implementierung
    • Relationale Algebra: Prozedurale Sprache, besonders nützlich zur Darstellung von Anfrageausführungsplänen und Optimierungstechniken (⇒ SQL)
    • Relationaler Kalkül: Deklarative, logikbasierte Sprache (⇒ QBE, Query-By-Example)

Das Verständnis von Algebra und Kalkül ist der Schlüssel zum Verständnis von SQL, Anfrageverarbeitung und -optimierung

现代查询语言 (例如 SQL) 和它们的实现建立在两种数学查询语言之上. Relationale Algebra 关系代数是过程式的, 特别适合表示查询执行计划和优化技术, 后来发展出 SQL; Relationaler Kalkül 关系演算是声明式的、基于逻辑的语言, 后来发展出 QBE (Query-By-Example, 在表格模板里填例子来查询). 绿框: 理解代数和演算, 是理解 SQL、查询处理和查询优化的关键.

本章只讲关系代数. 一个直观的对应: 写 SQL 时你写的是声明式的 SELECT … FROM … WHERE …, 数据库内部先把它翻译成一棵关系代数的运算树 (见本章最后的 运算树), 再对这棵树做优化.

关系代数概览
Einführung: Relationale Algebra · Motivation und Überblick

Folie 4
  • Relationale Algebra: formale Sprache zur Beschreibung von Datenbankanfragen im relationalen Modell
  • Theoretische Grundlage für relationale Anfragesprachen wie SQL
  • Alle Operationen der relationalen Algebra sind auf Mengen von Tupeln (Relationen) definiert

Warum relationale Algebra?

  • Formale, mathematisch saubere Beschreibung von Anfragen
  • Grundlage für die interne Repräsentation und Optimierung von SQL-Anfragen (z. B. Ausführungspläne)
  • Verständliches Modell für Lehre, Analyse und Implementierung
  • Beschränkt, aber dennoch ausdrucksstark – ideal zur systematischen Anfrageverarbeitung

Relationale Algebra beschreibt „wie“ Daten verarbeitet werden — sie ist prozedural

关系代数是在关系模型里描述数据库查询的形式语言, 是 SQL 这类关系查询语言的理论基础. 它的所有运算都定义在元组的集合 (也就是关系, 见 DBS 02 · 关系) 上.

为什么要学它: ① 用数学方式干净地描述查询; ② 数据库内部用它表示和优化 SQL 查询 (执行计划); ③ 便于教学、分析和实现; ④ 能力有限, 但表达力足够, 适合系统化地处理查询. 绿框再强调一次: 关系代数描述的是「怎样」处理数据, 它是过程式的.

Folie 5
  • Berechnungen auf Relationen bestehen aus
    • Operanden: Relationen
    • Operatoren: Ausdrücke der relationalen Algebra
  • Operatoren nehmen eine (unäre) oder zwei (binäre) Relationen als Eingabe
  • Ergebnis einer Operation ist immer eine (neue!) Relation
  • Relationale Algebra ist „abgeschlossen“ über Relationen

(Zwei Skizzen: „Unäre Operation der relationalen Algebra“: eine Tabelle r wird durch e(r) zu einer neuen Tabelle; „Binäre Operation der relationalen Algebra“: zwei Tabellen r und s werden durch e(r, s) zu einer neuen Tabelle.)

关系代数里的计算由操作数 (关系) 和运算符组成. 运算符接收一个关系 (unär 一元) 或两个关系 (binär 二元), 结果永远是一个新的关系. 这就是「abgeschlossen 封闭」: 关系进去, 关系出来.

封闭性为什么重要: 任何运算的结果又可以当作下一个运算的输入, 所以可以像算术表达式 (3+4)⋅5 一样把运算一层层嵌套起来, 拼出复杂的查询 (见 组合运算).

Folie 6

Unäre Operationen

  • Selektion: Wählt eine Teilmenge von Tupeln aus einer Relation aus
  • Projektion: Entfernt unerwünschte Spalten aus einer Relation
  • Umbenennung: Benennt Attribut(e) und Relation(en) um

Binäre Operationen

  • Kreuzprodukt: Kombiniert Tupel aus zwei Relationen
  • Vereinigung: Tupel aus Relation 1 und Relation 2
  • Differenz: Tupel aus Relation 1, die nicht in Relation 2 vorkommen

Da die relationale Algebra über Relationen abgeschlossen ist, können komplexere Anfragen durch Kombination mehrerer Operatoren formuliert werden (→ Minimalität)

六个Grundoperationen 基本运算, 考试常考, 要背下来:

运算元数作用
Selektion 选择 σ一元挑出满足条件的行
Projektion 投影 π一元只留下指定的列
Umbenennung 重命名 ρ一元给关系或属性改名
Kreuzprodukt 笛卡尔积 ×二元两边的元组两两拼接
Vereinigung 并 ∪二元两边的元组合在一起
Differenz 差 −二元在左边、不在右边的元组

绿框里的 Minimalität 最小性: 这六个运算谁也不能用其余五个表示出来, 少了任何一个表达力都会变弱; 其他运算 (交、除、连接) 都能用这六个拼出来. 本章最后的总结里也说「基本运算是最小的 (6 个)」.

算术表达式
Arithmetische Ausdrücke

Folie 7

Ein arithmetischer Ausdruck in relationaler Algebra kann rekursiv definiert werden:

  • Basisfall: jede Konstante und jeder Attributausdruck sind ein arithmetischer Ausdruck
  • Wenn E1​ und E2​ arithmetische Ausdrücke sind, dann auch
    • E1​+E2​
    • E1​−E2​
    • E1​⋅E2​
    • E1​÷E2​
  • Arithmetische Ausdrücke können umbenannt werden

算术表达式用递归定义: 最简单的情况 (Basisfall 基本情形) 是一个常数 (如 2) 或一个属性 (如 A); 如果 E1​、E2​ 已经是算术表达式, 那么它们的和、差、积、商也是. 所以 2⋅A、(A+B)÷2、preis⋅menge 都是算术表达式. 算出来的值可以重命名, 给结果列起名字.

Folie 8

Wo können arithmetische Ausdrücke auftreten?

  • Projektion
  • Selektion
  • Verbund (Join)
  • Aggregation
  • Umbenennung

aber nicht in

  • Mengenoperationen
  • Kartesisches Produkt

算术表达式能出现在投影 (算出新列, 如 π2⋅A​)、选择和连接的条件里 (σA⋅B>C​)、聚合函数里 (总价 sum(preis⋅menge))、重命名里. 不能出现在集合运算 (并、差、交) 和笛卡尔积里: 这些运算没有「参数」, 只接收两个关系, 没有地方写表达式.

选择
Selektion

Folie 9

Wähle alle Tupel aus einer Relation aus, für die eine aussagenlogische Formel P wahr ist

Notation

σp​(r)
  • r : Relation (Name)
  • P : Formel der Aussagenlogik, bestehend aus Bedingungen der Form: <Attribut> = <Attribut> oder <Konstante>

Definition

σp​(r):={t∣t∈r und P(t)=true}
  • Vergleichsoperatoren: =,=,<,>,⩾,⩽
  • Bedingungen können mit logischen Operatoren kombiniert werden: ∧ (und), ∨ (oder), ¬ (nicht)

Selektion 选择 σ 从关系里挑出所有让命题逻辑公式 P 为真的元组, 也就是筛行, 列不变. 定义: 结果是 r 中所有满足 P(t)=true 的元组 t 的集合. 条件由「属性 比较 属性」或「属性 比较 常量」组成, 比较符有 =,=,<,>,≥,≤, 多个条件用 ∧ (与)、∨ (或)、¬ (非) 组合.

对应 SQL 的 WHERE: σC>5​(r) 就是 SELECT * FROM r WHERE C > 5. 易错: 名字容易混, SQL 的 SELECT 对应的其实是投影 π, 不是选择 σ.

幻灯片小错: 同一张幻灯片前后不一致. 条件的形式只写了 <Attribut> = …, 下面又允许 =,<,>,≥,≤ 六种比较; 应写成 <Attribut> θ <Attribut> 或 <Konstante>, θ 是任一比较符. 另外记号里写的是小写 σp​, 正文和定义里用的是大写 P, 指的是同一个公式.

投影
Projektion

Folie 11

Gibt eine neue Relation mit nur den ausgewählten Attributen zurück

Notation

πA1​,…,Ak​​(r)
  • A1​,…,Ak​ : Attribute
  • r : Relation

Hinweise

  • Auch die Attributreihenfolge kann sich ändern
  • Kardinalität der Ergebnisrelation s : ∣πA1​,…,Ak​​(r)∣⩽∣r∣
    ⇒ Doppelte Zeilen, die durch die Projektion entstehen könnten, werden aus dem Ergebnis entfernt

Projektion 投影 π 返回一个只含指定属性的新关系, 也就是选列. 下标里的属性顺序就是结果的列顺序, 所以投影也能用来调换列的顺序 (πC,A​).

结果的元组数 ≤ 原来的元组数, 因为投影掉一些列以后, 原来不同的行可能变得完全一样, 而关系是集合, 重复的行只留一个.

易错: SQL 默认不去重: SELECT A, C FROM r 会返回重复行, 要写 SELECT DISTINCT A, C 才等于 πA,C​(r). 关系代数是集合语义, SQL 是多重集 (Multimenge, bag) 语义.

幻灯片小错: 「Kardinalität der Ergebnisrelation s」里的 s 在这张幻灯片上没有定义, 后面的式子里也没有用到它; 它指的是投影的结果 πA1​,…,Ak​​(r).

并与差
Vereinigung · Differenz

Folie 13

Kombiniert zwei Relationen, indem Tupel aus beiden in eine neue Ergebnisrelation übernommen werden

Notation

r∪s(r,s Relationen)

Definition

r∪s:={t∣t∈r∨t∈s}

Voraussetzungen

  • Relationen r und s müssen dieselbe Stelligkeit (Arity) besitzen
  • Attributdomänen müssen kompatibel sein (z. B. gleicher Datentyp in gleicher Spalte)
  • Es gilt (wegen Duplikateliminierung): ∣r∪s∣⩽∣r∣+∣s∣

Vereinigung 并 ∪: 结果包含在 r 里或在 s 里的所有元组. 前提: 两个关系的 Stelligkeit 元数 (列数, 英语 arity) 相同, 对应列的域兼容 (例如同一列都是整数). 满足这两条的两个关系叫并相容 (vereinigungsverträglich).

两边都有的元组只算一次 (去重), 所以 ∣r∪s∣≤∣r∣+∣s∣; 等号只在 r 和 s 没有共同元组时成立.

Folie 15

Liefert nur die Tupel zurück, die in einer Relation, aber nicht in der anderen vorkommen

Notation

r−s(r,s Relationen)

Definition

r−s:={t∣t∈r∧t∈/s}

Voraussetzungen

  • Relationen r und s müssen dieselbe Stelligkeit besitzen
  • Attributdomänen müssen kompatibel sein

Hinweise

  • Kardinalität: ∣r−s∣=∣r∣−∣r∩s∣
  • Grenzen: 0⩽∣r−s∣⩽∣r∣

Differenz 差 −: 在 r 里而且不在 s 里的元组. 前提和并一样 (元数相同、域兼容). 结果数 = r 的元组数减去两边共有的元组数, 所以在 0 (r 的元组全在 s 里) 和 |r| (两边没有共同元组) 之间.

差不满足交换律: r−s=s−r. 差是唯一能表达「否定」(「没有」「不是」) 的基本运算, 后面「没有人得 A 的课」这类查询都要靠它 (见 查询例子).

笛卡尔积
Kartesisches Produkt

Folie 17

Erzeugt eine neue Relation durch Kombination aller möglichen Tupelpaare beider Eingaberelationen

Notation

r×s(r,s Relationen)

Definition

{(a1​,…,am​,b1​,…,bn​)∣(a1​,…,am​)∈r∧(b1​,…,bn​)∈s}

wobei a1​,…,am​ Attribute von r und b1​,…,bn​ Attribute von s sind

Hinweise

  • Anzahl der Tupel: ∣r×s∣=∣r∣⋅∣s∣

Kartesisches Produkt 笛卡尔积 ×: r 的每个元组和 s 的每个元组拼成一个更长的元组. 结果的元数是两边元数之和 (m + n), 元组数是两边元组数之积. 和 DBS 02 的集合笛卡尔积不同的是, 这里拼出来的是「拉平」的元组 (a1​,…,am​,b1​,…,bn​), 不是二元组「(r 的元组, s 的元组)」.

笛卡尔积本身很少直接有用 (每个员工配每个部门), 但它是连接的基础: 先做积, 再用选择留下「配对正确」的行, 就是连接 (见 自然连接).

幻灯片小错: 「wobei a1​,…,am​ Attribute von r … sind」不准确. 定义里的 ai​、bj​ 是元组里的属性值 (Attributwerte), 不是属性本身; 应为「a1​,…,am​ Werte der Attribute von r」.

重命名
Umbenennung

Folie 19
  • Ermöglicht es, Ergebnissen von Ausdrücken der relationalen Algebra Namen zu geben (zur Referenzierung)
  • Erlaubt es, eine Relation mehrfach mit verschiedenen Namen zu verwenden (z.B. bei Selbstvergleichen)
  • Beispiel:
    • ρx​(E) bezeichnet den Ausdruck E unter dem neuen Namen x
  • Wenn der Ausdruck E die Stelligkeit k hat, dann bezeichnet ρx(A1​,A2​,…,Ak​)​(E) den Ausdruck E mit neuem Relationen- und neuen Attributnamen

Umbenennung 重命名 ρ (希腊字母 rho) 不改数据, 只改名字. 两个用途: ① 给一个表达式的结果起名, 后面好引用它; ② 同一个关系要用两次时 (Selbstvergleich 自比较), 给两份拷贝起不同的名字, 否则属性名重复, 分不清是哪一份的列.

ρx​(E) 只给关系改名; ρx(A1​,…,Ak​)​(E) 同时把 k 个属性依次改名为 A1​,…,Ak​.

例子: 找出比 Bob 年纪大的学生. 要把 Studierende 的每一行和 Bob 那一行比, 关系得用两次:

πS1.Name​(σS1.Alter>S2.Alter∧S2.Name=’Bob’​(ρS1​(Studierende)×ρS2​(Studierende)))

对应 SQL 里的表别名 FROM Studierende S1, Studierende S2.

Folie 20

Division

Folie 23

Geeignet für Anfragen, die den Ausdruck „für alle“ enthalten (→ Simulation des All-Quantors)

Notation

r÷s

Voraussetzung

Die Attribute in S müssen eine Teilmenge der Attribute in R sein, d. h. S⊆R

  • Sei r, s Relationen über den Schemata R bzw. S, wobei
    • R(A1​,…,Am​,B1​,…,Bn​)
    • S(B1​,…,Bn​)
  • Das Ergebnis von r÷s ist eine Relation über dem Schema R−S=(A1​,…,Am​)
  • Die Ergebnismenge besteht aus den Tupeln von r (über den Attributen R−S), die zu allen Tupeln in s passen

Definition

r÷s:={t[A1​,…,Am​]∣t∈r∧∀u∈s:(t[A1​,..,Am​]∪u)∈r}

Division 除法 ÷ 用来回答含「对所有」(für alle) 的问题, 例如「选了所有课的学生」, 它在关系代数里模拟全称量词 ∀.

前提: s 的属性是 r 的属性的一部分. r 的属性分成两组: 只在 r 里的 A1​,…,Am​, 和 s 也有的 B1​,…,Bn​. 结果只有 A 这一组属性. 一个 A 值组合 t 进入结果, 当且仅当 s 里的每一个元组 u 和 t 拼起来都在 r 里. t[A1​,…,Am​] 表示元组 t 在这些属性上的部分.

为什么叫「除」: 它是笛卡尔积的逆运算. 如果 q=r÷s, 那么 q×s⊆r, 而且 q 是满足这一点的最大关系, 和整数除法 7÷2=3 (3⋅2≤7) 一个道理.

除法也能用基本运算拼出来 (A 表示 A1​,…,Am​): r÷s=πA​(r)−πA​((πA​(r)×s)−r). 读法: πA​(r)×s 是「每个候选都配齐 s 的全部元组」的理想情况; 减去 r 得到候选缺的那些组合; 投影到 A 就是「至少缺一个」的候选; 从全部候选里去掉它们, 剩下的就是一个都不缺的.

幻灯片小错: 前提写成 S⊆R (子集, 可以相等), 应为真子集 S⊂R. 如果 S = R, 结果的模式 R − S 是空的, 没有属性, 除法就没有意义; 下面的 R(A1​,…,Am​,B1​,…,Bn​) 也默认了至少有一个 A (m ≥ 1).

Natürlicher Verbund (Join)

Folie 25

Kombiniert zwei Relationen über identische Werte in gleichnamigen Attributen

Notation

r1​⋈r2​(wobei r1​ und r2​ Relationen sind)

Definition

  • Relation r mit m+k Attributen: A1​,…,Am​,B1​,…,Bk​
  • Relation s mit n+k Attributen: B1​,…,Bk​,C1​,…,Cn​
  • Annahme: Ai​ und Ci​ sind paarweise verschieden → nur B1​,…,Bk​ sind gemeinsame Attribute
  • Stelligkeit von r⋈s: m+k+n
r⋈s:=ΠA1​,…,Am​,r.B1​,…,r.Bk​,C1​,…,Cn​​(σr.B1​=s.B1​∧⋯∧r.Bk​=s.Bk​​(r×s))

Natürlicher Verbund 自然连接 ⋈ (德语 Verbund = 连接, 英语 join): 把两个关系里同名属性取值相同的元组拼在一起. 设 r 和 s 的共同属性是 B1​,…,Bk​, 只在 r 里的是 A, 只在 s 里的是 C.

定义按三步读: ① r×s: 所有配对; ② σ: 只留共同属性全部相等的配对; ③ π: 共同属性在积里出现了两次 (r.B 和 s.B), 投影时只留一份. 所以结果的元数是 m + k + n, 不是 m + 2k + n.

幻灯片前后不一致: 记号写 r1​⋈r2​, 定义里却用 r 和 s; 定义中的投影写成大写 Π, 而 Folie 11 引入投影时用的是小写 π (Folie 41 的树里也是大写). 两种写法指的都是投影.

θ 连接
Theta-Verbund

Folie 28

Notation

r⋈C​s

C ist eine Bedingung über Attribute in R∪S

Definition

r⋈C​s=σC​(r×s)

Hinweise

  • C wird auch als θ (Theta) bezeichnet
  • Wenn R∩S=∅ und C diese Attribute referenziert, müssen sie ggf. umbenannt werden
  • Das Ergebnisschema ist wie beim natürlichen Verbund
  • Wenn C nur Gleichheitsvergleiche enthält, spricht man auch von einem Equi-Verbund

Theta-Verbund θ 连接 (bedingter Verbund 条件连接): 连接条件 C (也叫 θ) 自己写, 定义就是「先积, 再选」: σC​(r×s). C 里可以用任何比较符 (<、≤、≠ …), 不限于相等. 只用等号时叫 Equi-Verbund 等值连接.

两边有同名属性、而 C 又要用到它们时, 必须先重命名 (或写成 r.B、s.B), 否则分不清指的是哪一边.

幻灯片错误: 「Das Ergebnisschema ist wie beim natürlichen Verbund」不对. 按上面的定义 σC​(r×s), θ 连接的结果模式就是 r×s 的模式: 两边的属性全部保留, 同名属性出现两次 (元数 |R| + |S|); 自然连接则把同名属性合并成一份 (元数 ∣R∪S∣). 下一页的例子恰好没有同名属性, 两者看不出差别. 后面 Folie 36–38 的查询里, θ 连接之后 MNr、KNr 都出现了两次, 正是这个原因.

外连接
Weitere Verbund-Typen

Folie 30
  • Theta-Verbund und Natürlicher Verbund werden auch als Inner Joins bezeichnet
  • Inner Joins beinhalten nur Tupel, die die Verbund-Bedingung erfüllen
  • Wenn man auch Tupel ohne passenden Partner einbeziehen möchte, verwendet man Outer Joins

Full-Outer Join

θ 连接和自然连接都叫 Inner Join 内连接: 结果里只有满足连接条件的元组, 没找到搭档的元组直接丢掉. 想把没有搭档的元组也留下, 就用 Outer Join 外连接, 缺的那一边填空值 (NULL).

读图: r 的第一列 (绿色) 是 1、2, s 的是 1、3、4, 按这一列连接. 只有 1 两边都有. Full-Outer Join 全外连接 r ⟗ s 的结果 4 行: 1 配 1; 2 只有 r 的部分 (右边空白); 3 和 4 只有 s 的部分 (左边空白). 两边的元组一个都不丢. 右上角的小图是两个都涂满的圆.

Right-Outer Join

读图: Left-Outer Join 左外连接 r ⟕ s 保留左边 r 的所有元组: 1 配 1, 2 配空; s 的 3、4 丢掉 (2 行). Right-Outer Join 右外连接 r ⟖ s 保留右边 s 的所有元组: 1 配 1, 空配 3, 空配 4; r 的 2 丢掉 (3 行). 小图里涂满的圆就是被完整保留的那一边.

记符号: 连接符号 ⋈ 哪一边多出两道「横线」, 哪一边的元组就全部保留. 三种外连接的行数关系: 全外 = 内连接的行 + 左边落单的 + 右边落单的 = 1 + 1 + 2 = 4.

在 SQL 里外连接直接有关键字. 用图里的数据实际运行 (PostgreSQL 18.6, 空值显示为 NULL):

SELECT r.k AS r_k, s.k AS s_k
FROM (VALUES (1),(2)) r(k) FULL OUTER JOIN (VALUES (1),(3),(4)) s(k) ON r.k = s.k
ORDER BY coalesce(r.k, s.k);
 r_k | s_k
-----+------
   1 |    1
   2 | NULL
NULL |    3
NULL |    4

把 FULL 换成 LEFT 得到 (1, 1)、(2, NULL), 换成 RIGHT 得到 (1, 1)、(NULL, 3)、(NULL, 4), 和图一致.

Gruppierung 分组: 把在某些属性上取值相同的元组归成一组; Aggregation 聚合: 对每组算一个值 (个数 count、平均 avg、总和 sum、最小 min、最大 max). 记号 γ (gamma) 的下标分号前是分组属性, 分号后是聚合函数. 结果每组一行: 分组属性的值 + 各个聚合值.

幻灯片小错: 记号 γA1​,…,An​;F1​,…,Fn​​ 让分组属性和聚合函数都是 n 个, 好像两者个数必须相同. 实际上两者个数无关 (例子里就是 1 个分组属性配 1 个函数, 也可以 1 个配 3 个), 应写成 F1​,…,Fm​.

组合运算
Kombination von Operatoren

Folie 33–34
  • Es ist möglich, Ausdrücke der relationalen Algebra zu verschachteln (wie arithmetische Ausdrücke)
  • Ein Basisausdruck in der relationalen Algebra ist entweder:
    • eine Relation aus der Datenbank
    • eine konstante Relation (fester Tupelvorrat, z.B. {(1,2),(1,3),(2,3)})
  • Wenn E1​ und E2​ Ausdrücke der relationalen Algebra sind, dann sind auch folgende Ausdrücke gültig:
    • E1​∪E2​
    • E1​−E2​
    • E1​⋈E2​ (Verbund)
    • σP​(E), wobei P ein Prädikat auf Attributen von E ist
    • πA​(E), wobei A eine Attributliste aus E ist
    • ρx​(E), wobei x ein neuer Name für das Ergebnis von E ist

关系代数表达式可以像算术表达式一样嵌套, 定义也是递归的. Basisausdruck 基本表达式: 数据库里的一个关系, 或者一个直接写出来的常量关系 (如 {(1, 2), (1, 3), (2, 3)}). 如果 E1​、E2​ 是表达式, 对它们做并、差、连接、选择、投影、重命名得到的还是表达式. 封闭性 (Folie 5) 保证了这一点.

幻灯片前后不一致: Folie 34 的列表里有 ⋈, 却没有基本运算笛卡尔积 E1​×E2​; 而 Folie 6 和 Folie 42 都说基本运算是 6 个, 其中包括笛卡尔积, 连接只是附加运算 (Folie 20). 完整的递归定义应该列出 6 个基本运算: ∪,−,×,σ,π,ρ; 连接、交、除可以作为缩写再加上.

幻灯片错误: 投影里的属性写成 KursNr, 但 Folie 35 的表里课号属性叫 KNr, 两张表都没有 KursNr 这个属性, 照写会出错. 应为 πKNr​(KURSE)−πKNr​(σNote=′A′​(EINSCHREIBUNGEN)). 而且差的结果只有一列 KNr, 外层连接条件 KURSE.KNr = KNr 两边都叫 KNr, 也需要先重命名; 更简单的写法是直接用自然连接: πKursname​((πKNr​(KURSE)−πKNr​(σNote=′A′​(EINSCHREIBUNGEN)))⋈KURSE).

四个例子对应的 SQL, 用 Folie 35 的数据在 PostgreSQL 18.6 上实际运行, 结果和课件一致:

-- Folie 36
SELECT DISTINCT s.Name
FROM Kurse k
JOIN Einschreibungen e ON k.KNr = e.KNr
JOIN Studierende s ON s.MNr = e.MNr
WHERE k.Kursname = 'Datenstrukturen';          -- Alice, Dave

-- Folie 37
SELECT DISTINCT s.Name
FROM Einschreibungen e JOIN Studierende s ON s.MNr = e.MNr
WHERE e.Note = 'A';                            -- Alice, Bob, Carol

-- Folie 38
SELECT s.Name
FROM (SELECT MNr, count(KNr) AS AnzKurse
      FROM Einschreibungen GROUP BY MNr) g
JOIN Studierende s ON s.MNr = g.MNr
WHERE g.AnzKurse > 1;                         -- Alice, Bob, Carol

-- Folie 39
SELECT k.Kursname
FROM (SELECT KNr FROM Kurse
      EXCEPT
      SELECT KNr FROM Einschreibungen WHERE Note = 'A') x
JOIN Kurse k ON k.KNr = x.KNr;                 -- Algorithmen

对照: π ↔ SELECT DISTINCT, σ ↔ WHERE, ⋈C​ ↔ JOIN … ON, γ ↔ GROUP BY, − ↔ EXCEPT.

Weitere Beispielanfragen

  1. Finde die Namen der Studierenden, die in keinem Kurs eingeschrieben sind.
  2. Finde die Namen der Studierenden, die sowohl in „Datenstrukturen“ als auch in „Analysis“ eingeschrieben sind.
  3. Berechne das durchschnittliche Alter der Studierenden, die in jedem Kurs eingeschrieben sind.
  4. Finde die Namen der Studierenden, die „Mathematik“ studieren und im Kurs „Physik I“ eingeschrieben sind.
  5. Finde alle Studierenden, die insgesamt mehr als 3 Leistungspunkte belegen.

五道练习: ① 一门课都没选的学生的名字; ② 既选了 Datenstrukturen 又选了 Analysis 的学生的名字; ③ 选了每一门课的学生的平均年龄; ④ 专业是数学、而且选了 Physik I 的学生的名字; ⑤ 总共选课超过 3 学分的学生. 提示: 「没有」用差, 「既……又……」用交, 「每一门」用除, 「总共」用聚合.

答案 (先自己做再看)

为了简短, 下面把表名写成 S (Studierende)、K (Kurse)、E (Einschreibungen), 用自然连接 (共同属性正好是 MNr 或 KNr). 结果都用 Folie 35 的数据按定义算过.

① 没选课的学生: 所有学号减去出现在选课表里的学号.

πName​((πMNr​(S)−πMNr​(E))⋈S)

结果是空关系: 4 个学生每人至少选了一门课. 空结果也是正确答案, 不是查询写错了.

② 两门都选了: 分别求两个学号集合, 再取交.

πName​((πMNr​(σKursname=′Datenstrukturen′​(K)⋈E)∩πMNr​(σKursname=′Analysis′​(K)⋈E))⋈S)

结果: Alice. 易错: 不能写 σKursname=′Datenstrukturen′∧Kursname=′Analysis′​, 一行的课名不可能同时等于两个值, 结果永远是空的.

③ 选了每一门课的学生的平均年龄: 「每一门」用除法, 再聚合.

γ;avg(Alter)​((πMNr,KNr​(E)÷πKNr​(K))⋈S)

没有人 4 门课都选了 (每人最多 2 门), 除法结果为空, 平均值没有定义. SQL 里对空集求 avg 返回 NULL (实测 PostgreSQL 也是 NULL). 注意除之前要先把 E 投影到 (MNr, KNr), 否则 ENr 和 Note 也会被当成结果属性.

④ 学数学并选了 Physik I:

πName​(σStudienfach=′Mathematik′​(S)⋈E⋈σKursname=′Physik I′​(K))

结果: Bob. 学数学的是 Bob 和 Dave, 选了 Physik I (103) 的是 Bob 和 Carol, 两者都满足的只有 Bob.

⑤ 总学分超过 3: 先连接拿到每条选课记录的学分, 按学生求和, 再筛选.

πName​(σLP>3​(γMNr;sum(Leistungspunkte)→LP​(E⋈K))⋈S)

每人的学分: Alice 3 + 4 = 7, Bob 4 + 3 = 7, Carol 3 + 3 = 6, Dave 3. 结果: Alice、Bob、Carol. 易错: 题目问「学生」, 不要只返回学号; 也不能在求和前就筛选 Leistungspunkte > 3 (那是单门课的学分, 不是总数).

运算树
Grafische Darstellung relationaler Algebra-Ausdrücke

Folie 41
  • Relationale Algebra-Ausdrücke können grafisch in einer baumartigen Struktur dargestellt werden
  • Knoten im Baum repräsentieren Operationen (Ausdrücke)
  • Kanten im Baum stellen den Datenfluss zwischen Operationen (Relationen) dar

Beispiel

关系代数表达式可以画成树: 内部节点是运算, 叶子是关系, 边表示数据 (中间结果关系) 从下往上流. 根节点的输出就是整个查询的结果.

读图: 叶子 R1​,…,Rm​ 先一起做笛卡尔积 ×, 再用条件 p 选择 σp​, 最后投影到 A1​,…,An​. 写成表达式就是 πA1​,…,An​​(σp​(R1​×R2​×⋯×Rm​)). 这正是 SQL 查询 SELECT A1, …, An FROM R1, …, Rm WHERE p 的标准翻译: FROM → 积, WHERE → 选择, SELECT → 投影.

数据库就在这样的树上做优化, 例如把选择挪到积的下面 (先筛行再拼接), 或把积加选择换成连接. 树的形状变了, 结果不变.

总结
Zusammenfassung

Folie 42
  • Relationale Algebra als theoretische Grundlage von Anfragesprachen (z. B. SQL)
  • Basierend auf dem relationalen Modell und darauf abgeschlossen (Eingabe und Ausgabe jeder Operation sind Relationen)
  • Die Menge an Basisoperationen ist minimal (d. h. 6 Stück)
  • Komplexere Operationen (z. B. Joins) können daraus zusammengesetzt werden

四点总结: ① 关系代数是 SQL 等查询语言的理论基础; ② 它建立在关系模型上, 对关系封闭: 每个运算的输入和输出都是关系; ③ 基本运算是最小的一组, 共 6 个 (σ,π,ρ,×,∪,−); ④ 更复杂的运算 (连接等) 可以由它们组合出来.
