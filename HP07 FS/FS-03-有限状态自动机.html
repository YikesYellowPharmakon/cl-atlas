没有记忆的系统
Systems with no Memory

Slide 3
  • Systems where the output or the next state is determined solely by the current state and the current input, without any need to remember past inputs
  • They are everywhere:
    • Turnstiles: you pass if you insert a token
    • Vending machines: get food if you insert money
    • Traffic lights: previous color (+ timer)
    • Digital circuits: e.g., logic boards, switches
    • String searchers: find if match
    • …
  • Can all be implemented as finite state automata

这类系统的输出或下一个状态只由当前状态和当前输入决定, 不需要记住以前的输入. 例子随处可见: 地铁闸机 (投币就放行)、自动售货机 (投钱就出货)、红绿灯 (看上一个颜色加计时器)、数字电路 (逻辑板、开关), 以及本课最关心的字符串搜索 (判断有没有匹配). 它们都可以实现成 finite state automaton 有限状态自动机.

「没有记忆」要读准: 不是什么都不记, 而是不另外保存输入的历史. 过去的输入里有用的那一点信息, 已经体现在「现在处在哪个状态」上. 售货机不记得你先投了 1 分还是 2 分, 只记得「已经投了 3 分」这个状态. 状态的个数是有限的, 所以能记住的东西也有限, 这就是后面要讲的有限自动机的能力边界.

用有向图表示
Finite State Automata

Slide 4
  • Represented as a directed graph: a finite set of nodes (states) connected by a set of directed arcs (transitions)
    • State: situation in which the system remains an amount of time
    • Event/transition: action that happens instantly

有限状态自动机画成一张 gerichteter Graph / directed graph 有向图: 有限个节点是 state 状态, 节点之间的有向边是 transition 转移. 状态是系统会停留一段时间的情形; 转移是瞬间发生的动作.

读图: 开关只有 ON 和 OFF 两个状态. 处在 ON 时发生「switch off」这个事件, 就沿箭头到 OFF; 处在 OFF 时「switch on」又回到 ON. 箭头上的标签就是触发转移的输入. 后面所有自动机图都是这种读法: 圆圈是状态, 带标签的箭头是转移.

三个组成部分
Three Components of a Finite State Automaton

Slide 5
  1. Input tape
  2. Reader head
  3. Control unit

一个有限状态自动机由三部分组成: input tape 输入带、reader head 读头、control unit 控制单元. 下面三张幻灯片逐个讲. 图里读头刚读完第一个 b, 正指着第二格; 控制单元根据读到的符号决定换到哪个状态.

Slide 6

1. Input Tape

  • Purpose: Contains the input string to be processed
  • Characteristics:
    • Contains only symbols from the automaton’s alphabet (Σ)
    • Static (cannot be modified) and with finite length
    • It can be read sequentially: left to right

输入带的用途是存放要处理的输入串. 特点: 上面只有自动机字母表 Σ 里的符号; 它是静态的 (不能改写), 长度有限; 只能从左到右顺序读.

「只能读、不能写」很关键: 自动机没法把中间结果写回带上, 所以它唯一的记忆就是控制单元里的当前状态. 以后讲到的图灵机正好相反, 带可以写、读头可以左右移动, 能力也就强得多.

Slide 7

2. Reader Head

  • Purpose: Reads one symbol at a time from the input tape → sequential processing
  • Characteristics:
    • Starts with the leftmost symbol of the input
    • Reads a symbol and then moves one step to the right
    • Cannot move backward or modify the tape

读头一次从输入带上读一个符号, 也就是顺序处理. 它从输入最左边的符号开始, 读一个就右移一格; 不能后退, 也不能改带上的内容.

所以一个长度为 n 的串, 自动机正好走 n 步就结束, 每个符号只看一次. 这也是有限自动机识别字符串非常快 (线性时间) 的原因.

Slide 8

3. Control Unit

  • Purpose: Determines transitions between states
  • Components:
    • State Register: Tracks the current state
    • Transition Function (δ)

控制单元决定状态之间怎么转移. 它有两部分: Zustandsregister / state register 状态寄存器, 记住当前状态; Übergangsfunktion / transition function 转移函数 δ, 告诉它「在这个状态读到这个符号, 下一步去哪个状态」. δ 的形式定义见 Slide 13.

三部分如何协同工作
How They Work Together

Slide 9
  1. Initialization:
    • Input string loaded onto the tape
    • Reader head positioned at the leftmost symbol
    • Control unit set to the start state (q0​)
  2. Processing:
    • Reader head reads the current symbol
    • Control unit uses current state and input symbol to compute next state via δ
    • Reader head moves one step to the right
  3. Termination:
    • Reader head reaches the end of the input string
    • FSA halts and:
      • Accepts if in an accept/final state
      • Rejects otherwise

运行分三步. 初始化: 输入串放上输入带, 读头放在最左边的符号上, 控制单元置于 Startzustand / start state 初始状态 q0​. 处理: 读头读当前符号; 控制单元用「当前状态 + 输入符号」经 δ 算出下一个状态; 读头右移一格. 这三步一直重复. 结束: 读头走到输入串末尾, 自动机停机; 这时处在 Endzustand / accept state, final state 接受状态 (终态) 就 accept 接受, 否则 reject 拒绝.

易错: 是否接受只看读完整个串之后停在哪个状态. 中途经过终态不算数, 例如在 Slide 25 的羊叫自动机里, 串 ba!a 读到 ! 时已经到了终态 4, 但后面还有 a, 状态 4 读 a 没有转移, 自动机停机拒绝.

更复杂模型的额外部件
Finite State Automata: (extra) Components

Slide 10

Some more complex models may:

  • have additional memory
  • produce an output
  • move the reader head both left and right

更复杂的模型可能还有: 额外的记忆、输出、可以左右移动的读头. 图里的完整机器有输入带、有限记忆的控制单元、可以读写的额外记忆 (无限大), 以及输出带.

有限状态自动机把这些全部去掉, 只剩输入带、只往右走的读头和有限个状态. 加上一个栈作额外记忆就是以后的下推自动机, 加上输出就是有限状态转换器 (finite state transducer), 读头能左右走且能写带就是图灵机.

确定与非确定
Finite State Automata (FSA)

Slide 11
  • Finite (State) Automata are the simplest automata
  • Finite (bounded) memory is available in the control unit → used to remember states
  • Two kinds of FSA:
    • Deterministic
      • For every state and input symbol, there is exactly one transition to a new state
      • The machine’s behavior is completely predictable and determined by its current state and input
    • Nondeterministic
      • It may have multiple possible transitions for a given state and input symbol
      • It can "choose" among multiple paths or transitions
      • The machine’s behavior is not strictly predictable based solely on the current state and input
      • … stay tuned!

有限 (状态) 自动机是最简单的自动机. 它的控制单元里只有有限 (有界) 的记忆, 用来记住状态. 分两种: deterministisch / deterministic 确定性 (DFA) 和 nichtdeterministisch / nondeterministic 非确定性 (NFA).

DFA (确定)NFA (非确定)
同一状态 + 同一符号恰好一个转移可以有多个转移
行为完全可预测, 由当前状态和输入唯一决定可以在几条路径里「选择」, 光看当前状态和输入预测不了

非确定自动机下一讲再讲 (stay tuned). 这一讲和练习 3 只讲确定的 DFA.

「确定」只管同一状态、同一符号不能有两个去向; 至于某个符号有没有转移, 是下面「完全 / 不完全」讨论的事. 严格按 Slide 13 的定义 δ:Q×Σ→Q 是一个 (全) 函数, 每个状态对每个符号都恰好有一个转移, 所以 DFA 一定是完全的. 课件在 Slide 23 也把缺转移的自动机叫 DFA, 那是把 δ 放宽成部分函数的说法 (很多教材, 包括 J&M, 也这么用). 考试时说清楚用的是哪种定义就不会错.

形式定义
Formal Definition

五元组
Formal Definition

Slide 13

FSA is a Quintuple (Σ,Q,q0​,δ,F)

  • Σ: Input alphabet
  • Q: Set of states
  • q0​∈Q: Initial state
  • δ:Q×Σ→Q: Transition function
  • F: Final states
  • M=({a,b},{q1​,q2​},q1​, δ(q1​,a)=q1​,δ(q1​,b)=q2​,δ(q2​,a)=q1​,δ(q2​,b)=q2​,{q2​})

一个有限状态自动机是一个 Quintupel / quintuple 五元组 (Σ,Q,q0​,δ,F): Σ 是输入字母表; Q 是状态集合 (有限); q0​∈Q 是初始状态; δ:Q×Σ→Q 是转移函数, 把「状态, 符号」这一对映射到一个状态; F 是终态集合 (F⊆Q, 可以有多个, 也可以为空).

读图的约定: 没有起点的箭头 (这里是粗黑箭头) 指向初始状态; 双圈是终态; 自环表示读这个符号后留在原状态. 图里的 M 就是把五元组的每一项填出来, δ 逐条列出四个转移.

例子: 串 aab 从 q1​ 出发, a 留在 q1​, a 还在 q1​, b 到 q2​, 停在终态, 接受. 串 aba 最后读 a 回到 q1​, 拒绝. 规律是: 读完后停在 q2​ 当且仅当最后一个符号是 b, 所以 L(M) 是所有以 b 结尾的串 (用 Python 枚举了长度 ≤ 8 的全部串核对).

五元组里各项的顺序各书不同: 课件写 (Σ,Q,q0​,δ,F), 练习 3 题 1.6 和大多数教材 (Hopcroft、Sipser) 写 (Q,Σ,δ,q0​,F). 内容完全一样, 写形式定义时用课件的顺序, 但看到另一种顺序也要认得.

转移函数
Transition Function

Slide 14
  • It defines how the state of the automaton changes in response to an input symbol
  • Crucial role: it determines whether a given input string is accepted by the automaton

(Diagram as on Slide 13.)

δ(q1​,a)=q1​,δ(q1​,b)=q2​,δ(q2​,a)=q1​,δ(q2​,a)=q2​,{q2​})
M=({a,b},{q1​,q2​},q1​,δ,{q2​})

δab
q1​q1​q2​
q2​q1​q2​

转移函数规定自动机的状态怎样随输入符号变化. 它起决定作用: 一个输入串被不被接受, 完全由它决定 (再加上终态集合).

这一页给出 δ 的第二种写法: 五元组里只写 δ 这个名字, 再单独画一张 Übergangstabelle / transition table 转移表. 表的行是状态, 列是输入符号, 格子里是下一个状态; 例如第 2 行 a 列的 q1​ 就是 δ(q2​,a)=q1​. DFA 的转移表每个格子恰好一个状态, 一格不空, 这就是「确定且完全」在表上的样子. 图、逐条列出的 δ、转移表三种写法说的是同一件事, 练习里经常要互相转换.

幻灯片错误: 第一种写法列出的第四个转移印成 δ(q2​,a)=q2​, 应为 δ(q2​,b)=q2​. 原文这样写, q2​ 读 a 就同时有 q1​ 和 q2​ 两个去向 (不再是确定的), 读 b 又没有去向, 和图 (q2​ 的自环标 b)、下面的转移表以及 Slide 13 都对不上.

例子: 自动售货机
Example: Vending Machine

Slide 15

A greedy vending machine:

  • Product's price: 5 cents
  • Accepted coins: 1, 2 or 5 cents
  • Any sequence of valid coins is accepted
    • with total value 5 cents or bigger
  • No change returned

一台「贪心」的自动售货机: 商品 5 分钱; 收 1、2、5 分的硬币; 任何一串合法硬币, 只要总额 ≥ 5 分就接受; 不找零. 「贪心」指多投的钱它照收不退.

建模思路: 售货机不用记住投币的顺序, 只要记住已经投了多少钱. 已投金额只有 0、1、2、3、4 和「≥ 5」六种情况, 所以六个状态就够了.

Slide 16
  • Accepted sequences → Strings accepted by the automaton
    • Exact price: 11111, 221, 1112, 5, …
    • Too many coins: 11115, …
  • Rejected sequences
    • Not enough: 11, 21, …

图上的标题是「Vending machine: Model with final states」(有终态的模型). 状态名就是已投金额; 从状态 s 投 c 分, 就到状态 min(s+c,5). 例如从 3 投 2 或 5 都到 5, 从 2 投 2 到 4. 状态 5 对三种硬币都有自环, 多投的钱被吞掉.

被接受的投币序列就是自动机接受的串, 字母表是 Σ={1,2,5} (这里的「1」「2」「5」是符号, 不是数). 恰好够: 11111、221、1112、5; 投多了: 11115. 被拒绝: 钱不够, 如 11 (停在 2)、21 (停在 3). 这几条都用 Python 按图模拟过, 结果和幻灯片一致.

易错: 221 的路径是 0 → 2 → 4 → 5; 不是「2 + 2 + 1 是 5」这种算术, 而是一格一格地走状态. 另外这台机器是完全的: 每个状态对 1、2、5 都有转移.

完全与不完全的 FSA
Complete & Incomplete FSA

完全的 FSA
Complete FSA

Slide 18
  • It has transitions defined for all input symbols (Σ) in every state
  • It does not contain undefined transitions
  • It always processes any input string

vollständiger Automat / complete FSA 完全的有限自动机: 每个状态对字母表 Σ 里的每个符号都定义了转移, 没有未定义的转移, 所以任何输入串都能一直读到底. 换成转移表的说法: 表里没有空格.

Slide 19

Example of a complete DFA

  • All input symbols (a, b) are on the transitions of every state
  • This DFA accepts strings that have aba somewhere in it
  • Once the existence of aba is verified, the rest of the input is ignored (accepted without any extra verification)

每个状态都有 a 和 b 两条出边, 所以是完全的. 这个 DFA 接受所有某处含有 aba 的串; 一旦确认出现过 aba, 后面的输入就不再检查 (q3​ 读什么都留在 q3​).

状态的含义是「已经匹配到 aba 的前几个字母」: q0​ = 还没匹配上, q1​ = 刚读到 a, q2​ = 刚读到 ab, q3​ = 已经出现过 aba. 两个回退转移最值得看: 在 q1​ 再读 a 仍留在 q1​ (新读的 a 又可以作开头); 在 q2​ 读 b 得到 …abb, 没有任何后缀能作 aba 的开头, 所以退回 q0​. 例子: aabab 走 q0​→q1​→q1​→q2​→q3​→q3​, 接受; abba 走到 q1​ 结束, 拒绝. 用 Python 对长度 ≤ 10 的全部串核对过: 接受 ⇔ 含子串 aba.

陷阱状态
Sink States

Slide 20
  • Also called: dead state, trap state
  • Often present in complete FSAs
  • A specific type of state → non-accepting state
  • Once entered, the FSA remains in this state
    • Deal with unwanted inputs (e.g., symbols not part of the language)
    • Error handling
    • Prevent infinite loops
    • Simplify the design of the system

sink state 陷阱状态 也叫 dead state (死状态)、trap state (陷阱状态), 常见于完全的 FSA. 它是一种特殊的非接受状态: 一旦进入, 自动机就一直留在那里 (对每个符号都自环). 用处: 处理不想要的输入 (例如不属于这个语言的符号)、错误处理、防止无限循环、简化系统设计.

为什么完全的 FSA 常常需要它: 「完全」要求每个状态对每个符号都有去向, 可有些输入一出现就注定不可能被接受 (比如羊叫开头读到 a). 这些转移总得指向某个地方, 就统一指向一个陷阱状态. 它只是「已经失败」的记号, 不会让本来会被拒绝的串变成接受.

「防止无限循环」是从实际系统的角度说的; 对只读有限输入串的 FSA 来说, 读完就停, 本来不会无限循环.

Slide 21

Example of a complete DFA with a sink state

  • This DFA accepts strings that start with ab
  • Once the string starts with ab the rest of the input is ignored
  • State q1​ is a sink state
    • Once a machine enters a sink state, there is no getting out!
    • The input string is rejected once there is no more input information available

这个 DFA 接受所有以 ab 开头的串; 一旦开头是 ab, 后面的输入就不管了. q1​ 是陷阱状态: 进去就出不来; 读完输入时仍在 q1​, 串被拒绝.

两条进陷阱的路: 开头就读 b (q0​→q1​), 或开头 aa (q0​→q2​→q1​). 例如 abba 接受, aab 拒绝 (第二个 a 已经进了陷阱, 后面的 b 救不回来). q3​ 也有 a, b 自环, 但它是终态, 不叫陷阱状态: 陷阱状态按定义是非接受的.

不完全的 FSA
Incomplete FSA

Slide 22
  • This automaton has missing transitions for certain inputs in some states
  • Some input symbols do not lead to any state
  • Undefined transitions cause the FSA to halt and reject the input
  • Overall, simpler representations
    • Fewer states and transitions compared to a complete FSA
    • May require external error handling for undefined cases

unvollständiger Automat / incomplete FSA 不完全的有限自动机: 有些状态对某些输入缺转移, 有的符号读了不通向任何状态. 遇到未定义的转移, 自动机停机并拒绝输入. 总体上表示更简单: 状态和转移都比完全的 FSA 少, 但未定义的情况可能要靠外部的错误处理.

「停机并拒绝」是直接拒绝, 不管读头后面还剩多少输入, 也不管当前状态是不是终态.

Slide 23

Example of Incomplete FSA

  • This DFA accepts strings that start with ab
  • Once the string starts with ab the rest of the input is ignored
  • Missing transitions will cause the machine to halt (e.g., “b” exiting q0​)

和 Slide 21 接受的是同一个语言 (以 ab 开头的串), 只是去掉了陷阱状态 q1​ 和所有通向它的转移. 缺的转移会让机器停下, 例如 q0​ 读 b 没有出边. 把 Slide 21 的图删掉 q1​, 剩下的正好是这张图, 所以这里的状态名跳过了 q1​.

这张图换了一种画法 (JFLAP 软件的样式, 练习里的图也是): 三角形标初始状态, 双圈仍是终态. 反过来, 任何不完全的 DFA 都能补成完全的: 加一个陷阱状态, 把所有缺的转移都指向它, 它自己对每个符号自环. 练习 3 题 4 就是这样补羊叫自动机.

完全与不完全的比较
Complete vs. Incomplete FSA

Slide 24
  • Complete FSA:
    • Suitable for robust systems
    • Handles all possible inputs explicitly
    • Possible sink states
  • Incomplete FSA:
    • Simpler for small problems
    • Halts on undefined transitions
    • No sink states
完全的 FSA不完全的 FSA
适用健壮的系统小问题, 画起来简单
输入显式处理所有可能的输入遇到未定义的转移就停机
陷阱状态可能有没有 (缺的转移本身就起了陷阱的作用)

两者识别能力相同: 同一个语言, 完全版和不完全版只差一个陷阱状态. 区别只在表示和工程上的取舍.

    • But not: b!, baa, aa!

Formal Specification:

  • Input alphabet: Σ={a,b,!}
  • Set of states: Q={1,2,3,4}
  • Initial state: q0​=1
  • Transitions: δ(1,b)=2,δ(2,a)=3,δ(3,a)=3,δ(3,!)=4
  • Final state: F={4}

设计一个识别「羊叫」(sheep talk) 的 FSA: 以 b 开头, 然后一个或多个 a, 最后一个 !. 例如 ba!、baa!、baaaa! 属于这个语言; b! (没有 a)、baa (没有 !)、aa! (没有 b) 不属于. 这个例子来自 J&M 第 2 章.

为什么要两个读 a 的状态: 状态 2 → 3 的 a 保证「至少一个 a」, 状态 3 上的 a 自环负责「还可以更多」. 如果只在状态 2 上画 a 自环再读 ! 到终态, b! 也会被接受. 例子: baa! 走 1 → 2 → 3 → 3 → 4, 接受; baa 停在 3, 拒绝; b! 在状态 2 读 ! 没有转移, 停机拒绝.

这是一个不完全的 DFA: 只列了 4 个转移, 4 个状态 × 3 个符号本应有 12 个. 补成完全形式要加陷阱状态, 见练习 3 题 4. 写形式定义时的格式就照这一页: 五项各占一行, 转移逐条列出或用转移表. 用 Python 对长度 ≤ 7 的所有串核对过: 接受 ⇔ 串形如 b, 一个以上的 a, !.
