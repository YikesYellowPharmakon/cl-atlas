SQL 的由来与标准化
SQL · SQL-Standardisierung

Folie 1–2

Kapitel 5 · SQL

  • Entwicklung begann 1972 (zunächst als SQUARE, ab 1973 als SEQUEL, ab 1977 als SQL), unter der Leitung von Don Chamberlin und Ray Boyce (beide bei IBM Research)
  • Erste kommerzielle Implementierungen Ende der 1970er/Anfang der 1980er Jahre
  • SQL basiert auf Mengen- und relationalen Operationen mit Modifikationen & Erweiterungen
  • Ergebnis einer SQL-Abfrage ist eine Relation (Tupel-Multimenge) mit einem Schema, das durch die Attribute A1​,…,An​ definiert ist

(Fotos: Don Chamberlin, Ray Boyce (†1974).) [4] Neumann und Leis – „A Critique of Modern SQL and a Proposal Towards a Simple and Expressive Query Language“, 2024.

SQL 的开发从 1972 年开始, 最初叫 SQUARE, 1973 年起叫 SEQUEL, 1977 年起叫 SQL; 负责人是 IBM 研究院的 Don Chamberlin 和 Ray Boyce. 第一批商用实现出现在 70 年代末、80 年代初. SQL 建立在集合运算和关系运算 (第 3 章的关系代数) 之上, 但做了修改和扩充. 一个 SQL 查询的结果仍是一个关系, 不过是Multimenge 多重集 (元组可以重复), 模式由属性 A1​,…,An​ 决定.

「多重集」是和关系代数最大的不同: 关系代数里关系是集合, 投影后重复的元组自动合并; SQL 默认保留重复, 要去重得写 DISTINCT (Folie 10). 引用的 Neumann & Leis (2024) 是 TUM 数据库组对 SQL 设计缺陷的批评, 后面提到的 NULL、语法顺序等问题都在其中.

SQL 的标准化历程: 1986 年第一个 ANSI 标准; 1989 加完整性约束; 1992 大修订, 强调Orthogonalität 正交性 (语言构件可以自由组合, 比如子查询能出现在任何需要表的地方); 1999 加递归查询、存储过程、行类型和数组; 2003 加 XML、窗口函数、序列; 之后陆续加 XQuery、TRUNCATE/MERGE、时态数据、行模式识别和 JSON、多维数组, 2023 年加了 JSON 数据类型和属性图查询 SQL/PGQ.

标准是一回事, 各数据库实现的程度是另一回事: 课上默认的 PostgreSQL 和 DuckDB 都支持到窗口函数和递归查询, 但没有一个系统完整实现了全部标准. 本章的例子都在 PostgreSQL 18 和 DuckDB 2.0 上实际运行过.

幻灯片小错: SQL:1999 标准化的过程式扩展叫 SQL/PSM (Persistent Stored Modules, 1996 年作为 SQL-92 的补充, 1999 年并入标准). PL/SQL 是 Oracle 自己的过程语言, 不是 SQL 标准的一部分 (它影响了 SQL/PSM 的设计). 另外 MERGE 在 SQL:2003 就进了标准, SQL:2008 是对它的扩充.

SQL 查询的基本结构
Grundstruktur einer SQL-Anfrage

Folie 4

Eine typische SQL-Abfrage hat die folgende Form:

SELECT A1,A2,...,An -- Projektion
FROM r1,r2,...,rk   -- Kreuzprodukt
WHERE P             -- Selektion
  • A1​,…,An​: Attribute
  • r1​,…,rk​: Relationen
  • P: Prädikat

Diese Anfrage entspricht dem Ausdruck der relationalen Algebra

πA1​,…,An​​(σP​(r1​×r2​×⋯×rk​))

最典型的 SQL 查询有三个子句, 正好对应第 3 章的三个关系代数运算: FROM 列出的关系做笛卡尔积 (DBS 03 · 笛卡尔积), WHERE 按谓词 P 做选择 σ, SELECT 列出的属性做投影 π. 读公式要从里往外: 先积, 再选, 最后投影. 这也是 SQL 查询逻辑上的执行顺序 (Folie 34), 和书写顺序正好相反.

易错: SQL 的 SELECT 是投影 π, 不是选择 σ; 选择是 WHERE. 名字容易误导. 另外这里的投影不去重 (多重集), 关系代数的 π 去重, 所以严格对应的是 SELECT DISTINCT.

SELECT-Klausel

Folie 7
  • Wird verwendet, um die Attribute aufzulisten (und optional zu transformieren), die im Anfrageergebnis zurückgegeben werden sollen
  • SELECT-Klausel entspricht der Projektion in der relationalen Algebra

Beispiel Finde den Namen aller Lieferanten

SELECT Firmenname FROM LIEFERANTEN;

Ergebnis: Firmenname: Fresh Farms Inc. · Oceanic Traders · Global Supplies Ltd. · Eco Goods Co.

SELECT 子句列出 (并可以变换) 结果里要返回的属性, 对应关系代数的投影. 例子: 所有供应商的名字. 实测两个系统都返回这四行. 结果的行序没有保证 (Folie 23): 这里碰巧是插入顺序.

  • CAST ... AS interpretiert (und konvertiert) den angegebenen Attributwert in den gewünschten Datentyp
  • REPLACE ersetzt alle Vorkommen eines Teilstrings im Attributwert durch einen anderen String

SELECT 里不只能写属性, 还能写算术表达式、函数、常量. 例子把电话号码里的连字符删掉 (REPLACE: 把所有 '-' 换成空串), 再把字符串转成整数 (CAST … AS bigint), 并用 AS 给这个算出来的列起名 NUMMER. 没有 AS 时, 算出来的列名由系统决定 (实测 PostgreSQL 把这一列叫 replace).

标识符的大小写: 不加引号的名字在 PostgreSQL 里一律转成小写 (Telefon 实际是 telefon), 加了双引号的 "NUMMER" 才保留大小写. 所以结果列名是 NUMMER, 而不是 nummer.

幻灯片错误: 示例库 (Folie 6) 里的列叫 Kontaktperson, 这里和 Folie 8 却写成 Kontaktname (Folie 5 的英文模式图叫 ContactName). 按 Folie 6 建表后, 这条查询在两个系统上都报错: PostgreSQL column "kontaktname" does not exist, DuckDB Referenced column "Kontaktname" not found. 结果表的表头反而写的是 Kontaktperson.

版本差异: 带引号的 "Telefon" 在 PostgreSQL 里也会出错: 建表时没加引号, 列名存成小写的 telefon, 而 "Telefon" 要求大小写完全一致, 报 column "Telefon" does not exist. DuckDB 对带引号的标识符也不区分大小写, 能运行. 改成 SELECT Kontaktperson, CAST(REPLACE(Telefon,'-','') AS bigint) AS "NUMMER" FROM LIEFERANTEN; 后两个系统都得到上表.

FROM 子句
FROM-Klausel

Folie 11
  • Enthält mindestens einen Verweis auf eine Relation R (meist durch den Namen der Relation bezeichnet)
  • Wenn die FROM-Klausel mehrere Relationen enthält, z. B. FROM R,S,T, wird ein kartesisches Produkt gebildet (d. h. R×S×T)
  • Wenn zwei Relationen R und S ein Attribut A mit demselben Namen besitzen, muss dieses Attribut A entweder umbenannt oder vollständig qualifiziert werden (z. B. R.A, S.A)
  • Wir können Aliase für Relationen erzeugen (z. B. KUNDEN K), um diese an anderen Stellen wiederzuverwenden
-- vollständig qualifizierte Attribute und Aliase
SELECT K.Telefon, L.Telefon FROM KUNDEN K, LIEFERANTEN L;
-- Mischung aus qualifizierten Attributen, Aliasen und Sternchen-Notation
SELECT K.*, L.Telefon FROM KUNDEN K, LIEFERANTEN L;
-- Selbst-Kreuzprodukt
SELECT E1.SRC, E2.TRGT FROM EDGES E1, EDGES E2;

FROM 至少引用一个关系. 列出多个关系 (FROM R, S, T) 时做笛卡尔积. 两个关系有同名属性时, 必须vollständig qualifizieren 完全限定 (写成 R.A、S.A) 或者改名, 否则系统不知道你指哪一个. 可以给关系起Alias 别名 (KUNDEN K), 后面用 K 代替全名.

三个例子: KUNDEN 和 LIEFERANTEN 都有 Telefon, 所以要写 K.Telefon、L.Telefon; K.* 表示 K 的所有属性; 同一个表和自己做积时 (Selbst-Kreuzprodukt 自积), 必须用两个不同的别名 E1、E2 区分两份拷贝. EDGES (边表, SRC 起点、TRGT 终点) 不在示例库里, 自积 E1.TRGT = E2.SRC 就能找出两步可达的路径. 实测: 4 个客户 × 4 个供应商 = 16 行.

易错: 写 SELECT Telefon FROM KUNDEN K, LIEFERANTEN L 不加前缀, 两个系统都报「列名有歧义」.

WHERE 子句与 NULL
WHERE-Klausel · NULL-Werte

Folie 12
  • Entspricht der Selektion in der relationalen Algebra
  • Besteht aus einem Prädikat, das Attribute der in der FROM-Klausel genannten Relationen verwendet
  • Vergleich zwischen Attributwerten und Konstanten
    • Vergleichsoperatoren: =, <, >, >=, <=, <>
    • Test auf NULL: IS NULL und IS NOT NULL
  • Logische Verknüpfungen AND, OR und NOT können zur Formulierung komplexer Bedingungen verwendet werden

Beispiel Liste alle Bestellungen mit einem Gesamtbetrag über 100,00 € auf

SELECT *
FROM BESTELLUNGEN
WHERE Gesamtbetrag > 100.00;

WHERE 对应关系代数的选择, 由一个谓词组成, 谓词里用 FROM 中关系的属性. 可以比较属性和常量, 比较运算符有 =、<、>、>=、<=、<> (不等于); 测试 NULL 要用 IS NULL / IS NOT NULL; 可以用 AND、OR、NOT 组合. 例子: 总额超过 100 欧元的订单, 实测四个订单都满足 (150.75、230.00、320.50、180.25).

易错: SQL 里的小数点是点 (100.00), 课件表格里的德式逗号 (100,00) 不能写进查询. 不等于是 <> (多数系统也接受 !=).

Folie 13

NULL-Werte

  • NULL ≙ unbekannter, nicht existierender oder nicht zutreffender Wert
  • Wenn laut Schemadefinition für eine Tabelle erlaubt (d. h. kein NOT NULL-Constraint), können Attribute den Wert NULL annehmen
  • Ergebnis eines arithmetischen Ausdrucks mit NULL ist stets NULL
  • Ergebnis einer WHERE-Bedingung ist FALSE, wenn sie zu NULL evaluiert

NULL 表示值未知、不存在或不适用. 只要表定义没有 NOT NULL 约束, 属性就可以取 NULL. 算术表达式里只要有 NULL, 结果就是 NULL (5 + NULL = NULL). 比较也是: NULL = NULL 的结果不是 true 而是 NULL. 所以 SQL 用的是dreiwertige Logik 三值逻辑: true、false、null (unknown). 真值表的规律: AND 里只要有 false 就是 false, OR 里只要有 true 就是 true, 其余涉及 null 的都是 null; NOT null 还是 null.

WHERE 只保留条件为 true 的行, 结果为 null 的行和 false 一样被丢掉, 这就是「WHERE 条件为 NULL 时按 FALSE 处理」的意思. 但这不等于 null 变成了 false: NOT (L_ID = 5) 在 L_ID 为 NULL 时仍是 null, 那一行照样不出现, 不会因为「取反」而出现.

Folie 14

NULL-Werte · Beispiele

Gib alle Bestellungen mit fehlendem Lieferanten aus

SELECT * FROM BESTELLUNGEN WHERE L_ID IS NULL;

Liste alle Kunden auf, denen eine Adresse zugeordnet ist

SELECT * FROM KUNDEN WHERE Adresse IS NOT NULL;

Alle Aggregatfunktionen ignorieren Tupel mit NULL-Werten im Aggregatattribut — außer COUNT(*)

测试 NULL 只能用 IS NULL / IS NOT NULL. 写成 WHERE L_ID = NULL 永远不返回任何行, 因为比较结果是 null. 例子在示例库上: 没有缺供应商的订单, 第一条返回空; 所有客户都有地址, 第二条返回全部 4 行. 聚合函数 (Folie 25) 计算时跳过 NULL 值, 只有 COUNT(*) 数的是行数, 包括全是 NULL 的行.

SQL 中的连接
Joins in SQL

Folie 15
  • Joins werden (ähnlich wie in der relationalen Algebra) als Selektionsbedingung über einem kartesischen Produkt formuliert
  • In SQL muss man die Join-Bedingung explizit angeben (oder explizit NATURAL JOIN-Operatoren verwenden)
SELECT L.Firmenname, P.Produktname
FROM LIEFERANTEN L, ANGEBOTE A, PRODUKTE P
WHERE L.L_ID = A.L_ID AND A.P_ID = P.P_ID;

SELECT L.Firmenname, A.* FROM LIEFERANTEN L JOIN ANGEBOTE A ON L.L_ID = A.L_ID;
SELECT L.Firmenname, A.* FROM LIEFERANTEN L JOIN ANGEBOTE A USING (L_ID);
SELECT L.Firmenname, A.* FROM LIEFERANTEN L NATURAL JOIN ANGEBOTE A;

和关系代数一样, 连接就是「笛卡尔积 + 选择」(DBS 03 · θ 连接): 第一条查询把三张表做积, 再用 WHERE 留下外键对得上的组合, 得到「哪个供应商卖什么产品」. SQL 不会自己猜连接条件, 必须写出来, 或者明确用 NATURAL JOIN.

后三条是显式的 JOIN 语法, 效果相同, 写法不同: JOIN … ON 条件 写任意条件; USING (L_ID) 按同名属性相等连接, 并且结果里 L_ID 只出现一次; NATURAL JOIN 自动按所有同名属性连接. 实测第一条得到 5 行: Fresh Farms 卖 Bio-Äpfel 和 Vollkornbrot, Oceanic 卖 Mandelmilch, Global Supplies 卖 Freilandhuhn, Eco Goods 卖 Bio-Äpfel.

易错: NATURAL JOIN 很危险. 这里 LIEFERANTEN 和 ANGEBOTE 只有 L_ID 同名, 结果正确; 如果两张表恰好还有别的同名列 (比如都有 Telefon, 或者以后加了一个 Name), 它会悄悄把那一列也加进连接条件, 结果大幅变少. 显式写 ON 更安全.

Folie 16

Join-Abfragen Gib eine Liste aller Bestellungen mit dem Namen und der E-Mail-Adresse des Kunden aus

SELECT B.B_ID,
       K.Name AS KundenName,
       K."E-Mail" AS KundenEmail,
       B.Bestelldatum,
       B.Gesamtbetrag
FROM BESTELLUNGEN B JOIN KUNDEN K ON B.K_ID = K.K_ID;

Gib alle Bestellungen mit Lieferanteninformationen aus. Wenn eine Bestellung keinen Lieferanten hat, sollen die Lieferantendetails als NULL angezeigt werden

SELECT B.B_ID,
       B.Bestelldatum,
       B.Gesamtbetrag,
       L.Firmenname AS LieferantenName,
       L.KontaktPerson AS LieferantenKontakt
FROM BESTELLUNGEN B LEFT JOIN LIEFERANTEN L ON B.L_ID = L.L_ID;

第一条是普通的inner join 内连接: 每个订单配上它的客户. 属性名 E-Mail 含连字符, 必须加双引号, 否则会被读成 E 减 Mail. 第二条是LEFT JOIN 左外连接 (DBS 03 · 外连接): 左边 (订单) 的每一行都保留, 找不到匹配的供应商时, 右边的列填 NULL. 示例库里每个订单都有供应商, 所以两种连接结果相同 (实测 4 行); 区别要在有订单 L_ID 为 NULL 时才看得到.

L.KontaktPerson 和表定义的 Kontaktperson 大小写不同也能运行: 不加引号的标识符不区分大小写.

Join-Abfragen Finde Paare von Kunden, die sich in derselben Stadt befinden

SELECT K1.K_ID AS Kunde1ID,
       K1.Name AS Kunde1Name,

Liste alle Produkte und die zugehörigen Angebote auf. Zeige auch Produkte ohne Angebote an

SELECT P.P_ID,
       P.Produktname,
       A.L_ID,
       A.VerfügbarerBestand,
       A.Rabatt
FROM ANGEBOTE A RIGHT JOIN Produkte P ON P.P_ID = A.P_ID;

第一条是Self-Join 自连接: KUNDEN 和自己连接, 条件是同城. 附加条件 K1.K_ID < K2.K_ID 有两个作用: 排除一个客户和自己配对 (同城必然成立), 以及让每对只出现一次 (否则 (1,2) 和 (2,1) 各出现一次). 示例库里四个客户在四个不同城市, 实测结果为空.

第二条是RIGHT JOIN 右外连接: 保留右边 (产品) 的所有行, 没有报价的产品, 报价那几列为 NULL. 示例库里每个产品都有报价, 实测 5 行 (Bio-Äpfel 两个报价, 出现两次). A RIGHT JOIN P 等价于 P LEFT JOIN A, 多数人习惯只用 LEFT JOIN.

Folie 18

Join-Anfragen Wir möchten eine kombinierte Liste aller Kunden und aller Bestellungen erhalten, wobei für Kunden ohne Bestellungen deren Daten und für Bestellungen ohne Kundenzuordnung die Bestelldaten angezeigt werden.

SELECT K.K_ID,
       K.Name AS KundenName,
       B.B_ID,
       B.Gesamtbetrag,
       B.Bestelldatum
FROM KUNDEN K FULL OUTER JOIN BESTELLUNGEN B ON K.K_ID = B.K_ID;

? Wie kann man einen FULL OUTER JOIN nachbilden, wenn dieser vom verwendeten DBMS nicht direkt unterstützt wird?

FULL OUTER JOIN 全外连接: 两边都保留, 没有订单的客户, 订单列为 NULL; 没有客户的订单, 客户列为 NULL. 示例库里两边都一一对应, 实测 4 行.

问: 数据库不支持 FULL OUTER JOIN 时怎样模拟 (MySQL 就不支持)? 答: 左外连接和右外连接的结果求并:

SELECT K.K_ID, B.B_ID FROM KUNDEN K LEFT JOIN BESTELLUNGEN B ON K.K_ID = B.K_ID
UNION
SELECT K.K_ID, B.B_ID FROM KUNDEN K RIGHT JOIN BESTELLUNGEN B ON K.K_ID = B.K_ID;

左连接带来「有客户的所有行」, 右连接带来「有订单的所有行」, 两者重叠的 (匹配上的) 行由 UNION 去重. 实测: 另插入一个 K_ID 为 NULL 的订单 9 后, 结果是 (1,1)、(2,2)、(3,3)、(4,4) 和 (NULL, 9), 和 FULL OUTER JOIN 相同. 注意: 如果匹配上的行里本身有重复 (两张表都允许重复行), UNION 会把它们也合并掉; 更严格的写法是 UNION ALL 第二部分只取右边没匹配上的行 (WHERE K.K_ID IS NULL).

NULL 在排序里放哪? 两种做法: 最前或最后. 默认值因系统而异: MySQL 升序时 NULL 在最前, PostgreSQL 和 DuckDB 升序时 NULL 在最后. 用 NULLS FIRST / NULLS LAST 可以明确指定. 实测 PostgreSQL 和 DuckDB 都是 NULL 在最后、加 NULLS FIRST 后在最前.

Folie 25

Aggregation

  • Aggregatfunktionen arbeiten auf einer Multimenge von Werten und liefern einen einzigen Wert zurück
  • Typische Aggregatfunktionen: MIN, MAX, SUM, COUNT und AVG
  • Aggregatfunktionen können über die gesamte Relation oder innerhalb einer Gruppe (eine Partition mit gleichen Werten in einer Spalte) ausgewertet werden
  • NULL-Werte werden ignoriert (Ausnahme: COUNT(*))
-- Wie viele Lieferanten gibt es insgesamt?
SELECT COUNT(*) FROM LIEFERANTEN;
-- Wie viele verschiedene Produkte werden angeboten?
SELECT COUNT(DISTINCT P_ID) FROM ANGEBOTE;
-- Liste alle Produkte, die teurer sind als der Durchschnittspreis aller Produkte
SELECT * FROM PRODUKTE
WHERE PreisProEinheit > (SELECT AVG(PreisProEinheit) FROM PRODUKTE);

Aggregatfunktion 聚合函数把一个多重集的值汇成一个值: MIN、MAX、SUM、COUNT、AVG. 可以作用于整张表, 也可以作用于每个组 (组 = 某一列值相同的行构成的一块). NULL 值被忽略, COUNT(*) 除外. 三个例子实测: 供应商共 4 个; 报价表里不同的产品数 COUNT(DISTINCT P_ID) = 4 (P_ID 1 出现两次, 只算一次); 平均价格 (1.5 + 3 + 2.5 + 8)/4 = 3.75, 比它贵的只有 Freilandhuhn (8.00).

第三个例子把聚合放进子查询: WHERE 里不能直接写 PreisProEinheit > AVG(PreisProEinheit), 因为 WHERE 在聚合之前执行 (Folie 34), 逐行判断时还没有平均值.

易错: COUNT(*) 数行, COUNT(列) 数这一列不是 NULL 的行, COUNT(DISTINCT 列) 数不同的非 NULL 值, 三者结果可能都不一样. 空表上 COUNT 是 0, 而 SUM、AVG、MIN、MAX 都是 NULL.

HAVING

  • Optional können nur Gruppen im Anfrageergebnis berücksichtigt werden, die eine bestimmte Bedingung erfüllen
  • Dies wird mit der Klausel HAVING <BEDINGUNG> realisiert

Beispiel: ANGEBOTE ↓ GROUP BY P_ID HAVING COUNT(*)>1 ↓ (nur Gruppe 1 bleibt: A_ID 1 und 5, P_ID 1)

Gruppierung 分组: 把某些属性值相同的元组归成一组, 再对每组应用聚合函数. 按 P_ID 分组后, 报价表变成 4 组: P_ID 1 有两条报价 (A_ID 1 和 5), 其余各一条. 分组的中间结果不是「真正的」关系: 一组里 A_ID、L_ID 等列有多个值 (多值属性, 违反第一范式), 所以分组后 SELECT 里只能出现分组属性和聚合结果 (Folie 30).

HAVING 在分组之后筛选组: HAVING COUNT(*) > 1 只留下有两条以上报价的产品, 即 P_ID 1. 实测 SELECT P_ID, COUNT(*) FROM ANGEBOTE GROUP BY P_ID HAVING COUNT(*)>1 得 (1, 2).

WHERE 和 HAVING 的区别: WHERE 在分组前筛选行, 不能用聚合函数; HAVING 在分组后筛选组, 条件里用聚合函数.

Folie 28

Gruppierung & Aggregation · Syntax & Semantik

SELECT Attribut(e) [Aggregatfunktion]
FROM R1,R2,...,Rm
[ WHERE <P> ]
GROUP BY Gruppierungsattribut(e)
[ HAVING <Bedingung> ]

Eine Anfrage mit einer GROUP BY-Klausel wird wie folgt verarbeitet:

  1. Wähle alle Zeilen aus, die die Bedingung der WHERE-Klausel erfüllen
  2. Bilde aus diesen Zeilen Gruppen entsprechend der GROUP BY-Klausel
  3. Verwerfe alle Gruppen, die die Bedingung der HAVING-Klausel nicht erfüllen
  4. Wende Aggregatfunktion(en) auf jede Gruppe an
  5. Gib die Werte für die in der SELECT-Klausel aufgeführten Spalten und Aggregationen zurück

带 GROUP BY 的查询按五步执行: ① 用 WHERE 选行; ② 按 GROUP BY 分组; ③ 丢掉不满足 HAVING 的组; ④ 对每组算聚合函数; ⑤ 输出 SELECT 里的列和聚合值. WHERE 和 HAVING 都是可选的 (方括号). 和关系代数的分组运算 γ 对应 (DBS 03 · 分组与聚合).

第 ③ 和 ④ 的顺序是概念上的: HAVING 的条件本身常常要先算聚合 (如 COUNT(*) > 1), 实际系统会先算出需要的聚合值再筛组, 结果一样.

Folie 29

Beispiele

-- Ermittle die Gesamtzahl an Bestellungen, die von jedem Kunden aufgegeben wurden
SELECT K_ID, COUNT(B_ID) AS AnzahlBestellungen
FROM BESTELLUNGEN
GROUP BY K_ID;

-- Berechne den durchschnittlichen Gesamtbetrag der Bestellungen für jeden Lieferanten
SELECT L_ID, AVG(Gesamtbetrag) AS DurchschnittBestellbetrag
FROM BESTELLUNGEN
GROUP BY L_ID;

-- Berechne den Gesamtbetrag, den jeder Kunde ausgegeben hat, und zeige nur Kunden an,
-- die mehr als 300 € ausgegeben haben
SELECT K_ID, SUM(GesamtBetrag) AS GesamtBetragAusgabe
FROM BESTELLUNGEN
GROUP BY K_ID
HAVING SUM(Gesamtbetrag) > 300;

三个例子, 实测结果: ① 每个客户的订单数: 4 个客户各 1 单. ② 每个供应商的平均订单额: 供应商 1 为 150.75, 供应商 3 为 (230.00 + 320.50)/2 = 275.25, 供应商 4 为 180.25; 供应商 2 没有订单, 不出现 (分组只从已有的行里产生). ③ 消费超过 300 欧元的客户: 只有客户 3 (320.50).

想让没有订单的供应商也以 0 出现, 要从供应商表出发做左外连接再分组: SELECT L.L_ID, COUNT(B.B_ID) FROM LIEFERANTEN L LEFT JOIN BESTELLUNGEN B ON L.L_ID = B.L_ID GROUP BY L.L_ID. 这里必须是 COUNT(B.B_ID) 而不是 COUNT(*): 没有订单的供应商那一行 B 的列全是 NULL, COUNT(*) 会数成 1.

Folie 30

Weitere Details zu Gruppierung & Aggregation

Attribute, die in der SELECT-Klausel außerhalb einer Aggregatfunktion erscheinen, müssen in der GROUP BY-Klausel enthalten sein!

Beispiel: Berechne den Gesamtbetrag, den jeder Kunde ausgegeben hat, sowie dessen Status(se), und zeige nur Kunden an, die mehr als 300 € ausgegeben haben!

SELECT K_ID, Status, SUM(Gesamtbetrag) AS GesamtBetragAusgabe
FROM BESTELLUNGEN
GROUP BY K_ID
HAVING SUM(Gesamtbetrag) > 300; -- funktioniert nicht!

SELECT K_ID, STRING_AGG(Status,','), SUM(Gesamtbetrag) AS GesamtBetragAusgabe
FROM BESTELLUNGEN
GROUP BY K_ID
HAVING SUM(Gesamtbetrag) > 300; -- das ist korrekt

规则: SELECT 里出现在聚合函数外面的属性, 必须也写在 GROUP BY 里. 原因: 一个客户可能有好几个订单、好几种状态, 按 K_ID 分组后每组只输出一行, Status 不知道该取哪一个. 第一条实测报错: PostgreSQL column "bestellungen.status" must appear in the GROUP BY clause or be used in an aggregate function, DuckDB 的报错意思相同. 第二条把状态也用聚合函数处理: STRING_AGG(Status, ',') 把一组里的所有状态用逗号连成一个字符串, 实测得 (3, 'Ausstehend', 320.50).

易错: 老版本 MySQL (关掉 ONLY_FULL_GROUP_BY 时) 不报错, 而是随便取组里一行的值, 结果不可预测. PostgreSQL 有一个例外: 如果按主键分组, 同一张表的其他列可以直接出现在 SELECT 里 (它们由主键唯一确定).

Folie 31

Aggregationsabfragen ohne GROUP BY-Klausel – z. B. um ein Tupel mit dem maximalen/minimalen Wert in einer Relation zu finden – erfordern typischerweise eine Unterabfrage

Beispiel: Gib mir die neueste Bestellung (nach Bestelldatum)!

SELECT B_ID, MAX(Bestelldatum) FROM BESTELLUNGEN; -- funktioniert nicht!
SELECT B_ID, Bestelldatum FROM BESTELLUNGEN
WHERE Bestelldatum = (SELECT MAX(Bestelldatum) FROM BESTELLUNGEN); -- das ist korrekt

没有 GROUP BY 时整张表是一组, 同样的规则成立: 第一条把普通列 B_ID 和聚合 MAX 放在一起, 实测两个系统都报错 (B_ID 必须出现在 GROUP BY 里). 正确做法: 子查询先算出最大日期, 外层查询再找日期等于它的订单. 实测返回订单 3 (2024-11-04). 如果有两个订单日期都是最大值, 两个都会返回, 这正是我们想要的.

另一种写法是 ORDER BY Bestelldatum DESC LIMIT 1 (Folie 33), 但它在并列时只返回一行.

SQL 的书写顺序和 (逻辑上的) 执行顺序不同: 写的时候 SELECT 在最前, 执行时先 FROM (取表、做积和连接), 再 WHERE (筛行)、GROUP BY (分组)、HAVING (筛组)、SELECT (算输出列)、DISTINCT (去重)、ORDER BY (排序)、LIMIT (截取).

嵌套子查询
Verschachtelte Unterabfragen (Subqueries)

Folie 35
  • Bisher bestanden die WHERE-Klauseln in den Beispielen nur aus einfachen Vergleichen von Attributen und/oder Konstanten
  • SQL bietet Sprachkonstrukte zur Verschachtelung von Abfragen mittels Unterabfragen
  • Eine Unterabfrage ist ein SELECT-FROM-WHERE-Ausdruck, der in einer anderen Abfrage eingebettet ist
  • Unterabfragen können in der WHERE-, FROM-, SELECT- und sogar in der HAVING-Klausel erscheinen
  • Der häufigste Einsatz von Unterabfragen ist die Prüfung auf Mengenmitgliedschaft, Mengenvergleiche und Mengenkardinalität
  • Unterabfragen in einer WHERE-Klausel können beliebig mit logischen Verknüpfungen kombiniert werden
  • In den meisten Fällen erzeugt die innere Abfrage ein Zwischenergebnis, das in der äußeren Abfrage weiterverwendet wird

Unterabfrage 子查询是嵌在另一个查询里的 SELECT-FROM-WHERE 表达式. 可以出现在 WHERE、FROM、SELECT, 甚至 HAVING 里. 最常见的用途: 测试是否属于某个集合 (IN)、和集合比较 (ANY、ALL)、测试集合大小 (EXISTS). WHERE 里的子查询能和 AND、OR、NOT 任意组合. 多数情况下, 内层查询先产生一个中间结果, 外层再使用它.

Folie 36

Einzelwertige Unterabfragen in der SELECT-Klausel

Zeige jeden Lieferanten zusammen mit der Gesamtzahl an unterschiedlichen Produkten, die er liefert

SELECT L_ID,
       Firmenname,
       (SELECT COUNT(DISTINCT P_ID)
        FROM ANGEBOTE
        WHERE ANGEBOTE.L_ID = LIEFERANTEN.L_ID) AS GesamtanzahlProdukteGeliefert
FROM LIEFERANTEN;

SELECT 里的子查询必须是einzelwertig 单值的: 对外层的每一行只返回一行一列. 这里对每个供应商数它报价的不同产品数. 子查询引用了外层的 LIEFERANTEN.L_ID, 所以对外层每一行重新计算一次 (相关子查询, 下一页). 实测: Fresh Farms 2, 其余各 1. 子查询返回多于一行时会报错 (more than one row returned by a subquery).

Folie 37

Unterabfragen in der WHERE-Klausel · Zwei Arten von Unterabfragen: korrelierte und unkorrelierte Unterabfragen

  • Unkorreliert: Die Unterabfrage bezieht sich nur auf eigene Attribute
  • Korreliert: Die Unterabfrage referenziert Attribute aus der äußeren Abfrage
  • Referenzen auf äußere Relationen und Attribute erfolgen typischerweise über Aliase

Beispiel: Finde alle Bestellungen, deren Gesamtbetrag größer ist als der durchschnittliche Gesamtbetrag der Bestellungen desselben Kunden (Korrelierte Unterabfrage)

SELECT B_ID,
       K_ID,
       Gesamtbetrag
FROM BESTELLUNGEN B1
WHERE Gesamtbetrag > (
    SELECT AVG(B2.Gesamtbetrag)
    FROM BESTELLUNGEN B2
    WHERE B2.K_ID = B1.K_ID);

WHERE 里的子查询分两种: unkorreliert 不相关的只用自己的属性, 可以先单独算一次; korreliert 相关的引用了外层查询的属性, 概念上对外层每一行都要重算. 引用外层通常靠别名. 例子: 找出比同一客户的平均订单额高的订单. 同一张表用了两次, 别名 B1 (外层) 和 B2 (内层) 区分; B2.K_ID = B1.K_ID 把内层限制在当前外层订单的客户上. 示例库每个客户只有一单, 订单额等于自己的平均, 不会「大于」, 实测结果为空.

Folie 38

Beispiel: Finde alle Kunden, die eine Bestellung mit einem Gesamtbetrag von mehr als 500 € aufgegeben haben (unkorrelierte Abfrage)

SELECT K_ID,
       Name,
       "E-Mail"
FROM KUNDEN
WHERE K_ID IN (
    SELECT K_ID
    FROM BESTELLUNGEN
    WHERE Gesamtbetrag > 500);

不相关子查询: 内层只看 BESTELLUNGEN 自己, 先算出「下过 500 欧元以上订单的客户号」这个集合, 外层再用 IN 筛选. 示例库里最大的订单是 320.50, 实测结果为空. 同样的结果也能用连接写 (JOIN … WHERE B.Gesamtbetrag > 500, 加 DISTINCT 防止一个客户多单时重复).

Folie 39

IN & NOT IN

Gibt alle Datensätze aus der Hauptanfrage zurück, die im Ergebnis der Unteranfrage enthalten sind: <Ausdruck> IN <Unteranfrage>

Gibt alle Datensätze aus der Hauptanfrage zurück, die nicht im Ergebnis der Unteranfrage enthalten sind: <Ausdruck> NOT IN <Unteranfrage>

Beispiel: Liste alle Kunden auf, die keinen lokalen Lieferanten in ihrem Land haben

SELECT * FROM KUNDEN
WHERE Land NOT IN (SELECT DISTINCT Land FROM LIEFERANTEN);

IN 测试值是否在子查询的结果里, NOT IN 测试不在. 例子: 本国没有供应商的客户. 供应商在 USA、Australien、UK、Brasilien, 客户在 USA、USA、Kanada、UK, 实测只返回 Ahmed Khan (Kanada). 子查询里的 DISTINCT 可省, 不影响 IN 的结果.

易错: NOT IN 遇到 NULL 会失灵. 如果某个供应商的 Land 是 NULL, 那么 'Kanada' NOT IN ('USA', …, NULL) 的结果是 null 而不是 true (Kanada <> NULL 是 null, AND 进去整体变 null), 整个查询返回空. 实测: 往 BESTELLUNGEN 插入一个 K_ID 为 NULL 的订单后, K_ID NOT IN (SELECT K_ID FROM BESTELLUNGEN) 一行都不返回. 稳妥的写法是 NOT EXISTS (Folie 43).

Folie 40

ANY Der gesamte Vergleichsausdruck ergibt TRUE, wenn mindestens einer (ANY) der Einzelvergleiche zu TRUE evaluiert wird

Syntax: <Ausdruck> <Vergleichsoperator> ANY <Unteranfrage>

Beispiel: Finde alle Produkte, deren Preis niedriger ist als der Preis eines beliebigen Produkts in der Kategorie „Beverages“

SELECT P_ID, Produktname, PreisProEinheit
FROM Produkte
WHERE PreisProEinheit < ANY (SELECT PreisProEinheit FROM Produkte
                             WHERE Kategorie = 'Beverages');

值 比较符 ANY (子查询): 只要和子查询结果里至少一个值的比较为 true, 整体就为 true. 「价格低于饮料类中任何一个 (至少一个) 产品」, 即低于饮料类里最贵的那个: < ANY 等价于 < MAX. = ANY 和 IN 相同.

德语 eines beliebigen Produkts 和英语 any 一样有歧义 (「随便哪一个都」还是「某一个」), SQL 的 ANY 是「某一个」, 别和 ALL 搞混.

幻灯片前后不一致: 示例库的分类是德文 (Obst、Getränke、Bäckerei、Fleisch), 没有 'Beverages'. 按 Folie 6 的数据实测, 子查询为空, < ANY (空集) 永远为 false, 查询返回空. 改成 Kategorie = 'Getränke' 后返回 Bio-Äpfel (1.50) 和 Vollkornbrot (2.50): 唯一的饮料 Mandelmilch 价格 3.00, 比它便宜的就是这两个.

Folie 41

ALL Gibt TRUE zurück, wenn ALLE Werte der Unteranfrage die Bedingung erfüllen

Syntax: <Ausdruck> <Vergleichsoperator> ALL <Unteranfrage>

Beispiel: Finde alle Produkte, deren Preis niedriger ist als der Preis jedes Produkts in der Kategorie „Dairy“

SELECT P_ID, Produktname, PreisProEinheit
FROM Produkte
WHERE PreisProEinheit < ALL (
    SELECT PreisProEinheit
    FROM Produkte
    WHERE Kategorie = 'Dairy');

值 比较符 ALL (子查询): 和子查询结果里每一个值的比较都为 true 才为 true. 「比乳制品类每个产品都便宜」, 即低于其中最便宜的: < ALL 等价于 < MIN. <> ALL 和 NOT IN 相同.

空集的陷阱: 子查询为空时, 「对所有值都成立」是空真 (vacuously true), 所以 < ALL (空集) 为 true. 这和 < MIN 不同: 空集的 MIN 是 NULL, 比较结果为 null, 不返回任何行.

幻灯片前后不一致: 示例库里同样没有 'Dairy' 这个分类 (也没有德文的乳制品类). 按 Folie 6 的数据实测, 子查询为空, < ALL (空集) 恒为 true, 查询返回全部四个产品, 正好演示了上面说的空集陷阱.

Folie 42–43

EXISTS Gibt TRUE zurück, wenn die Unteranfrage mindestens einen Datensatz liefert. Syntax: EXISTS <Unteranfrage>

Beispiel: Finde alle Kunden, die mindestens eine Bestellung aufgegeben haben

SELECT K_ID, Name, "E-Mail"
FROM KUNDEN K
WHERE EXISTS (
    SELECT 1
    FROM BESTELLUNGEN B
    WHERE B.K_ID = K.K_ID);

NOT EXISTS Gibt TRUE zurück, wenn die Unteranfrage keine Datensätze liefert. Syntax: NOT EXISTS <Unteranfrage>

Beispiel: Finde alle Kunden, die noch nie eine Bestellung aufgegeben haben

SELECT K_ID, Name, Email
FROM KUNDEN K
WHERE NOT EXISTS (
    SELECT 1
    FROM BESTELLUNGEN B
    WHERE B.K_ID = K.K_ID);

EXISTS (子查询) 只问子查询有没有结果, 不关心结果内容, 所以子查询里习惯写 SELECT 1. 这两个例子都是相关子查询: 对每个客户 K 检查有没有 K_ID 等于它的订单. 实测 EXISTS 返回全部 4 个客户, NOT EXISTS (改正列名后) 返回空.

NOT EXISTS 是表达「从来没有」「对所有……都」的标准工具, 而且不怕 NULL: 子查询里 B.K_ID = K.K_ID 为 null 的行只是不算匹配, 结果仍然正确. 关系代数的除法 (DBS 03 · 除法) 在 SQL 里通常写成两层 NOT EXISTS.

幻灯片前后不一致: NOT EXISTS 的例子写的是 Email, 但示例库 (Folie 6) 和上面的 EXISTS 例子里列名是 "E-Mail". 按 Folie 6 建表后实测报错: PostgreSQL column "email" does not exist. Folie 46 的 INSERT 也有同样的问题.

Folie 44

Löschungen Syntax: DELETE FROM <Relation> <[WHERE-Bedingung]>

Beispiel: Lösche alle Kunden, die noch nie etwas bestellt haben

DELETE FROM KUNDEN WHERE K_ID NOT IN (SELECT K_ID FROM BESTELLUNGEN)

DELETE 删除满足 WHERE 条件的行; 不写 WHERE 就删除表里所有行 (表本身还在, 和 DROP TABLE 不同). 例子删掉从没下过单的客户. 实测: 先插入一个没有订单的客户 1000, 这条语句删掉了它 (DuckDB 报告删除 1 行), 其余 4 个客户保留.

易错: 这里同样有 Folie 39 说的 NOT IN + NULL 问题: 只要 BESTELLUNGEN 里有一个 K_ID 为 NULL 的订单, 子查询结果含 NULL, 条件对所有行都是 null, 一个都不删. 用 NOT EXISTS 更稳.

Folie 45

Beispiel: Lösche alle Kunden, deren Kontostand unter dem Durchschnitt aller Kunden liegt

DELETE FROM KUNDEN WHERE Account < (SELECT AVG(Account) FROM KUNDEN)
  • Problem: Wird die Bedingung nach jeder Löschung eines Tupels neu ausgewertet, ändert sich das Ergebnis der Unterabfrage
  • In SQL: Zuerst wird AVG(Account) berechnet und es werden alle Tupel aus KUNDEN bestimmt, die gelöscht werden sollen; dann erfolgt die Löschung dieser Tupel ohne erneute Berechnung von AVG(Account)

删除余额低于平均值的客户 (示例库没有 Account 这一列, 只用来说明问题). 问题: 如果每删一行就重新算平均值, 平均值会变 (删掉低的, 平均升高), 于是又有新的行低于平均, 结果取决于删除顺序. SQL 的规定: 先算出 AVG, 一次确定所有要删的行, 再统一删除, 删除过程中不重算. 这叫「快照语义」: 整条语句看到的是执行前的数据状态. UPDATE 也一样.

Folie 46

Einfügungen Füge den Kunden Scott (der in Miami lebt) hinzu

INSERT INTO KUNDEN
VALUES (1000,'Scott','scott@gmail.com','12345','321 The Road','Miami','USA');
-- ≙
INSERT INTO KUNDEN(K_ID, Name, Email, Telefon, Adresse, Stadt, Land)
VALUES (1000,'Scott','scott@gmail.com','12345','321 The Road','Miami','USA');
-- oder
INSERT INTO KUNDEN(K_ID, Name, Email)
VALUES (1000,'Scott','scott@gmail.com');

INSERT 插入新行. 不写列名时, 必须按表定义的列顺序给出所有列的值; 写了列名就按列名对应, 顺序可以和表不同; 只列出一部分列时, 其余列取默认值 (没定义默认值就是 NULL; 如果那一列有 NOT NULL 约束则报错). 实测第一种写法成功; 第二、三种因为列名写成 Email (表里叫 "E-Mail") 而报错, 见上一个红框.

三条语句都插入 K_ID 1000: 第一条成功后, 再执行后两条中的任一条都会因为主键重复而失败. 课件的意思是三选一.

Folie 47

Aktualisierungen

Ändere die Adresse des Kunden mit der ID 1000 auf „10 New Road“

UPDATE KUNDEN
SET Adresse = '10 New Road'
WHERE K_ID = 1000;

Ändere die Adresse des Kunden 1000 auf die Adresse des Kunden 1

UPDATE KUNDEN
SET Adresse = (SELECT Adresse FROM KUNDEN WHERE K_ID = 1)
WHERE K_ID = 1000;

UPDATE 修改满足 WHERE 的行里某些列的值; 不写 WHERE 会改所有行. SET 右边可以是常量、表达式, 也可以是单值子查询. 实测两条都成功, 客户 1000 的地址最后是客户 1 的 '123 Elm St.'.

易错: 忘写 WHERE 是数据库里最常见的事故之一. 习惯做法是先用同样的 WHERE 写一个 SELECT 看看会改哪些行, 确认后再改成 UPDATE / DELETE.
