# D 概念 | 英语定义   X 概念 | 讲解   S 父概念 | 子 id | 中文 | 外文 | 一句话

D python | Python is an interpreted, dynamically typed language in which whitespace (indentation) marks code blocks.
X python | 解释型: 解释器一边读一边执行, 写完立刻能跑, 代价是速度一般慢一些; Java、C++ 是编译型. 动态类型: 不用写 int x, 看赋的值就知道类型, x = 5 之后可以 x = "hi", 用 type(x) 查看. 空白有意义: Java/C 用花括号, 缩进只为好看; Python 缩进错了程序结构就变了, 甚至报 IndentationError. 1990 年代由 Guido van Rossum 开发, 是 AI、数据科学和 NLP 的主流语言.
S python | interp | 解释型语言 |  | 一边读一边执行.
S python | dyn | 动态类型 | Dynamically typed | 类型在运行时确定.
S python | indent | 空白有意义 |  | 缩进表示代码块.

D repl | The REPL (Read-Eval-Print-Loop) reads a line of input, evaluates it, prints the result and waits for the next input.
X repl | 在终端输入 python (macOS 上常是 python3) 进入, 提示符是 >>>, quit() 退出. 只输入一个表达式回车, REPL 会自动显示它的值, 写在 .py 文件里则必须 print. REPL 显示字符串值带引号, print 不带. 变量是存储单元, 有数据类型、变量名、变量值三个要素; = 是赋值, 判断相等用 ==.
S repl | var | 变量 | Variables | 名字 = 值.

D types | Python's built-in data types include numbers, strings, lists, dictionaries, tuples, files, sets, booleans and None; functions, modules and classes are program unit types.
X types | 数值运算: / 是浮点除法 (1/4 = 0.25, 4/2 = 2.0), // 是整数除法 (7//2 = 3), ** 是乘方; 比较运算的结果是 True 或 False. 函数、模块、类在 Python 里也是对象, 用来组织代码而不是存数据.
S types | num | 数值类型 | Number data types | int 和 float.

D str | Strings are immutable sequences of single characters.
X str | 序列: 可以按下标取, 负下标从末尾数; 切片 s[start:end] 含起点不含终点, 长度正好是 end − start, 越界的下标报 IndexError, 切片越界不报错; s[::-1] 反转字符串. 不可变: s[0] = 'T' 报 TypeError, 只能造新串. 四种写法: 双引号、单引号、三引号 (跨多行, 也用于 docstring)、r 前缀的原始字符串. 常用方法: join (分隔符在前)、find (找不到返回 −1)、replace、split (不给参数时按空白切, 是最简单的分词)、upper、lower. 原字符串都不变, 返回的是新字符串.
S str | strops | 字符串操作 | String operations | 下标、切片、join、split、find、replace.
S str | rawstr | 原始字符串 | raw string | 反斜杠不转义.

D enc | Unicode assigns a unique code point to each character; encodings such as UTF-8 and UTF-16 turn code points into bytes.
X enc | 计算机只能存字节, 所以要分两步: 字符 → 编号 (Unicode, 码位), 编号 → 字节 (UTF-8、UTF-16). ord("A") 是 65, chr(65) 是 'A'; 大写和小写是不同字符, 相差 32; 0–127 就是 ASCII. UTF-8 每个字符 1 到 4 个字节, 英文文本里绝大多数字符只占 1 字节, 所以通常比 UTF-16 省空间. 'Bäume' 有 5 个字符, encode 后是 6 个字节, 因为 ä 占两个字节 (\xc3\xa4). 解码用 b"…".decode("utf-8"). open() 不写 encoding 时默认编码取决于系统区域设置, 应该始终写 encoding='utf-8'.
S enc | unicode | Unicode | Unicode | 给每个字符一个码位.
S enc | utf8 | UTF-8 | UTF-8 | 每个字符 1 到 4 个字节.
S enc | encdec | 编码与解码 |  | encode 变字节, decode 变回字符串.

D list | Lists are ordered, mutable sequences that can hold arbitrary objects and have no fixed size.
X list | 和字符串一样支持 len、下标、切片、+ 和 *, 因为都是序列; + 和 * 返回新列表. append、pop (按位置, 返回被删的项)、insert、remove (按值, 不存在报 ValueError)、reverse、sort 都是就地修改, 返回 None: l = l.sort() 会让 l 变成 None, 想保留原列表用 sorted(l). 列表里可以再放列表表示矩阵, M[1][2] 先取第二行再取第三个元素.
S list | listops | 列表操作 | List operations | 就地修改的方法返回 None.
S list | nested | 嵌套列表 | Nested lists | 先选行再选列.

D dict | Dictionaries are mutable mappings from unique, immutable keys to values, with approximately constant-time access.
X dict | 字典不按位置取值, d[0] 是「键为 0 的值」. 键必须唯一 (再赋值是覆盖) 且不可变 (查找靠键的哈希值, 键一变就找不回来), 所以列表不能做键. 对不存在的键, 写 d['num'] = 1 是新建, 读 d['num'] 或 d['num'] += 1 报 KeyError. get 返回 None 或默认值; update 合并; pop 删除并返回值; del 只删不返回. 构造方式: dict(name='Bob')、dict([(k, v)])、dict(zip(keys, values)). 'age' in d 只查键; for k, v in d.items() 遍历. NLP 里最典型的用法是词频统计.
S dict | keyerr | KeyError |  | 读不存在的键.
S dict | dictops | 字典操作 | Dictionary operations | get、update、pop、del、items.

D tuple | Tuples are immutable lists written with parentheses.
X tuple | 支持下标、切片、+、len 等所有不修改内容的序列操作, 没有 append、pop、sort; t[0] = 9 报 TypeError. 用来表示固定的一组数据, 如坐标、字典的 (键, 值) 对. 陷阱题: t + (5, 6) 只是生成并显示了一个新元组, 没有赋值回 t, 所以 len(t) 不变.

D set | Sets are mutable, unordered collections of unique, immutable elements.
X set | 自动去重, 不能用下标; x in S 约为常数时间, 比在列表里找快得多. set('spaam') 把字符串拆成字符, 得到 4 个元素. {} 是空字典, 空集合要写 set(). 交集 intersection、并集 union、差集 difference (有方向) 都返回新集合. NLP 里 set(text.split()) 一步得到词汇表, len 就是 type 数.
S set | setops | 集合运算 |  | 交集、并集、差集.

D mutimm | Numbers, strings and tuples are immutable; lists, dictionaries, sets and objects of user-defined classes are mutable.
X mutimm | 不可变对象建好后内容不能改, 「修改」其实是造了一个新对象; 可变对象可以就地修改 (append、d[k] = v、add). 只有不可变对象能做字典的键和集合的元素. 这张表考试常考, 第 3 讲还会从引用的角度再讲一次.

D flow | if/elif/else chooses a branch, while repeats while a condition is true, and for iterates over the elements of any iterable.
X flow | if 条件后要冒号, 下一行缩进; elif 从上到下检查, 执行第一个为真的分支. while True 是无限循环, Ctrl-C 中断, 实际用 break 跳出. 在条件位置空字符串、空列表为假 (truthiness), 所以 while x 意思是「只要 x 不空」. Python 的 for 直接遍历元素, 能遍历字符串、列表、字典 (逐个键)、文件 (逐行); range(a, b) 从 a 到 b 之前.
S flow | ifs | if 语句 | if-statements | 冒号加缩进, elif 多路选择.
S flow | whiles | while 循环 | While loops | 条件为真就重复.
S flow | fors | for 循环 | For loops | 逐个取出可迭代对象的元素.

D file | open(filename, mode) returns a file object; with ensures that the file is closed when the block ends.
X file | 'r' 读 (默认), 'w' 写 (文件已存在会先被清空), 'a' 在末尾追加. read() 一次读完成一个字符串, 逐行读就 for line in f. write 不会自动换行, 要自己加 '\n'. 不写 encoding 时默认编码看系统, 所以要写 encoding='utf-8'.

D func | A function packages a group of statements under a name so that it can be run several times in a program.
X func | 好处: 最大化复用、最小化冗余; 把大任务分解成小函数; 支持递归. def 名字(参数): 后面缩进函数体. 没有 return 的函数返回 None. return 把结果交回给调用者, print 只是显示在屏幕上: b = g(3) 屏幕显示 6, b 却是 None.
S func | defn | 定义函数 | Defining functions | def、参数、return.
S func | retprint | return 与 print |  | 交回结果还是只显示.

D funcobj | In Python functions are ordinary objects: they can be assigned to variables, stored in containers and passed as arguments.
X funcobj | f = mul 让 f 指向函数 mul, 不带括号; f(3, 5) 才是调用. do(8, 4, add) 把函数当参数传进去, 这叫高阶函数, 例如 sorted(words, key=len). 函数可以存成字典的值, d['multipliziere'](3, 14) 先取出函数再调用, 这种「名字 → 函数」的字典可以代替一长串 if/elif.

D mod | A module packages code and data for reuse; each module has its own namespace, and roughly every .py file is a module.
X mod | 模块里定义的名字叫这个模块的属性, 用 math.pi 访问; 模块 a 和 b 里都可以有叫 count 的函数. 程序是一张由 import 连起来的模块网络, 只有一个入口文件. import collections 要带前缀, from collections import defaultdict 直接用名字, import numpy as np 起别名. if __name__ == "__main__": 下面的代码只在直接运行时执行. 虚拟环境: python3 -m venv env 创建, source env/bin/activate 激活, pip install nltk 装包, deactivate 退出; $ 是终端命令, >>> 是 Python 代码.
S mod | venv | 虚拟环境 | virtual environment | 每个项目一套自己的包.
S mod | main | __name__ == "__main__" |  | 只在直接运行时执行.

D unittest0 | Unit tests automatically check whether the smallest units of a program, usually functions, produce the expected output.
X unittest0 | 四个好处: 抓住容易自动发现的错误; 明确规格 (测试本身就是功能说明); 改代码更安心; 防止回归 (重构后确认原有功能没坏). Python 自带两个测试框架, 不用 pip 安装: 简单的 doctest 和功能更强的 unittest.

D doctest | The doctest module searches docstrings for text that looks like interactive REPL sessions, runs it and compares the result with the expected output.
X doctest | >>> 后要有一个空格, 期望输出紧接在下一行, 比较是按文本逐字进行的, 期望写 4.0 实际是 4 也算失败. 测试就是文档, 示例还保证是对的. 运行: python3 -m doctest -v example_module.py, -v 打印每条测试的过程, 不加时全部通过就什么都不输出; 1 items had no tests 只是信息, 不是错误.
S doctest | run | 运行测试 | Running the tests | python3 -m doctest -v.

D tdd | In test-driven development the tests are written first; the function body starts as pass, and the features are implemented until the failing tests pass.
X tdd | 好处: 事先明确输入和输出; 逼你考虑边界情况 (空字符串、空集合、float('inf')、0、负数), 例如求平均词长的函数输入空文本会除以 0; 通过的测试比例就是进度. 函数体只有 pass 时 square(2) 返回 None, doctest 报告 Got nothing.

D unittest | The unittest module, similar to Java's JUnit, puts tests in a separate test module: a class inheriting from unittest.TestCase with methods whose names start with test.
X unittest | 只有以 test 开头的方法才会被自动识别为测试. 要用继承来的 self.assertEqual 等断言方法, 不用内置的 assert, 因为前者失败时报告清楚、能被统计. 常用断言: assertEqual、assertTrue (看 bool(x))、assertIs、assertIsNone、assertIn、assertIsInstance. == 比较值, is 比较是不是同一个对象, 判断 None 惯用 x is None. 运行: python3 -m unittest -v test_square.py. 一个测试方法里第一条断言失败后, 后面的不再执行; 测试的单位是方法, 不是断言.
S unittest | asserts | 断言方法 | Different types of asserts | assertEqual、assertTrue、assertIs、assertIn.
S unittest | isvseq | == 与 is |  | 比较值, 还是比较是不是同一个对象.

D setup | setUp is executed before each test method to create shared preconditions; tearDown is executed after each test method for clean-up.
X setup | 执行顺序对每个测试方法重复一遍: setUp → testXxx → tearDown. 例子把三个 (输入, 期望输出) 元组存在 self.inputs_outputs 上, 测试方法用 for i, o in … 逐对检查, 测试数据和测试逻辑分开, 加新数据只改 setUp. tearDown 用得较少, 用来关闭连接、删除临时文件.

D vc | Version control manages changes to files over time; Git is a distributed version control system in which every copy carries the full history.
X vc | 版本控制记录历史、可以撤销和重做、支持并行开发, 不只用于代码. Git 由 Linus Torvalds 在 2005 年为 Linux 内核开发. 分布式: 没有网络、没有中央服务器也能查历史、提交、建分支; 集中式的 SVN 历史只在服务器上. 分支只是一个指针, 建分支几乎不花时间. Git 是装在你电脑上的程序, GitLab、GitHub 是托管仓库副本的网站.
S vc | distrib | 分布式 |  | 每份副本都有完整历史.

D snapshot | Git stores snapshots: each commit records what all files of the project look like at that moment; unchanged files are stored as links to the previous version.
X snapshot | 回到某个版本时, Git 把那张快照整个还原出来, 不是一步步倒推改动. 大部分操作只用本地文件. 每个提交有一个 40 位的 SHA-1 哈希值, 由内容算出, 平时写前 7 位就够. Git 基本只添加数据, 一旦提交几乎不会丢; 还没提交的改动才是真正可能丢的.
S snapshot | hash | 哈希值 |  | 40 位 SHA-1, 由内容算出.

D areas | Each file is untracked, unmodified, modified or staged; the states correspond to the working directory, the staging area (index) and the .git directory.
X areas | 工作区是你编辑的文件夹, 暂存区是下一次提交的打包台, .git 目录是存着完整历史的本地仓库, 删掉它这个文件夹就不再是 Git 仓库. 日常三步: 改 → add → commit; 反方向的 checkout 从历史里取出某个版本放回工作区. 暂存区的用处: 只挑一部分改动提交, 一次提交只做一件事. 第一次用先 git config --global 设名字和邮箱; 得到仓库只有 git init 和 git clone 两种方式.
S areas | wd | 工作区 | Working directory | 你编辑的文件夹.
S areas | stage | 暂存区 | Staging area | 下一次提交的内容.
S areas | gitdir | .git 目录 |  | 本地仓库, 存着完整历史.
S areas | init | 配置与建立仓库 | Initial configuration | git config、git init、git clone.

D commit | git status shows the state of each file, git add puts changes into the staging area, and git commit stores the staged snapshot permanently in the history.
X commit | git status 是最常用的命令, 看不懂下一步时先跑一次. git add 一个命令两种用途: 新文件开始被跟踪, 改过的文件进入暂存. add 的是文件此刻的样子, add 之后又改了要再 add 一次. commit -m 后写清楚改了什么. git rm 删文件并暂存删除, git rm --cached 只取消跟踪, git mv 改名.
S commit | status | git status |  | 每个文件处在哪种状态.
S commit | add | git add |  | 放进暂存区.
S commit | rmmv | git rm 与 git mv |  | 删除和移动文件.

D log | git log shows the commit history with hash, author, date and message, newest first.
X log | 历史长时进入分页, 按 q 退出. 常用选项: -p 显示改了哪些行; -2 只看最近两个; --stat 每个提交改了哪些文件; --oneline --graph --all 一行一个提交并画出分支线, 学分支时最推荐; --author、--since 按作者和时间筛选.

D branch | A branch is a movable pointer to a commit; HEAD points to the branch you are currently on.
X branch | 每个提交指向它的上一个提交. 在某分支上提交时指针前移到新提交, HEAD 跟着走. git branch testing 只建不切, git checkout testing 切换, git checkout -b testing 一次完成. 合并要先切到接收改动的分支, 再 git merge testing; 方向搞反是最常见的错误. 结果有两种: 快进 (fast-forward), 直接把指针往前挪; 两边都有新提交时, 做三方合并, 生成一个合并提交. Git 默认分支叫 master, GitLab、GitHub 上新建仓库默认叫 main.
S branch | head | HEAD | HEAD | 指向当前分支.
S branch | merge | 合并 | merge | 把别的分支并进当前分支.
S branch | ff | 快进 | fast-forward | 直接把指针往前挪.

D undo | git revert adds a new commit that undoes an earlier one; git reset moves the branch pointer back as if the commit had never happened.
X undo | 漏了文件: add 后 git commit --amend. 把文件从暂存区拿回来: git restore --staged. 丢掉对文件的修改: git restore, 没提交过的改动找不回来. revert 历史只增不减, push 之后要撤销用它; reset 改写历史, 只用于还没 push 的提交. master~1 是往前数一个提交. reset 三种模式只差在被撤掉的改动放到哪: --soft 留在暂存区, --mixed (默认) 退回工作区, --hard 彻底丢掉, 最危险.
S undo | rev | revert | revert | 新加一个抵消的提交.
S undo | res | reset | reset | 把分支指针往回挪.
S undo | modes | --soft、--mixed、--hard |  | 被撤掉的改动放到哪.

D remote | A remote is a short name for the address of a copy of the repository on a server; git clone adds a remote called origin automatically.
X remote | LMU 信息学院有自己的 GitLab. 连接有 https (用户名加密码或令牌) 和 ssh (一对密钥) 两种. ssh-keygen -t ed25519 生成密钥, 把 .pub 公钥交给 GitLab, 不带 .pub 的私钥绝不外传. git remote add 名字 地址、git remote rm、git remote -v. 每个远程列两行, fetch 和 push 各一行.
S remote | ssh | ssh 密钥 | ssh keys | 公钥交给 GitLab, 私钥留在电脑上.
S remote | clonec | 克隆 | Cloning | 连同历史复制一个仓库.
S remote | origin | origin |  | clone 时自动添加的 remote.

D sync | git fetch downloads new commits and updates the remote branch, git pull fetches and merges into the current branch, and git push uploads your new commits.
X sync | clone 之后 master 是你自己的本地分支, origin/master 是远程分支, 记录上次联系时服务器上的 master 在哪; 它不会自动更新, 要 fetch. 比较 master 和 origin/master 就知道哪些是只在本地的工作. fetch 不动你的文件, pull 相当于 fetch + merge, push 改的是服务器.
S sync | rbranch | 远程分支 | Remote Branches | origin/master.
S sync | fetchc | fetch | fetch | 下载, 不动本地文件.
S sync | pullc | pull | pull | fetch 加 merge.
S sync | pushc | push | push | 上传新提交.

D conflict | A merge conflict arises when both sides changed the same line; Git stops and lets you decide which version to keep.
X conflict | 改的是不同行时 Git 会自动合好. 经过: push 被拒 (服务器上有你没有的提交) → pull 时合并报 CONFLICT → 打开文件, <<<<<<< HEAD 到 ======= 是你的版本, ======= 到 >>>>>>> 是拉下来的版本 → 改成最终内容并删掉三行标记 → git add、git commit、git push. 忘了删标记就提交, Python 文件会报 SyntaxError. 小组循环: pull → 改 → commit → pull → push, 开工前和 push 前都先 pull.
S conflict | marker | 冲突标记 |  | <<<<<<< ======= >>>>>>>.
S conflict | teamflow | 远程工作流程 | Typical workflow with a remote | pull → 改 → commit → pull → push.

D mut | A mutable object can still be changed after creation; an immutable object never changes, and an apparent change creates a new object.
X mut | 关键是分清变量和对象: 变量只是名字 (标签), 指向内存里的对象. x = 'b' 没有改动字符串 'a', 而是让 x 改指向新对象. 本讲最重要的思维模型: 列表里存的不是值本身, 而是一排引用. append 在原列表对象末尾加位置, x 还指向同一个对象. x[2] = 'e' 改的是列表那个位置的指向, 字符串 'c' 一点没变. 多维列表也是同一张图: 外层位置里存着指向内层列表的引用.
S mut | refs | 列表里存的是引用 |  | 改的是指向, 不是元素本身.
S mut | multidim | 多维列表 | Multidimensional lists | 外层存着指向内层列表的引用.

D slicing | List indices start at 0, negative indices count from the end, and slicing myList[start:end] returns a new list from start up to end (exclusive).

D ttr | The type-token ratio (TTR), the number of types divided by the number of tokens, measures lexical diversity.
X ttr | 《创世记》44764 个 token、2789 个 type, TTR 约 0.062, 平均每个词用了 16 次. 《白鲸》7.4%, 《理智与情感》4.8%. TTR 受文本长度影响: 文本越长常用词重复越多, TTR 越低, 所以只有长度相近的文本才能比较. 取值最大是 1, 下限趋近 0. lexical_diversity 不是 NLTK 自带的, 要按 NLTK 书自己定义.

D lexres | A lexicon or lexical resource is a collection of words or phrases with associated information such as definitions or sentiment polarity.
X lexres | 词汇资源通常从文本派生, 借助文本建立和扩充. 最简单的三种: 排好序的词表、频率分布、条件频率分布. 停用词表、人名表、CMU 发音词典也是词汇资源.

D freqd | A frequency distribution records how often each type occurs; NLTK's FreqDist is a subclass of Counter.
X freqd | FreqDist(text1) 和 text1.vocab() 内容相同, 像字典一样查: whale 在《白鲸》里出现 906 次. 频率分布随文本和文本的类别变化. 只出现一次的词叫 hapax (hapax legomenon), 《白鲸》里有 9002 个, 几乎占全部 type 的一半. fdist1.plot(50) 的曲线开头急剧下降, 后面又平又长: 少数几个词占了大量出现次数, 这是齐普夫定律.
S freqd | hapax | 只出现一次的词 | hapax | hapax legomenon.
S freqd | zipf | 齐普夫定律 |  | 少数词占了大量出现次数.

D cfd | A conditional frequency distribution is a collection of frequency distributions, one for each condition; it is built from (condition, event) pairs.
X cfd | 频率分布数的是一个个事件 (词); 条件频率分布要把每个事件和条件配成一对. 用双层列表推导式为 news 和 romance 里的每个词生成 (体裁, 词) 对, 交给 ConditionalFreqDist. cfd["romance"] 本身是一个 FreqDist, cfd["romance"]["could"] 是 193. 条件也可以是语言 (udhr 语料, 事件是词长) 或年份 (就职演说语料, fileid[:4]).

D annot | Annotated corpora carry linguistic annotation such as POS tags, named entities, syntactic structure or semantic roles.
X annot | CoNLL 格式 (OntoNotes 风格) 每个词一行, 每层标注一列: POS、句法括号、谓词论元、命名实体、共指链编号, 一个句子同时带了词法、句法、语义、语篇四层标注. NLTK 自带 Brown、CESS 树库、CMU 发音词典、CoNLL 2000 组块数据等, 下载时写语料的 id. 知识库也是一种标注资源, 把文本里的实体归到类别下.

D stop | A word list is a special lexical resource consisting of a list of words; stopwords are very frequent words with little lexical meaning.
X stop | NLTK 带了停用词、人名、Swadesh 核心词表、英语单词表. 英语停用词表 179 个, 包括代词、疑问词、be 的各种形式和 you're 之类的缩写; 德语停用词有冠词、代词、介词、连词和助动词形式. 人名表 (男名、女名) 能为照应消解和机器翻译提供性别线索, 但 Adrian 两张表里都有, 只是概率性的. w in female_names 在列表里顺序查找, 先转成 set 快得多.
S stop | stopw | 停用词 | stopword | 高频、几乎没有词汇意义.
S stop | names | 人名表 |  | 性别是照应消解的线索.

D pipe | In an NLP pipeline such as Stanford CoreNLP, annotators run one after another on a shared annotation object, each reading earlier results and adding its own.
X pipe | CoreNLP 的顺序: tokenize → ssplit → pos → lemma → ner → parse → dcoref. 顺序有依赖: 词形还原和句法分析都要先有词性. 第二张图把流水线分成预处理 (分句、分词、规范化) 和处理 (词性标注之后的句法分析、特征标注、语义分析、语篇分析) 两大块; 本讲讲预处理, 词性标注是下一讲.

D prep | Preprocessing comprises sentence segmentation, tokenization and normalization (lowercasing, stopword removal, stemming, lemmatization).
X prep | 一个句子逐步经过: 按空格分词 → 去标点 → 小写 → 词干提取 (cars → car, different → differ) → 词形还原 (are → be) → 去停用词. NLTK 默认的 WordNet 词形还原器不会把 are 还原成 be. 分句用 PunktSentenceTokenizer, 它是从数据中学出来的模型, 记住了缩写、搭配和常在句首的词, 所以 Mr. 后面的句点不是句子边界; 平时用 nltk.sent_tokenize. LineTokenizer 按行切.
S prep | sentseg | 分句 | Satzsegmentierung | Punkt 模型.

D norm | Stemming and lemmatization both reduce inflected (sometimes derived) forms to a base form; lemmatization yields the dictionary form, stemming cuts off affixes.
X norm | ich laufe 的词元是 laufen, 词干是 lauf, 不一定是一个词. 词形还原判断表面不同的词有同一个词根: am、are、is 的词元都是 be. 最精细的是完整的形态分析: 形态学研究词怎样由语素构成, 语素分词干和词缀. 词干提取是简化的形态分析, 主要砍掉词尾; 最常用的 Porter 算法是一系列级联的改写规则, 结果像 this → thi、was → wa.
S norm | stem | 词干提取 | stemming | 砍掉词缀.
S norm | lemma | 词形还原 | lemmatization | 给出词典里的词元.
S norm | porter | Porter 算法 | Porter stemmer | 级联的改写规则.
S norm | morphem | 语素 | morpheme | 词干和词缀.

D morphlang | How much lemmatization and stemming help depends on the morphology of the language.
X morphlang | 1000 个平行句子里每个词元平均对应的词形: 泰语 1.00、汉语 1.01 (没有用语素表示的屈折变化), 芬兰语 1.53、土耳其语 1.65 (大量屈折词尾和格). 屈折越多, 同一个词元分散成越多 type, TTR 越高. 芬兰语名词有 15 个格, 土耳其语是黏着语, 一个词可以对应一整句英语, 不做形态切分几乎没法统计.

D kolloc | A collocation is a sequence of words that occur together unusually often and cannot easily be replaced by synonyms.
X kolloc | red wine 是搭配, the wine 不是; 换成近义词 maroon wine 就很别扭. 索引是针对一个给定的词、列出它每一次出现的查看工具; 搭配是从整个文本统计出来、比偶然更常一起出现的词组, 是分析结果. 只按频率排最前面是 of the、in the; text.collocation_list() 先过滤停用词, 再用互信息之类的统计量衡量.

D ngram | A bigram is a pair of adjacent words, a trigram three adjacent words, in general an n-gram.
X ngram | n 个词的文本有 n − 1 个二元组、n − 2 个三元组. nltk.bigrams 和 trigrams 返回生成器, 要用 list() 才能看到内容, 而且只能用一次. 「搭配就是频繁的二元组」是简化的说法.
S ngram | big | 二元组 | bigram | 相邻两个词.
S ngram | ng | n 元组 | n-gram | 相邻 n 个词.

D gen | Random text can be generated with a conditional frequency distribution over bigrams: the previous word is the condition and the following word the event.
X gen | cfd["living"] 是 living 后面跟过的词的分布, max() 是 creature. 从 living 出发每次打印当前词, 再换成最常跟在后面的词, 很快陷入 the → land → of → the 的循环, 因为每一步都确定地取最大值, 而且只看前一个词. 改进: 按频率随机抽下一个词, 用更长的上下文 (三元组、n 元组), 这正是语言模型的基本思想.

# ===== SP 07 · 词性标注 2026-11-13 =====
D posdef | Parts of speech = morphosyntactic word classes; POS tagging = the task of labeling each word with its corresponding POS.
X posdef | 同一词性的词共享句法和形态特征. 标注看的是词在这个位置的用法: They refuse to permit us to obtain the refuse permit 里 refuse 和 permit 各出现两次, 一次动词一次名词. NLTK 的 pos_tag 输出 (词, 标签) 元组, 用 Penn Treebank 标签.
S posdef | classes | 学校里的九大词类 | Typical categories | 名词、动词、形容词、副词、代词、限定词、附置词、连词、叹词.
S posdef | adp | 附置词 | Adposition | 介词和后置词的统称.
D posuse | Why POS? Basis (or replacement) for analyzing texts at a syntactic or shallow semantic level.
X posuse | 信息抽取: 名词指实体, 动词表关系; 机器翻译: like 是动词译 mag, 是介词译 wie; 语音合成: lead、wind、object 的读音随词性变; 句法分析: Time flies like an arrow 和 Fruit flies like a banana 结构不同. 自动得到的词性比更深的自动分析稳健.
S posuse | ie | 信息抽取 | Information extraction | 名词指实体、动词指关系.
S posuse | mt | 机器翻译 | Machine translation | 按词性选译词.
S posuse | tts | 语音合成 | Speech synthesis | 同形异音词按词性定读音.
D openclosed | Closed: limited number of words in each category; Open: unlimited number of words.
X openclosed | 封闭类 (助动词、限定词、连词、代词、介词、小品词、叹词) 可以列表穷举, 而且都很高频; 开放类 (名词、动词、副词、形容词) 不断加入新词, 没见过的新词几乎一定属于开放类.
D granul | Depending on the tagset, classes can be subdivided into more fine-grained classes; words are additionally annotated with morphological features.
X granul | 名词分专有名词和普通名词, 普通名词再分可数和不可数; 代词分人称、物主、关系、疑问. 形态特征: 名词的数、格、性; 动词的时、体、式、示证、态; 形容词的比较级和一致.
D tagset | The POS tagset defines the number and granularity of tags and how each tag is defined.
X tagset | 英语常用 Penn Treebank (36 个核心标签, 加标点 45 个), 德语常用 STTS, 多语言用 Universal Dependencies (NLTK 用 12 个标签的早期版本, 当前 v2 有 17 个). 同一语言的标签集也差别很大: 从 17 到 137 个. 细到粗的映射容易, 粗到细不行, 边界情况也不同 (something 在 Penn 是 NN, 在 Universal 是 PRON).
S tagset | penn | Penn Treebank | Penn Treebank tagset | 36 个核心标签, 非常英语化.
S tagset | universal | Universal 标签集 | Universal tagset | NLTK 里 12 个粗标签.
S tagset | mapping | 标签集映射 |  | 细到粗容易, 粗到细不行.
D tagcorp | We can reverse the order of the pairs, so that the tags are the conditions, and the words are the events.
X tagcorp | 把 (词, 标签) 交给 ConditionalFreqDist, 以词为条件得到每个词的标签分布 (yield: VERB 28, NOUN 20); 倒过来以标签为条件, 得到每个标签下的词. 以标签为条件时条件数就是 12 (Universal 标签数). 还能找出标签多于三种的词, 如 that、best、present、close、open.
D posamb | Tag ambiguity in the Brown and WSJ corpora: 14–15 % of types, but 55–67 % of tokens are ambiguous.
X posamb | 按词型 (Type) 大多数词只有一个标签, 按词元 (Token) 一半以上的出现要消歧, 因为有歧义的恰是 that、back、to 这些高频词. back 一个词就有 JJ、NN、VBP、VB、RP、RB 六种.
D deftag | Use the most frequent word class – one label for all words.
X deftag | DefaultTagger('NN') 给所有词元标 NN, 在 Brown 上准确率约 13%. 评价分类器至少要和「最常见类基线」比, 那是按每个词选它在训练集里最常见的类, 比默认标注器强得多.
S deftag | mfc | 最常见类基线 | Most Frequent Class Baseline | 每个词标它最常见的类.
D regtag | The regular expression tagger assigns tags to tokens on the basis of matching patterns; patterns are processed in order.
X regtag | 规则按词尾猜: -ing → VBG, -ed → VBD, -es → VBZ, -'s → 属格, -s → NNS, 数字 → CD, 其余 NN. 顺序重要: 先匹配的规则先用. 在 Brown 上约 20%; the、a 这类虚词全错成 NN, was、this 因以 s 结尾被错标.
D lookup | Find the hundred most frequent words and store their most likely tag, use this as the model for a lookup tagger (UnigramTagger).
X lookup | 只用 100 个高频词的查表就把准确率从 20% 提到约 47%, 因为高频词占了文本的大半. 表外的词得到 None. 用全部词训练 UnigramTagger 在训练数据上有 92%, 在留出的 10% 上约 88%.
D backoff | Many words have been assigned a tag of None; in these cases we would like to assign the default tag of NN – process known as backoff.
X backoff | 查不到就交给下一个标注器: UnigramTagger(model, backoff=DefaultTagger('NN')) 把准确率提到约 60%. 可以串成链: 二元 → 一元 → 默认. 二元标注器单独用时一遇到没见过的组合就给 None, 之后整句都是 None, 所以离不开后退.
D ngtag | Problem of unigram tagging: assigns one tag irrespective of context; n-gram tagging uses n items of context; preceding tokens are only represented by their POS tags.
X ngtag | the wind 和 to wind 里 wind 词性不同, 一元标注器分不出. 二元看前一个标签, 三元看前两个. 前面的词只以标签出现, 因为标签只有几十种, 组合还见得够多. 开发集上: 默认 10.7%, 一元 89.1%, 二元 91.3%.
D datasplit | Training data – Test data – Development data (validation set).
X datasplit | 在训练数据上测会偏高. 训练数据越多越好, 测试集太小评估不客观, 训练数据要和测试数据同类. 开发集在开发过程中反复使用, 测试集只在最后用一次. 按句子随机划分简单, 但同一文档的句子会两边都有, 结果偏乐观.
D tagdev | Developing a tagger is an iterative process: implement, train, test on development data, analyze errors, improve, finally test on test data.
X tagdev | 用 nltk.ConfusionMatrix(gold, test) 看错误: 社论语料上最多的是动词和形容词被标成名词 (没见过的词后退到 NOUN). 改进办法: 更多训练数据、更大的 n、针对混淆最多的标签改. 训练好的标注器用 pickle 存起来复用.
S tagdev | confusion | 混淆矩阵 | Confusion matrix | 行是金标准, 列是预测.
S tagdev | pickle | 保存标注器 | Storing a tagger | 用 pickle 存取.
D tageval | accuracy: #(pred=gold) / #(tokens); per tag: precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN).
X tageval | 准确率看整体. 单个标签 (如 VERB) 的假正例是预测成 VERB 但其实不是, 假负例是应该是 VERB 却预测成别的; 真负例和这个问题无关. 精确率和召回率分子相同、分母不同, F1 是两者的调和平均.
