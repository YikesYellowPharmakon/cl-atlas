# DBS 深层内容. 依据 DBS 01–03 笔记. 外文是德语 (课件语言).
# D 概念 | 德语定义   X 概念 | 讲解   S 父概念 | 子 id | 中文 | 外文 | 一句话

D warum | Bei alternativen Lösungen (z. B. selbst geschriebenen Python-Programmen) entstehen Redundanzen, Inkonsistenzen, eingeschränkter Zugriff, Probleme beim Mehrbenutzerzugriff, Datenverluste und Integritätsverletzungen.
X warum | 课上先提一个稻草人方案: 用 Python 自己管学生、课程和选课. 七类问题: 冗余与不一致 (Redundanz / Inkonsistenz, 同一信息存了好几份, 改一处忘一处)、受限的访问 (每种新查询都要专门写函数)、多用户访问 (一个人的修改覆盖另一个人的)、数据丢失 (写到一半崩溃)、完整性被破坏 (学分可以写成 blub)、安全问题、开发成本高. 讲座的示例程序实际运行时就出现了重复行、非法值和覆盖写文件. 每一点都自己解决, 等于重写一个数据库系统.
S warum | redinkons | 冗余与不一致 | Redundanz / Inkonsistenz | 同一信息多份, 改了一处忘了另一处.
S warum | zugriff | 受限的访问 |  | 每种新查询都要专门写函数.
S warum | mehrbenutzer | 多用户访问 |  | 同时修改会互相覆盖.
S warum | verlust | 数据丢失 |  | 写到一半崩溃, 文件就坏了.
S warum | integver | 完整性被破坏 |  | 没人检查数据是否合法.

D dbs | Ein Datenbanksystem (DBS) besteht aus einer Datenbank (DB), einer integrierten Sammlung persistent gespeicherter Daten, und einem Datenbankmanagementsystem (DBMS).
X dbs | 数据库 (Datenbank) 是数据本身: 整合的、相互关联的、持久 (persistent) 存储的数据集合, 描述现实世界的实体 (Entität) 和实体之间的联系 (Beziehung). DBMS 是管理数据库的软件, 如 PostgreSQL、MySQL、DuckDB. 应用不直接碰数据文件, 都经过 DBMS, 这正是解决上一节问题的关键: 检查、并发控制、权限都可以集中在 DBMS 里做.
S dbs | db | 数据库 | Datenbank | 持久存储的整合数据.
S dbs | dbms | 数据库管理系统 | Datenbankmanagementsystem | 管理数据库的软件.
S dbs | entbez | 实体与联系 | Entität & Beziehung | 数据描述的现实世界片段.

D zweck | Ein Datenbanksystem bietet Datenintegration, effizienten Datenzugriff, einen Datenkatalog, Benutzersichten, Integritätsbedingungen, Sicherheitsmechanismen, Transaktionen, Synchronisation und Recovery.
X zweck | 这些功能和七类问题一一对应: 数据整合 (每个信息只存一份) 解决冗余; 数据库语言 (SQL) 解决受限访问; 数据目录 (Datenkatalog) 存元数据; 不同用户看到不同视图, 加上安全机制, 解决安全问题; 完整性约束由 DBMS 保证数据合法; 事务 (Transaktion) 把多个操作合成一个逻辑单元, 要么全做要么全不做 (转账); 同步协调多个用户的事务; 恢复在崩溃后回到一致状态; 即席查询 (Ad-hoc) 随时提出没预先编程的查询. 课件把这份清单归到 Codd 的十二条规则.
S zweck | trans | 事务 | Transaktion | 要么全部完成, 要么全部不做.
S zweck | katalog | 数据目录 | Datenkatalog | 存放元数据.
S zweck | recovery | 恢复 |  | 崩溃后回到一致状态.
S zweck | adhoc | 即席查询 | Ad-hoc | 随时提出没预先编程的查询.

D gesch | Datenmanagement entwickelte sich von anwendungsspezifischen Dateien über Dateiverwaltungssysteme und hierarchische bzw. Netzwerk-Datenbanken zu relationalen Datenbanksystemen.
X gesch | 四个阶段, 每一步都在解决上一步的毛病. 60 年代初每个应用自己组织数据文件, 依赖设备、冗余、不一致; 60 年代末有文件管理系统 (SAM、ISAM), 不再依赖设备但仍冗余; 层次模型和网状模型用指针连数据, 程序沿指针导航, 内部存储和概念结构分不开; 70–80 年代关系数据库: 数据放在表里, 三层架构, 声明式语言. 1970 年 Codd 提出关系模型; 1974 年 IBM 的 System R 用 SEQUEL (后改名 SQL); 1975 年伯克利的 Ingres 是 PostgreSQL 的祖先.
S gesch | hiernetz | 层次与网状模型 |  | 用指针连数据, 查询要写清楚走哪条路.
S gesch | systemr | System R |  | 第一个关系数据库原型, 查询语言 SEQUEL.

D trends | Heutige Trends sind In-Memory-Datenbanksysteme auf neuer Hardware, Cloud-Datenbanken, Datenstromverarbeitung, Big Data und NoSQL-Systeme.
X trends | 新硬件: 多核 CPU 和 TB 级内存使内存数据库成为可能 (SAP HANA), 还有 FPGA、GPU 加速. 专门应用: 云数据库、数据流处理 (股票行情、传感器)、大数据. NoSQL 是 not only SQL: 非关系型、模式灵活 (如存 JSON), 通过去掉事务、声明式查询等复杂功能变得轻量; 按数据形态分文档、图、向量、时序、键值等. 要点是按数据长什么样、怎么被查询来选数据库.
S trends | inmem | 内存数据库 |  | 数据全放在内存里.
S trends | nosql | NoSQL | NoSQL | 非关系型、模式灵活.

D ebenen | Ein DBMS bietet eine abstrakte Sicht auf die Daten mit Sichtebene, logischer Ebene und physischer Ebene.
X ebenen | DBMS 隐藏数据在计算机上怎样存储的细节. 视图层 (Sichtebene): 用户和应用看到什么, 例如学生只看到自己的成绩. 逻辑层 (Logische Ebene, 也叫概念层): 存了哪些数据, 结构是什么, 例如学生、课程、选课三张表. 物理层 (Physische Ebene): 数据实际怎样存, 文件和索引怎样组织, 例如姓名上建了 B 树索引. 越往上抽象程度越高.
S ebenen | sicht | 视图层 | Sichtebene | 用户和应用看到的样子.
S ebenen | logisch | 逻辑层 | Logische Ebene | 存了哪些数据.
S ebenen | physisch | 物理层 | Physische Ebene | 数据怎样存储.

D schema | Ein Datenbankschema beschreibt eine Sammlung von Daten mit einem gegebenen Datenmodell; eine Instanz ist der tatsächliche Inhalt zu einem bestimmten Zeitpunkt.
X schema | 模式 (Schema) 和实例 (Instanz) 的区别就像编程里的类型和值. 模式例如「学生表有学号、姓名、年龄三列」, 很少改变; 实例是此刻表里的 16 行学生记录, 每次插入删除都会变. 模式也分三层: 概念 (逻辑) 模式是数据库设计的基础, 也是本课重点; 视图 (外部模式) 通常在需求分析时定义; 物理模式是存储结构.
S schema | konz | 概念模式 |  | 设计的基础, 本课重点.
S schema | extern | 外部模式 |  | 视图, 需求分析时定义.

D dunab | Datenunabhängigkeit bedeutet, dass Änderungen am Schema einer Ebene die Schemata höherer Ebenen nicht beeinflussen.
X dunab | 物理数据独立性 (physische Datenunabhängigkeit): 加索引、换存储格式不用改逻辑模式和应用, 为了提速常这样做; 课上的示例程序做不到, 换掉 CSV 格式所有读写函数都要重写. 逻辑数据独立性 (logische Datenunabhängigkeit): 给表加一列、拆表不用重写应用, 应用通过视图看到的样子不变, 这比物理独立性难. 方向是下层变、上层不受影响.
S dunab | phys | 物理数据独立性 | physische Datenunabhängigkeit | 改物理模式不影响逻辑层和应用.
S dunab | log | 逻辑数据独立性 | logische Datenunabhängigkeit | 改逻辑模式不影响应用.

D modell | Ein Datenmodell ist eine Sammlung von Konzepten zur Beschreibung von Daten, Beziehungen, Datensemantik und Constraints.
X modell | 数据模型 (Datenmodell) 分两类. 概念模型面向设计、贴近现实世界: ER 模型 (实体-联系模型)、语义数据模型、面向对象模型 (UML). 逻辑模型面向具体 DBMS 的实现: 关系模型 (本课主线)、对象关系模型、网状模型、层次模型、XML/JSON. 课件引用 Stonebraker 和 Pavlo 的文章: 几十年来的各种新数据模型最后大多回到关系模型或被它吸收.
S modell | konzm | 概念模型 |  | 面向设计, 如 ER 模型.
S modell | logm | 逻辑模型 |  | 面向实现, 如关系模型.

D ddldml | Die DDL definiert das Datenbankschema und legt Metadaten im Datenkatalog ab; die DML dient zum Abfragen und Ändern der Instanzen.
X ddldml | DDL (数据定义语言) 定义模式, 例如 CREATE TABLE 建一张助教表; 编译结果存进数据目录 (Data Dictionary), 也就是元数据. DML (数据操纵语言) 查询和修改实例, 分过程式 (prozedural, 写清楚怎样取, 像示例程序里的三层循环) 和声明式 (deklarativ, 只写要什么, 怎么取由 DBMS 决定). SQL 是声明式的. SELECT 属于 DML, 虽然它不修改数据.
S ddldml | ddl | 数据定义语言 | DDL | 定义模式.
S ddldml | dml | 数据操纵语言 | DML | 查询和修改实例.
S ddldml | dekl | 声明式与过程式 | deklarativ & prozedural | 只说要什么, 还是写清楚怎样取.

D arch | Die Architektur von Datenbankanwendungen basiert typischerweise auf dem Client-Server-Modell mit Benutzeroberfläche, Anwendungslogik und Datenverwaltung.
X arch | 一个应用的功能分三块: 界面与交互、应用逻辑 (Anwendungslogik / Business Logic)、数据管理. 两层架构: 客户端上同时有界面、应用逻辑和数据库接口, 直接连数据库服务器; 缺点是业务逻辑分散在每台客户端上, 更新麻烦, 每个客户端都要有数据库权限. 三层架构: 客户端只剩界面 (浏览器), 应用逻辑放到中间的应用服务器上, 今天的网站基本都是这样.
S arch | zwei | 两层架构 |  | 应用逻辑在客户端.
S arch | drei | 三层架构 |  | 应用逻辑在中间的应用服务器.

D relmodell | Das relationale Modell wurde 1970 von Edgar F. Codd eingeführt; es beruht auf einfachen, einheitlichen Datenstrukturen (Relationen) und einer soliden theoretischen Grundlage.
X relmodell | 关系模型 (Relationales Modell) 只有一种结构: 关系, 直观地说就是表. 关系就是数学上的集合, 所以可以用集合论和逻辑来推理, 这在关系代数、关系演算和查询优化里会用到. 今天绝大多数数据库系统都以它为基础. 关系可以直接用 SQL 建表得到, 也可以从 ER 模式推导出来.
S relmodell | einfach | 只有一种结构 |  | 数据只用关系表示.
S relmodell | theorie | 集合论基础 |  | 关系是集合, 可以用逻辑推理.

D domaene | Eine Domäne ist ein Wertebereich (Typ), eine logische Menge von Werten mit begrenzter oder unbegrenzter Kardinalität.
X domaene | 域 (Domäne) 是一个属性允许取的所有值组成的集合, 例如整数、字符串、日期, 或有限的 {rot, gelb, grün, blau}. 基数 (Kardinalität) |D| 是集合的元素个数. 这个词在本章有两个用法: 这里指域的大小, 后面指关系里元组的个数, 意思都是集合有多少个元素.
S domaene | kard | 基数 | Kardinalität | 集合的元素个数.

D kreuz | Das kartesische Produkt (auch Kreuzprodukt) ist die Menge aller möglichen Kombinationen von Elementen aus k Mengen.
X kreuz | 从 k 个集合里各取一个元素, 按顺序排成 k 元组. D₁ = {1, 2, 3}, D₂ = {a, b} 时 D₁ × D₂ 有 6 个有序对. 元组是有序的, (1, a) 和 (a, 1) 不同; (a, 1) 根本不在 D₁ × D₂ 里, 因为第一个分量必须来自 D₁.
S kreuz | anzahl | 元组个数 |  | 各集合元素个数相乘.

D relation | Eine Relation R über den Domänen D₁, …, Dₖ ist eine Teilmenge des kartesischen Produkts D₁ × … × Dₖ.
X relation | 先列出所有可能的组合, 关系从中挑出一部分. 空集也是关系, 全积也是; D₁ × D₂ 有 6 个元素, 所以一共有 2⁶ = 64 种可能的关系. 域无限时关系也可以无限, 但数据库里的关系一定有限. 关系的元素叫元组 (Tupel); 度或元数 (Stelligkeit) 是列数, 基数是元组个数, 属性 (Attribut) 是一个分量位置. 同一个学号出现两次作为数学上的关系是合法的, 只说明它不能当键.
S relation | tupel | 元组 | Tupel | 关系的元素, 表的一行.
S relation | stell | 元数 | Stelligkeit | 列数.
S relation | attr | 属性 | Attribut | 一列.

D relschema | Ein Relationenschema R(A₁ : D₁, …, Aₖ : Dₖ) legt den Namen und die Struktur einer Relation fest; eine Sammlung solcher Schemata ist ein relationales Datenbankschema.
X relschema | 关系模式 (Relationenschema) 有两种形式化: 有序 (geordnet) 把模式看成 k 元组, 按位置找属性; 无序 (ungeordnet) 把模式看成属性的集合, 域用 dom 给出, 元组看成从属性名到值的映射. 有序写法紧凑, 插入时按顺序写值即可; 缺点是逻辑数据独立性受限: 应用按位置访问列时, 中间插入新属性会让后面的列错开, 所以新属性只能加在末尾. 两种定义等价, 本课都用.
S relschema | geord | 有序写法 | geordnet | 按位置找属性.
S relschema | ungeord | 无序写法 | ungeordnet | 按名字找属性.

D instanz | Eine Relationeninstanz r(R) ist der konkrete Inhalt eines Relationenschemas und kann als Tabelle mit n Spalten verstanden werden.
X instanz | 关系实例 (Relationeninstanz) 通常简称关系: 表头是模式, 每一行是一个元组; 整个数据库模式的实例是所有表的实例. 因为关系是集合, 有两条性质: 行没有顺序; 没有重复行, {(0, a), (0, a), (1, b)} 只有 2 个元素.
S instanz | ordnung | 行没有顺序 |  | 关系是集合.
S instanz | dup | 没有重复行 |  | 同一个元组只算一次.

D integ | Integritätsbedingungen sind Regeln, die Korrektheit, Konsistenz und Gültigkeit der Daten sicherstellen; sie werden bei der Schemadefinition angegeben und vom DBMS überprüft.
X integ | 完整性约束 (Integritätsbedingung) 是模式的一部分, 每个合法实例都必须满足; 每次插入、修改、删除时由 DBMS 自动检查, 违反就拒绝这次操作. 规则只写一次, 由 DBMS 统一守住, 这就解决了第 1 章的完整性问题. 例子: 主键和外键约束、唯一性约束、非空约束.

D key | Eine Attributmenge S ist ein Schlüssel, wenn keine Instanz zwei Tupel mit gleichen Werten in allen Attributen von S enthält (Eindeutigkeit) und keine echte Teilmenge von S eindeutig ist (Minimalität).
X key | 键 (Schlüssel) 用来唯一识别元组, 键属性加下划线. 唯一性 (Eindeutigkeit) 要求任何实例里都没有两个元组在 S 的所有属性上相同 (部分属性相同可以). 最小性 (Minimalität) 要求去掉任何一个属性唯一性就丢了. 只满足唯一性的是超键 (Superschlüssel); 整个属性集总是超键; 键就是最小的超键, 键的任何超集都是超键. 判断最小性只需检查去掉每一个属性后是否还唯一. 唯一性针对所有可能的合法实例, 所以要看现实语义: 从数据能否定一个键, 不能证明一个键.
S key | eind | 唯一性 | Eindeutigkeit | 没有两个元组在键上相同.
S key | minim | 最小性 | Minimalität | 去掉任何属性就不唯一.
S key | super | 超键 | Superschlüssel | 只满足唯一性.

D keytypes | Alle Schlüssel einer Relation heißen Kandidatenschlüssel; einer davon wird als Primärschlüssel ausgewählt.
X keytypes | 复合键 (zusammengesetzter Schlüssel) 由多个属性组成, 例如 (课程号, 学期), 两个属性都加下划线表示合起来是键. 一个关系所有的键合称候选键 (Kandidatenschlüssel), 设计时要全找出来; 从中选一个作主键 (Primärschlüssel). 没选中的候选键仍可以加 UNIQUE. 常见做法是加一个人工的单属性主键, 叫代理键 (Surrogatschlüssel): 别的表引用它时只存一列, 自然属性改变也不影响引用.
S keytypes | zus | 复合键 | zusammengesetzter Schlüssel | 多个属性合起来是键.
S keytypes | kand | 候选键 | Kandidatenschlüssel | 所有的键.
S keytypes | prim | 主键 | Primärschlüssel | 从候选键里选出的一个.
S keytypes | surr | 代理键 | Surrogatschlüssel | 人工加的单属性主键.

D fremd | Ein Fremdschlüssel ist eine Menge von Attributen einer Kind-Relation, die auf den Primärschlüssel einer Eltern-Relation verweist.
X fremd | 外键 (Fremdschlüssel) 指向被引用关系的主键, 两边属性的域必须一致; 从 ER 模型的联系类型转换来的关系一定需要外键. 复合主键必须用复合外键引用. 一个元组满足外键约束, 当且仅当外键属性里有 NULL (引用未知), 或外键值确实是父关系里某个元组的主键值. 联系类关系里几个外键合起来常常就是主键. 所有外键约束都满足时就保证了参照完整性 (referenzielle Integrität): 没有悬空引用 (defekte Referenz).
S fremd | kindeltern | 子关系与父关系 | Kind-Relation & Eltern-Relation | 引用方和被引用方.
S fremd | refint | 参照完整性 | referenzielle Integrität | 没有悬空引用.
S fremd | fknull | 外键可以为 NULL |  | 引用未知时允许.

D sqlddl | Mit CREATE TABLE werden Name, Attribute, Domänen und Integritätsbedingungen einer Relation in SQL definiert.
X sqlddl | CREATE TABLE 的骨架: 表名, 然后每列一行「列名、类型、可选的列约束」, 最后可以加表约束. 列名 = 属性, 类型 = 域. 执行后得到模式和一个空实例, 数据之后用 INSERT 插入. 常用类型: INTEGER、SMALLINT、FLOAT、DECIMAL(p, q) (精确小数, 适合金额)、CHAR(n) (定长, 不足补空格)、VARCHAR(n) (变长)、DATE、TIMESTAMP. SQL 关键字和不带引号的名字不区分大小写.
S sqlddl | typen | 数据类型 |  | INTEGER、DECIMAL、CHAR、VARCHAR、DATE.

D constr | In SQL werden Einschränkungen als Spaltenbedingungen (NOT NULL, PRIMARY KEY, UNIQUE, DEFAULT, CHECK, REFERENCES) oder als Tabellenbedingungen angegeben.
X constr | 列约束写在列定义后面, 只涉及这一列: NOT NULL 不能为空; PRIMARY KEY 是单列主键, 隐含非空和唯一; UNIQUE 是候选键 (NULL 可以有多个); DEFAULT w 省略时填 w; CHECK f 插入和修改时检查条件; REFERENCES t(a) 是外键. 省略的列有 DEFAULT 就用默认值, 没有就是 NULL, 列又是 NOT NULL 则插入失败. 表约束写在所有列之后, 可以涉及多列: 复合主键、复合 UNIQUE、复合外键 (按位置配对) 和跨列的 CHECK.
S constr | spaltenb | 列约束 |  | 只涉及一列.
S constr | tabb | 表约束 |  | 可以涉及多列.
S constr | check | CHECK |  | 插入和修改时检查条件.

D refakt | Eine referenzielle Aktion legt fest, was beim Löschen oder Ändern eines referenzierten Tupels geschieht, z. B. ON DELETE CASCADE oder ON DELETE SET NULL.
X refakt | 默认 (NO ACTION) 时父关系里被引用的行既不能删, 也不能改键值, 操作被拒绝, 否则子关系里会出现悬空引用. ON DELETE CASCADE: 跟着一起删除, 例如删除一位讲师, 他的讲授记录自动删除. ON UPDATE CASCADE: 外键值跟着改. ON DELETE SET NULL: 外键列设为 NULL.
S refakt | noaction | 默认拒绝 |  | 被引用的行不能删也不能改键值.
S refakt | cascade | 级联 |  | 跟着删除或修改.
S refakt | setnull | SET NULL |  | 外键列设为 NULL.
