# BS 深层内容. 依据 BS 01–04 笔记. 外文按课件写法 (德语, 夹英语术语).
# D 概念 | 德语定义   X 概念 | 讲解   S 父概念 | 子 id | 中文 | 外文 | 一句话

D bs | Ein Betriebssystem ist eine Sammlung von Software, die die Hardwareressourcen eines Rechensystems verwaltet und auf geeignete Weise für die Anwendungen verfügbar macht.
X bs | 用户只和应用程序打交道, 应用程序不直接碰硬件, 都通过操作系统. 定义里的两个关键词就是两项任务: 「合适的方式」= 抽象, 「管理」= 资源管理. 课程按三大支柱组织: 虚拟化、并发、持久化, 外加贯穿三者的安全; 01–04 讲的是第 1 部分虚拟化.
S bs | aufg | 两项任务 |  | 抽象和资源管理.
S bs | saeulen | 三大支柱 |  | 虚拟化、并发、持久化, 外加安全.

D abstr | Die erste Aufgabe eines Betriebssystems ist die Abstraktion: standardisierte Schnittstellen zu Ressourcen wie CPU, Speicher und Festspeicher.
X abstr | 好处: 同类功能可以复用 (每个程序不必自己写磁盘驱动); 不同硬件用同一个接口; 还能提供更高层的功能. 难点是什么才是正确的抽象, 硬件细节要暴露多少. 本课最重要的三个抽象: CPU → 进程 (Prozess) 和线程 (Thread), 内存 → 地址空间 (Adressraum), 硬盘 → 文件 (Datei). 程序打开文件时完全不用知道数据在 SSD 还是 U 盘的哪个扇区.
S abstr | cpuabs | CPU → 进程 |  | CPU 被抽象成进程和线程.
S abstr | memabs | 内存 → 地址空间 |  | 内存被抽象成地址空间.
S abstr | datei | 文件 | Datei | 硬盘的抽象.

D resv | Die zweite Aufgabe ist die Ressourcenverwaltung: Das Betriebssystem verwaltet Ressourcen und entscheidet über ihre Nutzung.
X resv | 好处: 保护应用程序不被彼此访问 (一个程序不能读另一个程序的内存); 高效使用资源 (成本、时间、能耗); 公平分配. 难点: 什么机制合适, 什么策略 (Policy) 是对的. 机制和策略这对概念贯穿整门课, 第 2 讲正式讲它们的分离.
S resv | schutz | 互相保护 |  | 一个程序不能读另一个程序的内存.
S resv | fair | 公平分配 |  | 资源公平地分给各个程序.

D hist | Betriebssysteme entwickelten sich von der Stapelverarbeitung der Mainframe-Ära über Systemaufrufe und gleichzeitige Prozesse (MULTICS, UNIX) zu PC- und modernen Betriebssystemen.
X hist | 1955–1965 大型机时代, 人工操作员做批处理 (Stapelverarbeitung), 把一叠作业依次交给机器. 1965–1980 出现严格意义上的操作系统: 系统调用、多个进程同时执行, 代表是 MULTICS 和 UNIX. 1980–2000 个人电脑: DOS、Windows、MacOS、Linux. 2000 年至今: Windows NT 系列、Linux、Mac OS X、Android、iOS. 「系统调用」和「同时执行进程」正是第 2 讲的主题.
S hist | stapel | 批处理 | Stapelverarbeitung | 把一叠作业依次交给机器.
S hist | unix | MULTICS 和 UNIX |  | 系统调用和多进程的开端.

D sysprog | Systemprogrammierung bedeutet, möglichst systemnah zu programmieren und das Betriebssystem direkt aufzurufen, statt über eine Laufzeitumgebung wie die JVM.
X sysprog | Java 程序跑在 Java 虚拟机上, Haskell 程序跑在 GHC 运行时系统上, 它们挡在应用和操作系统之间, 所以程序几乎不用改就能在 Windows、Linux、macOS 上运行. 想动手试验、真正理解操作系统的设计, 就要绕过这一层, 直接调用操作系统. 这就是本课用 C 的原因. C 为开发 UNIX 而设计, 是贴近系统的命令式语言; 优点是性能好、可预测、能直接用底层 API, 缺点是要手动管理内存、可移植性差.
S sysprog | warumc | 为什么用 C |  | 贴近系统, 直接调用操作系统.
S sysprog | laufzeit | 运行时挡在中间 |  | JVM、GHC 运行时把操作系统细节抽象掉了.

D build | Beim Buildprozess wird der Quelltext vom Compiler in Assembly übersetzt und vom Assembler in Binärcode, den die CPU ausführt.
X build | 源代码 (Quelltext) 由 clang 或 gcc 编译成汇编 (Assembly, 人能读的机器指令, 这里是 x86-64), 再由汇编器 (Assembler) 翻译成二进制 (Binary). 汇编和二进制一一对应, 例如 push %rbp 就是字节 55. 实际操作: clang -o 名字 源文件 (不写 -o 时叫 a.out), 再用 ./名字 运行; 要写 ./ 是因为当前目录通常不在 PATH 里. #include 只是预处理器把头文件文本复制进来, 函数实现在 C 标准库里, 链接时才接上.
S build | quell | 源代码 | Quelltext | 人写的程序文本.
S build | asm | 汇编 | Assembly | 人能读的机器指令.
S build | bin | 二进制 | Binary | CPU 真正执行的字节.

D ctyp | C kennt Ganzzahltypen (char, short, int, long, long long, jeweils signed oder unsigned), Gleitkommatypen und void; der Standard legt nur Mindestgrößen fest.
X ctyp | 标准只规定大小关系 char ≤ short ≤ int ≤ long ≤ long long 和最少位数, 实际大小看平台: long 在 64 位 macOS/Linux 上 64 位, 在 64 位 Windows 上只有 32 位; 要精确位数就用 <stdint.h> 的 int32_t、uint64_t. C 原本没有布尔类型: 比较结果是 int, 条件里 0 为假、其他任何值都为真, 所以 if (x) 不等于 if (x == 1). C 允许读取未初始化的变量, 但结果是未定义的 (undefiniert), 取决于系统; 变量一律显式初始化, 编译时加 -Wall.
S ctyp | groesse | 大小看平台 |  | 标准只规定最少位数.
S ctyp | bool | 0 为假, 其他为真 |  | C 原本没有布尔类型.
S ctyp | undef | 未定义行为 | undefiniert | 读未初始化变量的结果没有保证.

D decl | Eine Vorwärtsdeklaration gibt den Funktionskopf mit Semikolon an, bevor die Funktion aufgerufen wird, weil der Compiler die Datei von oben nach unten liest.
X decl | otherFun 定义在 main 下面时, 要在文件开头写 void otherFun(void); 告诉编译器后面会有这样一个函数. (void) 表示没有参数. 去掉声明会得到两个错误: 调用了未声明的函数 (C99 起不允许隐式声明, 旧 C 默认它返回 int), 以及后面真正的定义返回 void 和隐式假定的 int 类型冲突.
S decl | implizit | 不允许隐式声明 |  | C99 起调用前必须声明.

D ptr | Ein Pointer ist eine Variable, die eine Referenz zu einer anderen Variablen oder Datenstruktur enthält; in C sind Pointer explizit und ihr Wert ist eine Speicheradresse.
X ptr | 三个基本操作: int *p 声明; &var 取地址; *p = 5 解引用 (Dereferenzierung), 写到 p 指向的地方. * 在声明里表示「是指针」, 在表达式里表示「取指向的值」. int *p1, p2; 里 p2 只是普通 int. C 的参数传递一律按值: inc(n) 改不了 main 里的 n, inc(&n) 通过地址才能改; scanf("%d", &num) 要写 & 也是这个原因. Java 的引用对应 C 的指针, 区别是 C 的指针值能打印、比较、做加减.
S ptr | deref | 解引用 | Dereferenzierung | 通过指针读写它指向的值.
S ptr | byval | 按值传递 |  | 要改调用者的变量就传地址.

D array | Ein Array in C kennt zur Laufzeit seine Länge nicht, und Zugriffe werden nicht auf Indexgrenzen geprüft.
X array | int numbers[10]; 声明并分配一个局部数组, 内容不确定. 函数结束后还要用的数组必须用 malloc 显式分配, 用完 free, C 没有垃圾回收. 内存里只存数据本身, 没有长度信息, 越界时程序要么崩溃, 要么悄悄读写了别的数据. 这就是缓冲区溢出 (Pufferüberlauf), 一再导致严重漏洞, 例如 libwebp 的 CVE-2023-4863. 所以 C 函数接收数组时通常另外传一个长度参数.
S array | overflow | 缓冲区溢出 | Pufferüberlauf | 越过数组边界读写.
S array | malloc | 用 malloc 分配 |  | 函数结束后还要用的数组.

D str | Strings sind null-terminierte Arrays von Zeichen des Typs char und verbrauchen Länge + 1 Bytes; meist werden sie über einen Pointer auf das erste Zeichen referenziert.
X str | char name[] = "LMU"; 建一个大小正好的数组, 把 4 个字节 'L' 'M' 'U' '\0' 复制进去, 所以 sizeof(name) 是 4 而 strlen(name) 是 3. 字符串函数靠结尾的 0 判断字符串在哪里结束. const char *name = "LMU"; 只保存只读数据区里字符串常量的地址: 不能改内容, 但指针可以指向别处. char * const p 则反过来: 指针不能改, 内容能改. 记法: const 修饰紧挨在它左边的东西, 左边没有时修饰右边.
S str | nullterm | 以 0 结尾 |  | 占长度 + 1 个字节.
S str | constptr | const 的位置 |  | 修饰左边紧挨的东西.

D struct | Ein struct gruppiert mehrere Felder zu einem Typ; C-Structs haben keine Methoden, und die Felder liegen in Deklarationsreihenfolge im Speicher.
X struct | 加一个标签 (Tag) 后就能写 struct point p; 声明同类型的变量, 类型名是两个词. 结构体里放 char 数组时字符就在结构体内部; 放指针时字符串在外面, 要另外管理. 字符串字段不能直接赋值, 要用 strcpy. 通过指针取字段写 (*p).id, 括号不能省; 语法糖 (syntaktischer Zucker) p->id 意思相同. typedef 只给类型起别名, 不产生新类型; 链表节点要引用同类节点, 结构体内部只能用标签, 因为 typedef 的名字还没定义完.
S struct | tag | 标签 | Tag | struct point 才是完整的类型名.
S struct | arrow | 箭头写法 |  | p->id 等于 (*p).id.
S struct | typedef | typedef | typedef | 给类型起简称.

D cfunk | Grundlegende Funktionen in C sind puts, printf und scanf für Ein- und Ausgabe sowie strcmp, strlen, strcpy und strcat für Strings.
X cfunk | 查资料首选 man pages: 第 2 节是系统调用, 第 3 节是 C 库函数, 例如 man 2 read. printf 和 scanf 的格式必须和参数类型匹配, 用 %d 打印 long 是未定义行为; scanf 返回成功读到的项数. 四个字符串函数在 <string.h> 里: strcmp 按字典序比较 (相等返回 0), strlen 不含结尾的 0, strcpy 和 strcat 不检查长度, 目标缓冲区太小就溢出. 判断两个字符串相等要写 strcmp(a, b) == 0; a == b 比较的是地址.
S cfunk | io | 输入输出函数 |  | puts、printf、scanf.
S cfunk | strf | 字符串函数 |  | strcmp、strlen、strcpy、strcat.
S cfunk | manp | 手册页 | man pages | 第 2 节系统调用, 第 3 节库函数.

D prozess | Ein Prozess ist die Instanziierung eines Programms, die sich in einem Ablauf befindet und einen konkreten Zustand hat.
X prozess | 执行流程是一串依次执行的指令, 也就是一个或多个线程. 状态是影响程序执行或被它改变的一切: 寄存器 (包括栈指针和指令指针 / 程序计数器)、地址空间 (代码、堆、栈)、打开的文件. 把状态保存下来, 以后原样恢复, 进程就能接着运行, 这是上下文切换的基础. 程序是磁盘上静态的代码和数据, 进程是它的动态实例; 几个用户同时执行 ls 时, 程序文件只有一个, 进程有好几个.
S prozess | ablauf | 执行流程 | Ablauf | 依次执行的指令.
S prozess | zustand | 状态 | Zustand | 寄存器、地址空间、打开的文件.
S prozess | befz | 指令指针 | Befehlszeiger | 指向下一条要执行的指令.
S prozess | progproz | 程序与进程 |  | 静态的代码对动态的实例.

D thread | Ein Thread ist ein „leichtgewichtiger Prozess“: ein Ausführungsablauf ohne eigenen Adressraum, aber mit eigenem Zustand (Register, Stack).
X thread | 一个进程可以有多个线程. 两个进程在同一个地址上可能看到不同的值, 因为每个进程有自己的地址空间; 同一进程的两个线程共享地址空间, 看到的是同一个值.
S thread | teilen | 共享地址空间 |  | 同一进程的线程看到同样的内存.

D cpuvirt | Bei der Virtualisierung der CPU soll jeder Prozess den Eindruck haben, die CPU für sich zu haben; auf einem Uniprozessor wird die CPU zeitlich aufgeteilt (Time-Sharing).
X cpuvirt | 资源可以按时间或按空间分配: CPU 按时间, 几个进程轮流用一小段时间 (分时, Time-Sharing); 主存和硬盘按空间, 每个进程一块. 虚拟化不能牺牲性能, 所以用直接执行: 用户进程直接在硬件上运行, 不做模拟, 操作系统只负责创建进程并调用它的 main().
S cpuvirt | ts | 分时 | Time-Sharing | CPU 按时间分给进程.
S cpuvirt | direkt | 直接执行 |  | 进程直接在硬件上运行.

D lde | Bei der eingeschränkten direkten Ausführung laufen Prozesse direkt auf der CPU, Betriebssystem und Hardware behalten aber in gewissem Maße die Kontrolle.
X lde | 直接执行有三个问题: ① 进程可能执行特权操作, 例如读写别的进程的数据; ② 进程可能永远不结束 (慢、有 bug 或恶意), 操作系统必须能打断它; ③ 进程等 I/O 时白白占着 CPU. 对应的解法: 用户态 / 内核态加系统调用; 时钟中断 (抢占); 进程状态加就绪队列和事件队列. 这三问三答就是第 2 讲的骨架.
S lde | p1 | 问题 1: 特权操作 |  | 解法: 特权级和系统调用.
S lde | p2 | 问题 2: 收回 CPU |  | 解法: 时钟中断.
S lde | p3 | 问题 3: 慢速 I/O |  | 解法: 进程状态和队列.

D modes | Hardware-Unterstützung für Privilege Levels: User-Prozesse laufen im User Mode (eingeschränkt), das Betriebssystem im Kernel Mode (uneingeschränkt).
X modes | 特权级是 CPU 里一个专门的状态位. 只有内核态能执行和设备通信的指令. x86 有 0–3 四个 ring, 常用的只有 0 和 3. 特权操作: 访问整个主存、磁盘 I/O、lidt 这类指令 (能改中断描述符表就能控制整台机器). 用户态执行特权指令时 CPU 不执行它, 而是产生异常 (general protection fault), 内核通常终止这个进程, Linux 上显示 Segmentation fault.
S modes | usermode | 用户态 | User Mode | 受限模式.
S modes | kernelmode | 内核态 | Kernel Mode | 不受限模式.
S modes | priv | 特权级 | Privilege Level | CPU 里的状态位.

D syscall | Ein System Call ist ein vom Betriebssystem implementierter Dienst, den ein User-Prozess über eine Trap-Instruktion aufruft, die das Privilege Level wechselt.
X syscall | 读文件的例子: 进程调用 C 库的包装函数 read(), 它把系统调用号放进 %rax, 再执行 syscall 指令; CPU 切到内核态, 跳到内核启动时设好的固定入口; 入口代码用编号查系统调用表, 跳到 sys_read, 用这个进程专属的内核栈; 内核把数据填进进程的缓冲区; 最后用 return-from-trap 回到用户态. 安全在于用户进程只能控制调用号和参数, 入口由内核设定, 内核还会检查参数. strace 可以把程序执行的系统调用显示出来.
S syscall | trapi | trap 指令 | trap | 切换特权级的指令.
S syscall | eintritt | 固定入口 |  | 用户进程不能跳进内核的任意位置.
S syscall | rft | return-from-trap | return-from-trap | 回到用户态.

D mechpol | Für Multiprogrammierung braucht das Betriebssystem einen Mechanismus zum Wechseln zwischen Prozessen und eine Policy, die entscheidet, welcher Prozess wann läuft; beide werden getrennt.
X mechpol | 策略做决定, 以优化某个性能指标 (第 3 讲的调度器); 机制是执行决定的系统代码 (这里的分派程序). 机制决定状态转换怎样执行, 策略决定何时执行. 分开的好处: 换一种调度策略时, 切换进程的底层代码不用改; 同一个分派程序可以配不同的调度策略.
S mechpol | mech | 机制 | Mechanismus | 怎样切换.
S mechpol | policy | 策略 | Policy | 切给谁.

D dispatcher | Der Dispatcher ist der Mechanismus, der in einer Schleife einen Prozess eine Zeitscheibe lang laufen lässt, ihn anhält, seinen Kontext sichert und den Kontext eines anderen Prozesses lädt.
X dispatcher | 后两步合称上下文切换. 由此引出两个问题: 进程在 CPU 上运行时操作系统并没有在运行, 分派程序怎样重新拿到控制权 (协作式还是抢占式)? 要保存和恢复哪些上下文 (进程控制块)? 时间片 (Zeitscheibe) 是进程一次能连续运行的时间.
S dispatcher | zeitsch | 时间片 | Zeitscheibe | 进程一次能运行的时间.
S dispatcher | kontrolle | 怎样拿回控制权 |  | 协作式或抢占式.

D ctxsw | Ein Context-Switch sichert den Kontext des laufenden Prozesses und lädt den Kontext eines anderen Prozesses.
X ctxsw | 时序: 时钟中断到来, 硬件把进程 A 的 PC、SP、标志位存进 A 的内核栈, 切到内核态; trap 处理程序再存 A 其余的用户态寄存器; 调度策略决定换成 B 后调用 switch(): 把内核寄存器存进 PCB(A), 从 PCB(B) 装入, 切到 B 的内核栈; return-from-trap 从 B 的内核栈取出寄存器, 回到 B. 两次保存: 用户态寄存器在内核栈上, 内核寄存器在 PCB 里. 诀窍是 switch 换了内核栈, 硬件以为在返回 A, 读的却是 B 的.
S ctxsw | zweimal | 两次保存 |  | 用户态寄存器进内核栈, 内核寄存器进 PCB.
S ctxsw | kstack | 换内核栈 |  | 返回时就回到了新进程.

D koop | Beim kooperativen Multitasking vertraut das Betriebssystem darauf, dass ein Prozess die CPU durch den Aufruf eines Traps abgibt.
X koop | trap 的例子: 系统调用; 缺页 (Page Fault, 访问了不在主存里的页面); 错误 (非法指令、除以零); 专门让出 CPU 的系统调用 yield(). Windows 3.11 及以前、经典 Mac OS 9 及以前用这种方式. 缺点: 一个进程只要不触发 trap, 例如死循环 while (1) {}, 就能永久霸占机器, 只能重启. 现代操作系统不再用, 只有非常简单的嵌入式系统例外.
S koop | yield | yield() |  | 专门让出 CPU 的系统调用.
S koop | pf | 缺页 | Page Fault | 访问不在主存里的页面.

D praem | Beim präemptiven Multitasking erlangt das Betriebssystem durch Timer-Interrupts der Hardware garantiert regelmäßig die Kontrolle zurück.
X praem | 时钟中断 (Timer-Interrupt) 由 CPU 内部或单独的芯片产生: 传统的 tickful 内核固定周期 (例如每 10 ms), 现代 tickless 内核把时钟设到当前时间片结束的时刻, 空闲时不必被唤醒, 省电. 关键前提: 屏蔽中断的指令是特权指令, 用户进程不能屏蔽时钟中断.
S praem | timer | 时钟中断 | Timer-Interrupt | 到点自动进入操作系统.
S praem | tickless | tickless 内核 |  | 按需设定时钟.

D pcb | Der Process Control Block (Prozessdeskriptor) speichert den Kontext eines Prozesses, solange er nicht läuft; in Linux ist das task_struct.
X pcb | PCB 里存: 进程号 PID; 进程状态; 执行状态 (寄存器、程序计数器、栈指针); 调度优先级; 管理信息 (父进程、子进程); 权限; 打开的文件 (文件描述符). 中断发生时硬件自动把 PC、标志位和栈指针存到内核栈上, 这几样必须由硬件存, 因为内核代码一运行就会改掉它们. 第 4 讲的 base 和 bounds 寄存器也属于进程状态, 切换时存进 PCB.
S pcb | pid | 进程号 |  | 每个进程唯一的 PID.
S pcb | taskstruct | task_struct |  | Linux 内核里的 PCB.

D zust | Ein Prozess ist laufend (auf der CPU), bereit (wartet auf die CPU) oder blockiert (wartet auf I/O oder Synchronisation).
X zust | 正在运行的进程执行不需要 CPU 的操作 (例如 read() 访问慢速硬件) 时, 操作系统切换到需要 CPU 的进程. 四种转换: 运行 → 就绪 (被撤下, 例如时间片用完); 就绪 → 运行 (被调度); 运行 → 阻塞 (发起 I/O); 阻塞 → 就绪 (I/O 完成). 没有阻塞 → 运行: I/O 完成后要等调度器选中. 也没有就绪 → 阻塞: 只有运行中的进程才能发起 I/O.
S zust | laufend | 运行 | Laufend | 正在 CPU 上.
S zust | bereit | 就绪 | Bereit | 可以运行, 在等 CPU.
S zust | blockiert | 阻塞 | Blockiert | 在等 I/O 或同步.

D queues | Prozesse werden nach ihrem Zustand in Warteschlangen verwaltet: die Ready-Queue enthält alle bereiten Prozesse, je Ereignis gibt es eine Event-Queue mit den wartenden Prozessen.
X queues | 操作系统要跟踪系统里的每个进程, 每个进程有唯一的 PID. 事件队列每种事件一个 (例如磁盘 I/O、锁), 装的是阻塞的进程. 事件完成时, 操作系统把对应队列里的进程移进就绪队列. 从就绪队列里选哪一个, 是第 3 讲调度器的问题.
S queues | ready | 就绪队列 | Ready-Queue | 所有就绪的进程.
S queues | event | 事件队列 | Event-Queue | 每种事件一个.

D fork | fork() klont den aufrufenden Prozess; exec() ersetzt Code- und Datensegment des aktuellen Prozesses durch die einer ausführbaren Datei.
X fork | 创建进程原则上两种办法: 从零建一个空进程 (posix_spawn、CreateProcess, 参数很多), 或复制现有进程再修改 (Unix 的 fork + exec). fork 复制代码、数据、栈和 PCB, 子进程 (Kindprozess) 和父进程 (Elternprozess) 几乎一样, 只有返回值不同: 父进程里是子进程的 PID, 子进程里是 0. exec 换掉程序, PID 不变. 在 fork 和 exec 之间子进程可以重定向输出、改权限, shell 的 > 和 | 就在这里实现. 先复制再覆盖可能很浪费, 现代系统用写时复制 (copy-on-write): 父子先共享物理页面, 谁写才复制那一页.
S fork | kind | 子进程 | Kindprozess | fork 产生的新进程.
S fork | eltern | 父进程 | Elternprozess | 调用 fork 的进程.
S fork | cow | 写时复制 | copy-on-write | 有人写时才复制那一页.
S fork | shell | shell 的循环 |  | 读命令, fork, 子进程 exec, 父进程 wait.

D exitwait | Ein Prozess endet mit exit(retval); der Elternprozess wartet mit wait() bzw. waitpid() auf das Ende eines Kindprozesses und erhält dessen Rückgabewert.
X exitwait | main 执行 return 时也会自动调用 exit. 习惯上 0 表示成功, 在 shell 里用 echo $? 查看. 子进程结束后, 内核要保留它的 PCB 直到父进程调用 wait, 这段时间子进程是僵尸 (Zombie, defunct): 不运行、不占内存, 只占进程表的一项. 父进程先结束时, 子进程由 init (PID 1) 收养, init 立刻对它调用 wait. 一个从不 wait 的父进程不断创建子进程, 会把进程表占满, 最后 fork 失败.
S exitwait | zombie | 僵尸 | Zombie | 已结束、还没被 wait 的进程.
S exitwait | init | 由 init 收养 |  | 父进程先结束时.
S exitwait | retval | 返回值 |  | 0 表示成功.

D workload | Ein Workload beschreibt eine Menge von Jobs (Ankunftszeit, Laufzeit); ein Job ist eine Anforderung an die CPU für begrenzte Zeit, ein CPU Burst.
X workload | 一个进程在 CPU 和 I/O 之间交替, 也就在就绪队列和阻塞队列之间来回; 每段连续使用 CPU 的时间是一个作业. 四个简化假设: ① 每个作业运行时间相同; ② 所有作业同时到达; ③ 只用 CPU, 没有 I/O; ④ 运行时间事先已知. 课上每去掉一条就引出一种新的调度器, 这是 OSTEP 第 7 章的讲法.
S workload | job | 作业 | Job | 一次 CPU 突发.
S workload | burst | CPU 突发 | CPU Burst | 连续使用 CPU 的一段.
S workload | annahmen | 四个简化假设 |  | 运行时间相同、同时到达、只用 CPU、运行时间已知.

D scheduler | Der Scheduler ist die Policy, die entscheidet, welcher bereite Job die CPU erhält.
X scheduler | 调度器只管状态图里就绪 ↔ 运行这两条边: 什么时候把谁换上去. 它和执行切换的分派程序分开. 总结里的原则: 设计调度器要针对特定的指标和工作负载; 通用调度器必须支持目标不同的进程; 过去的行为是预测未来行为的好指标.
S scheduler | allzweck | 通用调度器 |  | MLFQ、CFS、EEVDF.

D metrik | Metriken für Scheduling sind u. a. Durchlaufzeit, Reaktionszeit, Wartezeit, Durchsatz, Ressourcenauslastung, Overhead und Fairness.
X metrik | 周转时间 (Durchlaufzeit) = 完成时刻 − 到达时刻, 要最小化. 响应时间 (Reaktionszeit) = 第一次运行的时刻 − 到达时刻, 交互式作业要尽快安排. 另外: 等待时间 (在就绪队列里等的时间) 最小、吞吐量最大、资源利用率最大、开销 (切换次数) 最小、公平性最大. 这些目标相互冲突: 响应时间好的调度要频繁切换, 周转时间和开销往往变差. 本讲主要比较前两项.
S metrik | durchlauf | 周转时间 | Durchlaufzeit | 从到达到完成.
S metrik | reaktion | 响应时间 | Reaktionszeit | 从到达到第一次运行.
S metrik | konflikt | 目标相互冲突 |  | 响应时间好, 周转时间往往差.

D fifo | FIFO (First In, First Out, auch FCFS) führt Jobs in der Reihenfolge ihrer Ankunft aus.
X fifo | 三个 10 秒的作业同时到达时, 周转时间 10、20、30, 平均 20 秒. 甘特图 (Gantt-Diagramm) 显示作业随时间在 CPU 上的执行. 去掉假设 1: A 要 60 秒、B 和 C 各 10 秒时, 平均周转时间变成 70 秒, 这就是护航效应.
S fifo | gantt | 甘特图 | Gantt-Diagramm | 作业随时间的执行图.

D konvoi | Beim Konvoi-Effekt müssen kurze Jobs hinter einem langen Job warten, wodurch die Durchlaufzeit steigt.
X konvoi | 一个慢作业排在前面, 后面所有作业只能跟着排队, 就像推着满满一车东西的人排在只买一瓶水的人前面. 后面的 SJF 就是为了避免护航.

D sjf | SJF (Shortest Job First) wählt immer den Job mit der kürzesten Laufzeit; bei gleichzeitiger Ankunft minimiert es die durchschnittliche Durchlaufzeit.
X sjf | 同一个工作负载 (A 60 s, B、C 10 s) 下 SJF 的平均周转时间约 36.7 秒. 为什么最优: 排在第 i 位的作业的运行时间会计入它自己和后面所有作业的完成时间, 越靠前被计入次数越多, 所以最短的放最前 (交换论证). 去掉假设 2 后 B、C 在第 10 秒才到, SJF 是非抢占的, 只能等 A 跑完, 平均约 63.3 秒, 护航又回来了.
S sjf | optimal | 同时到达时最优 |  | 交换论证.
S sjf | nachteil | 到达时间不同时失效 |  | 非抢占, 只能等长作业跑完.

D praemsch | Nicht-präemptive Scheduler starten einen neuen Job erst, wenn der aktuelle die CPU freigibt; präemptive Scheduler können dem aktuellen Job jederzeit die CPU entziehen.
X praemsch | 非抢占 (nicht-präemptiv) 时只有当前作业主动让出 CPU (exit、yield、开始 I/O) 才换人, FIFO 和 SJF 属于这一类. 抢占 (präemptiv) 时任何时刻都可以换, 需要抢占的机制, 也就是第 2 讲的时钟中断. STCF、RR、MLFQ、CFS 都是抢占式的.
S praemsch | nichtp | 非抢占式 | nicht-präemptiv | 等作业让出 CPU.
S praemsch | pr | 抢占式 | präemptiv | 随时可以剥夺 CPU.

D stcf | STCF (Shortest Time-to-Completion First, auch SRTF) führt immer den Job mit der kürzesten Restlaufzeit aus und kann dafür den laufenden Job unterbrechen.
X stcf | 同一个例子: 第 10 秒 B、C 到达时 A 还剩 50 秒, 所以抢占 A: A 0–10、B 10–20、C 20–30、A 30–80, 平均周转时间约 36.7 秒, 和同时到达时的 SJF 一样好. 它仍然依赖假设 4: 要知道每个作业还剩多少时间.
S stcf | srtf | SRTF |  | STCF 的另一个名字.

D rr | Round Robin wechselt die Prozesse der Ready-Queue nach jeder festen Zeiteinheit (Zeitscheibe); neue Prozesse werden am Ende der Ready-Queue eingereiht.
X rr | FIFO、SJF、STCF 都倾向于把作业一口气做完, 优化的是周转时间, 响应时间可能很差. 三个 5 秒的作业同时到达时, FIFO 平均响应时间 5, RR (时间片 1 秒) 只有 1. 缺点: 作业一样长时平均周转时间极差, 例中 RR 是 14 秒, FIFO 是 10 秒, 每个作业都被拖到最后. 不知道运行时间时短作业也能很快完成.
S rr | quantum | 时间片 | Zeitquantum | 每过一个时间片轮换.
S rr | rrnach | 周转时间差 |  | 作业一样长时每个都拖到最后.

D iosch | Bei Berücksichtigung von I/O wird jeder CPU Burst eines Jobs als eigener Job behandelt, sodass die CPU während der I/O eines Jobs einen anderen ausführt.
X iosch | 作业 A 运行 10 秒、读磁盘 10 秒、再运行 10 秒时, 把 A 当作一个整体, A 做 I/O 的时间 CPU 就闲着. 把每段 CPU 突发当作独立作业后, 用 STCF 时 A 的每一段都比 B 短, A 做 I/O 时 CPU 运行 B, CPU 和磁盘同时忙. 前三个假设都去掉了, 只剩「运行时间已知」: 现实中操作系统不知道作业要跑多久, 需要从过去的行为推测, 这就是 MLFQ.
S iosch | overlap | CPU 和 I/O 重叠 |  | 利用率提高.

D mlfq | Die Multi-Level Feedback Queue besteht aus mehreren RR-Warteschlangen mit verschiedenen Prioritäten; die Priorität richtet sich nach dem bisherigen Verhalten des Prozesses.
X mlfq | 它要同时照顾交互式程序 (看重响应时间) 和批处理程序 (看重周转时间). 规则 1: 优先级高的先运行. 规则 2: 同级按 RR. 规则 3: 新进程从最高层开始. 规则 4: 用完整个时间片就降一级, 低层时间片更长. 计算密集 (CPU-bound) 的长作业逐渐沉到底层, 交互式进程 (I/O-bound) 一直留在顶层, 不需要知道运行时间就近似 SJF. 两个问题: 底层作业可能饿死 (Verhungern), 进程行为也会变, 所以定期把所有作业的优先级提高; 进程可以在时间片快用完时做一次 I/O 钻空子, 所以改为累计计算它在这一层用了多少 CPU 时间.
S mlfq | regeln | 四条规则 |  | 高优先、同级 RR、新进程在顶层、用完时间片降级.
S mlfq | cpubound | 计算密集 | CPU-bound | 沉到底层.
S mlfq | hunger | 饿死 | Verhungern | 定期提升优先级.

D cfs | Der Completely Fair Scheduler (Linux) berechnet, wie viel CPU-Zeit jedem Prozess zusteht, und plant immer den Prozess mit der bisher geringsten (gewichteten) CPU-Zeit, der vruntime.
X cfs | 就绪进程按 vruntime 存在红黑树里, 最左节点 vruntime 最小, 下一个就调度它; 查找插入删除 O(log n), 最左节点有缓存. 每个时间片结束更新 vruntime. 进程进入就绪队列时 vruntime 至少设为当前最小值, 否则睡了很久的进程醒来会独占 CPU. 时间片 = sched_latency (例如 48 ms) / 进程数, 但不低于 min_granularity (例如 6 ms), 9 个进程时就取 6 ms. 结果是各进程的 vruntime 始终相差不超过一个时间片.
S cfs | vrt | 虚拟运行时间 | vruntime | 加权后的已用 CPU 时间.
S cfs | rbtree | 红黑树 |  | 最左节点就是下一个.
S cfs | latency | sched_latency |  | 一轮的基准长度, 平均分给进程.

D cfsprio | Nice-Werte von 19 (sehr niedrig) bis −20 (sehr hoch) werden in Gewichte von 15 bis 88761 umgerechnet; Prozesse mit hoher Priorität erhalten längere Zeitscheiben, und für sie vergeht die Zeit langsamer.
X cfsprio | 进程 k 的时间片 = 它的权重占所有就绪进程权重之和的比例 × sched_latency. 运行 runtimeₖ 后 vruntime 增加 weight₀ / weightₖ · runtimeₖ, weight₀ = 1024 是 nice 0 的权重. 权重大的进程 vruntime 涨得慢, 更常被认为最需要 CPU. nice 相差一级权重约差 25%, CPU 份额约差 10 个百分点. 例: A nice 5 (权重 335) 和 B nice 0 (1024), A 的时间片 11.83 ms, B 36.17 ms, 两者 vruntime 同步增长, 实际 CPU 时间 A 只有 B 的约三分之一.
S cfsprio | nice | nice 值 |  | 19 最低, −20 最高.
S cfsprio | weight | 权重 | Gewicht | nice 0 是 1024.

D eevdf | Earliest Eligible Virtual Deadline First basiert auf CFS und verwendet zusätzlich eine virtuelle Deadline; seit 2023 (Linux 6.6) ist es der Standard-Scheduler von Linux.
X eevdf | 进程 k 的虚拟截止时间 = vruntime + 按权重折算的请求时间片. 进程可以用 sched_setattr 自己选时间片长度. 得到的 CPU 时间没有超过应得份额的进程是可行的 (eligible); EEVDF 在可行的进程里选截止时间最早的. 时间片短的进程更快重新轮到, 但每次运行更短. CFS 只看谁欠得最多, 音频、界面这类延迟敏感的进程没法表达「频繁而短暂地运行」, EEVDF 用截止时间把这一点纳入, 而「可行」保证短时间片不会多拿 CPU.
S eevdf | deadline | 虚拟截止时间 |  | vruntime 加折算后的请求时间片.
S eevdf | eligible | 可行 | eligible | 没有超过应得份额.

D uni | Bei Uniprogrammierung läuft nur ein Prozess zur Zeit, der auf den gesamten Speicher zugreifen kann; der physische Speicher ist der Adressraum.
X uni | 最低处是操作系统, 上面是用户进程 (代码、堆、栈). 缺点: 一次只能运行一个进程; 没有保护, 进程可以覆盖甚至接管操作系统. 多道程序 (Multiprogrammierung) 下就需要内存虚拟化.
S uni | multi | 多道程序 | Multiprogrammierung | 多个进程同时在内存里.

D memvirt | Bei der Virtualisierung des Speichers erhält jeder Prozess die Illusion eines privaten Adressraums; Mechanismen sind Time-Sharing, statische Verschiebung, dynamische Verschiebung, Base + Bounds und Segmentierung.
X memvirt | 第 1 部分虚拟化的两半: 虚拟 CPU 的抽象是进程, 机制是上下文切换, 策略是调度; 虚拟内存的抽象是地址空间, 机制是地址转换、分页、换出, 策略是页面置换. 四个目标: 透明 (进程不知道内存是共用的)、保护 (不能破坏操作系统和别的进程, 也不能读别人的数据)、效率 (不浪费内存)、共享 (合作的进程可以共用部分地址空间). 问题在于地址已经写死在每个进程的机器码里, 例如 x = x + 3 的三条指令一共 5 次内存访问, 地址都是固定的; 多个进程同时运行时要避免冲突. 后面每种机制都按四个目标评价.
S memvirt | ziele | 四个目标 |  | 透明、保护、效率、共享.
S memvirt | fuenf | 五种机制 |  | 分时、静态重定位、动态重定位、base + bounds、分段.

D adr | Jeder Prozess hat einen Adressraum, eine Reihe von Adressen, die auf Bytes abgebildet werden; er hat statische (Code, globale Variablen) und dynamische Komponenten (Stack, Heap).
X adr | 代码在最低处, 堆紧挨在上面向高地址长; 栈在最高处向低地址长; 两者朝中间的空闲区长, 不用事先定好各自的大小. 进程需要动态内存, 因为编译时不知道要多少内存、递归不知道会嵌套多少层、链表和树的节点数运行时才知道. 动态分配有栈和堆两种. 程序里的对象: 全局变量在静态数据区, 函数的机器码在代码区, 局部变量 (包括指针变量本身) 在栈上, malloc 出来的东西在堆上.
S adr | statisch | 静态部分 |  | 代码和全局变量.
S adr | dynamisch | 动态部分 |  | 栈和堆.

D stack | Der Stack ist nach dem LIFO-Prinzip organisiert: Speicher wird in umgekehrter Allokationsreihenfolge freigegeben, und ein einziger Stackpointer trennt belegten und freien Bereich.
X stack | 分配就是把栈指针减小 (栈向低地址长), 释放就是增大, 所以极快, 但只能按固定顺序. 栈顶是当前函数的栈帧 (Stack Frame), 存局部变量和参数; 每次递归调用都有自己的一套变量. 释放的内存不会马上清除, 要等以后的栈帧覆盖, 所以返回指向局部变量的指针是经典错误: 看似正常, 下一次函数调用就把它覆盖了.
S stack | sp | 栈指针 | Stackpointer | 分开已用和空闲部分.
S stack | frame | 栈帧 | Stack Frame | 一次函数调用的局部变量和参数.

D heap | Der Heap besteht aus Objekten, die unregelmäßig und mit statisch unbekannter Größe allokiert werden und zu beliebigen Zeitpunkten freigegeben werden können.
X heap | Java 的 new、Haskell 对构造器求值都在堆上分配. 堆对象的生命期事先不确定, 释放顺序任意, 空闲空间会变得零碎. 优点: 适用于任何数据结构; 缺点: 分配可能慢, 用一段时间后出现外部碎片. 操作系统一次给进程一大块, 每次分配由标准库管理: malloc 按字节数分配, free 释放 (不用给大小), realloc 改变大小, 必要时搬家, 旧指针之后不能再用. main 返回时没 free 的堆内存就是内存泄漏.
S heap | api | malloc、free、realloc |  | C 的堆接口, 在 stdlib.h 里.
S heap | halde | Halde | Halde | 堆的德语别名.

D freelist | Die Free List ist eine verkettete Liste der freien Blöcke im Heap, die die Standardbibliothek bei malloc und free pflegt; die Listenknoten liegen in den freien Blöcken selbst.
X freelist | malloc 从链表里挑一个空闲块, 切下请求的大小, 剩下的放回链表; free 把块放回链表, 并合并 (coalescing) 相邻的空闲块. 挑块策略: First Fit 找第一个够大的 (快); Best Fit 找能放下的最小块 (要扫全表, 留下很多极小碎块); Worst Fit 找最大的块; Next Fit 从上次切开的块之后找. 一般没有最优策略, 要看程序的使用模式. 例: 空闲块 10、30、20, 申请 15: First Fit 用 30, Best Fit 用 20, Worst Fit 用 30.
S freelist | ff | 首次适应 | First Fit | 第一个够大的块.
S freelist | bf | 最佳适应 | Best Fit | 能放下的最小块.
S freelist | wf | 最差适应 | Worst Fit | 最大的块.
S freelist | nf | 循环首次适应 | Next Fit | 从上次的位置接着找.

D buddy | Beim Buddy Allocator sind Speicherblöcke als Binärbaum mit Zweierpotenzgrößen organisiert; bei der Allokation wird halbiert, bei der Freigabe mit dem freien Buddy verschmolzen.
X buddy | 分配时找尽量小的空闲块, 不断对半分, 直到再分就放不下请求. 释放时伙伴 (同一次对半分出的另一半) 也空闲就合并, 并递归向上. 大小 2ᵏ、地址 a 的块, 伙伴在 a XOR 2ᵏ, 例如地址 32 的 16 字节块伙伴在 48. 元数据: 每种大小一个空闲链表, 每个块一个状态位和「阶」. 缺点: 最小块大小固定; 申请 6 字节拿到 8 字节, 浪费在块里面, 这是内部碎片.
S buddy | xor | 伙伴地址 |  | 地址 XOR 块大小.
S buddy | merge | 递归合并 |  | 伙伴空闲就合并, 再往上.

D frag | Interne Fragmentierung ist ungenutzter Platz innerhalb zugeteilter Blöcke fester Größe; externe Fragmentierung entsteht, wenn genug Speicher frei ist, jeder freie Block aber zu klein ist.
X frag | 外部碎片 (externe Fragmentierung): 反复分配和释放后, 例子里一共 28 字节空闲, 最大的连续块只有 16 字节, 申请 20 字节就失败, 浪费在块与块之间. 内部碎片 (interne Fragmentierung): 分配器发固定大小的块 (如伙伴分配器), 块里用不到的部分浪费掉. 两种问题不只出现在堆里: base + bounds 和分段在物理内存里产生外部碎片, 下一讲的分页产生内部碎片.
S frag | extern | 外部碎片 | externe Fragmentierung | 浪费在块之间.
S frag | intern | 内部碎片 | interne Fragmentierung | 浪费在块里面.

D time | Bei der zeitlichen Aufteilung des Hauptspeichers wird, analog zur Virtualisierung der CPU, der gesamte Speicher eines nicht laufenden Prozesses auf den Festspeicher ausgelagert.
X time | CPU 是这样虚拟化的: 进程不运行时把寄存器存到内存. 类比到内存: 进程不运行时把整个内存存到磁盘. 问题: 每次上下文切换都要读写磁盘, 时间片是毫秒级, 写出几百 MB 却要以秒计, 性能是灾难. 所以后面的方案都让进程同时共用内存, 按空间分割.

D statisch | Bei der statischen Verschiebung schreibt das Betriebssystem jedes Programm um, bevor es als Prozess in den Speicher geladen wird, und verwendet für verschiedene Prozesse unterschiedliche Adressen.
X statisch | 改的是跳转目标和静态数据的地址, 例如同一段代码给进程 1 改成从 0x1000 开始, 给进程 2 改成从 0x3000 开始; 栈上相对 %rbp 的地址不用改. 缺点: 没有保护, 进程仍可以访问任何物理地址; 装好以后地址写进了代码, 地址空间不能再移动.
S statisch | keinschutz | 没有保护 |  | 进程仍能访问任何物理地址.

D dynamisch | Bei der dynamischen Verschiebung ändert die MMU die Prozessadresse bei jeder Speicherreferenz: physische Adresse = logische Adresse + Basisregister.
X dynamisch | 进程产生逻辑 (虚拟) 地址, 内存硬件用物理 (实际) 地址. 硬件要提供两种模式: 内核模式下地址不经转换, 操作系统可以改 MMU; 用户模式下 MMU 把每个地址加上基址. 例: P1 在 1 KiB、P2 在 4 KiB, P1 的 100 → 1124, P2 的 100 → 4196. P2 写不进 P1, 但 P1 的 store 3072 会写到 4096, 正好是 P2 的开头: 只有基址没有上界, 保护不完整. 转换必须由硬件做 (每次访问都要转换), 基址寄存器只能由操作系统在特权模式下修改.
S dynamisch | logadr | 逻辑地址 | logische Adresse | 进程自己地址空间里的地址.
S dynamisch | physadr | 物理地址 | physische Adresse | 内存硬件用的地址.
S dynamisch | basis | 基址寄存器 | Basisregister | 存地址空间的起点.

D mmu | Die Speicherverwaltungseinheit (MMU) ist Hardware, die bei jeder Speicherreferenz logische in physische Adressen übersetzt; sie wird vom Betriebssystem konfiguriert.
X mmu | 最简单的 MMU 只有一个基址寄存器, 加上界限寄存器后先比较再相加, 两步可以在硬件里并行, 所以很快. 分段时 MMU 里每个进程一张段表. 操作系统不参与每一次转换, 只在上下文切换和出错 (越界异常) 时介入.
S mmu | segtab | 段表 | Segmenttabelle | 分段时 MMU 里的表.

D bb | Bei Base + Bounds begrenzt ein Boundsregister den Adressraum: Ist die logische Adresse nicht kleiner als Bounds, wird eine Exception ausgelöst, sonst wird Basis addiert.
X bb | 基址是最小的物理地址, 界限是虚拟地址空间的大小 (有时定义成允许的最大物理地址). 同一个例子界限都是 1024 时, P1 的 store 3072 ≥ 1024, MMU 产生异常, 操作系统终止 P1. 上下文切换时两个寄存器存进 PCB, 用户进程不能修改它们, 也不能自己切到特权模式. 优点: 进程之间读写都受保护; 进程可以整个搬走 (复制内存、改基址); 简单便宜; 快. 缺点: 每个进程要一整块连续物理内存, 堆和栈之间的空隙也占着; 不能只共享一部分 (如共享库).
S bb | bounds | 界限寄存器 | Boundsregister | 存地址空间的大小.
S bb | exc | 异常 | Exception | 越界时陷入操作系统.

D seg | Bei der Segmentierung wird der Adressraum in logische Segmente (Code, Stack, Heap) unterteilt, die unabhängig platziert, vergrößert und geschützt werden können.
X seg | 可以理解成每个段一对 base + bounds, 堆和栈之间的空隙不再占物理内存. 地址的高位选段, 低位是段内偏移; 位数不够时由访问类型隐式决定, 或用 x86 的段寄存器. 段表每段有 Base、Bounds 和保护位. 换算: 14 位地址、4 个段时段号 2 位、偏移 12 位; 0x2010 的高 2 位是 10 = 段 2, 偏移 0x010, 物理地址 = 该段 Base + 0x010. 先拆段号再加 Base, 不能把整个虚拟地址加上 Base. 写只读段或偏移超过 Bounds 都会触发异常. 堆不够时 malloc 用 sbrk 推高堆段的界限. 缺点: 段大小不一, 仍有外部碎片, 下一讲的分页用固定大小的页解决.
S seg | segnr | 段号与偏移 |  | 高位选段, 低位是偏移.
S seg | schutzbit | 保护位 |  | 每段单独的读写权限.
S seg | sbrk | sbrk() |  | 推高堆段的界限.
